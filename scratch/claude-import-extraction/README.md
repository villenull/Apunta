# Claude conversation capture — extraction prototype

A research prototype for lane 1 of
`docs/research/claude-direct-import-feasibility.md`: can a browser extension walk
a signed-in Claude account and hand Apunta a file the **existing** importer
already reads, without losing anything and without claiming completeness it did
not achieve?

Findings and the criterion-by-criterion verdicts are in
`docs/research/claude-import-extraction-results.md`. Sources are in `SOURCES.md`.
The extension's shape and its costs are in `extension/NOTES.md`. The second
stage — D1, D15, and the browser run — is in
`docs/research/claude-import-browser-readiness.md`. The third — the relay, the
hardened ancestry classifier, and a real click-through with a download read back
from disk — is in `docs/research/claude-import-relay-results.md`.

## Everything here is synthetic

There is no real account, no real export, no browser profile, no cookie, no
patient record and no port in this directory. The account the tests walk is
`fixtures/truth.mjs` — sixteen invented conversations, written by hand, with
English names from the prototype's sample people and Spanish names from the
`e2e/fixtures/eval-es/NAMES.md` registry. No exporter code has been executed
against anything. The one place a real repository file is read is
`server/src/import/claude.ts`, imported read-only by
`test/importer-contract.test.mjs` to prove the contract.

## Running it

```sh
# the four dependency-free suites (Node's own runner, no repository tooling)
node --test scratch/claude-import-extraction/test/traversal.test.mjs \
            scratch/claude-import-extraction/test/resilience.test.mjs \
            scratch/claude-import-extraction/test/fidelity.test.mjs \
            scratch/claude-import-extraction/test/extension.test.mjs

# everything, including the two files that read the real TypeScript importer
node_modules/.bin/tsx --test scratch/claude-import-extraction/test/*.test.mjs

# the extension, as the files Chrome loads: parse, allow-list, format guard,
# save gate, and byte-equality with the reference walk
node --test scratch/claude-import-extraction/test/extension.test.mjs

# the relay, offline: bounded messages, correlation, validation, tab resolution,
# and the thirteen ancestry shapes
node --test scratch/claude-import-extraction/test/relay.test.mjs

# the user path, in a real browser, by pressing real buttons. Needs a sandbox run
# folder from scripts/v2/sandbox.mjs and two free ports in 7800-7889.
RUNFOLDER=$(node scripts/v2/sandbox.mjs env --port 7815 \
  | grep -oP "(?<=APUNTA_DATA_DIR=')[^']+" | xargs dirname)
node scratch/claude-import-extraction/browser/roundtrip.mjs "$RUNFOLDER" 7815 7816
node scratch/claude-import-extraction/browser/check.mjs "$RUNFOLDER" 7815 7816

# the repository's own checks, which cover this directory
npx eslint scratch/claude-import-extraction
npx prettier --check "scratch/claude-import-extraction/**/*.{mjs,md,json}"
```

No network, no port, no database, no fixture on disk that is not generated by the
tests themselves in a temporary directory. `tsx` is the repository's existing dev
dependency and is used only to load TypeScript; nothing is installed.

## The shape of it

```
src/canonical.mjs    sorted-key JSON and SHA-256, so a digest is evidence
src/shapes.mjs       one normalizer per response shape, into the export shape
src/sources.mjs      the two mechanisms over one `request` seam
src/walker.mjs       inventory → every conversation → every artifact, with a
                     checkpoint after each unit and one honest verdict at the end
src/checkpoint.mjs   memory and atomic-file stores, digest-guarded
fixtures/truth.mjs   the account, specified by hand
fixtures/account.mjs the account as an HTTP-shaped `request`, able to misbehave
fixtures/expected.mjs what a correct capture must contain, written independently
extension/           a loadable MV3 prototype: core, page world, ISOLATED bridge,
                     worker, popup, mock
browser/check.mjs    the walk, in Chromium, on a throwaway profile
browser/roundtrip.mjs the user path: real popup click, real relay, real download
test/                traversal, resilience, fidelity, branch fidelity, extension,
                     relay, and the contract with the importer that exists
```

The seam is the whole design: `request(method, url) -> {status, json}`. Everything
above it — the walk, the normalizers, the manifest, the verdict — is
mechanism-agnostic, and the only difference between the tests and a live run
would be that one function.

## The verdict

A capture is `complete`, `complete_with_gaps`, `partial` or `blocked`, and the
first two carry the reason. The file may be handed to the import side only when
the verdict is `complete`, or when it is `complete_with_gaps` and a person has
acknowledged the named gaps. `partial` and `blocked` are never handoffable,
which is the property the rest of the prototype exists to make hard to violate.
