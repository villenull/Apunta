# Four-model local comparison — 2026-09-22

This report is Linux-only, synthetic-only evidence. It does not claim clinical safety, Mac fit, or a production replacement. No patient database, export, recording, or cloud evaluator was used.

## Decision

**Retain the current `qwen3.5:4b-q4_K_M` control for now.** The four-arm synthetic corpus completed on Linux; the control has the lowest observed fabrication flag rate and strongest safety denominator among the four. The smaller Qwen and both Bonsai Q1_0 candidates introduce more corpus failures, so no replacement is justified. Corrected reset-cold/keep-alive performance arms are recorded separately and are not allowed to override quality and safety regressions.

## Reproducibility contract

- Runner: `scripts/model-comparison/runner.ts`; acquisition: `scripts/model-comparison/acquire.mjs`; schema: `scripts/model-comparison/schema.mjs`; artifact catalog: `scripts/model-comparison/artifacts.json`.

- Schema records use version `1.1.0`; unavailable timing/memory values are
  `null` and carry a condition/method reason. Non-null numbers are finite,
  non-negative and unit-labeled by field name (`Ms`, `Bytes`, token counts).
  `processIdentity`, `baselineVramBytes`, and `peakVramDeltaBytes` are
  optional only for retained historical rows created before those fields were
  added; new measurements emit them. The retained corpus's
  `environment.revision` is the literal `working-tree-frozen-by-integrator`,
  not a commit fingerprint, and is reported as-is rather than retroactively
  rewritten. Corrected performance arms restart the isolated Ollama service
  before the first request (cold load), then issue sequential requests with
  `keep_alive=30m` (warm residency); each record carries sample count. RSS

  frame/event sampling); VRAM uses DRM counters when available, with same-host
  GPU isolation caveat.

Frozen hashes: see `scripts/model-comparison/freeze.json` generated by `node scripts/model-comparison/freeze.mjs`; the final run records the exact revision and all fixture/instruction/rubric/schema hashes.

## Accuracy and safety rubric

The existing rubric is reused rather than replaced. Lead endpoint is fabrication: F1 banned strings and gating F6 unsupported conclusions. Secondary denominators include structural validity, salient-fact coverage, safety-fact all-or-nothing coverage, blank preservation, required uncertainty markers, section routing, retraction correction, number/negation fidelity, and retry/truncation failures. The existing corpus also reports its original F7/medication/clinical-term flags transparently where present; those are descriptive corpus evidence, **not** an adoption blocker or optimization target for this user scope. Ordinary session fidelity, risk negation, numbers and retraction safety remain the promotion gates. Every row names expected and observed facts in the raw record. Manual review samples source/output pairs for intent inflation, chronology, negation, retraction topic, section routing, and prior-note provenance; deterministic scores are not called clinical safety.

## Raw evidence and limitations

Raw compact records: `scripts/model-comparison/results/records.jsonl` (generated,
synthetic only). Corrected representative performance records:
`scripts/model-comparison/results/perf-final.jsonl` and
`perf-final-summary.json`; per-arm files retain the 11 records and source
fingerprint. Contract/smoke/near-budget records are in the same results
directory; strict retained-output Discussion rescore is
`discussion-matrix.jsonl`, implemented by `rescore-discussion.mjs`.
`freeze.json` is the current reproduction input/fingerprint set; it is not
retroactive source proof for the historical corpus rows. The diagnostic
`app-*` text probes and `critical-app-matrix.jsonl`/`refine-critical-probe.jsonl`
files have distinct app-check shapes and are not common benchmark records.
Acquisition evidence: disposable artifact directory outside the repository
plus final Ollama tags. The runner records unsupported arms explicitly.
Limitations include one Linux workstation, one Ollama version/backend,
synthetic language, no physical microphone/room test, no Mac test, no cloud
grader, and no claim that historical daemon-only sampling is a corrected
performance measurement.

## Recommendation

Retain the current control with **no automatic model switch**. The corpus comparison favors the control on fabrication flags (18/60), gated runs (42/60), safety facts (42/60), and retraction/negation (54/60), while qwen2, Bonsai8 and Bonsai4 are worse on one or more of those dimensions. Bonsai4's warm p50/p95 (734/756 ms) and lower sampled RSS are descriptive only: the 19-word smoke output was not equal work, and its real-app critical gate failed. More importantly, the real 4B app run exposed an absolute retraction/number failure and retained withdrawn content; no candidate is clinically cleared by this comparison. Promotion requires manual review, preserved retraction/negation/number behavior, no schema/truncation regression, and no new fabrication/safety regression; smaller weights or provider speed alone are not actionable wins.
