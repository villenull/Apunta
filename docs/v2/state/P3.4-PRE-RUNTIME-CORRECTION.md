exists to do it. The string comparison is the whole bug.

## 2. The exact patch (`02-patch.diff`, 4 hunks, +43/−20, one file)

1. **`waitForLabel(stderrSource, label, deadline, clock, schedule)`** takes the
   *existing* deadline and clock and waits with the **existing shared
   `pollObservation`** (same 250 ms `OBSERVATION_POLL_MS` step, through the
   injected `schedule`). No private timer, no `Date.now()` budget, no new helper.
   A label that is not unique yet stays "not yet"; only the deadline ends it.
2. **`patientDeadline = createTargetDeadline(clock.now())` before** the label
   discovery, and the **same object** goes to `runFlowGuarded` (identically
   `noteDeadline`). No second budget, no time-widen, no reset/extend.
3. **`runFlowGuarded` tests `args.deadline.expired(args.clock.now())`** on
   failure instead of the reason string. The result shape is unchanged, so the
   model is **not** re-ported and no new field appears. `killActiveCommands` is
   untouched: still this harness's own tracked pids, never `pkill`.
4. The two `check(…, false, …)` messages keep their before-texts and append the
   poll's own reason. The one over-width line is wrapped exactly the way prettier
   formats it, so applying the patch keeps `npm run lint` green.
