## 3. The V3 command, decoded exactly (not executed here)

The decode is mechanical and is the card's own codec plus one strip. Derived and
proved on synthetic fixtures only, in
`static-completion-proposal/01-decode-and-negative-control.txt`:

1. read the cell through `parseCells` (`docs/v2/tools/plan-lib.mjs`, via
   `parseCard`), which trims it and GFM-unescapes `\|` → `|`;
2. **strip exactly one leading and one trailing code-span backtick** (the step
   attempt 6 omitted);
3. assert the decoded body contains **no residual backtick** and does **not**
   start or end with one — the structural guard `bash -n` cannot provide,
   because `bash -n` exits 0 on the bad wrapper (it is a valid command
   substitution);
4. `bash -n` the decoded body: exit 0;
5. record the body's sha256, execute once, record exit and output.

The decoded V3 body is byte-identical to the corrected cell the runtime worker
already recorded (`build/p34-runtime6/V3.command.corrected.txt`, sha256
`94dd69952e08bc153165fa6503901a02f9760777e89c5f52bbc744b197de4168`, 624 bytes),
`bash -n` clean. It is reproduced verbatim in
`static-completion-proposal/02-decoded-v3-command.txt`; a reviewer can compare
the executed bytes to that hash, which is what makes the exit attributable.

**Synthetic-fixture negative control** (proved, `01`): a body still wrapped in
backticks passes `bash -n` (exit 0) but the structural guard fires, and running
the wrapper on a harmless synthetic `printf` reproduces the attempt-6 symptom
exactly — exit 127, `P3.4-V3:: command not found`. No V3 shipping guard was run
to prove this.
