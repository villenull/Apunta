## 1. The blocker, in one paragraph (qualified per IR-04)

The AppImage bundles GStreamer's **core** libraries but no plugins and no
scanner, and `AppRun.wrapped` **unconditionally** sets
`GST_PLUGIN_SYSTEM_PATH_1_0=$APPDIR/usr/lib/gstreamer-1.0:<prior>`, replacing
GStreamer's compiled-in `/usr/lib/gstreamer-1.0`. The host's `libgstapp.so`
(which provides `appsink`) is therefore invisible inside the AppImage — hence
`GStreamer element appsink not found` while `gst-inspect-1.0 appsink` exits 0 on
the host. Separately `autoaudiosrc`/`alsasrc`/`pulsesrc` are genuinely **not
installed** (only `gst-plugin-pipewire` and the `-libs` packages). Two problems;
`E6` alone fixes neither.

The supported fix for the first is one supported config key,
`bundle.linux.appimage.bundleMediaFramework` (`@tauri-apps/cli` 2.12.1 schema,
`default: false`): it copies the host's plugins and installs an AppRun hook
pointing at them. It copies the scanner only from the script's guessed helpers
directory, **which does not exist on Arch**, so on this host the flag alone does
**not** bundle `gst-plugin-scanner` (IR-04; §2c). It cannot add plugins the host
lacks, so the install must come **first**.
