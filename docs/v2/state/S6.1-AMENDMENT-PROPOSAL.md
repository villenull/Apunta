# S6.1 bounded amendment proposal — for owner approval

**Status: A PROPOSAL. Nothing here is applied.** `docs/v2/state/reviews/S6.1-ir.md`
returned DEFECT on eight of its ten checks and CLEAR on two. This file supplies
the missing inputs and drafts the exact replacement card text. It changes **no
candidate, no threshold, no contract rule, no acquisition row, no hard stop and
no dependency**, and it adds no host and no network.

**This file is uncommitted on purpose** (coordinator instruction, and the
standing rule about other agents' in-flight trees). It is a draft for the
coordinator to review before anything is proposed to the owner.

## The same thing in plain English

1. The card fixes a Spanish-aware word splitter, but the splitter lives in a
   file the card is not allowed to touch, so today every accented Spanish word
   would be cut in half. This proposal names the files that must be editable,
   and nothing more.
2. The card promises Spanish keeps its own list of "words I always accept" and
   that the English list carries over untouched. It never says where that list
   is stored. This proposal fixes the storage, says the English list is not
   rewritten at all, and says what happens to a word added in Spanish.
3. The card promises "if the dictionary will not load, show an error and let
   typing continue" and there is no way to show an error today: the app
   deliberately says nothing, and any message the therapist reads has to exist
   in both languages. This proposal names the state, the exact message key, the
   screen it appears on, and the test that proves it.
4. Two of the card's four checks are not commands. This proposal writes them as
   real commands, inside two separate throwaway test folders on two free
   sandbox ports, so nothing touches the live app.
5. Adding the Spanish word list is the one thing this project has ever been
   allowed to ship under a copyleft licence, and the owner has never actually
   said so in writing; the notice the licence requires also has blanks in it
   that only the owner can fill. This proposal stops the card until the owner
   answers, and lists the questions as questions.

**What is deliberately *not* decided here.** The licence arm, the two blank
fields in the required notice, the Spanish wording of the new message, and
whether one e2e spec needs one config line are all owner calls. Each appears
below as a numbered decision with the options and a recommendation. No legal
conclusion is drawn anywhere in this file, and no owner's name, identity or
intent is asserted.

## 2. Where the review overstates or is simply wrong

### 2.1 D5 and D11's proposed fix would break the run (the most important correction here)

The review says V2 "needs **two** servers" and proposes
`node scripts/v2/sandbox.mjs env --port 7813 > … && . … && node scripts/v2/sandbox.mjs env --port 7814 > … && . …`.
**Do not do that.** `sandbox.mjs`'s `printEnv` exports exactly seven variables
(`APUNTA_DATA_DIR`, `APUNTA_PORT`, `APUNTA_NO_OPEN`, `APUNTA_TEST_RUN_ID`,
`APUNTA_V2`, `APUNTA_CHECK_URL`, `APUNTA_E2E_PORT`; `scripts/v2/sandbox.mjs:299-310`)
and neither `APUNTA_E2E_ES_PORT` nor `APUNTA_E2E_ES_DATA_DIR` among them. Sourcing
a second env after the first therefore moves the **English** server onto the
second port and leaves the Spanish one on a port nothing reserved. This is not a
new finding: `docs/v2/cards/S2.10.md:659-668` and `docs/v2/cards/S2.11.md:510-540`
both record it, and `reviews/S2.6-ir.md:290-322` is the review that wrongly
demanded two envs in the first place.

**What is actually needed** is one `sandbox.mjs env --port <p1>`. The Playwright
config then allocates the Spanish server itself, on `<p1> + 1` with its own data
folder beside the English one inside the same run folder
(`e2e/playwright.config.ts:32-36`, the two `webServer` entries at `:115-142`).
The review is right that the card names no port and no sandbox line; it is wrong
that a second `env` is the answer. A *second, separate* run folder is legitimate
and is what V6 uses — created and sourced inside a subshell of its own, never
into the outer shell (S2.10's own `<p2>` pattern).

**Also an overstatement in D11:** "V3's build is not in the L1 command set". The
web build is already inside the browser row: the `webServer` command is
`npm run build && node server/dist/index.js` (`e2e/playwright.config.ts:119`).
V3 needs no separate build command; it needs an assertion.

### 2.2 D8's "the card does not pin the version"

`shared/src/i18n/locales.ts:70-76` already carries
`dictionary: 'dictionary-es-mx@2.0.0'` for `es-MX`, and
`shared/src/i18n/locales.test.ts:52-59` asserts that exact string. C-LANG@1
clause 2's locale table (`docs/v2/CONTRACTS.md:292-299`) is the single place

should **read** that pin, not invent one, and V1/V4 should assert the three
copies of it agree. The reviewer's substantive point stands: the card's own text

### 2.3 D14's SHA-256 requirement is stricter than the policy

`docs/v2/ACQUISITION.md:5-7` requires "SHA-256 (**or** the package manager's
integrity string)". S1.5 §6 records the SHA-256 as `[not found]` because
computing it would have meant a download. Making this card compute a tarball
SHA-256 adds an acquisition-shaped step the policy does not ask for. The
replacement card records what the policy asks for — the lockfile `integrity`
string, the resolved version, the per-file sizes, the URL and the date — and
treats a tarball digest as optional.

### 2.4 D3's "silently drops every word she has added"

The risk is real if the stored shape is ever changed, but it is a *future*
hazard, not today's behaviour, and it is fully avoidable by a rule that needs no
data movement at all (§5). The card's own sentence is not "false" — it is
unimplementable inside its May edit. Worth stating precisely so the implementer
does not read D3 as licence to rewrite stored settings.

### 2.5 D4 is understated, not overstated

The reviewer names the three files that would have to change. There is a fourth
consequence worth putting in the card: `scripts/check-ui-strings.mjs` is now
failing by default (`REPORT_ONLY = false`, `:62`; exits 1 on any finding, `:259`)
and `shared/src/i18n/t.test.ts:568-580` holds a type-level parity rule between
the two catalogues. So a literal in a component fails `npm run lint`, and a key
added to one catalogue and not the other fails `npm run build:shared`. Both are
reasons the message must be a catalogue key in **both** files, which the
replacement card states.

## 5. The three design decisions the card must state in full

### 5.1 Storage shape and read rule for the per-language word lists (D3)

**Storage.** Settings is a flat key → JSON-value store
(`shared/src/settings.ts:9-18`: "later packets add keys … without a migration"),
and keys must match `/^[a-z][a-z0-9_]*$/` (`:12-16`), so a key cannot be spelled
`es-MX`. The two lists are therefore two keys:

| Locale | Key | Value |
| --- | --- | --- |
| `en` | `spelling_words` (unchanged, `shared/src/spelling.ts:16`) | JSON array of strings, exactly as today |
| `es-MX` | `spelling_words_es_mx` (new) | JSON array of strings |

**Read rule, stated so there is nothing to guess.**

1. The active list is chosen by the **active UI language** (`language` setting),
   not by a note's locale and not by the text in the field. One checker, one
   dictionary, one list.
2. `en` reads `spelling_words`. `es-MX` reads `spelling_words_es_mx`, and an
   absent or malformed `spelling_words_es_mx` reads as `[]`.
3. **A Spanish list is never seeded from the English list.** The two are
   independent. A word she adds in Spanish is not silently accepted in English,
   and vice versa.
4. `stt_vocabulary` (`shared/src/transcribe.ts:99`) is **not** part of this
   change. It is a transcription vocabulary — a medication or a name she taught
   whisper — and it stays applied in both languages, exactly as today. It is
   named here so that nobody mistakes it for the second half of a migration.
5. `MAX_SPELLING_WORDS = 1000` and `MAX_SPELLING_WORD_CHARS = 60` keep their
   values and now apply **per key**, i.e. per locale. Both lists may hold 1000.
6. **No stored value is rewritten.** There is no backfill, no delete, no
   migration step and no schema change. `spelling_words` is read as the English
   list and is written back only when she adds an English word, in which case it
   is written back as an array, the shape it already has. If a future card ever
   changes the stored shape, it is that card's work, and this card is its
   evidence that the English list was never disturbed.

**One sentence for the card, in the implementer's own words:** *the existing
English list migrates unchanged to `en`* means *it is read as `en`'s list and is
never moved, converted or rewritten*, not *a migration runs*.

### 5.2 The dictionary-load error surface (D4)

Today: `SpellingProvider.tsx:79-81` swallows the failure on purpose
(`// No dictionary, no marks. The editor is entirely usable without them.`) and
the `Spelling` interface (`:21-31`) has no error field, so nothing *can* show
one. The card's promise therefore needs four things named, and all four are new
code:

1. **State.** `Spelling` gains `readonly error: string | null` — a message
   **key**, never a literal. `null` means no failure. It is set when a locale's
   dictionary load rejects, cleared on the next successful load, and reset to
   `null` on a language change before the new load starts. The `INERT` default
   (`:33-38`) gains `error: null`.
2. **Behaviour while failed.** Unchanged from today and stated as such:
   `speller` stays `null`, no marks are drawn, `findMisspellings` is never
   called, `addWord` and `ignoreWord` still work, and typing is untouched. The
   card's phrase "leaves typing usable" means *exactly* today's behaviour, not a
   degraded mode.
3. **Surface.** `web/src/components/SpellLayer.tsx` renders one line, once, in
   the editor's own wrap, immediately above or below the editor, with
   `role="alert"`, using `t('spelling.loadFailed')`. It is rendered by the shared
   spell layer rather than by the menu, because with no dictionary there are no
   marks and therefore no menu to open — a fact the review states and the card
   must respect.
4. **The key, in both catalogues.** One new key `spelling.loadFailed`. English
   text proposed: **"Spell check is unavailable"** (adjacent in style to the
   existing `spelling.none` = "No suggestions", `spelling.ignore` = "Ignore",
   `spelling.add` = "Add to dictionary"). It takes no placeholder. Adding it to
   one catalogue and not the other fails `shared/src/i18n/t.test.ts`'s parity
   rule; putting a literal in the component fails
   `scripts/check-ui-strings.mjs`, which `npm run lint` runs
   (`REPORT_ONLY = false`, `:62`, `:259`).

The **Spanish** text is not written here. It is copy, and S2.7/S2.8 own Spanish
copy — see OD-3. The card states the key, the placeholder set (empty), and the
stop.

### 5.3 NFC tokenisation that leaves English provably unchanged (D1, D6)

`web/src/lib/spelling.ts:27` is `const WORD = /[A-Za-z]+(?:['’][A-Za-z]+)*/g`
and `plainWord` (`:37-39`) only folds `’` to `'`. `allowedWords` (`:160-167`)
re-tokenises every allow-list entry with the same pattern. That is why `José`
in a note becomes `Jos`, why `José Ramírez` in the allow-list contributes
`jos` + `ramirez`, and why `¿Cómo` yields `C` + `mo`.

The card's replacement text, which is small and checkable:

```ts
/**
 * A word: English letters plus the Spanish ones the es-MX dictionary needs,
 * and any combining marks a keyboard or an IME may leave attached — so a word
 * typed as `sesio` + U+0301 is one token, not two.
 *
 * The ASCII range is unchanged and comes first on purpose: for text containing
 * no Spanish letter this pattern matches exactly what the old one matched, and
 * `plainWord` is a no-op on ASCII, so English tokenisation is provably
 * unchanged. `spelling.test.ts` asserts that against the old pattern.
 */
const LETTER = '[A-Za-zÁÉÍÓÚÜÑáéíóúüñ\\u0300-\\u036f]';
const WORD = new RegExp(`${LETTER}+(?:['’]${LETTER}+)*`, 'g');
```

```ts
function plainWord(word: string): string {
  // NFC first, so a decomposed `sesión` and a precomposed one are the same
  // word; then the curly apostrophe, which is not part of any word.
  return word.normalize('NFC').replace(/’/g, "'");
}
```

Four properties the card states, because each one is a way this could go wrong:

- **Normalisation is per matched word, never on the whole text.** `Misspelling`
  carries `[start, end)` character offsets into the original text
  (`spelling.ts:20-24`) and they drive the caret and the menu. NFC applied to
  the whole text would change the length of a decomposed string and shift every
  offset after it. Per-word normalisation leaves every offset exact.
- **No accent folding, ever.** `ñ` stays `ñ`; there is no `NFD`, no
  diacritic-stripping and no transliteration anywhere in the path. This is the
  card's "without removing accents", and it is testable: the V1 case below
  asserts a decomposed input and a precomposed input give byte-identical
  results.
- **`¿` and `¡` are not letters.** They are outside the class, so they are
  punctuation, and a word after them is matched whole.
- **The allow-list gets the same treatment for free**, because
  `allowedWords` calls the same `WORD` and the same `plainWord`. That is what
  makes a typed `José` match an allow-listed `José Ramírez` instead of
  `Jos` matching `jos`.

**The suggestion alphabet is deliberately left alone** (`spelling.ts:123`,
`LETTERS = "abcdefghijklmnopqrstuvwxyz'"`), because widening it would change
English suggestions. With it unchanged, an accent-only correction comes from
`nspell's` own suggester behind the neighbour search, which is the existing
fallback. See OD-6.

## 6. The licence half

### 6.1 The mechanism, named exactly (D8)

`scripts/collect-licenses.mjs:48` is `DUAL_LICENSED_CHOICES`, and its own doc
comment calls it "Dual licences where Apunta has deliberately taken the
**permissive** arm". MPL-1.1 is not permissive, and `reportedLicense()` (`:59-64`)
renders `taken (offered as …)` into a table that ships to the user, so putting
this package in that map would describe a copyleft arrival as a deliberate
permissive choice. **A separate map, and `DUAL_LICENSED_CHOICES` is not
touched.** The exact addition:

```js
/**
 * Data objects shipped under a non-permissive arm of a multi-licence, elected
 * by the owner and recorded in THIRD-PARTY-LICENSES.md and docs/decisions.md.
 *
 * Kept apart from DUAL_LICENSED_CHOICES on purpose: that map is for permissive
 * arms, and a copyleft arm described as a permissive choice would make this
 * guard say the opposite of what it is for.
 *
 * `dictionary-es-mx` — the Mexican Spanish Hunspell word list, data only
 * (`index.aff` + `index.dic`), shipped unmodified under its own names. Election,
 * obligations and the notice: THIRD-PARTY-LICENSES.md, "Mozilla Public License
 * 1.1". Nothing else may be added without the same recorded election.
 */
```
