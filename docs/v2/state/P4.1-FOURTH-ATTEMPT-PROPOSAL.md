## 1. The defect, exactly

**Function and line.** `scripts/v2/probe-redirects.mjs:188-199`, function
`queryKeyNames`; the throwing expression is **line 196**:

```js
.map((pair) => decodeURIComponent(pair.split('=')[0] ?? pair)),
```

No `try`/`catch`. It has two call sites, both inside `describeLocation`:
`:248` (the `query_key_not_allowed` loop) and `:266` (the returned `queryKeys`).
`describeLocation` wraps only `new URL(raw)` in `try`/`catch` (`:218-238`), so a
`Location` that **parses** but whose query carries a malformed percent escape in
a **name** takes the unguarded path.

**Why it is a crash and not a diagnostic.** `main()` calls `describeLocation` at
`:461` inside a bare loop with no `try`/`catch`, and `writeFile` happens only at
`:466`. The throw therefore kills the process **before** `redirects.md` is
written — leaving the previous run's file on disk, where it would be read as
this run's record while V2's "the script wrote the file" expectation is no
longer true of anything on disk.

**The repository has already settled the right behaviour for this exact input.**
`installer/src/readiness.ts:116-134`, function `queryParameterNames`, does the
identical job with the identical `decodeURIComponent`, and wraps it:

```ts
let decoded = name;
try {
  decoded = decodeURIComponent(name);
} catch {
  // A malformed escape is left as it arrived: an unreadable name is not a
  // name that can be on a list, so it fails closed below.
}
```

`installer/src/readiness.test.ts:453-455` pins it: *"leaves a malformed escape
as it arrived, so it fails closed against any list"* —
`expect(queryParameterNames('?%zz=1')).toEqual(['%zz'])`. The probe's copy of
that logic diverges from the in-repo convention. Classified **DEF-1**, "in
AM-057's own stated scope and unclosed", at
`docs/v2/state/reviews/P4.1-attempt3-impl.md:292-338`; reproduced independently
by the coordinator and recorded at `docs/v2/ORCHESTRATION-LOG.md` (2026-09-27,
"P4.1 partial repair preserved, remaining defect blocked").

**Not a regression, and that matters for the ask.** The base has the identical
unguarded call (`git show d0b8292:scripts/v2/probe-redirects.mjs`, line 213).
Attempt 3 did not introduce it; it left the other half of its own repair scope
(AM-057: *"it must prove malformed diagnostics do not crash"*) open.

**The enforcement path is not affected, and this bounds the consequence.** The
guard the product actually ships is `assertRequestAllowed`
(`installer/src/readiness.ts:191`), which reads its names from
`queryParameterNames` at `:245` — the copy that **already** fails closed and is
already tested. A malformed escape cannot make a downloader admit a query, and
cannot put a name on a list it is not on. **The defect is confined to a
diagnostic script's own evidence record.** That is why this is a bounded fourth
attempt and not a stop condition, and it is also why the honest product
consequence in §6 is about a misleading file rather than an unsafe download.

  renderer's `.length`/`.map` (`:232`, `:266`) stay safe — the array-in-every-
