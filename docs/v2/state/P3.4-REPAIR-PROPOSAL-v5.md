## C. Contract 1 — epoch, complete frame, selection

**C.1 What the hook publishes (delta only; nothing is removed or renamed).**
Inside `sendRects`, beside the existing `rects` and `batch` parameters, one
run-local counter becomes a **short safe-integer epoch**, the same value on
every batch of one publication, and the rectangle key becomes the **global**
index:

```js
const global = index * batchSize + at;          // instead of `at`
query.set(`epoch`, String(epoch));              // one per sendRects call
query.set(`i${String(global)}_x`, String(rect.x));
query.set(`i${String(global)}_y`, String(rect.y));
query.set(`i${String(global)}_w`, String(rect.w));
query.set(`i${String(global)}_h`, String(rect.h));
query.set(`i${String(global)}_l`, rect.label);
query.set(`i${String(global)}_t`, rect.tagName);
query.set(`i${String(global)}_d`, rect.testId);  // data-testid, '' when absent
```

No full-JSON signature, no URL-length increase beyond two short scalars, and
**no counter that can wrap into a safe-integer collision**: the epoch is
compared as a safe integer and a non-integer, non-positive or unsafe epoch is
malformed, which never raises the highest seen epoch.

**C.2 What the reader installs.** A sighting is *well formed* only if `batch`,
`rects` and `epoch` are strict safe integers (`epoch ≥ 1`), `batch` is inside
`0 … ceil(rects/40) − 1`, every index present is a strict integer below `rects`,
every index of that batch's own slice is present, and all seven fields
(`x y w h l t d`) are present for each. Only a well-formed sighting is
installed, **whole** — it replaces the batch's entire rectangle map, never
merges into one. A malformed or truncated sighting is discarded: never merged,
never installed, never a conflict, and it raises nothing.

**C.3 Selection.** `highestSeenEpoch` rises on every well-formed header, **even
while that publication is still incomplete**, so a newer incomplete epoch
forbids falling back to an older complete one. The selectable frame is the
highest seen epoch only, and only when it is complete: batches
`0 … ceil(rects/40) − 1` all present, all declaring the **same** `rects` and the
same `epoch`, and the union of global indices exactly `0 … rects − 1`. Lower and
out-of-order epochs are ignored. Two **complete** sightings of the same
`(epoch, batch)` with identical fields are idempotent; with differing fields they
are a **conflicting duplicate and the row FAILs**. An A → B → A rectangle set is
three distinct epochs and the third is selected. A frame still incomplete when
the deadline expires is the row's `FAIL`, carrying the count — never a fallback,
never a click, and **never reported as "the hook published no rectangle"**.

**C.4 Target selection.** A target is a unique `(label, tag, testId)` triple.
The appended tooltip carries the same label with a **different** `tag`, and it is
told apart by that comparison — no fixed hover wait, no re-warp, no re-read, no
invented interception rationale. More than one live rectangle matching the
triple is `ambiguous` and FAILs with the count and the global indices; there is
no first-match-wins rule and none may be added.

**What is not claimed:** nothing here makes an older frame unselectable once a
newer complete frame exists, and nothing makes a read observe the page's latest
state. The hook publishes on change and does not retract; a stronger guarantee
would need a retraction protocol, which is not sought here. No freshness claim is
made anywhere in this proposal.

## D. Contract 2 — calibration, then exactly one click

1. Read the window natively once (`xdotool getwindowgeometry --shell` →
   `X Y WIDTH HEIGHT`). Non-integer `WIDTH`/`HEIGHT` is `NOT RUN`.
2. Read `vpW`, `vpH` from a published fact line; require `vpW ≥ 400 && vpH ≥ 300`.
3. Two fixed targets derived from the viewport, never hard-coded:
   `P1 = (round(vpW·0.50), round(vpH·0.50))`, `P2 = (round(vpW·0.75), round(vpH·0.60))`.
   Both interior, both clear of the top edge.
4. **Bootstrap, the only two untransformed points.** Move 1 asks for
   `(windowX + cx₁, windowY + cy₁)` — the naive 1:1 guess, stated as an
   assumption, pressing nothing, and its only named outcome is `NOT RUN`
   "the first bootstrap point produced no pointermove", **no click**. Move 2
   asks for the **displacement** `(X₁ + Δcx, Y₁ + Δcy)`, which is
   transform-independent; it is containment-checked **before** the warp, and a
   point outside the window is `NOT RUN` "the second bootstrap displacement left
   the window rectangle" with **no warp issued at all**.
5. For each move: record `ptrN`, dispatch, then require a fact line whose `ptrN`
   is **strictly greater**; read the pointer back with
   `xdotool getmouselocation --shell` and require `|X_read − X_asked| ≤ 1` and the
   same in y, plus `WINDOW` equal to the app window id **or**
   `xdotool getwindowpid` equal to the app's positive pid.
6. **Solve, per axis, before anything is converted:**
   `k_x = (sx₂ − sx₁)/(cx₂ − cx₁)`, `o_x = sx₁ − k_x·cx₁`, likewise y. The
   two client points must differ in **both** axes and every measurement must be
   finite; then each `k` must satisfy `0 < k ≤ 4`. **These checks run before the
   first conversion, not as an assertion afterwards.** A degenerate or
   non-finite solve ends the row `NOT RUN` with the numbers, **without a target
   warp and without a click**.
7. **Containment before every move and read-back after every move**, on every
   point computed through the solved transform — including the target — and the
   two bootstrap points of step 4 are its only exemption.
8. **One fresh witness, then one click.** Warp to the target centre, re-read
   (≤1 px, over the app), then require a **fresh** pointer observation within
   **2 client pixels** of that centre — an out-of-sample check, because fitting
   two points is not validation — and only then dispatch **one** `xdotool click 1`.
   After it: `clickN` advanced by **exactly 1**, `clickCX/clickCY` within 2 px of
   the target centre, and `clickEl`'s `tagName`, `data-testid` and trimmed
   `innerText` equal to the three fields read from the rectangle that was
   selected.
9. **The landing is a fact, not a rectangle.** The patient-open step requires a
   fact line published after the click whose **`href` differs** from the
   pre-click `href` — not `location.pathname`, which this app never changes — and
   the final step requires **`scriptText === 'true'`**. `rectSignature` is kept
   as diagnostic text in the failure detail and is **never** a pass condition.
10. **Exactly one click per target.** No second point, no retry, no widened
    window, no late click after any terminal outcome.

## E. Contract 3 — one immutable 30-second target deadline

One deadline is taken once, before the first dispatch, and it covers
calibration, selection, every command, every await, the witness and the landing.
**It has no `reset`, no `extend` and no per-step cap that could renew**: the only
bound any await gets is the deadline's own remaining time, so a hung command
ends at the deadline instead of extending the row, and a result that arrives
after it is a failure, not a success. Every dispatch and every await is guarded;
a dispatch after the deadline never happens, and no terminal path — failed
calibration, ambiguous target, incomplete frame, read-back miss, command
failure, expired deadline — issues a click. The row's existing 45 s first-fact
window and 30 s click window keep their current lengths; **no timeout is
widened to accommodate a wait**.

## F. Contract 4 — command outcomes, the gate, the assertion, the cascade

**F.1 Fail closed on every command.** `spawnAsync` resolves with
`{code, signal, stdout, stderr}`. Any signal, any non-zero status, or `XError` in
either stream is an immediate failure naming the command, the status and the
line — before the click is dispatched, never a click that proceeds and is judged
afterwards by a page fact.

**F.2 The presence gate.** The existing first-fact wait keeps its 45 s window
and its shape, and its predicate widens from `href` to
`href` **and** `ipcProbe` **present**. Presence only; settling belongs to the
assertion.

**F.3 (a), one assertion with one pass condition, all conjuncts together:**
`tauri === 'undefined'`; `ipc === 'object'`; `ipcInvoke === 'function'`;
`ipcProbe === 'rejected'` **and** `ipcProbeMsg` exactly
`Command plugin:event|listen not allowed by ACL`. The probe command is
`plugin:event|listen` — a known-existing built-in — and the exact string is the
evidence, because a rejection alone proves nothing about which gate stopped it.
The reachable not-found rejection is `Command listen not found`, built from the
**stripped** command name, so it is that same failure. **`resolved` is a
failure** — the command was reached — even with a harmless value; **`pending` at
the deadline is a failure**, and no timeout can produce a pass. The assertion's
own 30 s window is unchanged; it is not a second `NOT RUN` and not a second
cascade. One denied command is not proof that every command is denied, and the
card's static half (no `invoke_handler`, no `withGlobalTauri: true`, no
`capabilities/` directory) stays exactly as it is, unrelaxed.

**F.4 Exactly one five-row cascade, with a two-arm cause.** The five rows keep
their order and their `NOT RUN` outcome. The cause distinguishes **zero marker
lines** (the silent-hook arm) from **marker lines that never carried `href` and
`ipcProbe` together** (reported with the count that distinguishes them).
Presence of lines does not make the one-armed explanation true, so both arms are
recorded, together, and none of them is ever a pass. Only the (a) label changes,
to the new title.

**Before-texts reused unchanged:** the harness gate at `:845-849`, the five rows at `:856-860`, `assertNoIpc` at `:960-973`, the card's `NOT RUN` sentence at `docs/v2/cards/P3.4.md:584-593` and its fact-set bullet at `:176-190`.
