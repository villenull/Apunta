## C. Contract 1 — epoch, valid header, complete batch, selection

**C.1 What the hook publishes (delta only; nothing removed or renamed).** Inside the
existing hook, beside the nine facts and the existing `rects`/`batch`, one run-local
counter becomes a **short safe-integer epoch**, the same on every batch of one
publication, and the rectangle key becomes the **global** index:

```js
const global = index * batchSize + at;          // instead of `at`
query.set(`epoch`, String(epoch));              // one per sendRects call
for (const [field, value] of [['x', rect.x], ['y', rect.y], ['w', rect.w], ['h', rect.h],
                              ['l', rect.label], ['t', rect.tagName], ['d', rect.testId]])
  query.set(`i${String(global)}_${field}`, String(value));   // i{n}_d is data-testid, '' when absent
```

Cost, stated honestly: **one** extra scalar (`epoch`) per `sendRects` call plus **two**
extra key/value pairs per rectangle (`i{n}_t`, `i{n}_d`) — up to 80 extra pairs for a
full 40-rectangle batch, on top of the existing five per rectangle. No full-JSON
signature and no URL-length claim. **No counter that can wrap into a safe-integer
collision**: the epoch is compared as a safe integer, and a non-integer, non-positive or
unsafe epoch is an invalid header, which raises nothing.

The nine facts stay exactly as they are. Added to the same fact line: viewport
`vpW`/`vpH`; pointer `ptrN` (monotonic), `ptrCX`/`ptrCY`; click `clickN`,
`clickCX`/`clickCY` and the three descriptor fields `clickTag` (`tagName`),
`clickTestId` (`data-testid`, `''` when absent), `clickText` (trimmed `innerText`); IPC
probe `ipcProbe`/`ipcProbeMsg`. All of them come from **one** capture-phase `click`
listener and **one** `pointermove` listener inside the existing hook, published by the
existing 250 ms poll: **no second hook, no second gate, no second poll, no new
interval** — that seam with P3.5's in-flight `main.tsx` is why this stays a delta.

**C.2 Two things the reader keeps apart.** A **valid header** is: `epoch` a strict
safe integer ≥ 1, `rects` a strict safe integer, `batch` a strict non-negative
integer, and `batch` inside `0 … ceil(rects/40) − 1`. A **complete batch**
additionally has every index of that batch's own slice present with all seven fields
(`x y w h l t d`), every present index below `rects`, and no index outside the
slice.

- A valid header raises `highestSeenEpoch` **immediately**, before the body is
  looked at, **even when the body turns out to be truncated**; a newer publication
  therefore forbids falling back to an older complete one while it is incomplete. An
  **invalid** header raises nothing.
- Only a complete batch is installed, **whole**: it replaces that batch's entire
  rectangle map and never merges into one. A truncated or malformed body is never
  installed, never merged over a good batch, and **never a conflict** — a conflict
  needs two **complete** sightings of the same `(epoch, batch)` with differing
  fields, which FAIL the row.

**C.3 Which frame is selectable.** The highest seen epoch only, and only when it
is complete: batches `0 … ceil(rects/40) − 1` all present, all declaring the
**same** `rects`, and the union of global indices exactly `0 … rects − 1`. Lower
and out-of-order epochs are ignored; identical complete duplicates are
idempotent; a repeated A → B → A rectangle set is three distinct publication
epochs and the third is selected. A frame still incomplete when the deadline
expires is the row's `FAIL`, carrying the count — never a fallback, never a
click, and **never reported as "the hook published no rectangle"**. An epoch with
a valid header and no complete batch is reported as exactly that.

**C.4 Target selection.** A target is a rectangle whose **(label, tag) pair** is unique
in the frame. The appended tooltip carries the same label with a **different** tag and
is told apart by that comparison — no fixed hover wait, no re-warp, no re-read, no
invented interception rationale. More than one live rectangle matching the pair is
`ambiguous` and FAILs with the count and the global indices; there is no
first-match-wins rule and **no `testId` tie-breaker** — `testId` is compared **after**
the click, against the descriptor of the selected rectangle. **What is not claimed:**
nothing makes an older frame unselectable once a newer complete frame exists, and
nothing makes a read observe the page's latest state; the hook publishes on change and
does not retract, a stronger guarantee would need a retraction protocol, and no
freshness claim is made anywhere here.

## D. Contract 2 — calibration, then exactly one click

1. Read the window natively once (`xdotool getwindowgeometry --shell` → `X Y WIDTH
   HEIGHT`, its status/signal/output checked like every command) plus the app's pid —
   a non-integer or non-positive `WIDTH`/`HEIGHT`, or a non-positive-integer pid, is
   `NOT RUN` — and **wait** for `vpW ≥ 400 && vpH ≥ 300` in a published fact line.
2. Two fixed targets derived from the viewport, never hard-coded: `P1 =
   (round(vpW·0.50), round(vpH·0.50))`, `P2 = (round(vpW·0.75), round(vpH·0.60))`.
   Both interior, both clear of the top edge, and different in both axes.
3. **Bootstrap, the two untransformed points — and there is no exemption from
   step 6 for either of them.** Move 1 asks for `(windowX + cx₁, windowY + cy₁)`, the
   naive 1:1 guess stated as an assumption, pressing nothing; move 2 asks for the
   **displacement** `(X₁ + Δcx, Y₁ + Δcy)`, which is transform-independent. Each is
   named in its failure, each is containment-checked **before** its own warp, and a
   point outside the window rectangle is `NOT RUN` "…left the window rectangle" with
   **no warp issued**.
4. For every move — both bootstrap moves and the target — **wait** (bounded by the
   one deadline) for a `ptrN` baseline, then dispatch and **wait** for a fact line
   whose `ptrN` is **strictly greater**; read the pointer back with `xdotool
   getmouselocation --shell` and require `|X_read − X_asked| ≤ 1` and the same in y,
   plus `WINDOW` equal to the app window id **or** `PID` equal to the app's positive
   pid. A stale counter waits for the next 250 ms tick; one that never advances ends it.
5. **Solve, per axis, before anything is converted:** `k_x = (sx₂ − sx₁)/(cx₂ − cx₁)`,
   `o_x = sx₁ − k_x·cx₁`, likewise y, where `sx`/`sy` are the **measured native read-backs**
   (within 1 px), never the commanded points. The two measured client points must differ
   in **both** axes and every measurement finite; each `k` must satisfy `0 < k ≤ 4`, all
   **before the first conversion**. A degenerate or non-finite solve ends the row `NOT RUN`
   with the numbers, **without a target warp and without a click**.
6. **Containment before every move and read-back after every move**, on every point
   computed through the solved transform **and** on both bootstrap points. There is
   no bootstrap exemption: move 1's containment is decidable with no transform at
   all (`windowX + cx₁` against `windowX … windowX+WIDTH`), so checking both costs
   one comparison each.
7. **One fresh witness, then one click — in that order, never before the warp.** Warp
   to the target centre, read back (≤1 px, over the app), then **wait** (same deadline)
   for a fact line whose `ptrN` is strictly greater than the one recorded before this
   warp **and** whose `ptrCX/ptrCY` are within **2 client pixels** of that centre — an
   out-of-sample check, because fitting two points is not validation. **Nothing
   about the pointer's position is checked before the target warp.** Only then
   dispatch **one** `xdotool click 1`.
8. **After the click, three things and then the landing.** **Wait** for a fresh click
   fact: `clickN` advanced by **exactly 1**; `clickCX/clickCY` within 2 px of the target
   centre; `clickTag`, `clickTestId`, `clickText` compared one by one against the three
   fields of the selected rectangle — a stale fact waits, a fresh wrong one fails. Then
   **wait** for the landing: the patient-open step requires a fact line published after
   the click whose **`href` differs** from the pre-click `href` — not `location.pathname`,
   which this app never changes — and the final step requires **`scriptText === 'true'`**;
   an unchanged landing fact waits; `rectSignature` stays diagnostic text, never a pass.
9. **Exactly one click per target.** No second point, no retry, no widened window,
   no late click after any terminal outcome.

## E. Contract 3 — one immutable 30-second target deadline

One deadline is taken once, before the first dispatch, and it covers calibration,
selection, every command, every await, the witness and the landing. **It has no
`reset`, no `extend` and no per-step cap that could renew.** Every dispatch and every
await is **raced against the deadline's own remaining time**, not merely checked
against it before starting: a hung `mousemove` and a hung `click` both end at the
deadline instead of extending the row, and no continuation runs afterwards. A result
that arrives after it is a failure, not a success. There are no phase timers and no
second budget. A dispatch after the deadline never happens, and no terminal path —
failed calibration, undelivered pointermove, ambiguous target, incomplete frame,
read-back miss, command failure, expired deadline — issues a click. The row's 45 s
first-fact window and 30 s click window keep their lengths; **no timeout is widened
to accommodate a wait**.

## F. Contract 4 — command outcomes, the gate, the assertion, the cascade

**F.1 Fail closed on every command.** `spawnAsync` resolves with
`{code, signal, stdout, stderr}`. Any signal, any non-zero status, or `XError` in
either stream is an immediate failure naming the command, the status and the line —
before the click is dispatched, never a click judged afterwards by a page fact.

**F.2 The presence gate.** The existing first-fact wait keeps its 45 s window and its
shape, and its predicate widens from `href` to `href` **and** `ipcProbe` **present**.
Presence only; settling belongs to the assertion.

**F.3 (a), one assertion with one pass condition, all conjuncts together:** `tauri ===
'undefined'`; `ipc === 'object'`; `ipcInvoke === 'function'`; `ipcProbe === 'rejected'`
**and** `ipcProbeMsg` exactly `Command plugin:event|listen not allowed by ACL`. The
probe command is a known-existing built-in and the exact string is the evidence,
because a rejection alone proves nothing about which gate stopped it; the reachable
not-found rejection `Command listen not found` is built from the **stripped** name, so
it is that same failure. **`resolved` is a failure** — the command was reached — even
with a harmless value; **`pending` at the deadline is a failure**, and no timeout can
produce a pass. The assertion's own 30 s window is unchanged; it is not a second `NOT
RUN` and not a second cascade. One denied command is not proof that every command is
denied, and the card's static half (no `invoke_handler`, no `withGlobalTauri: true`, no
`capabilities/` directory) stays as it is, unrelaxed.

**F.4 Exactly one five-row cascade, with a two-arm cause.** The five rows keep their
order and their `NOT RUN` outcome. The cause distinguishes **zero marker lines** (the
silent-hook arm) from **marker lines that never carried `href` and `ipcProbe` together**
(reported with the count that distinguishes them). Presence of lines does not make the
one-armed explanation true, so both arms are recorded together and neither is ever a
pass. Only the (a) label changes, to the new title.
