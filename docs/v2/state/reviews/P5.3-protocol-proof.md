amendment, not production correctness.** Only the two owned files were written; nothing committed.

## What this is, and what ran

A deterministic state-machine simulation (`proofs/P5.3-protocol-proof.mjs`, Node builtins only,
injected clock, explicit event schedule) that (a) asserts today's semantics failing in four specific
ways and (b) asserts one coherent proposed protocol — P1–P10 — surviving positive, adversarial and
**ordering** schedules. **Passing proves the protocol internally consistent; it proves nothing about
Fastify's hook order, Tauri, or a real browser.**

## The one recommended protocol (P1–P10, as proved)

- **P1 Initiation.** `quiesce{}` on the shell's own stdin only (C-BRIDGE@1 rule 2); no route, no
  IPC, no browser trigger. **One quiesce at a time**: a second `initiate` in flight is refused, and
  a *settled* quiesce keeps maintenance on until an explicit shell release, so nothing can displace
  a successful quiesce's snapshot window.
- **P2 Identity and registration.** The window mints its own `windowId` (`sessionStorage`), sent as
  an explicit `x-apunta-window-id` header; no cookie (U2). A **persistent** window table survives
  quiesces; at entry each registered window gets a **per-quiesce binding** with a single-use
  `flushToken`. Registration alone binds — a window need not hold a wait at that instant; `wait()`
  and `drop()` are safe at any point; and a window registering *during* a quiesce is bound too.
- **P2a Liveness, and what "gone" means.** A held wait **is** liveness: such a window is refreshed
  by the sweep and only the 30 s bound can decide it. A window that is gone, or that holds no wait
  for a whole named bound (`LIVENESS_MS`, 2 s) after being asked, is *abandoned*; one that never
  reported keeps the drain open, yields `no_response`, and is never excluded from the settle test.
  This re-arm gap is the only thing the 2 s bound governs — not a flush timeout, not a keepalive.
- **P3/P4 The hook and the flush-save permission.** The refusal set is keyed by **method + path** and
  consulted for every method; outside maintenance every request is served normally, asserted on a write
  rather than on a flag. Within maintenance exactly one save is outstanding per `(window, quiesce)`,
  with that window's token and bound to its **currently open note**. Foreign, unknown, wrong-note,
  **no-open-note**, concurrent, replayed, revoked and settled credentials each get their own code and
  none starts a job. A note declared before the quiesce is retained; one declared during it takes
  effect at once.
- **P5 Job accounting.** One id **per operation**, never a note/patient/session id; a colliding id
  is refused, not taken over. `active()` counts **every** live job, including one inherited from an
  earlier generation, and every job that ends ends **exactly once** whatever the quiesce did
  meanwhile; a repeat completion call is refused, not re-counted.

- **P6/P7 Completion and deadline.** Exactly one report per `(window, quiesce, token)`; duplicates, stale
  generations, header/body mismatches and malformed blocker lists each get their own code. One
  **global** 30 s clock covers drain + flush + report, and every deadline and sweep callback is scoped to
  the generation that armed it, so a stale timer can never decide, settle or revive another.
- **P8 Fail closed.** The close check is a **one-shot** probe: the first accepted answer consumes
  it, whatever it says, and a second is `stale_probe`. A missing, non-object, array or wrongly-typed
  answer returns `malformed_answer` / `defer_malformed` — never a throw, never `close`. An unknown
  window, a second outstanding probe and a window that cannot be asked all defer.
- **P9 Rollback.** Timeout, `conflict` and `save_error` lift maintenance, revoke every binding and
  snapshot nothing; a consumed token never returns. **Rollback ends no jobs** — see D5.

- **P10 Successful lifetime, and the close probe.** After `ok:true` maintenance stays on until an
  explicit shell message lifts it; **which message is unresolved (U1)**. The shell names the closing
  window and any booleans it attaches are ignored; the window answers the probe reading its own refs
  *at answer time*.

## 5. Honest limitations and unresolved engineering choices

Not owner questions; recorded so nobody reads more into the proof than it shows.

- **`LIVENESS_MS` is a real risk.** A window taking more than 2 s to re-arm its wait after being asked is
  declared abandoned, and a backgrounded or throttled renderer can plausibly do that. The bound is a proposal,
  not a contract number, and the card should decide it with the real client in view. The model's answer is
  "re-arm the sweep on any wait activity"; a real server needs that.
- **`shortWrites` granularity is coarse** — it counts refused *requests*, the unit a streaming clause
  needs, not refused bytes or lines; and `status().windowsBound` is diagnostic only.
- **The sweep assumes a synchronous world.** Every event is schedule-driven; real Fastify interleaving
  could expose two binds of one window between awaits. The invariants (one token per `(window, quiesce)`, one
  report, one completion) are written so such interleaving cannot mint a second token, but the proof does not
  demonstrate it.
- **Nothing here authorises a card, contract, May-edit amendment or acceptance row**: U1 and U5 remain the
  owner's, and U2's ownership crossing is unadopted. Model: an Orca worker on `opencode-go/space-bunny-free`.
