## Part 2 — The three blocking findings, with counterexamples

### B-1 — the token sits before the phrase's own negator, so both controls are non-discriminating

**Where.** `:622-627` (invented-negation `mustNotContain`), `:650-653`
(lost-negation `mustNotContain` / `mustCapture`), `:657-663` (the substitution
table), `:591-595` and `:670-676` (the direction prose).

**The text.** The invented-negation control's four `mustNotContain` entries are
`"{{lexicon}} no refiere"`, `"{{lexicon}} no reporta"`, `"{{lexicon}} niega(?:ndo)?"`
and `"{{lexicon}} jam[aá]s"`. The gold's own entries for the same class
(`eval-es/tuning/invented-negation/{01,03,05}`) are `no refiere`, `no reporta`,
`niega(?:ndo)?`, `jam[aá]s` — that is, **the negator is already inside the
authored phrase**. Substituting the alternation *in front of* the phrase yields
`(?:no|nunca|jamás|…) no refiere`: two adjacent negators.

**Measured** (FD2b's expansion, FD2c's boundary, `compile()`'s `'i'`, collapsed
lowercased note text; control notes are synthetic Spanish, no held-out content):

| synthetic control note | as written in the card | token in the negator slot | the gold's own four |
| --- | --- | --- | --- |
| invents one negation: "No refiere antecedentes de hipertensión. Niega dolor." | 0 / 4 fire | 1 / 4 fires | 2 / 4 fire |
| invents `jamás`: "Jamás ha tomado el medicamento." | 0 / 4 | 1 / 4 | 1 / 4 |
| faithful: "No refiere antecedentes. Niega dolor." | 0 / 4 | 1 / 4 fires (**false positive**) | 2 / 4 fire |

The third row is the tell: with the token in the negator slot the pattern is
correct *for a per-fixture claim* — it fires on `no refiere` whether the source
supports it or not, and the per-fixture judgement stays with the sidecar, which is
exactly what `:670-676` says. As written, the pattern fires on neither.

**Consequence for V2.** The invented-negation control's `mustNotContain` never
matches, so `bannedHits` is empty, so `F1 banned string` is absent from `gating`
(`score.ts:395`), and its `mustCapture` is `[]`, so `capturedFacts === totalFacts
=== 0`. The predicate at `:1005-1015` therefore evaluates to **`pass`**, while
`expect` is `flagged` — a missed control, which is inadmissible and **exit 3**
(`:1118-1132`). V2's expected exit 0 fails on a correct implementation.

**Consequence for V3.** The same control is missed **with the lexicon intact**,
so the exit-3 message the cell expects would be produced for the wrong reason,
and FD8's/V3's claim that the miss is *caused by blinding* is false. The
negative control would no longer be evidence about the lexicon.

**Same root cause, other direction.** The lost-negation control's
`mustCapture` fact is `["{{lexicon}} (?:puede )?dormir", "{{lexicon}} dorm(?:e|ió|ir)"]`.
The gold's `sueno-no-restaurado` fact carries the negated form as `no ha vuelto a
dormir bien`, `no duerme bien`, `sigue sin dormir(?: bien)?`, `no descansa bien`
and four more. Measured against three correct notes that keep the negation, the
card's two patterns capture **none** of them, while a token in the negator slot of
the gold's own surface forms (`{{lexicon}} ha vuelto a dormir`,
`{{lexicon}} duerme`, `sigue sin dormir(?: bien)?`) captures the first two and
still fails on the restatement. So as written the fact is **unsatisfiable**: it is
uncaptured for every note, including a faithful one. The control still reports
`flagged` — through `capturedFacts < totalFacts`, the disjunct the proposal was
careful to add — but it flags because the pattern cannot match, not because the
note dropped anything. A control that cannot pass is not a control.

**One specific correction, no new mechanism.** Put the token **in the negator's
slot** in both examples and let the rest of the phrase stand, exactly as the gold
writes it: `"{{lexicon}} refiere"`, `"{{lexicon}} reporta"`, `"{{lexicon}} niega(?:ndo)?"`,
`"jam[aá]s"` (this one needs no token, because the phrase *is* the negator and a
bare negator must stay out of `mustNotContain` per `:670`), and for the
lost-negation fact quote the gold's `sueno-no-restaurado` alternatives with the
token in each one's negator slot. The substitution table at `:657-663` is then
literally true, and `mustNotContain` still never receives a bare negator term.
The direction prose at `:591-595` needs one clause: the token replaces the
negator the phrase already contains; it is not prefixed to the phrase.

### B-2 — the `en` controls' negation entries cannot load under `--locale en`

**Where.** `:913-924` (the `en` tree, which contains `positive/01-lost-negation.txt`
and `positive/02-invented-negation.txt`), `:996` (the FD6 key table: "Only the

**The contradiction.** Validation rule (2) is explicit: "a `lexicon` value the
run's locale does not have — `negation` under `--locale en` is this error,

**Two readings, both fatal.** Either the `en` lost/invented-negation sidecars

### B-3 — "empties that lexicon" collides with validation rule (4)

**Where.** `:483-485` (FD1: the flag "empties that lexicon for the run"),
`:1167-1174` (FD8: "The flag empties that lexicon for the run"), `:560-566`
(FD2b: "Blinding is a substitution too"), `:573-576` (validation rule (4): "a

## Part 3 — The remaining findings, briefly

**M-1 (major, textual but inside a normative paragraph).** `:561-564` justifies
`(?!)` over `(?:)` with "an empty alternation would match the empty string, so
every `mustNotContain` entry containing it would fire on **every** note".
Measured, for the card's own examples: `(?:) no refiere` on "el paciente refiere
antecedentes" is **false** — the trailing ` no refiere` still has to match, so the
empty group removes the negator requirement and nothing else. The same
construction in the **corrected** B-1 shape, `(?:) refiere` on the same note, is
**true**. So the conclusion (`(?!)`, not `(?:)`) is right, but the reason holds
only for a pattern whose remainder is optional, and as written it is offered as
the reason for a pattern whose remainder is mandatory. Fix the sentence with the
B-1 shape in mind; the choice of `(?!)` stands either way, and it is the right
choice, since a blind run must remove gating rather than manufacture it.

**m-1 (textual nit).** `:543` "the literal 12 characters `{{lexicon}}`" — measured
`'{{lexicon}}'.length === 11`. `12` is `{{negation}}`, the spelling the next
sentence rejects. Harmless to behaviour; wrong in a sentence whose purpose is to
be quotable.

**m-2 (measurement, documented nowhere).** FD2c's boundary is explicit and
correct, and it has one precondition the document does not state: it does not
match NFD-decomposed text (measured: the precomposed pattern for `dejó` does not
match `"dejó"` normalised to NFD, whose final character is a combining acute), and
a combining mark following a term is treated as a boundary (measured:
`no` + U+0301 matches as a whole token). All 66 tuning transcripts are NFC
(measured 66/66), so the attestation table and every figure above are unaffected,
and no corpus fixture is at risk. Model output is not under the card's control, so
one clause — the vocabulary is matched against NFC text, and `es-MX.txt` is
written in NFC — closes it. This is a documentation gap, not a defect in the rule.

**m-3 (coordinator procedure).** Part B's `{{S32_ATTEMPT}}` is "an integer `n ≥ 1`
… and never reused" with no upper bound, and nothing states its relation to the
card's finite budget: `COORDINATOR.md` §4 allows three attempts per card with the
counter in `state/cards/S3.2.json` (currently `attempt: 1`), and
`build-dispatch.mjs` refuses `--attempt 5` outright and gates `4` behind an owner
amendment naming the authorising row. The proposal's own resumption paragraph
(`:1322-1336`) needs a *new* `{{S32_ATTEMPT}}` for a re-attempt after a fix, which
is a legitimate reading — but a reader cannot tell whether the evidence-directory
index and the card's attempt counter are the same thing, and if they are, the card
runs out at 3. One sentence fixes it: the evidence directory index is independent
of the card's three-attempt budget, and when that budget is exhausted the card is
`BLOCKED`, owner, per `COORDINATOR.md` §4. The partial-resumption procedure itself
is otherwise exact and I could not fault it: the eight files are named, one
attempt directory each, no topping up across directories, no borrowing, and the
refusal makes a spent index harmless.

**m-4 (nit).** FD5's refusal is specified by its effect ("exits 2 with a named
reason … it does not write, and it does not report a measurement") but not by its
position. The invariant — a report is never overwritten, before or after model
execution — holds under either position, which is why this is a nit and not B-3's
kin. But V4's own sentence "Without it all eight invocations would spend the
measurement and then fail `ENOENT` on the write" reads as a write-time failure,
and a pre-flight refusal is strictly better: it fails before the first fixture and
before any model call. Say "before the first fixture".

**m-5 (nit).** FD6's key table marks ten keys "as needed" that
`Fixture extends FixtureExpectations` types as **required** (`corpus.ts:40-57`)
and that `scoreNote` dereferences unconditionally (`new Set(fixture.blank)`,
`fixture.statedAbsence.map`, `new Set(fixture.noConclusion)`,
`fixture.noConclusion.length`, `fixture.mustCapture.filter`, and so on). The
intent is recoverable — the six supplied keys are exactly the other six — so this
is a wording fix ("declared by the sidecar", or "supplied as listed above"),
not a design change.
