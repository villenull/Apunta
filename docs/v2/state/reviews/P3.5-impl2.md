## Source defects

### D2-1 (minor, latent) — a partial marker missing only `_x` installs a rectangle at the origin

`scripts/v2/tauri-audio.test.mjs:1042-1052`:

```js
const rect = {
  x: Number(newest.get(`tid_${testId}_x`)),
  …
};
if (![rect.x, rect.y, rect.w, rect.h].every((value) => Number.isFinite(value))) continue;
if (rect.w <= 0 || rect.h <= 0) continue;
```

`newest.get(...)` returns `null` for an absent field and `Number(null) === 0`,
which is finite; the id is admitted to `ids` from whichever of the four keys the
marker happens to carry. So a newest marker carrying `_y`, `_w`, `_h` but not
`_x` — a *partial* marker, the exact class this function exists to refuse —
installs a rectangle at `x = 0`, and empty coordinate values (`tid_…_x=`) do
the same in both axes.

Reproduce (pinned Node, no app, no input):

```
$ node build/p3.5-review2/d2-current-rectangles.mjs
PASS D2 ADVERSARIAL: a newest marker missing only `_x` installs a rectangle at x=0
  (Number(null)===0): {"x":0,"y":222,"w":80,"h":40}
PASS D2 ADVERSARIAL: empty coordinate values read as 0 and install a rectangle at the
  origin: {"x":0,"y":0,"w":80,"h":40}
… 22/22 passed, exit 0
```

Durable copies: `docs/v2/evidence/P3.5/review-2/d2-current-rectangles.{mjs,md}`,
`d2-output.txt`.

Why it is minor and not blocking: the emitter writes all four fields or none,
**in the order `x`, `y`, `w`, `h`** (`web/src/main.tsx:124-128`), so a truncated
query drops the tail — `h`, then `w` — and a dropped `w`/`h` is refused by the
positivity check. The shape above is unreachable from the shipped hook today,
and a rectangle at `x = 0` would still have to pass `rectInsideWindow`
(`:811-821`), whose check would fail a click outside the window rather than aim
it. It is a wrong-control hazard class, so it should not be left standing.

It is nevertheless a real defect, because the invariant is asserted in two
places and does not hold: the function's own doc comment
(`:1025-1028`, "installed only when that one marker carries all four of `x`,
`y`, `w`, `h` as finite numbers") and the repair report (`:97-104`, fixtures
`:112-115`). The guarantee currently lives in `web/`'s emission order, which the
harness neither asserts nor can assume. One-line fix inside the same function:
require presence as well as finiteness, e.g. build the rect only from
`['x', 'y', 'w', 'h'].every((field) => newest.has(`tid_${testId}_${field}`))`
(or parse with a `null`-rejecting reader) before the numeric checks. Not patched
here.
