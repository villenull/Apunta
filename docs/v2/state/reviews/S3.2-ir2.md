### D-1 — the Read scope omits two files the card's own rules require reading

- **ID and location.** IR-01. `docs/v2/cards/S3.2.md`, `## Read`.
- **What is missing.** Two things. (a) FD7 enumerates what `/api/health`
  returns and cites `server/src/routes/health.ts:104-130`, but that file is not in
  Read. (b) FD2c makes the lexicon locale-scoped, and the only way to do that

  with its module-level `cachedLexicon` (`score.ts:118-124`), which `run.ts:144`
  already uses. Neither `score.ts:111-124` nor `run.ts:144` is inside the Read
  windows (`score.ts` 100-130, 260-330; `run.ts` 55-115, 150-175).
- **Failure scenario.** An implementer reads the card, sees that `--locale`
  selects the lexicon, sees `score.ts` declared not-editable but not told where
  the terms enter `scoreNote`, and concludes the locale must be resolved inside
  `score.ts`'s cached default. They add a locale parameter to `lexicon()` and
  edit a file the card forbids — HS-9 territory — or, having been told not to,
  they stall. Either way the card made them guess to satisfy its own rule.
- **Correction.** Add to `## Read`: `server/src/routes/health.ts` (lines
  104-130), `server/src/eval/score.ts` lines 111-124 (`ScoreOptions`,
  `lexicon(options)`, `cachedLexicon`) and `run.ts:144`, and add one sentence to
  FD2c: "the locale-scoped term list reaches `scoreNote` through the existing
  `ScoreOptions.lexicon`, which `run.ts:144` already passes; `score.ts` needs no
  change, and its module-level `cachedLexicon` default must not become the path
  by which a locale-specific lexicon is loaded."

### D-2 — FD2b's own worked example contradicts FD2b's placement rule

- **ID and location.** IR-03. `## Fixed decisions`, **FD2b**, the
  `invented-negation` control's JSON entry: `"{{lexicon}} niega(?:ndo)?"`, read
  against FD2b's Placement bullet and its own closing sentence.
- **The conflicting text.** Placement (B-1): "The token goes in the negator's
  slot, and only there … The expansion **replaces** the negator the authored
  phrase already carries; it is never prefixed to a phrase that already has one."
  The gold it claims to mirror writes that entry as `niega(?:ndo)?` — a phrase
  with **no** negator at all (verified in both tuning corpora). Expanding the
  card's entry yields `(?:no|nunca|jamás|…) niega(?:ndo)?`, which is a *double
  negative assertion*, not the invented claim the class is about, and it is a
  negator prefixed to a phrase that carries none — the exact shape the rule
  forbids. The card's own next sentence already states the correct handling for
  this situation ("an entry whose whole phrase *is* a lexicon term keeps its own
  authored negator and no token") but does not extend it to a phrase with no
  negator.
- **Failure scenario.** The es-MX invented-negation control's `controlNote`
  commits the class's error by writing "Niega dolor." Following the card's own
  JSON, three of the four `mustNotContain` patterns fire and the control is
  correctly `flagged` — so V2 passes and the defect hides. But V1's mandated B-1
  assertion ("the expanded `mustNotContain` / `mustCapture` patterns are the ones
  FD2b prints — token in the negator's slot, no doubled negator anywhere") has no
  way to evaluate "the negator's slot" for a phrase that has none, and a
  reviewer comparing the card to the gold sees the invented-negation detection
  asserting the opposite of the class's error.
- **Correction.** In FD2b's `invented-negation` entry, change
  `"{{lexicon}} niega(?:ndo)?"` to `"niega(?:ndo)?"` (no token), and add one
  clause to the Placement bullet: "a phrase whose negator is not a lexicon term —
  including a phrase with no negator at all, such as `niega(?:ndo)?` or
  `jam[aá]s` — carries its own authored negator and **no** token."

### D-3 — the rule V3's exit 3 silently depends on is not stated as a rule

- **ID and location.** IR-03. **FD6** (coverage: "A positive control is authored
  from the **same** source as that class's real detection — … the sidecar-shaped
  gold for the rest") read against **FD8** and **V3** ("its `mustNotContain`
  patterns each contain the `{{lexicon}}` token").
- **What is missing.** V3 is decidable only if **every** `mustNotContain` entry
  of `es-MX/positive/02-negacion-inventada.txt` carries a `{{lexicon}}` token,
  because blinding must turn all of them into `(?!)`-prefixed never-matching
  patterns for `F1 banned string` to disappear and the control to be missed.
  FD8 and V3 *describe* the four entries FD2b prints; nothing states the
  constraint as an author-time rule, and FD6's coverage paragraph invites the
  implementer to port the gold's own list — which contains `jam[aá]s` and
  `niega(?:ndo)?`, neither of which can carry a token.
- **Failure scenario.** The implementer adds `jam[aá]s` (the gold's most
  characteristic invented-negation entry) to the sidecar's `mustNotContain`. The
  non-blinded V2 run still flags the control, so V2 passes. The blinded V3 run
  leaves `jam[aá]s` intact, it fires on the control note, `F1 banned string`
  stays in `gating`, the control is **not** missed, and V3 exits **0** instead of
  the reserved **3**. The negative control silently stops being a negative
  control, and the card's most load-bearing exit-code claim becomes
  implementation-dependent.
- **Correction.** Add to FD6's key-table row for `lexicon` (or to FD2b's
  validation list, as a fifth author-time `CorpusError`): "for an `es-MX`
  `invented-negation` control, **every** `mustNotContain` entry must contain a
  `{{lexicon}}` token — a non-token entry there leaves the control flagged under
  `--blind-lexicon negation` and V3 can no longer reach exit 3 — and add to V1:
  "a test that every `mustNotContain` entry of
  `fixtures-controls/es-MX/positive/02-negacion-inventada.txt` contains
  `{{lexicon}}`, so V3's exit 3 is a property of the fixture, not of the
  author's list."
