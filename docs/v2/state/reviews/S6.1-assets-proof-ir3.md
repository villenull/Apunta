   election implied, notice unshipped) is correct and must not change.
2. **`project` is declared in `MANIFEST_SHAPE` and `RECORD_SHAPE` but never cross-checked.**
   Measured in `s61-extra.mjs`: setting `record.project = 'chromium'` inside an es-MX run, and

   the field is decorative, so one line saying so (or dropping it from the two shapes) would stop
   the next reader assuming it is gated.
3. **The shape contracts are a type-check whitelist, not a total schema.** `observedInArrivalOrder`,
   `buildRoot` and `spanishAvailable` are read by `validate` and absent from `RECORD_SHAPE`. I
   probed all three for reachable missing-key failures and each is safe and named:
   `buildRoot` absent → `E-MISSING`; `buildRoot: '/etc'` → `E-PATH: absolute path`;
   `buildRoot: '../../..'` → `E-PATH: … escapes`; `observedInArrivalOrder` absent / `null` / `[]` →
   `E-MISSING: observedInArrivalOrder`; `[3]` → `E-DERIVATION`; `spanishAvailable` absent →
   `ok: true`, which is **correct** because attribution is bound to the stored setting, never to
   availability (D-01). Worth one sentence in the header, since the header currently reads as though
   the specs are exhaustive. Note also that `safeRead(SCRATCH, String(record.buildRoot), …)` coerces
   first, so the `E-PATH: not a relative path` branch is unreachable at that call site — an absent
   `buildRoot` lands on `E-MISSING`, not `E-PATH`. Harmless; worth knowing.
4. **Six stale `test-results/s6.1-assets-proof-*` directories** dated 2026-10-01 23:23–23:25
