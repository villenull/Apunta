### R7 — IR-03 — `style-src 'self' 'nonce-<n>'` on every HTML response blocks the app's React inline styles

- **ID and location:** `cards/P3.4.md:83-87` ("**The minimum set is rule 6's six
  directives, exactly** … `style-src` is not in rule 6, so with no `style-src`
  inline styles fall back to `default-src 'self'` and are blocked") and `:88-101`
  (the nonce bullet), read together with `:161-167` (every `text/html` response
  carries the header) and `:169` (V1(i), V2(d)).
- **Text that conflicts:** the `onSend` hook "cannot tell a static file from the
  SPA fallback or the boot page by route table", so it cannot scope `style-src`
  to the boot page only; one header shape therefore lands on the app's
  `index.html` too. A nonce (or a hash) authorises `<style>` **elements** only —
  CSP3's `style-src-attr` falls back to `style-src` and a nonce does not apply to
  `style=""` attributes. The app sets inline style attributes in ten components
  (Baseline verification): the wordmark and brand mark, the live-recording level
  meter, the patient-row drag ghost (`PatientsColumn.tsx:1397,1406,1434`), the
  sidebar resizer and view menu positions, the spelling menu and patient menu
  positions.
- **Concrete failure scenario:** the CSP is implemented exactly as decided and V1
  and V2(d) both pass — they assert header presence, never rendering — while the
  running app loses every absolutely-positioned overlay: the spelling menu and
  the patient menu appear at 0,0 or unstyled, the drag ghost does not follow the
  pointer, the recording meter is invisible. No row in this card looks at layout,
  so the regression is invisible until P3.6 or the owner. The alternative is
  worse for the reviewer: the implementer adds `style-src 'unsafe-inline'`, which
  trips the card's own stop condition.
- **One specific correction:** add a clause to the nonce bullet naming the scope
  decision the card must make: either (a) `style-src` is emitted **only** on the
  boot page's responses, with the card stating how the hook distinguishes them
  (content check on the payload, since route-table distinction is excluded) and a
  V1 case asserting the app's `index.html` carries **no** `style-src` at all; or
  (b) `style-src` goes on every HTML response and the card records, as a known
  consequence with a named follow-up card, that React inline style attributes are
  blocked app-wide and `web/**` must move them to CSS modules. Option (a) is the
  one I would recommend; either way the card must not leave the implementer to
  discover it.
- **Round 1 status:** new in round 2. Round 1's D2 concerned the boot page's
  `<style>` only; the collision with the app's inline styles was not raised.
