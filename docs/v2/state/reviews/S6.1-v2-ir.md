## A. Blocking technical defects

### IR-01 — V0's gate regex cannot match, so Stop 1 can never open — **DEFECT**

V0's second command is:

```
rg -n "dictionary-es-mx.*(MPL-1\.1\|GPL-3\.0\|LGPL-3\.0)\|2\.0\.0" docs/decisions.md
```

Inside a double-quoted shell string `\|` reaches ripgrep as an **escaped literal
pipe**, not as alternation. The pattern therefore asks for the literal text
`MPL-1.1|GPL-3.0|LGPL-3.0` and then a literal `|2.0.0`. Tested against a
realistic `docs/decisions.md` row in `/tmp`:

```
| 2026-10-01 | dictionary-es-mx (GPL-3.0 OR LGPL-3.0 OR MPL-1.1) at 2.0.0 | why | files |
→ no match (exit 1)
```

This is exactly the failure mode the prior review's A8 was raised to prevent, in
a worse shape: a *match count* gate is replaced by a *regex* gate that matches
nothing. The row is not merely weak evidence, it is unfalsifiable evidence, and
per §13 stop 1 the card is `BLOCKED` forever. Note that unescaping the pipes is
**not** the fix either: `A|B|2\.0\.0` binds as `(A)|(B)|(2\.0\.0)`, so a bare
`2.0.0` anywhere in the file would satisfy the row and the "same line carries
package, arm and version" requirement in *Expected* would be a claim the regex
does not enforce.

**Bounded fix.** Use one pattern with both requirements on one line, and keep
*Expected* as the human check it already is:

```
rg -n "dictionary-es-mx.*(MPL-1\.1|GPL-3\.0|LGPL-3\.0).*2\.0\.0" docs/decisions.md
```

Add to *Expected*, one sentence: the alternation is unescaped and the trailing
`.*2\.0\.0` is inside the same branch, so a line that carries only a version does
not match. The quoted-row requirement in *Expected* stays and remains the real
gate. Verified: this pattern matches the sample row above and rejects a row that
carries only `2.0.0`.

### IR-04 — V1(a)'s parity case compares the wrong two lists — **DEFECT**

V1(a) is well constructed in intent — an ASCII-only corpus, the *literal* old
pattern, exact list equality — and F1 is genuinely closed by the corpus being
specified ASCII-only. The mechanism is wrong, though. "A speller stub recording
every word it is asked about" records what reaches `Speller.correct`, and
`findMisspellings` (`web/src/lib/spelling.ts:41-52`) asks about a word **twice**
(`plain`, then `plain.toLowerCase()`), and asks about **nothing** for a word that
`worthChecking` rejects (`:30-35`: length < 2, all-uppercase, inner capital) or
that the allow-list absorbs (`:47`). So the recorded list is neither the old
pattern's output nor the new pattern's output; it is a filtered, lowercased,
doubled projection of both. Asserting it equals the old pattern's list cannot
pass, and asserting it equals a projection would not prove tokenisation parity —
which is the only thing §2.2's *"the English tokenisation must be proved
identical"* needs.

**Bounded fix.** Keep the stub, the corpus and the exact-equality assertion, and
make the two sides the same kind of object by comparing tokenisations, not
speller traffic. One sentence replacing the mechanism clause:

> the case tokenises the corpus with the new `WORD` and with the literal old
> pattern `/[A-Za-z]+(?:['’][A-Za-z]+)*/g`, applies `plainWord` to each match of
> each, lowercases, and asserts the two `string[]` are identical; the speller
> stub is still required to be asked about exactly that set, in that order, once
> per distinct lowercased word.

Everything else in (a) — the ASCII-only corpus, the contractions, digits,
punctuation, the URL fragment, the em dash, the "identical" wording — stands.

### IR-05 — V1(c) claims byte-identical results across two encodings that cannot be byte-identical — **DEFECT**

V1(c) requires that "the precomposed and the decomposed (`sesio` + U+0301) forms
of the same sentence give **identical word lists and identical misspellings**",
and §7 repeats it as "byte-identical results". They are not, and cannot be: in
the decomposed form the matched token is 6 code units long and in the precomposed
form 5, so `Misspelling.start`/`end` (`spelling.ts:19-24`, `:49`) differ for
every word after the accented one, and the `word` string itself differs in its
bytes. This is the *correct* behaviour of the design — per-word NFC is exactly
what keeps the offsets indexing the original, which §7 argues well — so the
assertion is wrong, not the mechanism. As written the case goes red for a correct
implementation, which is the contingency §9.1 exists to prevent.

**Bounded fix.** Split the requirement in two, which is also what makes it
stronger:

- the **words** are identical: `m.word.normalize('NFC')` and the lowercased
  forms handed to the speller are equal across the two inputs, and the set of
  flagged words is equal;
- the **offsets** are exact **in each input separately**:
  `original.slice(m.start, m.end) === m.word` for both, and each `m.end` is the
  code-unit length of `m.word` in *that* string.

Delete the phrase "identical misspellings" and "byte-identical results"; §7's
existing bullet — "the returned offsets index the original string in both the
precomposed and the decomposed case" — is already the right claim and survives
verbatim.

> must leave the active list empty, and a snapshot taken under `es-MX` and
