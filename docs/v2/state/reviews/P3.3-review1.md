## Blocking defects

### D1 HIGH — closing the app's own window orphans the server, leaks the port and the data lock

Reproduced 2/2 on the built AppImage (test identity, sandbox 7831, `Xvfb :77`).
After a plain `xdotool windowclose` on the `Apunta` window: shell gone at t+2s,
child still alive at t+20s, `127.0.0.1:7831` still bound, `apunta.lock` still
naming the reparented server (ppid `systemd --user`), AppImage FUSE mount
`/tmp/.mount_ApuntabMMJNP` left behind (`app2-stderr.log`, `app4-stderr.log`).

`main.rs:111-126` runs the ladder only from `RunEvent::ExitRequested`. On a real
window close that never runs: GDK's X error handler kills the process instead —
`Gdk-WARNING: received an X Window System error … BadDrawable (error_code 9)`.
This is exactly what the implementer's SIGTERM watchdog was added to prevent, on
the path the owner will actually use. Correction: also run the ladder from the
main window's `WindowEvent::CloseRequested`/`Destroyed` (or a `RunEvent::Exit`
fallback), and make it one-shot (D2).

### D2 HIGH — SIGTERM livelocks the shell: the child dies, the shell spins at ~4.3 cores

Reproduced 2/2. After `kill -TERM <shell>` the child shuts down correctly, then
the shell reports `State: R (running)`, `Threads: 41`, **434 cpu jiffies in 5 s**
(~4.3 cores) and never exits; new tids appear and vanish each cycle (2667862,
2667866). Mechanism: `main.rs:115-120` reads `child.pgid` but **never clears it**,
and `main.rs:120` calls `api.prevent_exit()` on *every* `ExitRequested` —
including
the one provoked by the watchdog's own `watchdog.exit(0)` (`main.rs:198-203`).
Each cycle prevents the exit again and spawns another ladder thread whose
`next_step` is `Done` at once (group gone), which calls `exit(0)` again.
Correction: add `quitting: AtomicBool` to `Spawned`; if already set, return
without `prevent_exit`; store `pgid = 0` once the ladder completes.

### D3 HIGH — the CI `rust` job cannot pass: no GTK/WebKitGTK system dependencies

`tauri` 2.12.1's `default = ["wry", …]` puts `tauri → tauri-runtime-wry → wry
0.57.0 → gtk / webkit2gtk-sys 2.0.2 / soup3-sys` in the graph, and
`webkit2gtk-sys-2.0.2/build.rs` is `if let Err(s) =
system_deps::Config::new().probe() { … process::exit(1) }`.
`.github/workflows/ci.yml:82-116` has no `apt-get` step, and the `ubuntu-latest`
(24.04) image's apt list has **no** `libgtk-3-dev`, `libwebkit2gtk-4.1-dev`,
`librsvg2-dev` or `libayatana-appindicator3-dev` (it does have `pkg-config`,
`patchelf`, `xvfb`, `libssl-dev`). So `cargo clippy --all-targets` (`ci.yml:113`)
dies at `webkit2gtk-sys` and `cargo test` would die at link. Return Deviations 7
claims only bundling needs the packages; compiling does — `cargo fmt --check`
passes and the other two never get there. Correction: before the three checks,
`sudo apt-get update && sudo apt-get install -y libwebkit2gtk-4.1-dev
libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev` (A03's "Ubuntu archive via
`apt`" already admits these names).

### D6 MEDIUM — V3's "home screen" assertion is vacuous and cannot prove the page rendered

`scripts/v2/tauri-lifecycle.test.mjs:351` waits for `xdotool search --name
'^Apunta$'`. xdotool's `--name` regexp is **case-insensitive**, and the app has a
hidden 20×20 GTK helper window named `apunta` that matches first:
`xdotool search --name "^Apunta$"` → `2097153 [apunta] X=20 Y=20 20x20`, then
`2097190 [Apunta] X=-580 Y=-360 2560x1720`. `windowTitles()` takes the first match,
so the assertion can be satisfied by the helper window appearing at GTK init —
before any bridge line. The real app window is also mostly **off-screen** on a
1400×1000 display and nothing asserts that.

The page *does* render — I checked the pixels, not the title:
`build/p33-review-scratch/v3-root.png` (`import -window root`) has **919 unique
colours**, sd 9247 (a blank webview is 1 colour, sd 0), and its downsampled
luminance map shows a header band, a left list column, a main pane and a bottom
band: an application layout, not a blank or an error page. V3's substance is true;
nothing in V3 proves it.

Correction: match case-sensitively (or use `--classname`/`--pid` scoped to the
app pid), assert the window rectangle lies inside `xdotool getdisplaygeometry`, and
assert the window capture is non-uniform.

rule 5).** `main.rs:399` uses `t.as_str().starts_with(&allowed)` with
`allowed = "http://127.0.0.1:<port>"`; the prefix ends in the port, so it admits
