## Numbered findings for the implementer

None of these is a reason to refuse the card. Two are one-line fixes in files
this card owns; two are decisions that are the coordinator's, not the code's.

1. **`scripts/v2/probe-redirects.mjs:249-251` — the `unparseable` branch pastes
   a raw `Location`, query and all, into a committed evidence file.** A relative
   `Location` is legal HTTP, Node's `fetch` hands the header back as sent, and
   `new URL('/ggml/resolve/main/x.bin?Expires=1789&Signature=AbCd…')` throws
   `ERR_INVALID_URL` — which I observed — so `describeLocation` takes its `catch`
   and the whole raw string, signature included, is written verbatim. Every other
   path in the file runs through `redactQuery`. **Latent, not an incident:** it
   did not fire in my run or the implementer's, I did not observe a leak, and
   the file as produced carries 14 `<redacted>` and no value. It is reported
   because the brief asked me not to assume attempt 1's state was sound, and
   because it is the one place the design's central promise is not kept. **Fix:**
   `lines.push(\`- raw: \\\`${redactQuery(location.raw)}\\\`\`)`, and say in that
   branch that the record is incomplete. Full write-up, and the argument for a
   test the card's May edit list does not yet permit, in `review-probe.md`.
   Not in the attempt-2 diff; the implementer cannot be blamed for it and the
   coordinator may prefer to carry it into whichever card next touches the probe.

2. **`installer/src/readiness.ts:245-252` — nothing to fix; recording that I
   tried to break it and could not.** 39 adversarial names, all refused, and 13
   legitimate shapes, all admitted: every case-folded spelling, every prefix,
   every suffix, `*`, `Sig*`, `.*`, a value alone, `=abc`, `%26Signature`,
   `%2553ignature`, `Signa+ture`, `Signature%00`, `Signature%0A`, `Signature%3D`.
   The one normalisation present — percent-decoding a **name** — makes the guard
   agree with the server rather than diverge from it, which I verified case by
   case against `URL.searchParams`: `%53ignature=1` is admitted and the server
   reads the name `Signature`; `Signature%0A=1` is refused and the server reads
   `Signature\n`. And the check is upstream of the socket on every path, asserted
   by request count rather than by the error alone: an off-list name on the
   initial URL is **0 calls**, on a `Location` is **1 call** with the offending
   address in none of them. Evidence in `review-security.md`.

3. **The card's Fixed decision 2 sentence is unimplementable and the implementer
   was right to say so.** "Empty for every entry but the six C-STT ones" — the
   six candidates are not catalogue entries (`grep` finds all six nowhere in
   `installer/src/`; exactly two `SpeechModelEntry` values exist), so the literal

4. **`sizeBytes: 77_704_715` is a transcription, and a wrong pin is a 75 MiB

   the download runs again — verified, committed, refused identically, for ever.
   The refusal message is the right one, but nothing stops the loop. Detecting
   stop condition 5's *second* mismatch is genuinely impossible inside May edit

   probe, which Fixed decision 10 forbids), and I agree with that reasoning. **For
   the coordinator and the owner:** this pin is load-bearing on the first-run
