# S6.1 asset-evidence pipeline — executable synthetic proof (round 3 correction)

**Scope: a proposal proof, not production correctness and not card acceptance.** Nothing in the
S6.1 card, contract, gate, threshold or checkpoint was changed. Files written: this report and
`docs/v2/state/proofs/S6.1-assets-proof.mjs`, both left uncommitted. Round 1's and round 2's
independent reviews (`-ir1.md`, `-ir2.md`) are **preserved unchanged**; round 3 corrects round 2's
own artefacts against ir2's seven findings with small changes plus regression cases, not a rewrite.

**What this proof does *not* certify.** Every record, filename and digest is synthetic, and the
dictionary assets are **fabricated Hunspell-shaped stubs** written by the proof itself. No browser
ran, no Playwright project ran, no `npm run build`, no server, no database, no dictionary install,
no licence research and no network call. **Nothing here is evidence about real browser behaviour,
real Vite asset hashes, or the shipped `dictionary-es-mx`.** A passing run means the gate logic
fails closed on the shapes listed, not that the browser rows can produce them. The shape contracts
the entrypoints run are a **type-check whitelist, not a total schema**, and the `project` field is
**decorative and path-bound** rather than gated; §3 states both limits, which absent *required* key
still refuses by name, and which absence is permitted.

## 3. Part B — what round 3 changed

**Parseable is not shaped.** Round 2 wrapped `JSON.parse` but then dereferenced whatever came back,
so `manifest = null` and `record = null` threw `TypeError` — the round-1 complaint, unfixed. Now
`parseJson` refuses anything that is not a non-null, non-array object (`E-SHAPE`), and each
entrypoint also runs a declared **shape contract** before its first dereference: the manifest
(`sessionId`/`runId`/`project`/`publication` strings, `statuses`/`artifacts` objects), the record
(including its whole `build` map) and the build manifest (`modules` map of `{aff,dic}` path+digest
pairs, `emitted` list). Every digest is then checked to be a **full 64-hex sha256** rather than
merely a string. Two limits of those contracts, so that nothing here reads as exhaustive: they
are a **type-check whitelist, not a total schema** — keys such as `observedInArrivalOrder`,
`buildRoot` and `spanishAvailable` are read by `validate` and are absent from the shapes — and the
three absences are **not** one case: the two **required** keys fail closed by name (`buildRoot`
absent → `E-MISSING`, present but absolute or escaping → `E-PATH`;
`observedInArrivalOrder` absent/null/`[]` → `E-MISSING`, wrong contents → `E-DERIVATION`), while
`spanishAvailable` absent yields `ok: true`, which is **correct** because attribution is bound to the
stored setting, never to availability (D-01) — so it is permitted, not refused. The `project` field
is likewise **decorative and path-bound**: it is declared in both shapes but this synthetic model
does not cross-check it, and identity is carried by the path (`manifest-<project>.json`,
`observed-<project>.raw.json`) and by `record.runId` against the folder basename. A record whose
`project` disagrees with its own folder therefore still validates here; that is a limit of what this
synthetic model measures, not a production guarantee about the shipped collector. The new matrix
**N28–N31** drives 24 malformed shapes — null, array, number, string,
missing and wrong-typed nested fields, truncated digests — through all three entrypoints and asserts
each is refused **by name**, with `assert.doesNotThrow` as the explicit no-throw check. There is
deliberately **no broad `try/catch`** anywhere in the pipeline: a genuine assertion or programmer
error still fails the proof loudly. Each matrix case mints a **fresh build id** on purpose: because
the reuse path now *refuses* a tampered build, a shared id would stop minting and the case would
silently be exercising an earlier gate instead of the one it is named for.

**The build fixture is immutable as a measured property, not a comment.** Round 2 wrote the four
asset files with a plain `write()` **before** the reuse check, so re-minting a tampered build
silently repaired it — the exact `O_EXCL` property its own JSDoc claimed. `mintBuild` now has two
paths and only two: **CREATE** writes every file with `flag: 'wx'`, and **REUSE** writes nothing at
all — it re-hashes what is on disk against the manifest and refuses on any mismatch with a new code
`E-BUILD-TAMPER`. N32a asserts a re-mint leaves every file byte-identical *and* every asset mtime
unmoved; N32b tampers an asset from outside, re-mints, and asserts the refusal **and** that the
tampered bytes and mtime are still exactly as they were — no silent repair. N18 still tampers with a
build, and still reaches `E-ASSET-BYTES` through `validate`, which is a different gate on purpose.

**Foreign-folder fixture ownership.** Round 2's N19b created `join(SCRATCH, '..', 'foreign-<pid>')`
with a recursive `mkdir` and removed it unconditionally, with no `try/finally` — a path it might not
own, contradicting its own "remove exactly the directory this process created". It now creates a
second `mkdtemp` parent (`test-results/s6.1-assets-proof-foreign-XXXXXX`, itself outside this run's
scratch so it is a genuine refusal target) and a `mkdtemp` child inside it, removes the parent in a
`finally`, and asserts the foreign folder survives the refusal untouched. **No pid, no fixed name,
no recursive delete of a path this process did not create.**

**The sealed observation log, explained.** `logs/observed-<project>.txt` is the arrival-order list
exactly as the collector wrote it down, kept so a reader can see the pre-sort claim. It is **not** the
authoritative data: the authoritative pair is `evidence/observed-<project>.raw.json` (arrival order —
`E-DERIVATION`, `E-DUPLICATE`) and `evidence/observed-<project>.txt` (sorted-unique —
`E-KIND`, `E-UNSORTED`). The log is sealed by the manifest digest walk and by nothing else, which is
why no gate derives a decision from it. `EN_PAIR`/`ES_PAIR`/`EMITTED_A` are labelled in the script as
Part A's cosmetic names, not build facts.

Everything round 2 established still holds: the module→asset relation is derived from shipped source
(`locales.ts` carries `dictionary: null` for en and `'dictionary-es-mx@2.0.0'` for es-MX;
`speller.ts` resolves `node_modules/dictionary-en/index.aff|.dic`), same-build identity is
byte-derived with full digests, manifest key-set equality is checked before the digest walk, and
`E-SAME-DICTIONARY` remains unreachable by construction (N22). **New codes:** `E-SHAPE`,
`E-BUILD-TAMPER`.

## 5. D-06 — minimal exact wording fix

Unchanged from round 1 and still measured on `Vino a la sesión con José mañana` and its NFD form using
the proposed Unicode `WORD` shape: raw flagged word sets **differ**, raw `[start, end]` pairs
**differ**, per-input `slice(start,end) === word` and `end - start === word.length` both hold exactly,
NFC lengths `[4,1,2,6,3,4,6]` vs NFD `[4,1,2,7,3,5,7]`, and the NFC projections are **equal**. So the
clause "**and the flagged sets are equal**" in V1(c) is false under the raw reading and redundant under
the projected one. **Minimal fix — three words, either form:** delete the clause, or read it as "and
the flagged sets, as `{plainWord(m.word)}` sets, are equal". The scanner's *shape* is reported as
§1/§3 describe: `\p{M}` is a strict superset of U+0300–U+036F, identical for this fixture, chosen for
readability and not because a lint rule required it.
