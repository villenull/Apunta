## 1. F1–F4 closed, with independent evidence

### F1 — geometry command classified (fail closed)

`runFlow` calls `checkCommand('getwindowgeometry', geometry.value)` at
`model.mjs:812`, immediately after the geometry await and **before** any field
is consumed. A non-zero status, a signal or an `XError` in either stream is an
immediate failure naming the command. The same uniform protocol is applied to
`mousemove` (`:604`), `getmouselocation` (`:612`) and `click` (`:690`) — all
four commands classified, no geometry special-case.

The adapted probe confirms the fix is classification, not an early
missing-field refusal: the healthy geometry carrying the full
`code/signal/stdout/stderr` protocol still runs the whole flow and clicks
(`ok=true clicked=true`), while the three failing geometries are refused with
`ok=false clicked=false` and the correct reason. Model case `F1-g` pins this.

### F2 — one shared deadline-raced observation poll

`pollObservation` (`model.mjs:206-225`) is the ONE shared poll. It reads the
injected `currentFact` repeatedly, waits between reads through the injected
`schedule`, and races **every read and every wait** against the SAME immutable
deadline. `classify(fact)` is tri-state: `ok`, terminal fail, or pending (wait
for the next 250 ms hook tick). A thrown predicate is fail-closed. There is no
phase timer and no reset.

It is used for every "require a fact line" step: the viewport (`:826`), the
`ptrN` baseline (`:587`), the post-warp witness (`:623`), the `clickN` baseline
(`:672`), the fresh click fact (`:697`) and the landing (`:719`). A **stale**
fact waits; a **fresh but wrong or malformed** fact fails closed, so a
known-wrong fresh descriptor is never skipped while a good one is awaited.
`landingFact` reports `pending: true` for an unchanged landing so the landing
poll waits instead of failing a healthy-but-not-yet-published landing.

The adapted probe confirms: (a) a delayed pointer observation is waited for
and succeeds (`ok=true ticks=4`); (b) a delayed landing is waited for and
succeeds (`ok=true ticks=4`); (c) a never-delivered pointermove ends at the
deadline (`ok=false clicked=false reason=the target deadline expired`). Model
cases `F2-a` through `F2-i` pin every variant.

### F3 — the solve uses the measured native read-back

`guardedMove` returns `native = { x: read.value.X, y: read.value.Y }` — the
measured read-back it already validated to ≤ 1 px — alongside the measured
client `seen` (`model.mjs:618`). `runFlow` solves from `one.native`/
`two.native`, not from the commanded `naive`/`displacement` (`model.mjs:867-870`).
The ≤ 1 px read-back check is unchanged and still matters.

The adapted probe confirms: two flows identical except the read-back differs by
exactly 1 px (inside tolerance) ask for **different** target native points —
`{"x":627,"y":653}` vs `{"x":628,"y":653}` — and the independently computed
measured solve asks `x=628`. Model cases `F3-m` (1 px read-back difference
moves the target by 1 px) and `F3-n` (asymmetric per-point native errors at
scales 1, 1.5 and 2; the target equals the independently computed measured
solve and the fresh witness validates before the click) pin this.

### F4 — the duplicate comparison is field-by-field

`createBatchReader` compares two complete sightings with `sameRect`, which
compares the seven named field values (`x y w h l t d`) index by index
(`model.mjs:337-341`), instead of `JSON.stringify`. Query-parameter order and
index order are irrelevant, so a permuted identical duplicate is idempotent; a
changed value is still a conflict.

The adapted probe confirms: a permuted identical duplicate (both parameter
order and index order changed) is `idempotent-duplicate` with `conflict=null`
and `frame.ok=true`; a changed value is `conflict` with `frame.ok=false` and
the reason `two complete sightings of epoch 2 batch 0 differ`. Model case
`F4-r` pins this; the pre-existing `G5` still pins the differing-value
conflict.

## 2. Contract conformance, clause by clause

### Contract 1 — epoch, valid header, complete batch, selection

- **Valid header read separately from complete batch.** A valid header (safe
  integer epoch ≥ 1, strict safe-integer `rects`, strict non-negative-integer
  `batch` in range `0 … ceil(rects/40) − 1`) raises `highestSeenEpoch`
  immediately at `model.mjs:394-395`, before the body is looked at, even when
  the body is truncated. An invalid header raises nothing (`:385-390`).
  Probed by `G4`, `G6`, `G7`, `G13`, `G4b`.
- **Complete batch installed whole.** Only a complete batch (every index of
  the batch's own slice present with all seven fields, every present index
  below `rects`, no index outside the slice) is installed, replacing that
  batch's entire rectangle map (`:441-443`). A truncated or malformed body is
  never installed, never merged, and never a conflict — a conflict needs two
  **complete** sightings of the same `(epoch, batch)` with differing fields
  (`:426-439`). Probed by `G4`, `G5`, `G5b`, `G6`, `G12`.
- **Highest seen epoch only, no fallback.** `frame()` selects the highest seen
  epoch only, and only when it is complete: batches `0 … ceil(rects/40) − 1` all
  present, all declaring the same `rects`, union of global indices exactly
  `0 … rects − 1` (`:446-482`). Lower and out-of-order epochs are ignored;
  identical complete duplicates are idempotent; A → B → A is three distinct
  publication epochs and the third is selected. A frame still incomplete when
  the deadline expires is the row's `FAIL`, carrying the count — never a
  fallback, never a click. Probed by `G3`, `G8`, `G9`, `G10`, `G13`.
- **Selection by unique (label, tag) pair.** `selectTarget` keys on the pair,
  never on `testId` (`:500-518`). The appended tooltip carries the same label
  with a different tag and is told apart by that comparison. More than one
  live rectangle matching the pair is `ambiguous` and FAILs with the count and
  the global indices. `testId` is compared **after** the click, against the
  descriptor of the selected rectangle. Probed by `H1`, `H2`, `H3`, `H4`.

**On "highest seen publication target not fixed old frame if newer arrives":**
the contract §C.3 says the highest seen epoch only, and a newer incomplete
publication forbids falling back to an older complete one. The model
implements exactly this: `frame()` always returns the highest seen epoch's
frame, and a newer valid header (even with a truncated body) raises
`highestSeenEpoch` so the older complete frame is no longer selectable. The
contract explicitly does **not** claim that an older frame becomes
unselectable once a newer complete frame exists, nor that a read observes the
page's latest state — the model makes no such claim and invents no
re-selection ritual. The selection happens once, at selection time, with the
frame the reader has at that moment. This is the contract's scope, not a gap.

### Contract 2 — calibration, then exactly one click

- **Window read natively once, pid validated.** `runFlow` reads the window
  with `awaitGuarded` (`:804-807`), classifies the command (`:812`), then
  validates: non-integer or non-positive `WIDTH`/`HEIGHT` is `NOT RUN`
  (`:816-817`), non-finite `X/Y` is `NOT RUN` (`:818-819`), non-positive-integer
  pid is `NOT RUN` (`:820-822`). Probed by `F11`, `F1-g`.
- **Viewport wait.** The viewport is a bounded wait for `vpW ≥ 400 && vpH ≥ 300`
  in a published fact line (`:826-840`). Absent means "not published yet"
  (wait); present but malformed or too small is a terminal fail. Probed by
  `F2-a`, `F2-d`, `F11`.
- **Two fixed targets derived from the viewport.** `P1 = (round(vpW·0.50),
  round(vpH·0.50))`, `P2 = (round(vpW·0.75), round(vpH·0.60))` (`:782-787`).
  Both interior, both clear of the top edge, different in both axes. Probed by
  `D8`.
- **Bootstrap, no exemption.** Move 1 asks for `(windowX + cx₁, windowY + cy₁)`,
  the naive 1:1 guess stated as an assumption; move 2 asks for the
  displacement `(X₁ + Δcx, Y₁ + Δcy)`, transform-independent (`:849-863`). Each
  is containment-checked **before** its own warp (`:582-583`), and a point
  outside the window rectangle is `NOT RUN` with no warp issued. Probed by
  `F3` (both bootstrap points containment-checked before their warp, with a
  600 px window refusing the first and an 800 px window refusing the second).
- **Baseline before every warp.** `guardedMove` reads a `ptrN` baseline
  before the dispatch (`:587-597`), a bounded wait for its presence. Probed by
  `F2-a`, `F2-d`.
- **After warp, fresh counter ≤ 2 px before exactly one click.** The witness
  poll waits for a fact whose `ptrN` is **strictly greater** than the baseline
  and whose `ptrCX/ptrCY` are within **2 client pixels** of the target centre
  (`:623-644`). **Nothing about the pointer's position is checked before the
  target warp.** Only then does `runClick` dispatch **one** `xdotool click 1`
  (`:685-688`). Probed by `J1` (the pointer left at calibration still clicks),
  `J2` (a stale witness beyond 2 px means no click), `J3` (off-screen target
  refused before the move).
- **After click, descriptor wrong FAIL before waiting landing.** The fresh
  click poll waits for `clickN` advanced by **exactly 1**, `clickCX/clickCY`
  within 2 px of the target centre, and the three descriptor fields matching —
  a stale fact waits, a fresh wrong one fails (`:697-713`). Only then does the
  landing poll run (`:719-729`). Probed by `J6b` (each descriptor field compared
  on its own), `J6c` (a click the page never observed is a failure), `J6e` (a
  counter that does not advance means no click), `F2-g` (a fresh but malformed
  click fact fails closed).
- **Actual href/scriptText landing.** `landingFact` requires the patient-open
  step to have a fact line published after the click whose **`href` differs**
  from the pre-click `href`, and the final step to have **`scriptText ===
  'true'`** (`:752-771`). An unchanged landing fact waits; `rectSignature`
  stays diagnostic text, never a pass (`:774-777`). Probed by `F8` (lands on
  scriptText), `F9` (refuses a landing that never happens), `J7`, `J8`.
- **Exactly one click per target.** No second point, no retry, no widened
  window, no late click after any terminal outcome. Probed by `J5b` (a hung
  click dispatch ends at the deadline and never clicks twice), `F2` (the
  exported flow clicks once).

### Contract 3 — one immutable 30-second target deadline

One deadline is taken once, before the first dispatch, and it covers
calibration, selection, every command, every await, the witness and the
landing. It has no `reset`, no `extend` and no per-step cap that could renew
(`:126-135`). Every dispatch and every await is **raced against the deadline's
own remaining time** (`:144-186`): a hung `mousemove` and a hung `click` both
end at the deadline instead of extending the row, and no continuation runs
afterwards. A result that arrives after it is a failure, not a success. There
are no phase timers and no second budget. A dispatch after the deadline never
happens, and no terminal path issues a click. Probed by `C1`, `C2`, `C3`, `C4`,
`C5`, `J5`, `J5b`, `J5c`, `J6`, `F2-i`, `F2-f`, `F7`.

### Contract 4 — command outcomes, the gate, the assertion, the cascade

- **Fail closed on every command.** `checkCommand` (`:233-245`) fails on any
  signal, any non-zero status, or `XError` in either stream. Applied to
  `getwindowgeometry` (`:812`), `mousemove` (`:604`), `getmouselocation`
  (`:612`) and `click` (`:690`). Probed by `F1`, `F1-g`, `J6d`.
- **Presence gate.** `firstFactGate` widens from `href` to `href` **and**
  `ipcProbe` present (`:531-533`). Presence only; settling belongs to the
  assertion. Probed by `I1`.
- **One assertion, one pass condition, all conjuncts together.** `assertNoIpc`
  requires `tauri === 'undefined'`, `ipc === 'object'`, `ipcInvoke ===
  'function'`, `ipcProbe === 'rejected'` **and** `ipcProbeMsg` exactly `Command
  plugin:event|listen not allowed by ACL` (`:548-561`). `resolved` is a failure;
  `pending` at the deadline is a failure; no timeout can produce a pass.
  Probed by `I2`.
- **Exactly one five-row cascade, two-arm cause.** `cascadeCause`
  (`:539-545`) distinguishes zero marker lines (the silent-hook arm) from
  marker lines that never carried `href` and `ipcProbe` together (reported with
  the count). Both arms are recorded together and neither is ever a pass. The
  five rows keep their order and their `NOT RUN` outcome. Probed by `I3`.

### Read-back window/pid identifies the actual app; finite axes bounded before use

- `checkReadback` (`:299-312`) requires `|X_read − X_asked| ≤ 1` and the same
  in y, plus `WINDOW` equal to the app window id **or** `PID` equal to the app's
  positive pid. Probed by `D7`.
- `solveTransform` (`:254-280`) checks all eight values finite **before** any
  conversion, checks both client axes differ, checks each `k` satisfies
  `0 < k ≤ 4` **before** the first conversion, and checks the offsets finite
  before returning `toNative`. Probed by `D1`, `D2`, `D3`, `D4`, `D5`.
