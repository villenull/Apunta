## What Stop 8 was firing on

P3.6 pinned P3.4's V3 command **as it stood at `5dcabae`** — a 318-byte, three-
command cell whose first two conjuncts were the backslash-escaped BRE greps
`grep -rn "invoke_handler\|withGlobalTauri\": true" …` and
`! grep -rn "VITE_APUNTA_TEST_IDENTITY\|p3.4-observe" …`. **AM-179** repaired
P3.4's green-always defect: a table cell forces `\|`, and an unescaped pipe in a
BRE is a literal, so both greps exited 1 on a tree carrying `invoke_handler` as
readily as on a clean one and **the row was green always**. The repaired cell is
a 628-byte (raw) / 624-byte (parsed) `for` loop over four fixed words with

copy still carried the old spelling, so a difference between the pinned copy and
P3.4's current cell existed **in the direction Stop 8 anticipated least** — not a
widened Rule B set (Rule B's bullet is byte-identical, 2154 bytes both sides,
`02-pins.txt`) but a reworded guard.

**Quoting is deliberate, and it is the one thing a mechanical copy must get
right.** `parseCells` on P3.4's V3 cell returns the command with **bare `||`**
(the shell's OR), 624 bytes; the literal table cell carries `\|\|`, 628 bytes
(`03-v3-command-derivation.txt`). P3.6's copies sit in bullets and a numbered
list, **not a table**, so they carry the **bare `||`** — the command a reader
copies out and runs. The old copy's `\|` had been a `grep` escape and is gone;
this repair does **not** reintroduce the inert BRE grep, because a fixed-string
loop needs no alternation and cannot be silently defanged by a table escape.
