## Numbered findings

### 1. BLOCKING — FD6 breached: for three or more changes, the English on the wire is not the English it was

`server/src/ai/refine-request.ts:592-599`, in `changeSentence`.

Attempt 3 replaced `I ${parts.join(' and ')}.` with a two-step
`chat.list.last` + `chat.change.summary`. For **one** part and for **two** parts
the rendered English is byte-identical. For **three or more** it is not:

```
base  77767c2 : "I shortened the Location section and expanded the Discussion section and expanded the Intervention section."
head  c5a62c8 : "I shortened the Location section, expanded the Discussion section and expanded the Intervention section."
```

Both lines are output I generated in one session by running the base module and
the head module on the same input — `review-a3-fd6-english.md` has the driver,
the base source and both transcripts. The cause is one line: `first` is
`parts.slice(0, -1).join(', ')` where base joined the same parts with `' and '`.

FD6, verbatim: *"Every English value this card writes is the string the server
sends today, character for character… A key whose English is not what the wire
carries today is a **stop**, not a copy improvement — S2.7 and S2.8 own the
copy."* This is that case exactly, and the resolution FD6 prescribes — stop and
report — is not what happened.

Three things make it more than a stray comma:

1. **The sentence is persisted.** FD5 renders the refine reply at write time and
   stores it as text, and a stored row is displayed as stored. So a thread
   refined before this change keeps `a and b and c` for ever and one refined
   after it gets `a, b and c` — a permanent visible inconsistency inside a
   single note's own history, in the one surface where the bytes *are* the
   record.
2. **The commit message asserts the opposite.** `ccb3dc2`: *"English is
   unchanged character for character: `I rewrote the Location section and
   expanded the Discussion section.` renders exactly as it always has."* True of
   that two-part sentence; false of the three-part form of the same sentence.
3. **The code comment asserts the opposite, inside the function.**
   `refine-request.ts:566-567`: *"The English is unchanged, character for
   character: this is the sentence the wire has always carried."* The next
   author of this function is the reader of that comment, and it is false in
   the branch it covers.

Nothing caught it because **no assertion anywhere in the repository pins the
three-part English.** `routes/chat.test.ts` pins the one-part form at `:146`,
`:164`, `:1303`, `:1492` and the two-part form at `:1467`; the new case in
`refine-request.test.ts` pins a two-part form; and the one new case that thinks
about commas — *"English is unchanged, comma and all"* — is testing
`listSections`, where the comma was already in the base.

I want to be exact about what I am **not** saying. The Spanish is right:
`a, b y c` is how Spanish writes a three-item list, and base's `a y b y c` would
have been wrong. `a, b and c` is also better English. My objection is not to the
judgement; it is that this card's fixed decision reserved exactly that
judgement for S2.7 and S2.8, and the judgement was made here and reported — in
the return file, in the commit message, and in a code comment — as not having
been made. On a card whose third review exists because a scope instrument could
not describe what it licensed, an invariant claimed as verified and not verified
is the failure mode worth stopping on.

**What makes it pass** (all of it inside the licence this card already holds —
no amendment, no owner, no new plumbing): keep the English at
`a and b and c` and the Spanish at `a, b y c`. Those cannot come out of one
join, so either the separator moves inside the key on the language, or the
sentence carries a second key for the English shape. Two lines in
`changeSentence`, plus one assertion on a three-part diff pinning
`'I shortened the Location section and expanded the Discussion section and expanded the Intervention section.'`
