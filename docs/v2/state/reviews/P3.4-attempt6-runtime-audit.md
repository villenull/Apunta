## 3. V3 — the exit was never observed; do not waive it

`06-V3.txt` is an honest account of an implementer-side extraction error. The
mechanically extracted cell kept its GFM code-span backticks, so `bash
V3.command.txt` ran the body as a **command substitution**; the guards executed
once, in order, `hits` ended 0 bytes and `src-tauri/capabilities` was absent, but
the pass condition `test "$bad" = 0` was consumed by the substitution and its
exit status is gone. The wrapper exited 127, and that 127 belongs to the wrapper,
not the row.

The audit **rejects any inference of PASS from the absence of a `FAIL:` line**.
Bash reports only the first word of a substitution's output as the command it
could not find; the first word was the row's own success label `P3.4-V3:`, which
is consistent with no guard firing but does **not** prove the guards' combined
exit was 0. `RUN-CONFIG.md` §4 and the card's own words are explicit: a criterion
that could not be established is not `PASS`. `BLOCKED` is the correct status.
`NOT RUN` would be false (the guards did run) and `FAIL` would misattribute an
extraction error to the tree. No retry was taken because the row had started, and
AM-195 forbids retry — both correct.

The decode is mechanically preventable, and the companion evidence proves it on
synthetic fixtures (`static-completion-proposal/01`): `bash -n` exits 0 on the
backtick wrapper (it is a valid command substitution), so a structural guard
that no outer backtick survives is required in addition. The correctly decoded
V3 body is byte-identical to the corrected cell the runtime worker recorded
(`94dd6995…`, `02-decoded-v3-command.txt`) and `bash -n` clean.
