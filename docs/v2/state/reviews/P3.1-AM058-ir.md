## D1 — AM-058's only non-vacuous version check has no predicate (IR-03, IR-04)

- **Location / missing:** dispatch `:192-196` asks to "verify these two runtime version
  reads are eliminated from the bundle" without naming a fingerprint. The companion value
  assertion (health `version`, lock `appVersion` = `server/package.json`'s) **cannot
  discriminate** — `server/package.json:4` is `"version": "0.0.0"` and both readers fall
  back to the same literal (`config.ts:174`, `data-lock.ts:56`). Relocation catches only
  one bundler outcome: a `require` esbuild left as a live `createRequire` read resolves
  against the *moved* bundle and fails, but one esbuild **inlined as an object literal**
  travels with it and the path strings are gone — the obvious grep then passes while the
  metadata ships.
- **Failure scenario:** bundle; grep `'../package.json'` → 0 hits → PASS; copy to
  `/tmp/apunta-v2/<runId>/bundle/`; health and lock both `0.0.0`; V1/V2/V3 green with the
  read still in the bundle — the check proves nothing.
- **Correction** (inside AM-058's scope, no new gate): pin the predicate to the two ways
  esbuild can leave the read behind, both source-verified now — `createRequire` occurs in
  exactly two files repo-wide (`config.ts:4,11`, `data-lock.ts:13,50`) and
  `"@apunta/server"` in **zero** files under `server/src` or `shared/src`, while being
  that package.json's `name`. Fail unless `grep -cE 'createRequire|@apunta/server'
