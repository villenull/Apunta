4. **Evidence overstates a check that cannot fail — `docs/v2/evidence/S1.5/evidence.md:39-53`.**
   The "substantive" follow-up (`npx prettier <file> | diff - <file>`, diff exit
   0) is vacuous for exactly the reason the paragraph above it identifies: with
   the file ignored by `.prettierignore`, `prettier` passes the bytes through
   unchanged, so a zero diff is a property of the ignore rule, not of the file.
   Forced past the ignore (`--ignore-path /dev/null`) the output differs: table
   column padding at lines 25–29 and `_italics_` for `*italics*` at lines 53,
   83, 94 and 109. The sentence "prettier's own output is byte-identical to what
   is on disk" is therefore true only of the pass-through, and the inference
   "the file is clean under the check whether or not the check ignores it" does
   not follow. *Passes when* the claim is scoped to what was run ("prettier's
   output for an ignored file is its input") or the forced result is reported;
   the file itself needs no change under AM-014.
5. **Self-description now false at the reviewed head — `docs/research/es-mx-spellcheck.md:189`, `docs/v2/state/returns/S1.5.md:5,11`, `docs/v2/evidence/S1.5/evidence.md:19`.**
