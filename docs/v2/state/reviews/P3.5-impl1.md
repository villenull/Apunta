## Candidate defects (source / evidence — the implementer's to fix)

### D1 — `pactl list short source-outputs` column mapping is wrong; the real-microphone leak check is vacuous

`scripts/v2/tauri-audio.test.mjs:1298-1300`:

```js
const streamLines = sourceOutputs.split('\n').filter((line) => line.trim() !== '');
const onVirtual = streamLines.filter((line) => line.split(/\s+/)[2] === SOURCE_NAME);
const onRealMic = streamLines.filter((line) => (line.split(/\s+/)[2] ?? '').startsWith(REAL_MIC_PREFIX));
```

The short text output of `pactl list short source-outputs` on this host's own
`pactl` is `"%u\t%u\t%s\t%s\t%s\n"` with:

| col | value |
| --- | --- |
| [0] | source-output index (numeric) |
| [1] | **source index** (numeric) |
| [2] | **client index** (numeric, printed with `"%u"`) |
| [3] | a pointer field (`(null)` when unset) |
| [4] | sample specification |

So column `[2]` is a decimal client index such as `167`; it is never a source
name and never `apunta_p35_mic` or `alsa_input.usb-UGREEN…`. Consequences:

- `onVirtual.length > 0` (`:1303-1307`) **can never be true**, so V3/V4's
  "a capture stream is present on `apunta_p35_mic`" assertion fails on a
  perfectly correct capture.
- `onRealMic.length > 0` (`:1308-1313`) **can never be true**, so the
  safety-critical assertion "no capture stream on the owner's real microphone"
  passes even when the app is capturing the owner's microphone. It is a false
  negative on the one check the card exists to make.

Proof (host ground truth, read-only): the host's `/usr/bin/pactl` is
`libpulse 17.0+r98+gb096704c0-1`. Disassembling
`get_source_output_info_callback` at `0x4018c5` shows the short-format branch
loads `%u`/`%u`/client/pointer/sample-spec, and the client string is built with
`pa_snprintf(buf, 0x20, "%u", *(u32*)(info+0x14))` — i.e. a **numeric client
index**. The `%u\t%u\t%s\t%s\t%s` format string is at `.rodata` `0x11763`.

Reproduction: `build/p3.5-review1/source-outputs-mapping.mjs` extracts the exact
three predicate lines from the shipped harness and evaluates them against a
fabricated but faithful source-outputs table (a live stream on the virtual
source *and* a simultaneous stream on the real microphone). Result, exit 0:
the shipped predicate returns `onVirtual=0` and `onRealMic=0`, while the correct
mapping (resolve col [1] through `pactl list short sources`) returns 1 and 1.
Evidence: `docs/v2/evidence/P3.5/review-1/source-outputs-mapping.md`.

The fix is to resolve the source index (column [1]) against the source table
(`pactl list short sources`: `index name …`), or to parse the long
`pactl list source-outputs` (`Source: %u`) / `--format=json`. Comparing any raw
column to a source name is wrong. (The coordinator return flagged this as
"appears to compare raw columns"; this review confirms it and shows it is
column `[2]`, the client, not even column `[1]`.)

### D2 — stale rectangles: `readReported` unions `tid_` rectangles across all markers and never clears them

`scripts/v2/tauri-audio.test.mjs:977-989` builds `state.tids` by iterating
**every** marker in chronological order and writing each `tid_<id>_<field>`
into one Map. When a later marker omits a `data-testid` (the element left the
screen), the earlier rectangle is **not removed**. `waitForPublished` /
`rectOf` therefore can return a rectangle for an element that is no longer
present, and `rectInsideWindow` only checks it lies inside the window, not that
it is current.

Reproduction: `build/p3.5-review1/stale-rectangle.mjs` (exit 0) feeds marker 1
with `tid_record-start_*` and marker 2 without it, and shows
`tids.get('record-start')` still returns the old `{x:100,y:200,w:80,h:40}`.
This did not fire in the recorded V3 run (the click set reached `record-start`
correctly), but it is a latent wrong-control click hazard. Evidence:
`docs/v2/evidence/P3.5/review-1/stale-rectangle.md`.

### D3 — the return and V3 evidence claim "all five real clicks landed"; the fifth (`record-stop`) never ran

`docs/v2/evidence/P3.5/V3-capture-spoken.md:82-91` ("Five real pointer clicks …
All five landed") and `docs/v2/state/returns/P3.5.md:54` ("All five real clicks
landed and the app's recorder was started") are contradicted by that row's own
log: after `PASS click record-start`, the run failed
`FAIL V3 the phase reached recording` and returned at
`scripts/v2/tauri-audio.test.mjs:1255-1257`, before the containment block and
before the `record-stop` click at `:1324-1326`. Four card clicks landed
(`home-action-note`, `home-search`, the result option, `record-start`), plus the
onboarding `Continue`; `record-stop` did not. The row is correctly BLOCKED and
makes no downstream claim, but the "five landed" sentence is false and should be
corrected. The same "five real clicks" phrasing in the checkpoint is fine (it
counts records, not clicks).

### D4 (minor) — the containment read is a single sample, not continuous

`scripts/v2/tauri-audio.test.mjs:1280-1283` takes **one**
`pactl list short source-outputs` sample, at the first poll where
`timerReached > 10`, and never samples again. A stream that appears on the real
microphone after that instant is not observed. The card's own text says the read
"narrows the window; it does not close it", so this is within the letter of the
card — but the assertion is worded as "no capture stream on the owner's real
microphone" for the recording, which a single sample cannot support. Combined
with D1 this check is currently both vacuous and non-continuous. Worth
strengthening (periodic sampling, or at least a sample before and after), not
blocking on its own.

## Environment / manifest / card issues (not candidate source defects)

### ENV1 — `appsink not found` is a bundle-path masking problem, not a missing host package; `E6` is necessary but not sufficient

- Host, independently re-checked: `gst-inspect-1.0 appsink` → exit 0
  (`libgstapp.so`, `gst-plugins-base-libs 1.28.6-3`);
  `autoaudiosrc` / `alsasrc` / `pulsesrc` → exit 255 ("No such element or
  plugin"); `pipewiresrc` → exit 0. `gst-plugins-base` and `gst-plugins-good`
  are **not installed** (only the `-libs` packages and `gst-plugin-pipewire`).
- The AppImage's `Apunta (test).AppDir` bundles the GStreamer **core** libraries
  (`usr/lib/libgstreamer-1.0.so.0`, `libgstapp-1.0.so.0`, `libgstbase`,
  `libgstaudio`, …) but has **no `usr/lib/gstreamer-1.0/` plugin directory** and
  no `gst-plugin-scanner`.
- `AppRun.wrapped` (the linuxdeploy launcher) **unconditionally** sets
  `GST_PLUGIN_SYSTEM_PATH_1_0=$APPDIR/usr/lib/gstreamer-1.0:<prior>`
  (disassembly at `0x40190f`; `getenv` → `cmove` empty → `snprintf` → `putenv`;
  the binary's PLT has no `stat`/`access`/`g_file_test`, so there is no
  existence check). With `<prior>` unset, GStreamer's compiled-in system plugin
  path (`/usr/lib/gstreamer-1.0`, where the host's `libgstapp.so` lives) is
  **replaced** by a directory that does not exist. That is exactly why the
  AppImage reports `appsink` missing while the host has it.
- Therefore installing `gst-plugins-base`/`gst-plugins-good` (E6) would add the
  genuinely-missing capture sources (`autoaudiosrc`, `alsasrc`, `pulsesrc`) but
  would **not by itself** make `appsink` visible inside the AppImage. Do not
  record E6 as a proven fix for the appsink error.
- **Recommended minimal next action** (bounded, for the coordinator, not this
  card's May edit): (a) fix the bundle so the GStreamer plugin search path
  includes the host plugin directory — either bundle the needed plugins into
  `usr/lib/gstreamer-1.0` (and the scanner) or ensure the launcher appends
  `/usr/lib/gstreamer-1.0` rather than replacing it; and (b) install the missing
  capture plugins. Both are needed; neither alone is proven. Verify read-only
  with the AppImage's own environment before any capture row. This is a
  packaging concern (P7a-class) and a bounded manifest/owner decision, not a
  P3.5 source change.
- The `GDK_SCALE=1` deviation is assessed only as the author states it: a
  test-environment statement with the app-reported scale asserted from the
  app's own stderr line. This review does **not** adopt it as a proven P3.4
  diagnosis; the P3.4 geometry question is the P3.4 reviewer's.
