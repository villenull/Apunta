## IR-04 — DEFECT

- **ID and location:** IR-04; `docs/v2/cards/S1.5.md` §Verification V1
  (rendered identically in `docs/v2/state/dispatch/S1.5-ir.md` §S1.5
  Verification, V1 row). Rule: `docs/v2/RUN-CONFIG.md` §2, L0 row.
- **The text that conflicts:** V1 is `npx prettier --check
  docs/research/es-mx-spellcheck.md`, expected `exit 0`. The repository's
  `.prettierignore` line 2 is `*.md`, so prettier does not format-check any
  Markdown file — including this one. The command still prints "All matched
  files use Prettier code style!", which reads like a pass. Its only failure
  mode is exit 2 when the file does not exist.
- **One concrete failure scenario:** the worker writes a research document
  with invented licence wording, a missing `[not found]` label, no FITS /
  DOES NOT FIT verdict, or garbled Markdown. V1 exits 0 and the evidence line
  reads "All matched files use Prettier code style!", so the card reads
  SUBMITTED with V1 PASS and a wrong deliverable; only the manual V2 read can
  catch it, and V1 carries no information about the document at all. Verified
  with the repository's own prettier 3.9.6 against a deliberately misformatted
  Markdown file in a scratch directory using a copy of this repository's
  `.prettierignore`: exit 0 with the same "All matched files use Prettier code
  style!" line; the same file exits 2 when absent; adding
  `--ignore-path /dev/null` makes it exit 1 on that file, as a format check
  should. The card's V1 was not run against its own deliverable.
- **One specific correction:** make V1 in `docs/v2/cards/S1.5.md` actually
  check the file, e.g. `npx prettier --check --ignore-path /dev/null
  docs/research/es-mx-spellcheck.md`, then regenerate the dispatch
  (`node docs/v2/tools/build-dispatch.mjs S1.5 --base 46216fe`). Coordinator
  decision, not a worker decision: the same one-word command is used as V1 or
  V2 by S1.1, S1.2, S1.3 and S1.4, and the L0 gate in `docs/v2/RUN-CONFIG.md`
  §2 says `npx prettier --check <changed files>`, so the whole Markdown
  research lane is currently unverified. Removing `*.md` from `.prettierignore`
  would fix the lane but would retroactively fail the four existing
  `docs/research/*.md` files, which were written while the ignore was in
  force; that is why the correction above is the card-local one.
