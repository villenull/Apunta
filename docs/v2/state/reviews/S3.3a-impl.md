## Defects

### D1 — multi-id `--only` refuses the second id; a documented, previously working invocation is broken

Both scripts. `check-refine.mjs:194-198` and `check-note-format.mjs:200-204`
collect every bare token after `--only` in an inner loop, then advance the outer
index by one instead of to the last token consumed, so the next outer iteration
lands on the second id and `refuseUsage('unexpected argument …')` fires (`:201` /
`:207`).

```
APUNTA_V2=1 APUNTA_CHECK_URL=http://127.0.0.1:1 node scripts/check-refine.mjs \
  --only tone-request shorten-keeps-facts
  → Refusing to run: unexpected argument shorten-keeps-facts.   exit 2

APUNTA_V2=1 APUNTA_CHECK_URL=http://127.0.0.1:1 node scripts/check-note-format.mjs \
  --only 1-typed-brief 2-presentation-and-talk
  → Refusing to run: unexpected argument 2-presentation-and-talk.   exit 2
```

At `9d92d7b`, `check-refine.mjs:62` was
`new Set(process.argv.slice(2).filter((arg) => arg !== '--only'))`, so two ids ran
and every bare positional was an id. The candidate's own header at
`check-refine.mjs:11` still advertises the two-id form. **This is a
backward-compatibility regression**, which is what Stop 5 and Fixed decision 2
exist to catch, and neither suite has a multi-id case, which is why V5 is green.
In practice `--only` accepts exactly one id.

**Minimal repair, one line, in each script.** After the inner loop, set the outer
index to the last consumed token instead of `index += 1` — `index = next - 1`,
with `next` declared outside the loop header. No other behaviour changes: the
no-flag path is untouched, and the same code serves both scripts.

### D2 — the seeder reads `.id` off a `Response`, so it can never seed and never reports success

`seed-check-instance.mjs`: `api` (`:65-69`) returns the `Response`; `post`
(`:71-76`) returns `api(...)`; `seed` reads `format?.id` (`:97`) and
`patient?.id` (`:102`) off that `Response`. A `Response` has no `id` property, so
`undefined` is falsy and `:97` refuses.

Reproduced with a fabricated in-memory `fetch`, no listener and no socket
(SUPPLEMENT §3.2):

| Invocation | Created | stderr | exit |
| --- | --- | --- | --- |
| 1, empty instance | format (stored, HTTP 201) | `That Apunta took the format and returned no id for it.` | 2 |
| 2, format present | patient (stored, HTTP 201) | `That Apunta took the patient and returned no id for it.` | 2 |
| 3, both present | nothing | `Nothing to seed: …` | 0 |

Two consequences. The header's "It is safe to run twice, which is the point: the
second run finds both records and creates neither" (`:17-18`) is false — the
second run still fails. And V7 conjunct 1 chains `seed && seed && check`, so the
first non-zero aborts the chain and the check script never runs.

Isolation before HTTP was checked separately and is **correct**: the `APUNTA_V2`
guard (`:52-59`), the loopback guard (`:61-63`) and the helpers precede the first
`fetch` at `:82`. Unset URL → 2, `http://10.0.0.1:7800` → 2 as a string with
nothing dialled, dead loopback → 2 after one refused request.

**Minimal repair, two lines.** `const format = await (await post('/api/formats',
{…})).json();` and the same for the patient — which also makes the `format.name`
in the success line at `:98` and `:103` correct, since it reads off the same body.

### D3 — the `PINNED_*` blocks make the literal-presence test self-validating; the anti-drift guarantee in the source is false

`check-refine.mjs:69-73` and `check-note-format.mjs:69-74` state, in the source,
that the dump and the rules "cannot drift apart without the suite going red". The
test named for it
(`check-refine.test.mjs:116-126`, `check-note-format.test.mjs:159-167`) reads the
**whole file** and greps for `/<source>/<flags>` anywhere in it — and the
`PINNED_*` block is in that file, so the assertion is satisfied by the copy it is
supposed to police.

Proven on copies only, with the shipped test bytes:

- **`check-note-format.mjs`, all three effective `flagsFor` regexes replaced**
  (`:410`, `:416`, `:419`), `PINNED_FLAG_RULES` untouched →
  `✔ print-rules-shape: each pattern is the literal the rule function uses`,
  `ℹ pass 13`, `ℹ fail 0`. **Thirteen of thirteen pass with the entire executing
  rule surface changed.**
- **`check-refine.mjs`, effective `CLAIM_VERBS[0]` and the effective `sectionsOf`
  regex replaced**, `PINNED_CLAIM_VERBS` and `PINNED_HEADING` untouched → the
  literal-presence test **passes**. Two tests fail incidentally, because the
  `sectionsOf` regex happens to be covered by a self-test control; `CLAIM_VERBS`
  has no control and its divergence was caught by nothing.
- **The other direction too:** only `PINNED_BORROWED` changed `{25,}` → `{99,}`
  with `exampleSentences()` untouched → `ℹ pass 13`, `ℹ fail 0`, and the dump
  reports a pattern nothing executes.

The declared deviation (return file §1) is honest about the duplication and fair
in claiming FD4 and Must-not-edit cannot both hold without a second copy. The
sentence "so the copy cannot drift silently" is **false**, and that is the part
S3.3 will inherit: S3.3's V3 proves each pin literal **byte-present** in
`git show 9d92d7b:…`, which is the same whole-file grep, so S3.3's checker and pin
will go green on a copy while the dump describes a surface nothing runs.

**Recommended minimal repair (coordinator decision; it needs no scope widening).**
Single-source the dump instead of pinning a copy: amend Must-not-edit for the
seven named rule sites only, and have each rule reference the dumped constant —
`sectionsOf` → `PINNED_HEADING`, `wordCount` → `PINNED_WORD_SPLIT`, `CLAIM_VERBS`
→ `PINNED_CLAIM_VERBS`, `SERVER_OPENINGS` → `PINNED_SERVER_OPENINGS`,
`splitSections` → `PINNED_HEADING`, `exampleSentences` → `PINNED_BORROWED`, the
three `flagsFor` regexes and `'None.'` → `PINNED_FLAG_RULES`. About ten one-line
substitutions inside already-named functions, no behaviour change, and the
literal-presence test then becomes a real invariant rather than a tautology. The
fallback if the coordinator keeps the copies is to add a self-test control per
dumped pattern, so a divergence makes a control miss — that catches the effective
direction for `CLAIM_VERBS` and the three `flagsFor` regexes, which today nothing
catches, but it still cannot catch a `PINNED_*`-side edit.
