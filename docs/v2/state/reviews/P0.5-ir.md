  at `docs/v2/cards/P0.5.md:42-47` and in both regenerated dispatches):
  "**Test isolation (HS-2):** V1/V2 run the repository's own test suite, which
  opens only temporary databases created by its harness
  (`server/src/test/harness.ts`) and never the platform data folder or the live
  instance. As in RUN-CONFIG §3 (which runs `npm test` bare), these rows run
  bare, not through `sandbox.mjs`; no server is launched and port 7717 is never
  contacted." That is option (i) from round 1's defect block — the *exemption*
  reading — adopted under AM-024's blanket authorisation, which requires the
  coordinator to apply exactly the reviewer's stated correction. The card now
  names HS-2, states the routing (bare), and gives the safety property, so the
  implementer no longer has to choose between wrapping and reporting `BLOCKED`.
- **The cited precedent is real.** `docs/v2/RUN-CONFIG.md` §3 runs
  `TZ=UTC npm test` … `TZ=Australia/Sydney npm test` bare, and the *only*
  sandboxed line in that suite is the e2e line
  (`node scripts/v2/sandbox.mjs env --port 7810 …`). So the card's routing
  matches the plan's own bare-`npm test` precedent, and the L1 recipe in §2 lists
  `npx vitest run <paths>` unwrapped as well.
- **Every factual claim in the new line checks out against the tree:**
  - `server/src/test/harness.ts:44-51` creates a fresh
    `mkdtempSync(join(tmpdir(), 'apunta-test-'))` per suite, sets
    `APUNTA_DATA_DIR` to it and `APUNTA_PORT: '0'`, opens SQLite on
    `config.dbFile` inside it (`:55`), drives requests with `app.inject` after
    `app.ready()` (`:72`), and on `close()` closes the DB and `rmSync`s the
    directory (`:79-83`).

    that do **not** use the shared harness each create their own temp dir or

    `readable-export.test.ts:20-22`, `db/migrate.test.ts:18,121,136`,
    `db/notes.test.ts:19-20`, `db/plans.test.ts:33-34`,
    `db/repositories.test.ts:22-23`, `routes/licenses.test.ts:29,35-39`,
    `routes/health.test.ts:34,37-40`, `seed.test.ts:22-23`. The only
