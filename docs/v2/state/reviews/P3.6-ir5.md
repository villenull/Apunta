## DEFECTs — settleable now

### D10 — the de-escaped pipe makes both copied greps literal, so the invariant P3.6 holds cannot fail (IR-03, IR-04)

- **Where:** `docs/v2/cards/P3.6.md:103` (May edit), `:129-130` (Must not edit),
  `:279` and `:281` (S1's anchor), `:475` (Stop 8's payload), and the gloss at
  `:104`.
- **Conflicting text.** P3.4's V3 cell, read from `docs/v2/cards/P3.4.md` itself,
  carries the alternation escaped:
  `grep -rn "invoke_handler\|withGlobalTauri\": true" …`. P3.6 carries it
  **unescaped** in all four of its copies:
  `grep -rn "invoke_handler|withGlobalTauri\": true" …` and
  `grep -rn "VITE_APUNTA_TEST_IDENTITY|p3.4-observe" …`. The card glosses the
  difference at `:104` as *"the `\|` in P3.4's cell is that table's escape for the
  same `|`, so this is the same text."*
- **That gloss is true of the rendered string and false of the command, and the
  command is the part P3.6 newly relies on.** In POSIX BRE — which is what `grep`
  uses without `-E` — a bare `|` is an ordinary literal. I verified both forms
  against synthetic files in `/tmp`: on a file containing `invoke_handler`, the
  escaped form returns **exit 0 with the line printed**; the unescaped form returns
  **exit 1, no match**. Same test for the hook strings: escaped **exit 0**,
  unescaped **exit 1**. On the real tree today **both** forms return exit 1, so
  nothing is currently red — the difference is only visible when something is
  actually there.
- **Why agents hit the wrong one.** P3.4's escape is load-bearing *in the file as
  stored*, and cards are read as raw text. The escaped form survives a
  copy-from-source; the de-escaped form in P3.6 is what a reader copies, and it is
  the one that cannot fail.
- **Failure scenario.** A change lands `invoke_handler` in `src-tauri/build.rs` —
  or `p3.4-observe` / `VITE_APUNTA_TEST_IDENTITY` anywhere under `src-tauri/src` —
  from another session or a merge, which is precisely the class of edit May edit
  exists to fence. S1's anchor runs "all three of P3.4's commands" and **all three
  hold**: both greps match nothing because they are looking for a literal string
  containing a pipe that will never exist, and `test ! -e src-tauri/capabilities`
  genuinely passes. The anchor reports the P3.4 V3 invariant intact, the card's
  Must-not-edit claim *"nothing that could break that row"* goes unchallenged, the
  build proceeds, and the string is baked into every shipped binary — **while
  P3.4's own row, run from its own source, goes red and nobody is looking at
  P3.4.** That is the vacuous-pass class this project has now paid for four times
  (AM-142, AM-147, D8, and here), arriving through a card repair that was closing
  the previous instance of it. The gloss at `:104` is what makes it durable: it
  tells the next reader the two spellings are interchangeable, which is the belief
  that produced it.
- **Correction.** Restore the escape in all four copies — `"invoke_handler\|withGlobalTauri\": true"`
  and `"VITE_APUNTA_TEST_IDENTITY\|p3.4-observe"` — and amend `:104` to say the
  escape is **load-bearing for `grep`'s BRE alternation and not merely a table
  escape**, so the copy cannot be "tidied" back. All four sites are bullets or a
  numbered list, **not** table cells, so the backslash is unambiguous there and no
  markdown escaping is needed. Nothing else changes: the completeness D9 asked for
  is already in place and stays.
- **Not a re-run of a closed finding.** Round 4 verified that the quote now carries
  four paths and three commands; it treated `\|` as a rendering artefact. Nobody
  has yet asked whether the copy, *as a command*, can fail. It cannot, and I
  measured it rather than reading it.
