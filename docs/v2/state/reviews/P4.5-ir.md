## IR-03 — `redactQuery`'s new rule pastes the query value on a `Location` carrying both `?` and `#`

- **ID and location:** `docs/v2/cards/P4.5.md:157-167` (Fixed decision 3), against `:26-31` (Objective 2) and `:38-40` (the Read bullet naming the header claim at `scripts/v2/probe-redirects.mjs:26-28`).
- **The text that conflicts, or exactly what is missing:** Decision 3 says `redactQuery` "truncates at the first `#` when there is one, otherwise at the first `?`", and states that "a `Location` carrying both loses everything from the `#`". That is unambiguous, and it is wrong for one input class. When the `#` comes **after** the `?` — the ordinary order for a signed URL with a fragment — the `#` is still the first `#`, so the rule truncates there and the entire query, values included, is written verbatim. The card's own Read bullet says the probe header's claim that "a query string's **values** are never written" is "what this card makes true", and Objective 2 says "Nothing that could be a credential … reaches the evidence file". On this input the new rule breaks both, and it breaks them in the exact way `cards/P4.1.md:504-512` named when it called the existing behaviour "a real redaction gap": a line that **reads as redacted and is not**.
- **One concrete failure scenario:** a real A07 `Location` arrives as `https://us.aws.cdn.hf.co/xet-bridge-us/<hash>/<hash>?X-Amz-Signature=<value>&X-Amz-Expires=<n>#section=<v>`. `describeLocation` records `query: present — <redacted>, never pasted` and a `fragment_present` refusal, then `renderArtifact` writes `  - exact \`Location\`, query redacted: \`https://us.aws.cdn.hf.co/.../<hash>?X-Amz-Signature=<value>&X-Amz-Expires=<n>#<redacted>\`` at `:367`. The signature is in the evidence file. Today's code truncates at the first `?` and hides the same value, so on this input the card is a **regression**, not a fix — and the record's own `query:` field at `:338` now contradicts the line printed beneath it.
- **One specific correction or named prerequisite:** change decision 3's rule to *truncate at whichever of `#` or `?` occurs first in the string, keeping that delimiter.* This preserves decision 3's entire rationale — for `…#token=1?x=2` the `#` is the first delimiter, so it still truncates there and the case-5 shape is unaffected — while making the header claim at `probe-redirects.mjs:26-28` true for every input. Add a tenth case for a query-then-fragment `Location` asserting the fabricated query value does not survive, and add the same shape to the V3 control's expected-failure list. (This is a specification correction, not a scope widening: the owner authorised "the `#`-before-`?` rule" for the fragment leak, not the loss of query-value redaction that follows from reading it as "the first `#`, unconditionally".)
