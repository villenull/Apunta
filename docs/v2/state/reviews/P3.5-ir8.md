## Positions, not content — does the rule hold?

**It holds.** Nothing P3.5 grants can carry typed text, an input value, a note
body or a patient name:

- The grant is geometric. "Each is published as the client rectangle of the
  element carrying that exact `data-testid` … and publishes its
  `getBoundingClientRect()`, keyed by the test id and by nothing else." Four
  numbers plus the test id; the lookup is by test id, so the element's text is
  never read, let alone transmitted.
- The card says so explicitly and names the three dangerous carriers: "The
  input's `value` never travels in it, the typed search text never travels in
  it, and no note body, note title, transcript or patient name travels in it —
  `home-search`'s rectangle says where to click, never what is in the box."
- The delivery bullet holds the same line independently: "the marker carries
  **phase, timer, level and `levelPeak` only** — never a patient name, never
  transcript text, never anything from the live instance." The privacy bullet is
  unchanged and still names John Smith as the only name in a run, created by the
  harness through the API in the run folder (HS-8).
- **The harness asserts positions, not contents.** V3's load-bearing assertions
  are the phase marker moving `idle → starting → recording`, `record-timer`
  advancing past 10 s, `levelPeak` **not** `0`, and the `/api/transcribe` URL
  appearing in the captured stderr. Each is a phase, a count or a coordinate
  frame-count; none is a string of the patient's, and the note-content claims are
  deferred to S4a.2 by name. Typing "John Smith" into `home-search` is the
  harness's own keystrokes (HS-8's fabricated person), and the assertion is that
  the click landed and the option opened — not that the box contains anything.

One wording observation, **not charged, and I want to be explicit that I
considered charging it**: the sentence "the same is true of every other
rectangle, inherited or own" is slightly over-broad, because the two *inherited*
text-leaf rectangles are published under their visible text by P3.4's rule, and
the option rectangle's visible text *is* the patient name ("John Smith"). So
strictly, one name does travel in one inherited rectangle. It cannot mislead an
implementer: the name is HS-8's fabricated sample person, which HS-8 and P3.4's
own text explicitly permit in exactly this role; nothing here authorises
publishing it in P3.5's own rectangles; and the sentence grants no permission, so
no implementer can act on it wrongly. The one-line tightening, if the coordinator
ever wants it, is "…in every rectangle **this card** publishes"; the inherited
pair is P3.4's fact under P3.4's own HS-8 allowance.
