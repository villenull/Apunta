## Defects — settleable now (card text only)

**N-1 — V4's determinism conjuncts are inverted, so the row is red for a correct
implementation and green for a broken one.** *(new; introduced by the D-4
closure)*
*Where:* V4's command cell, the two `cmp -s` lines added between the second
`r-en2`/`f-en2` dumps and the locale-sensitivity pair; contradicted by V4's
Expected clause (b) and by Stop 6.
*Conflicting text:* `cmp -s "$b/r-en.json" "$b/r-en2.json" && { echo "FAIL: two
dumps of the same check-refine tree differ, so the blob is not deterministic";
exit 1; };` — `cmp -s` exits **0 when the files are identical**, so the `&&`
branch fires on success. The Expected says "each script's `en` dump is taken
**twice** and the two are compared with `cmp -s`, so a blob that varied run to run
… is red here". The card's own locale-sensitivity conjuncts use the same idiom
with the **opposite** polarity (identical *is* the failure there), and that is
what the new lines were copied from.
*Failure scenario (executed against scratch):* two byte-identical dumps → `cmp -s`
exit 0 → the row prints FAIL and exits **1**; two differing dumps → `cmp -s` exit
1 → the row continues → exit **0**. So V4 can never be green for a deterministic
blob, and a blob that varies between runs — the exact defect the conjunct claims
to catch — passes it.
*Correction:* negate the condition, e.g.
`! cmp -s "$b/r-en.json" "$b/r-en2.json" || { echo "FAIL: two dumps of the same
check-refine tree differ, so the blob is not deterministic"; exit 1; };` and the
same for `f-en`/`f-en2`; or, keeping one shape for all four comparisons,
`cmp -s a b && <fail-if-identical>` for the locale pair and
`cmp -s a b || <fail-if-different>` for the determinism pair.

**N-2 — Stop 1's lead sentence still carries the clause D-3 withdrew.** *(new;
residue of the D-3 closure)*
*Where:* Stop condition 1, first sentence: "Any attempt to reach anything that is
not a dead loopback address. No host outside `127.0.0.1` / `localhost`, no DNS,
**no port other than the one this card is dispatched**, no live data folder, no
model pull …" — against the closing paragraph three bullets later, which permits

*Conflicting text:* the withdrawal sentence only withdraws "the earlier wording

The clause "no port other than the one this card is dispatched" survives in the
current text and, read literally, forbids the two ports the card's own rows and
FD8 require.
*Failure scenario:* an implementer reads the lead sentence as the rule and the
closing paragraph as commentary, treats `127.0.0.1:1` as a Stop 1 event, and stops
on V2/V3/V4 — the unachievable-guard class AM-173 called the headline finding,
re-introduced in the one sentence that was supposed to have removed it.
*Correction:* delete "no port other than the one this card is dispatched," from
the lead sentence and let the closing paragraph be the single port rule, or

**N-3 — V4's two dead-URL conjuncts require an exit code the scripts cannot
produce, so the row is red on a conforming implementation.** *(new; introduced by
the D-6 closure)*
*Where:* V4's last two conjuncts, `test "$rc" -ne 0 -a "$rc" -ne 1`, against FD1's
