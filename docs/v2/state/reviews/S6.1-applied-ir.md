## Detail on the DEFECTs

### F-04 — V4 contains its own contradiction (OWNER-ONLY)
`S6.1.md:501` ends the licence proof with "Finally, `rg -n "dictionary-es-mx"
THIRD-PARTY-LICENSES.md` must additionally find the hand-written notice section
described in the Notice section", then in the next paragraph requires
`THIRD-PARTY-LICENSES.md` to carry "**no** notice section, **no** `{{OWNER: …}}`
placeholder and **no** blank field". Both cannot hold. The sentence is a
proposal-§9 leftover (the AM-203 correction was appended without removing it),
and the `rg` it names is absent from V4's command. Correction: delete the
leftover sentence; V4's `BLOCKED` verdict already carries AM-203 item 2(a).
This does **not** weaken V4.

### F-05 — header `Level` is not a valid level (plan-editor)
`S6.1.md:7` holds `L1, plus the sandboxed browser rows V2, V3 and V6; V9 is a
non-browser row`. `check-plan.mjs:31` defines `LEVELS = {L0,L1,L2,L3,L2+L3}` and
`:45` rejects anything else; the pre-amendment card had `Level | L1`. Result:
`node docs/v2/tools/check-plan.mjs` exits 1 with `S6.1: unknown level …`, so
V0's first command is red. `build-dispatch.mjs:141` also branches on
`card.level`. Correction: `Level` = `L1`, with the browser-row/V9 sentence moved
to body prose.

### F-06 — bold verification ids are invisible to the tooling (OWNER-ONLY)
`plan-lib.mjs:142` recognises a verification row only as `/^\| V\d+ \|/`. The
applied rows are `| **V0** | …` (`S6.1.md:497-506`), so `card.verification` is
empty: `check-plan.mjs:46` reports `S6.1: no verification rows`, and
`build-dispatch.mjs:288,326` renders `{{CRITERIA_ROWS}}` with nothing in it — the
implementer's return file would have no machine-checkable criteria. Correction:
un-bold the ids (`| V0 | …`). This changes no criterion's content.

### F-07 — V0's regex cannot match the recorded row (OWNER-ONLY)
`S6.1.md:497` runs
`rg -n "dictionary-es-mx.*(MPL-1\.1\|GPL-3\.0\|LGPL-3\.0).*2\.0\.0" docs/decisions.md`.
The only `2.0.0` in `docs/decisions.md:256` sits **before** the arm
("`dictionary-es-mx` 2.0.0, exact) … under **MPL-1.1**"), so the alternation's
trailing `.*2\.0\.0` never matches: `rg` exits 1 with zero lines. The card's own
rule then makes this **Stop 1**, i.e. the card is `BLOCKED` and "the install in
Steps does not run" — even though AM-203 item 1 is on record. Correction:
`rg -n "dictionary-es-mx.*2\.0\.0.*(MPL-1\.1\|GPL-3\.0\|LGPL-3\.0)" docs/decisions.md`
(verified to match `:256` at exit 0), and reword *Expected* accordingly.

### F-11 — Stop 2's scope is ambiguous (OWNER-ONLY)
Stop 2 (`S6.1.md:633-638`) reads "this stop **is in force**: stop, `BLOCKED`",
which a fresh implementer can only read as halting the whole card. That
contradicts V4's row-level `BLOCKED` and AM-203 item 2(a), whose subject is the
unshippable notice. Correction: say Stop 2 blocks the notice and V4 only, and
that V0–V3/V5–V9 proceed and are recorded. This is also the answer to (5)
below: it is the two `[unknown]` fields, not the §1.10 scope line, that could be
misread as a whole-card stop.
