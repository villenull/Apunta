## Round-1 re-check

### IR-01 — closed

The write scope now covers everything the card's own objective and verification
require. `scripts/v2/check-es-fixtures.mjs` (new) is the fourth May-edit entry
(card 27; identical at `S3.1.md:24-27` and `S3.1-ir.md:75-78`), so the only way
V1 can exit 0 is a path HS-9 authorises. The four gold sidecars are named in
Fixed decisions as
`e2e/fixtures/eval-es/{tuning,heldout}/expectations.json` and
`e2e/fixtures/eval-owner-es/{tuning,heldout}/expectations.json`, and May edit
says in terms that the two globs include them; a trailing `/**` reaches the
files directly inside the split root, so this is a naming clarification over
existing scope, as round 1 predicted, not new scope. The second, smaller gap —
no authorised top-level path under `eval-owner-es/` — is closed by
construction: the card requires no top-level file there, NAMES.md is one
registry for both corpora (HS-8, and Fixed decisions' last bullet), and the
sidecars live one level down inside the two authorised globs.

### IR-03 — closed

The data shape is now explicit at the level the loader demands. One
`expectations.json` per split root, four paths enumerated; the same `_schema`
keys as the two English sidecars, which are cited by path and are Read; one
entry per transcript, keyed by `<trap-type>/<name>.txt` relative to the split
root. That keying is exactly what `corpus.ts:76-98` cannot yet do — it reads
`join(directory, 'expectations.json')`, globs `/^\d{2}-.*\.txt$/` non-recursively
and keys by bare filename — and the card names the consequence as a prerequisite
on S3.2 together with the May-edit list that authorises it
(`server/src/eval/**` in `docs/v2/cards/S3.2.md`). S3.2's own V2 points at
`--corpus e2e/fixtures/eval-es/tuning`, a single split root, which is
consistent with one sidecar per split root.

The count rule is now satisfiable and self-consistent. "Exactly 5 fixtures per
trap type per corpus" with "hold out indices `i` where `i % 5` is 1 or 3" gives
3 tuning and 2 heldout per trap type; across the 11 named trap types that is
33/55 = 60% tuning and 22/55 = exactly 40% heldout **per corpus**, which
satisfies C-EVAL rule 2's "tuning at least 60%, heldout at least 40%" under
either a per-corpus or an aggregate reading, and the denominator is now named
(`heldout/(tuning+heldout)`, separately for `eval-es` and `eval-owner-es`). The
legacy floor is also met with room: 110 Spanish fixtures against an English
total of 25 (21 in `e2e/fixtures/eval`, 4 in `e2e/fixtures/eval-owner`).

### IR-04 — closed

V1 no longer rests on a four-word parenthetical. It enumerates six assertions —
filename shape, names present in NAMES.md with no other personal name, the
per-corpus 40% floor, a gold expectation for every transcript, exactly 5
fixtures per trap type per corpus, and the coverage table — and adds the
`--root <dir>` flag with the shipped corpus roots as default, which is what
makes the negative case possible without touching the shipped tree. V3 is the
failure outcome round 1 asked for: a copy outside the shipped tree, one
transcript's name removed from that copy's NAMES.md, expecting a non-zero exit
whose message names the missing name; then one heldout fixture moved to tuning,
expecting a non-zero exit naming the split ratio. Both sub-cases are arithmetically
sound against the rule they test: the corpus sits at exactly 22/55, so moving
one heldout fixture to tuning gives 21/55 ≈ 38.2%, genuinely below the floor.

V2 is no longer vacuous, and the fix is structural rather than a claim. The
`.prettierignore` still ignores `*.md` (line 8), and the corpus trees are `.txt`
plus two `.md` files, so a directory containing only those would still pass for
free. But Fixed decisions now mandate four `expectations.json` files, and
prettier recurses into subdirectories of a directory argument and parses
`.json`, so V1's own sidecars are what prettier will format-check. The two
corrections land together, exactly as round 1 noted they must.
