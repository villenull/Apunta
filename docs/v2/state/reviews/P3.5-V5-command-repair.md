## 1. The audit's §4 finding, confirmed by execution

Reproduced on this host with read-only `pactl`, on a clean machine (no
`apunta_p35` sink, source or module exists). The command is the card's own old
cell with the cell's `\|` resolved to a bare pipe, exactly as the dispatch emits
it:

```
$ bash -c "pactl get-default-source; pactl list short sources | grep -c appointa_p35; \
           pactl list short sinks | grep -c appointa_p35; \
           pactl list short modules | grep -c 'module-null-sink|module-remap-source'"

0
0
0
ROW EXIT=1
```

Three independent defects, all still present in the card as dispatched:

1. **The alternation is inert.** `escapeCell`/`parseCells` turn the card's
   `\|` into a bare `|`, and a bare `|` is a **literal** in a BRE, so the pattern
   could only ever match the whole 37-character string
   `module-null-sink|module-remap-source`. No `pactl` output contains it.
2. **The polarity is inverted.** `grep -c` exits 1 when it matches nothing, and
   the row's exit code was the last command's — so *zero* leaked modules, the
   correct outcome, was the failing case, and a leak would have been the passing
   one.
3. **The Expected cell's own requirement was asserted by nothing.** "a non-zero
   count on the second or third command is a `FAIL`" cannot be true of a
   `;`-separated chain: the source and sink counts were printed and discarded,
   and a leaked `apunta_p35` source or sink still exited 1 — indistinguishable
   from clean.

A fourth defect, found here and **not** in the audit, is in §5: the row greps for
a name the run never creates.

## 3. How the new cell maps onto the Expected assertions, one by one

The Expected cell is unchanged, so this is a claim about coverage, not a
redefinition.

| Expected cell's assertion | How the command asserts it |
| --- | --- |
| `pactl get-default-source` prints the host's real default again, **not** `apunta_p35_mic` | the value is captured, a fixed-string `grep -q` fails the row on any `apunta_p35` line, and the value is echoed so the evidence carries it |
| `pactl list short sources \| grep -c appointa_p35` is `0` | the count is `grep -cF` over the captured sources file for the name the run creates; `test "$n" = 0` or `bad=1`, with the offending lines printed (§5 explains the spelling) |
| `pactl list short sinks \| grep -c appointa_p35` is `0` | the same loop over the captured sinks file |
| neither `module-null-sink` nor `module-remap-source` is loaded **with this run's `sink_name=apunta_p35` arguments**; "the row greps for `apunta_p35` in the module arguments, not for the module name alone"; "a count of `2` for a `module-null-sink` line naming another sink is not this run's leak" | a **word loop** over the two module names: a line is an offender only when it matches its module word **and** `apunta_p35`, so an unrelated `module-null-sink` for another sink and an unrelated `module-remap-source` are both left alone. This is the Expected cell's own correctly spelled requirement, quoted here verbatim from it |
| a non-zero count on the second or third command is a `FAIL` | all five counts feed `bad`, and the row's exit code is `test "$bad" = 0` — nothing is discarded by a `;` |
| "checked from the outside, not from the harness's own bookkeeping" | every input is a fresh `pactl` read, captured to `$b` before it is examined |

Three properties are inherited from AM-179's V3 form on purpose: **no
alternation anywhere** (a card cell forces `\|` to a bare `|` to the shell, and
a bare `|` is a literal in a BRE, so a card cannot safely hold one), `grep -F`
fixed-string matching with one pattern per call, and `bad` plus a final `test`
so the row's verdict is not one command's exit code. The four `pactl` reads also
propagate failure: a non-zero `pactl` prints a `FAIL` line and sets `bad`,
instead of leaving an empty file that reads as clean.

**One clause is deliberately not turned into a check: the literal device name.**
The Expected says the default source prints "the host's real default again
(`alsa_input.usb-UGREEN_Camera_2K_…`)". Asserting that exact string would be a
**new** acceptance criterion — it names one host's hardware in a check, fails on
any other machine, and duplicates what V0 already records — so it is not
invented here. The obligation is already witnessed elsewhere in the card,
unchanged: V0's Expected asserts "the default source line is `*` and is **not**
`apunta_p35_mic`" and requires the full `pactl list short sources` output to be the
very first thing recorded in `docs/v2/evidence/P3.5/V0-host-and-build.md`; Fixed
decisions step 1 remembers `PREV_DEFAULT`, step 5 restores it, and the `trap`
paragraph requires `PREV_DEFAULT`, `SINK_ID` and `SRC_ID` to be written to
`sideEffectsDone` in `docs/v2/state/cards/P3.5.json` as each row creates them.
So the restore is witnessed before the run (V0's recorded output, plus a value a
resumed session can re-apply), performed by the teardown on every exit path, and
checked from the outside afterwards by V5's "not `apunta_p35_mic`" half with the
actual name echoed into the evidence. **This is reported, not claimed as a
check.** If the coordinator wants the exact device name asserted as well, that
is an amendment to V5's Expected, not an implementer's choice.

## 5. Finding the audit did not make: the card greps for a name it never creates

`docs/v2/cards/P3.5.md` at HEAD spells the task-owned name two ways. The Fixed
decisions create it correctly —

```

                sink_name=apunta_p35 sink_properties=device.description=Apunta_P3.5)"
449-450:  SRC_ID="$(pactl load-module module-remap-source \
                source_name=apunta_p35_mic master=apunta_p35.monitor)"    # 2. create

```

— and then **seven occurrences of the misspelling with an `o`** appear, all
verified as raw bytes from `git show`, not as anything retyped:

| Line | Where | The misspelled text |
| --- | --- | --- |
| 451 | Fixed decisions, the exact command block, **step 3 "default"** | `pactl set-default-source appointa_p35_mic` |
| 624 | **V0's command cell** | `pactl list short sinks \| grep -c appointa_p35` |
| 624 | **V0's Expected cell** | "`pactl list short sinks \| grep -c appointa_p35` is `0`" |
| 629 | **V5's old command cell** | twice, both `grep -c appointa_p35` |
| 629 | **V5's Expected cell** | twice, both "`grep -c appointa_p35` is `0`" |

Everything else in the card — 26 occurrences — uses the name the run actually
creates, including V5's Expected sentence "neither `module-null-sink` nor
`module-remap-source` is loaded **with this run's `sink_name=apunta_p35`
arguments**" and "the row greps for `apunta_p35` in the module arguments, not
for the module name alone".

**Two consequences, and the second is the reason this repair is not cosmetic.**

1. **The old greps were vacuous, not merely inverted.** A fixed-string search
   for a name the run never creates matches nothing *whether or not residue
   exists*. So on the old cell the audit's clean-host run printing `0` was not
   evidence of a clean host, and a real leak would have printed `0` too. The
   audit's measurement stands as a measurement of the *exit code*, not of the
   host.
2. **Line 451 is a live host mutation.** Step 3 is the one permitted host-global
   mutation this card performs, and as written it points
   `set-default-source` at a source that does not exist. On this host that call
   would fail, and the card's own stop condition — "the current default source
   is a physical device and the virtual source cannot be made the default
   first … stop and report `BLOCKED`" — would then fire for a typo rather than
   for a real condition. This is the more serious of the two and it is
   **outside this repair's write scope**: line 451 is a Fixed-decision command,
   line 624 is V0's row, and line 629's Expected cell is protected
   byte-identical by the dispatch.

**What this repair did about it.** The new command greps for the name the run
creates — `apunta_p35`, the spelling the card uses in 26 places and the one its
Fixed decisions pass to `load-module` — so "zero task-owned sources, sinks and
modules" is now a real assertion rather than an unfalsifiable one. The Expected
cell was **not** touched: its requirement ("no `apunta_p35` source, sink or
module of this run remains, the owner's microphone is the default again") is
asserted exactly; only the two sentences that *quote the old command's spelling*
now read as a quotation of a command that never worked. **That is a coordinator
amendment, not an implementer's choice**, and it is the one thing this repair
deliberately left standing: V0's row and Fixed-decision step 3 need the same
one-character correction, and no acceptance criterion needs to change for it.
