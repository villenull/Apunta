## Re-check: IR-03 (round 2 DEFECT) — now CLEAR

**What round 2 found.** Fixed decision 1 asserted three things that could not all
hold: (a) an admitted host goes into an allowance's `allowedRedirectHosts` and
nowhere else; (b) `ALLOWED_DOWNLOAD_HOSTS` "grows by exactly the admitted hosts and
nothing else"; (c) a test asserting the union of the allowances' `allowedHosts`
plus the hosts the licence pages name. Under (a) the admitted hosts are in no
`allowedHosts`, so (c) was false the moment the probe recorded anything; and (c) was
already false at the base commit, because `registry.ollama.ai`
(`catalog.ts:36`) is named by no licence URL and by no allowance, while the
catalogue's own comment (`catalog.ts:31-34`) says it stays on the record. Every way
out was barred (delete the host, weaken the assertion, or put the CDN host in
`allowedHosts` and widen the initial-request list past A07's two columns).

**What changed** (`cards/P4.1.md` § Fixed decisions, decision 1; dispatch
`P4.1-ir.md:178-183`):

> and `ALLOWED_DOWNLOAD_HOSTS` is the union of every allowance's `allowedHosts`
> **and** `allowedRedirectHosts`, plus the hosts the licence pages already name
> (`registry.ollama.ai`); a test asserts that union. The admitted redirect hosts
> enter through the allowances' `allowedRedirectHosts`, so they are included by
> construction — there is no second, separate list.

**Re-check, leg by leg.**

1. *Admitted hosts vs the union test.* Resolved. The union now spans both
   allowance fields, so an admitted `cdn-lfs.hf.co` sitting in
   `allowedRedirectHosts` is a member of the asserted union. The follow-on
   sentence states the mechanism in the implementer's own terms ("included by
   construction"), so there is no separate hand-maintained list to fall out of
   step — which is what made (a) and (c) incompatible before.
2. *`registry.ollama.ai`.* Resolved as a matter of required membership. The
   sentence names the host explicitly as something the union contains, so the test
   the card orders cannot exclude it, and step 2's "extend
   `ALLOWED_DOWNLOAD_HOSTS` by exactly those hosts" (dispatch `368-371`) is
   consistent with a derived union: the list grows precisely when an allowance's
   field grows, and the pinned literal at `catalog.test.ts:26` that step 2 also
   updates must agree with the derived union — a stronger check, not a second
   contradiction. The catalogue comment's requirement is met without deleting
   anything.
3. *Satisfiability, worked through.* Take the ordinary outcome: both allowances
   `allowedHosts: ['huggingface.co']`, both `allowedRedirectHosts: ['cdn-lfs.hf.co']`
   after the probe, licence-page hosts `huggingface.co` and `ollama.com`. The
   asserted union is `{huggingface.co, cdn-lfs.hf.co, ollama.com,
   registry.ollama.ai}`, and today's list plus exactly the admitted hosts is
   exactly that. A catalogue satisfying the card exists, so the implementer is
   never forced to choose between two rules.
4. *The rest of IR-03* — the fifteen-string code union in `readiness.ts`, the
   receipt pinned verbatim as eight keys with `Math.floor(stat.mtimeMs)`, `dev`,
   `ino` and the write conditions, `readonly sizeBytes` beside `approxBytes` with
   `77_704_715`, `algorithm: "sha1"` for a `sha256: null` entry, hop 0 uncounted
   with 5 as the ceiling, and the injected-`fetch` transport — is untouched by
   this round and was verified in round 2 against sources that have not moved
   (`installer/` is byte-identical between the two bases).

Residual, judged non-blocking: the parenthetical attributes `registry.ollama.ai`
to the licence pages, and no licence URL names it — the licence URLs are
`huggingface.co` (`catalog.ts:123,146`) and `ollama.com`
(`catalog.ts:180,186,197,216`). That is a wrong *reason* attached to one conjunct
whose *membership* the same sentence states by name, so no implementer's answer
changes: the host is in the union either way. See observation 2 for the one-line
fix.

## Re-check: IR-04 (round 2 DEFECT) — now CLEAR

**What round 2 found.** The card declared an outcome in which the redirect list is
empty — "an empty list is the correct answer, not a gap" (dispatch `172-173`) —
while V1 required all 23 cases unconditionally, and cases 2, 10, 11, 12 and 9 all
need an admitted host to exist. With an empty `allowedRedirectHosts` there is no
admissible substitute inside the card's own rules, so V1 would report 21 of 23 and
be `FAIL` by its own wording, with no stop condition to report instead.

**What changed** (new stop condition 3, `cards/P4.1.md` § Stop conditions;
dispatch `451-455`):

> 3. The probe runs and step 2 admits **no** redirect host (it recorded no
>    `Location`, or none passed the domain test). The tests that need an admitted
>    CDN host — the `Location`-following success case and the multi-hop case —
>    cannot run: report `BLOCKED` with the probe evidence and the same
>    plan-editor action as stop condition 1, rather than quietly skipping them.

**Re-check.**

1. *The outcome is now first-class and has a concrete response.* Exactly the two
   things round 2 asked for: a named branch, and `BLOCKED` carrying the probe
   evidence plus the same plan-editor action as stop condition 1 (which is
   already spelled out at `434-443`: the coordinator fills A07's redirect cell
   through the plan editor before S4a.2 is unblocked, and S4a.2's own stop
   condition permits it). The card also says the failure mode out loud —
   "rather than quietly skipping them" — which closes the alternative an
   implementer would otherwise have taken.
2. *V1's 23-case requirement no longer dead-locks.* The requirement binds on the
   non-blocked path, where step 2 admitted at least one host by definition. On the
   empty outcome the card reports `BLOCKED` before V1 can carry a PASS/FAIL verdict
   on the full set, so the anticipated outcome is a report rather than a
   fabricated FAIL.
3. *No contradiction with decision 1's "correct answer, not a gap".* That sentence
   is about the probe's *finding* — nothing is missing from the list — and the
   block is about what the card may then claim. A list that is correct and empty
   yields `BLOCKED`, not a skipped test and not a widened host set. Both sentences
   can hold at once.
4. *Overlap with stop condition 1 is benign.* The new condition's parenthetical
   "(it recorded no `Location`, or none passed the domain test)" also covers the
   case where a recorded host failed the domain test — which is stop condition 1.
   Both demand `BLOCKED`, condition 1 names the action and condition 3 defers to it
   by reference, so an implementer that fires either one takes the same path. Two
   triggers, one response: not a defect.
5. *The 23 cases themselves* are unchanged and each names the observable it
   asserts, so no case requires a value the card does not supply. The affected
   cases are identified in substance ("the tests that need an admitted CDN host"),
   with two named as examples rather than an exhaustive list (observation 4).
