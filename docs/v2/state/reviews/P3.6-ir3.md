## DEFECTs — settleable now

### D1 — V0 and V1 assert the identity count in prose only, and V0's claim about the directory is false (IR-04)

- **Where:** `docs/v2/cards/P3.6.md:325` (V0) and `:326` (V1), command cells.
- **Conflicting text:** both commands end `… && npm run tauri:build:test` and
  `… && npm run tauri:build`. **Neither contains an `ls` or a count.** The
  *expected* cells nevertheless assert *"holds exactly one match for
  `'Apunta (test)_'*.AppImage`"* and *"exactly one match for `Apunta_*.AppImage`"*,
  and V0 adds *"**At this point the directory holds only this identity**, because
  V1 has not run yet."*
- **Failure scenario:** a resumed session where attempt 1 completed V1. If
  `tauri build` does not clean `bundle/appimage/` (see *A1* below), the production
  image from attempt 1 is still on disk. V0 rebuilds and its test image overwrites
  its own name, the directory holds two AppImages, and V0's prose — "holds only
  this identity" — is false while the row's exit code is `0`. The reader has to
  notice a claim no command checked, on the row whose whole purpose is not
  launching a stale artefact.
- **Correction:** append to both command cells
  `&& test "$(ls -1 src-tauri/target/release/bundle/appimage/'Apunta (test)_'*.AppImage | wc -l)" -eq 1`
  (V0) and the `Apunta_*.AppImage` equivalent (V1), and delete the sentence
  *"At this point the directory holds only this identity"* — the ordering is what
  makes it true for V0's own artefact, not the directory.

### D2 — `version` is in May edit, but V4's path is the literal `Apunta_0.0.0_amd64.AppImage` (IR-04)

- **Where:** `:83-85` grants `version`; `:329` (V4) sets
  `A=$(ls -1 src-tauri/target/release/bundle/appimage/Apunta_0.0.0_amd64.AppImage …)`.

  produces the same two files.
- **Correction:** either remove `version` from the May edit list, or state in V4
  that the production name is derived from the `version` V0's `tauri.conf.json`
  holds (e.g. resolve it as `Apunta_<version>_amd64.AppImage`) and count that exact
