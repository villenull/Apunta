## IR-06 — the root last-paragraph fix: preserves, does not delete

The author named this, so I read the exact diff rather than the intent. Repair 2
ended the fail-closed list with:

> "Re-running one capture run appends a fourth record and therefore also fails
> closed; **the re-running session removes the record of the abandoned run
> first**, which is exactly the cleanup this trap exists for."

Repair 3 replaces that with:

> "Re-running one capture run within one attempt appends a fourth record at that
> attempt and therefore also fails closed."

and adds, in the paragraph above:

> "**Earlier-attempt history is kept, never deleted, and never excuses
> anything** … A resumed session cleans up any live modules and restores the
> recorded default; it **preserves** the abandoned run's durable records so the
> next reader can audit the cleanup."

So the deletion instruction is gone, the preservation instruction replaces it,
and the history *is* preserved: measured, the attempt-1 records and anchors are
still there after the row runs and the row exits **0** having named them in the
ignore line (the row writes nothing; it is a read). `grep -n` over the whole card
finds no remaining instruction to delete a durable record. **CLEAR**, and it is
the right direction: a resumed session restores the *host*, not the *ledger*.

One consequence to state rather than leave for a session to discover (NOTE, not
a defect — no branch is unlocked by it): the same-attempt re-run is now
unrecoverable *within that attempt*, since deleting the duplicate is no longer
the remedy and the attempt anchor excludes it only once `attempt` advances. The
recovery the card implies — a new attempt, which the attempt selection then
excludes the duplicates through — is not named in the bullet. Nothing in the
budget depends on it: no implementation has run and no attempt has been spent.
