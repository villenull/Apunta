## Defects

### DEF-1 — a `Location` that parses but carries a malformed percent escape still crashes the probe (moderate, in scope, unclosed)

- **Where:** `scripts/v2/probe-redirects.mjs:196`
  `.map((pair) => decodeURIComponent(pair.split('=')[0] ?? pair))`, with no
  `try`/`catch`. Reached from `:248` (the new refusal loop) and `:266` (the
  returned `queryKeys`).
- **Demonstrated offline, this review, exit 0 for the probe script:**

  ```
  describeLocation('https://us.aws.cdn.hf.co/p?%E0%A4%A=SIGVAL', a07)
    -> THREW URIError: URI malformed
  describeLocation('https://us.aws.cdn.hf.co/p?%zz=SIGVAL', a07)
    -> THREW URIError: URI malformed   (also through renderArtifact)
  ```

  `main()` calls `describeLocation` at `:461` inside a bare loop with no
  `try`/`catch`, and `writeFile` happens only at `:466` — so the throw kills the
  process **before** `redirects.md` is written. The consequence is worse than a
  stack trace: the previous run's file survives untouched and would be read as
  this run's record, while V2's "the script wrote the file" expectation is no
  longer true of anything on disk.
- **Why it is a defect and not a nit:** this is the other malformed shape, and
  AM-057's scope names the property — "Repair malformed-Location diagnostics …
  it must prove malformed diagnostics do not crash". The unparseable shape is
  covered; this one is not. The repository has **already settled the right
  behaviour for this exact input**: `installer/src/readiness.ts:116-134`
  `queryParameterNames` wraps the same `decodeURIComponent` in `try`/`catch`
  with the comment "A malformed escape is left as it arrived: an unreadable name
  is not a name that can be on a list, so it fails closed below", and
  `readiness.test.ts` carries the case "leaves a malformed escape as it
  arrived, so it fails closed against any list". The probe's copy of that logic
  diverges from the in-repo convention, and this attempt is the one that
  exported the function and shipped a suite certifying the no-crash property.
- **Not a regression.** The base has the identical unguarded call
  (`git show d0b8292:…`, line 213, one call site; this attempt adds a second at
  `:248`). So attempt 3 did not introduce the crash — it left the other half of
  its own repair scope open.
- **Reachability.** Narrow and vendor-dependent: it needs the origin to send a
  `Location` whose query **name** contains a malformed escape, and the current
  V2 record shows all seven names decoded correctly, so this run was not
  affected. That is why no row is red.
- **Fix shape, for the coordinator to accept or reject** (not applied here, and
  it needs no owner decision, no new gate and no config edit): give
  `queryKeyNames` the same `try`/`catch` and fail-closed comment
  `readiness.ts:125-130` already has, and add one V4 case using a fabricated
  parseable URL with a malformed name. One function, one case, no threshold
  moved.
