### D2 — IR-01 / IR-05 / IR-08: the permission module cannot compile inside the scope the card grants it, and the handler's real signature is not the one described

- **Location:** `cards/P3.5.md` May edit, the `src-tauri/src/permissions.rs` and
  `src-tauri/src/main.rs` bullets ("a target URL that passes the shell's existing

  the pinned source.
  1. `src-tauri/src/main.rs:592` is `fn is_allowed_origin(target: &tauri::Url,
     allowed: &str) -> bool` — **private to the crate root module**. A sibling
     module cannot call it as `crate::is_allowed_origin`; that is E0603,
     "function `is_allowed_origin` is private". Making it `pub(crate)` is a
     **third** change to `main.rs`, which the card forbids in as many words.
  2. `WebviewWindowBuilder::on_permission_request` takes
     `F: Fn(Webview<R>, PermissionKind) -> PermissionResponse + Send + Sync`

- **One concrete failure scenario:** the implementer writes `permissions.rs`
  exactly as instructed, adds `mod permissions;` and the one

  `crate::is_allowed_origin`. The only fixes are a third edit to `main.rs` (a
  stop-and-report the card demands) or a duplicate of `is_allowed_origin` inside
  `permissions.rs` (a second copy of a security decision, which the card's own
  "the shell's existing" wording rules out). Either way the implementer stops on
  a card whose first real obstacle is a one-word visibility the card never
  mentioned.
- **One specific correction:** state the third line. Name `pub(crate)` on
  `main.rs:592` explicitly as part of the two-and-a-half-line grant — "**three**
  changes: `mod permissions;`, `pub(crate)` on `is_allowed_origin` at `:592`, and
