## DEFECTs — settleable now

### A1 — S3's mandated row order makes V3 and V4 unsatisfiable
**Where:** `:224-228` (S3, "V0 and V1, then V3 and V4, in that order"), against
`:166-168` (Fixed decisions: V3's harness "fails with the directory listing if the
glob matches zero or more than one file") and V4's own command
(`test "$(ls -1 …/*.AppImage | wc -l)" -eq 1`).
**Conflicting text:** S3 orders V0 and V1 *both* before V3 and V4. Both builds write
into the same `src-tauri/target/release/bundle/appimage/`, and they produce two
differently-named files — `Apunta (test)_0.0.0_amd64.AppImage` (V0) and
`Apunta_0.0.0_amd64.AppImage` (V1).
**Failure scenario:** after V0 and V1 have both run, that directory holds two
`*.AppImage` files. V4's `-eq 1` assertion fails outright, and V3's harness — which
resolves `*.AppImage` and refuses on "more than one" — refuses to launch. In the
opposite branch, if `tauri build` clears the bundle output directory, V1 **destroys
V0's test AppImage** and V3 then finds zero files and is `NOT RUN`. The card's own
stop 3 then fires on the implementer for doing exactly what the card ordered. One
way or the other, three of the card's five rows cannot pass in the order S3
mandates.
**Correction:** state the order as **V0 → V3 → V1 → V4** (the test identity is
driven before the production build overwrites the directory), and make both
assertions identity-specific — V3's glob `Apunta (test)_*.AppImage` and V4's count
over `Apunta_*.AppImage` excluding the test name — or copy each artefact into
`docs/v2/evidence/P3.6/` immediately after its build so the next build cannot take
it.

### A2 — V3's freshness walk uses `<base>`, which nothing substitutes

<base>…HEAD` together with `git status --porcelain`"*.

`<base>` rule, and `<base>` is not a shell placeholder. AM-142 records exactly this

and Rule B's primary freshness predicate **passes vacuously** — the row goes green
on a stale bundle, which is the precise failure class Rule B exists to catch.
**Correction:** use the dispatch's base commit literally, or write `{{BASE}}` so the
generator fills it.

### A4 — V4 and V2 are not routed through `sandbox.mjs`, and V4 asserts something false about itself
**Where:** `:295-303` stop 2, V4's command, and V4's closing sentence *"Extraction is
a read: the AppImage is not executed, the app is not launched, no port is bound and
no data folder is created by this row."*
**Conflicting text:** `RUN-CONFIG.md` §2 makes L3 *"the card's listed commands, all
through `sandbox.mjs`"*. V0, V1 and V3 route through it; **V2 and V4 do not**. V4
also *does* execute the AppImage's ELF runtime — only the application is not
launched — so the sentence as written is false about the binary it is asserting a
property of.
**Failure scenario:** the reader takes "the AppImage is not executed" literally, runs
the row in the developer's own environment with no `APUNTA_DATA_DIR`,
`APUNTA_NO_OPEN` or port containment, and a runtime that mis-parses the flag (an
older runtime, or a hostile `APPIMAGE_EXTRACT_AND_RUN`) proceeds to mount instead of
extract. Low probability, and the row's assertions would still fail — but the card
claims a containment property it does not have.
**Correction:** route V4 through `node scripts/v2/sandbox.mjs env --port 7879`
like the other rows and reword to *"the AppImage **runtime** is executed with
`--appimage-extract` and the application is not launched; no port is bound and no
data folder is created"*. V2 is a pure `diff -r` over two tracked trees and needs no
sandbox; say so explicitly rather than leaving the L3 blanket rule apparently broken.
