## Bounded observations (no defect, no acceptance change)

- **O1 — IR-dispatch port header.** The IR header reads "No sandbox port
  assigned" while the card body (Verification intro) says the dispatch "is
  therefore generated with `--port 7879` ... so the header and the body agree."
  This is a mode artifact, not a defect: the implementation dispatch
  `docs/v2/state/dispatch/P3.6.md` was generated with `--port 7879` and its
  header reads "Sandbox port for this card: 7879"; the IR brief is generated
  `--ir --base` without a port (`build-dispatch.mjs` usage line 7) and needs
  none. No command is affected — every row pins `7879` literally. If the
  coordinator wants the sentence true of both artifacts, the IR dispatch can be
  regenerated with `--port 7879`; no card or row change is implied.
- **O2 — "ten" vs eleven.** The card says "ten flows" and lists eleven names in
  three places (Fixed decisions, V3 Expected, S4). The clarification resolves
  it: drive and record all eleven by name. Because the assertion is "by name",
  the count word cannot make a row pass or fail wrongly.
- **O3 — Read line 66 superseded.** The Read list describes the siblings'
  mechanism as "driving the UI through `xdotool` against the rectangles P3.4's
  observation hook publishes". That mechanism is unavailable in V3's unflagged
  build, which the clarification states and replaces with screenshot grounding.
  The card's Fixed decisions already carry the "where one exists / otherwise the
  app's own API" fallback, so this is guidance reconciled by the clarification,
  not a contradiction in acceptance.
- **O4 — copy-flow read channel.** For "publish and copy" the only observable
  fact is the app's visible "Copied" state (the host clipboard has no supported
  local read: `xclip`/`xsel` absent, `wl-*` is Wayland). The clarification says
  it "can be asserted by native screenshot/state", while the Fixed decisions say
  "a screenshot is evidence, never the assertion". Read together with F3's
  accepted remedy, the intended shape is: actuate the copy click, treat the
  grounded screenshot of the reached, actuated "Copied" state as the read of
  that state, and record the clipboard *contents* as not-read with the reason.
  A one-sentence coordinator note making that reading explicit would remove the
  last ambiguity; it is not a row change and this review does not treat it as a
  defect, because F3 was the accepted preparation correction and the user's
  brief asks that historical findings not be re-filed.
- **O5 — housekeeping wording.** "Preserve prior test images by hash if
  reversible housekeeping is needed" is read as read-only provenance (record
  hashes before a rebuild), consistent with `src-tauri/target/**` being Must
  not edit and Stop 3 refusing to delete a stale sibling. It is not read as a
  licence to move or delete anything under `target/`.
- **O6 — stale tool line numbers.** The card cites `build-dispatch.mjs:177` for
  the "No sandbox port assigned" line (now `:370`) and `:178` for the Checkpoint
  line (now `:392`); `build-dispatch.mjs` moved after those were written. Prose
  only; the mechanism claims in V3 are commit-pinned to `193fc4d` and stand.
