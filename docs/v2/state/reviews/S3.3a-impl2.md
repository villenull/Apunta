## What the candidate got right

1. **The original rules were not touched.** Verified twice over. Textually, each
   rule region diffed clean against `9d92d7b`; and through a reviewer-written
   AST reader, the executing bodies of `sectionsOf`, `wordCount`, `stillHas`,
   `losses`, `claimProblems`, `CLAIM_VERBS`, `SERVER_OPENINGS`, `HELD_BACK`,
   `splitSections`, `exampleSentences`, `flagsFor` and `noteFromStream`, plus
   both scripts' pre-flight refusal blocks and every printed summary line, are
   byte-identical to the pristine original. The only in-rule edit is the
   `dir` → `treeDir` rename, which resolves the same string on every reachable
   path. Twenty-one comparisons, all equal.
2. **The `:62` defect is genuinely fixed.** `only` is now built only from the
   tokens that follow `--only`; the parse sits above the built-server import and
   above every request. `--print-rules` and `--self-test` exit 0 on a tree with
   no `server/dist` at all, and the built-server refusal is still `2` with its
   original text.
3. **The multi-id form works**, including a flag after several ids, a repeated
   `--only`, a missing value, a bare positional, and an unknown id in second
   position — twelve direct invocations, each with its exit and stderr.
4. **The anti-drift guard is sound, and I attacked it.** 26 one-node mutations in
   an ignored copy: twelve that move a rule that executes are all red, seven that
   move only a `PINNED_*` copy are all red, and — the direction that matters —
   three that put the pattern in a **comment** and two that add a **dead
   duplicate** that never runs are all correctly **green**. So the guard cannot
   be satisfied by a description of a rule that no longer exists. Thirteen of
   those directions are ones the shipped suite does not itself mutate; they are
   red for the same reason, so the gap is coverage, not soundness.
5. **The seeder is idempotent for real.** Three consecutive runs, one process
   each, against one synthetic store that only the requests themselves change:
   exactly two `POST`s in total, one `Seeded` line and two `Nothing to seed`, and
   the store ends with one format carrying the four English section names and one
   `John Smith`. No-id, malformed and refused-request refusals are all `2` and
   stop at the record they cannot trust.
6. **The return file is honest.** It records V8 as FAIL, V6 and V7 as NOT RUN
   with the hold named, discloses that `sectionsByFixture` has no AST node and
   that `fixtureFilter` is single-sourced, and carries the two forward notes
   (`check-refine.mjs:513` hardcodes the `refine` tree while `--only` validates
   against `tree`; `--expect-fixtures` on `check-refine.mjs` counts files). I
   confirmed both forward notes against the source.

## Numbered findings

None of these is a defect in the candidate. They are recorded so the coordinator
can decide what is a card repair and what is a row repair, and so S3.3 inherits
an accurate picture.

1. **V8's base token is stale, and that is the whole of its failure.**
   `docs/v2/state/dispatch/S3.3a-review.md` V8 diffs against `dbafbc1`, which is
   two commits behind the coordinator's own dispatch (`85dc7ce`), so the
   committed half of the sweep reads the coordinator's reconciliation writes as
   implementer scope breaches. Thirteen lines, all `docs/`, none a source path.
   *Would fix it:* point V8's `git diff` at the candidate's parent interval, or
   exclude the coordinator's own state paths. The prefix conjunct the repair
   added is working — it accepts this review's own
   `docs/v2/evidence/S3.3a/review-2/` — it simply cannot reach a path that is not
   under a card prefix.
2. **The seeder's idempotence case is a prefilled fixture, not a repeat.**
   `scripts/check-note-format.test.mjs:769` hands the child a store that already
   contains one format and one patient, and the harness ignores the POST bodies,
   so no case shows a second run reading back what a first run created. The
   behaviour is correct — I proved it independently (§3 of the supplement) — but
   the shipped proof is one step short of the property it names.
   *Would make it pass:* keep the store in a file the harness mutates from the
   requests, and run the seeder twice across two processes.
3. **`fixtureFilter` is single-sourced, so one leg of the anti-drift comparison
   is tautological.** `check-refine.mjs:229` dumps `[...FIXTURE_FILES]` and
   `:512`–`:513` iterate the same constant, so both sides move together. Every
   other compared field is a genuine `PINNED_*`-copy-against-executing-node
   comparison. This is honest and the return file says so; it is repeated here
   so S3.3's checker does not read that leg as evidence.
4. **The anti-drift suite mutates nine directions; the mechanism covers twenty-six.**
   `check-refine.test.mjs:350` and `check-note-format.test.mjs:495` move four and
   five executing nodes and four pinned copies. Not exercised: the effective
   `CLAIM_VERBS[1]` and `[2]`, a middle `SERVER_OPENINGS` entry, the effective
   `riskSentinel` string literal *inside* `flagsFor`, the `flagsFor` cadence rule,
   and the effective `flagsFor` section name. All red in my matrix. Coverage
   only — no card criterion requires a particular mutation count.
5. **`check-refine.mjs:513` hardcodes `'refine'` while the id check at `:312`
   validates against `tree`.** Unobservable today (`--locale es-MX` exits `5`
   first), but it becomes a live defect the moment S3.3 lands `refine-es/`. The
   card's Must-not-edit owns that loop, so this is correctly reported, not fixed.
6. **`--expect-fixtures` on `check-refine.mjs` counts fixture files (2 for `en`),
   not scenarios.** Consistent with Fixed decision 1's wording ("counts fixtures
   read, in either script") and with S3.3's V2 passing the `-es` scenario count
   through `--expect-scenarios`. Recorded so S3.3 does not assume otherwise.
7. **The seeder has no non-loopback refusal case**, because `no-restricted-syntax`
   refuses a non-loopback URL literal anywhere under `scripts/`. The refusal is
   unchanged and V1 covers the same guard in both check scripts. A deliberate
   trade, disclosed in the return file; not a gap I would close.
