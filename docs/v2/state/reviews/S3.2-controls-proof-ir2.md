## Verdict: **DEFECT** — the mechanism is now sound; two claims about the artefacts are not

Findings **1** and **2** are blocking for the report's own claims. 3–4 major, 5–6 minor. Each
carries a repro against the verbatim core and a minimal fix.

### 1 — the two English controls are built with Spanish section names, so the proof's own sidecars do not hold (blocking)

`note(body, sections = ES)` (`:210`). `EN_LEGACY.invented.controlSections` is
`note(EN_INV_BAD)` (`:332`) and `EN_LEGACY.lost.controlSections` is `note(EN_LOST_BAD)`
(`:342`) — both take the **default**, so the objects are keyed `Subjetivo/Objetivo/Analisis/Plan`
while `sections` is `Subjective/Objective/Assessment/Plan`. Measured
(`node -e "import('./test-results/proofs-ir2-s32/core.mjs')…"`, exit 0):

```
EN_LEGACY.invented  mustNotContain ["denies","denying","never (?:takes?|took)"]
  controlSections {"Subjetivo":"Denies any history of hypertension.", …}
  scored text   "Subjective: Objective: Assessment: Plan:"     <- the note body is gone
  compile('denies').test(text)  false
  runControls([EN_LEGACY.invented], {locale:'en'}) -> exit 3  missed control: positive/02-invented-negation.txt
  runControls([EN_LEGACY.lost],    {locale:'en'}) -> exit 0  by accident: empty text leaves mustCapture unsatisfied
```

So the English invented-negation control, exactly as the file declares it, **misses**. The
suite cannot see it: the paired-control case (`:402-411`) passes a note rebuilt through
`asNote(sidecar, bad)` (`:370`), i.e. it replaces the very field that is wrong, and case 5
only reads `mustNotContain` patterns. Report §2 item 2 ("All four pairs (es/en ×
invented/lost) reach exit 0") is therefore true of the harness's rebuilt note and false of
the proof's own constants; §4's "closed on synthetic controls" inherits it.

**Minimal fix.** `controlSections: note(EN_INV_BAD, EN)` and `note(EN_LOST_BAD, EN)`, and in
the paired case assert the sidecar's *own* `controlSections` (drop the `asNote` rebuild) so
this class of defect cannot recur behind the harness.

### 2 — G3 is opt-in, so the loophole it closes reopens for any control that omits the marker (blocking)

The guard runs only when the sidecar carries `precondition: 'negation-free-source'`
(`:138`) — a field no shipped schema has, that this proof invents. Measured:

```
CORRECTED.invented, controlSource 'el paciente no camina todos los dias', precondition removed
  -> exit 0   all controls hold
CORRECTED.lost,    controlSource 'el paciente no duerme bien'   (no reachable precondition)
  -> exit 0
```

Report §3 states G3 unconditionally — "*an invented-negation control's `controlSource` may
contain no inventory negator*" — while the implementation is conditional on an opt-in field,
and nothing classifies a control as invented-negation. ir1 finding 3 is closed only for the
control that opts in. **Minimal fix.** Derive the class from the control itself (key or
mechanism) rather than a self-declared field, **or** add the undeclared-control case above,
restate G3 in the report as opt-in, and say what happens to a control that forgets it.

### 3 — G1 and G2 are surface-syntax checks and regex forms walk past them (major, unstated)

```
G1  (?:{{lexicon}})          LOADED (exit 0)      G1  {{lexicon}}|x          LOADED (exit 0)
G2  {{lexicon}} (?:refiere|no)   LOADED           G2  {{lexicon}} (?<!x)no? refiere  LOADED
G2  {{lexicon}} (?:no|refiere)   refused: puts "no" after {{lexicon}}
G2  {{lexicon}} [no] refiere      refused: puts "no" after {{lexicon}}
```

`(?:{{lexicon}})` is the bare-token hazard G1 exists to stop, written in regex syntax. As
*proposed clause text* G1/G2 are literally accurate, so this is not a contradiction — but
L1–L3 and the report do not record the limit, and the report presents G1/G2 as closing the
loophole. **Minimal fix.** One sentence in the header and in report §3 ("surface-syntax
checks; an equivalent-in-effect regex form is not detected") plus one adversarial case each.

### 4 — the correction silently drops gold slots (major, disclosure; not a mechanism defect)

Gold `invented-negation/01-todos-los-dias.txt` (`e2e/fixtures/eval-es/tuning/
expectations.json:1067-1072`) carries `no (?:hace|realiza) ejercicio`, `sin ejercicio` and
`sin actividad f[ií]sica`. Measured against the corrected control: `"No hace ejercicio."`,
`"No realiza ejercicio."`, `"Sin ejercicio."`, `"Sin actividad fisica."` → **0 hits** each,
while `No camina` / `No menciona ejercicio` / `Sin antecedentes de…` all hit. The header
(lines 15-16) and L3 do say the slot lists are authored for this synthetic source, so the
mechanism claim stands; but report §3 presents the B-1 clause text as the correction and
describes only the `jam[aá]s` drop. **Minimal fix.** State in §3 which gold slots the
proposed text does not carry and why, so adoption does not read as full parity.

### 5 — "matches every note" overstates G1 (minor)

The refusal text (`:127`) and report §2 both say a bare token matches *every* note. Measured:
the expansion flags `"Ninguna noche limpia."` and is silent on `"Duerme bien."` — it matches
every note **carrying an inventory negator**, which is the real hazard and what case G1
correctly demonstrates. Fix the wording in both places.

### 6 — case 24's exit code is coupled to mutable repo state (minor)

`:662` `assert.equal(card.attempt, 1)`. The model never enforces the counter — that claim is
honest and correct (`pipelineRun` never receives it) — but the assertion will fail the whole
proof once S3.2's second attempt is recorded, which reads as a proof failure. The report says
the counter is read "to show it is an integer" and does not mention the `=== 1`. **Minimal
fix.** Assert `Number.isInteger(card.attempt) && card.attempt >= 1` only, or state the
coupling in the report.
