# Independent review #1: `S6.1-assets-proof.mjs` (synthetic proof review)

**Role: independent review of a completed synthetic proof I did not author.** Review-only; the
sole tracked file I wrote is this one. No proof, proposal, card, contract, production file, state
file or existing report modified; nothing committed; no branch or worktree touched. No build,
install, server, database, browser, dictionary, model, network, port 7717 or live data. Scratch:
my own gitignored `test-results/proof-review-s6/` (`ce.mjs`, `ce2.mjs`), kept as evidence. Base
`2235fee`.

**Inputs.** `CLAUDE.md`, `HARD-STOPS.md`, both targets and reports, `reviews/S6.1-v2-ir3.md`
(D-01…D-06), the V9 row of `state/S6.1-AMENDMENT-PROPOSAL-v2.md:864`, and the two contracts
the proof reads (`shared/src/i18n/locales.ts`, `web/src/lib/speller.ts`). **Method:** the
coordinator's 25/25 was not taken as evidence — I transcribed the proof's own `collect` /
`validate` / `compareIdentity` into scratch and attacked it with adversarial fixtures; every
finding carries a command and an exit code.

## Verdict: **DEFECT** — A is sound, B's gates are weaker than its own prose

Section A I checked and accept: the `v9` transcription is byte-faithful to the proposal's V9 row
(diffed), A1–A4 reproduce D-02, D-03, D-05 and D-04 as predicted, and D-06 is measured
correctly with a right three-word wording fix. Section B does not establish what report §5 says
it does: §5 claims "attribution must come from the stored language with a **module→asset
relation** (D-01)" and that "build identity must be recorded and compared rather than assumed
(D-03)" are closed, yet both are **self-asserted strings** no gate links to any asset byte.
Three of the coordinator's suspicions reproduce exactly; two more surfaced that the report does
not mention. **1** and **2** are blocking, 3–5 major, 6–7 minor, 8 a nit.

### 1 — the two rows can be swapped (blocking)

`validate` (`:201-205`) checks that the row's **self-declared** `storedLanguage`
matches `ROW_LOCALE[project]` and that its **self-declared**
`dictionaryModule` equals `MODULE_BY_LOCALE[storedLanguage]`. Both fields come from
the collector's own arguments (`:130-141`). Nothing ties a module name to the bytes
the row observed. Measured
(`node test-results/proof-review-s6/ce2.mjs`, exit 0):

```
CE3 — the two rows are SWAPPED and still pass
  ACCEPTED  es-MX row observes the English pair, chromium row the Spanish pair
           diff=["index-B2yR7tLp.aff","index-Dq1xK9ab.dic"]
           attribution={"es-MX":"dictionary-es-mx@2.0.0","chromium":"dictionary-en"}
```
The returned `difference` is the **English** pair while the attribution block claims
it is the Spanish dictionary's — D-01's failure in a new dress, and exactly what A2 warns
about ("no English/Spanish split is demonstrated at all"), now inside the corrected
pipeline. `E-NOT-EMITTED` is the only asset-side gate and both pairs sit in the same emitted list.
**Minimal correction.** Record per row the **request URLs** (or the module resolved at import
time in the page) naming the asset's origin, and require the observed `.aff`/`.dic` to arrive
under the expected module's URL prefix — one recorded field, one `E-MODULE-ASSET` check. Absent
that, report the module field as an assertion by the collector, not a relation.

### 2 — build identity is a self-asserted fingerprint (blocking)

`:122-126` `fingerprint(seed)` derives three hashes from a **seed string**, and `:223-224`
compares only those three between the rows — never against `manifestHash`'s own file, any
source file, or the emitted bytes. Measured (`ce2.mjs`, exit 0): the chromium row's emitted
list, logs and records were replaced with unrelated names and re-sealed —

```
CE4 — build fingerprint is self-asserted
  ACCEPTED  chromium row rebuilt from other bytes, re-sealed, fingerprint identical
```
— and the row passes, so D-03 is closed only *formally*: identity is recorded and compared,
as report §5 says, but two builds differing exactly as A2 demonstrates still satisfy the
gate. **Minimal correction.** Derive the fields from real inputs — `sourceHash` from the
built `web/dist` tree, `emittedListHash` from the bytes of
`emitted-dictionary-assets.txt`, `manifestHash` from the manifest file — and assert
`manifestHash === sha(manifest bytes)` in `validate`. That changes the fixture, not the
design: the B-side collector is the one the card will write.

### 3 — the sorted copy is never derived from the record (major)

`:188-194` validates `observedInArrivalOrder` (array, non-empty, duplicate-free) and the
sorted file (size 2, ascending, two extensions) **independently**; nothing compares them.
Measured (`ce2.mjs`, exit 0):

```
CE2b — sorted copy never checked against observedInArrivalOrder
  ACCEPTED  raw record says ["index-Rm8Wc3vd.dic","index-Hh5TzQ01.aff"]
           sorted+logs file says index-Third.aff / index-Third.dic
```
Report §3 calls `observed-<project>.txt` "the sorted-unique copy" of the record; the validator
does not establish that. **Correction.** One line: `if (JSON.stringify([...new Set(seen)]
.sort()) !== JSON.stringify(names)) return reject('E-DERIVATION', …)`.

### 4 — manifest completeness and schema unchecked (major)

`validate` iterates `Object.entries(manifest.artifacts)` (`:184-185`) — whatever the manifest
happens to list — and checks `record.schema` but never `manifest.schema`. Measured (`ce.mjs`
CE5, exit 0): deleting the `evidence/observed-es-MX.txt` entry (the observation copy itself)
and setting `schema: 'apunta.s6.1.asset-manifest@999'` → **ACCEPTED**, defeating the tamper
gate wholesale: drop an artefact and its digest is never checked. **Correction.** Compare
`Object.keys(manifest.artifacts).sort()` against the four expected relatives and check
`manifest.schema` against its own constant.

### 5 — path safety comes after the read, and a parse error throws (major)

`compareIdentity` (`:213-218`) calls `raw()`, which `existsSync`s and `JSON.parse`s the **es
row's** record, *before* `validate`, so `E-PATH` (`:163`) is not the first check. Measured
(`ce2.mjs` CE7b, exit 0): a synthetic foreign folder outside owned scratch holding one record
naming `dictionary-en` returned `E-SAME-DICTIONARY`, proving the foreign file was read and
trusted first. Report §3's "the validator refuses a folder outside it" holds for `validate`,
not for the comparator calling it. Separately (`ce.mjs` CE6), `{not json` in a record
**throws a `SyntaxError`** out of `compareIdentity` instead of returning a named code — a
crashing validator is not a failing-closed one. **Correction.** Do the `E-PATH` resolve first
in `compareIdentity`; wrap each `JSON.parse` and return `E-UNPARSEABLE`.

### 6 — the extension gate is "two distinct extensions" (minor)

`:194` accepts any pair with two different suffixes. Measured (`ce2.mjs` CE1, exit 0):
`index-Hh5TzQ01.aff` + `index-Zebra.txt` → **ACCEPTED**, no `.dic` anywhere, while the code's
own message reads `'one .aff, one .dic'`. The proposal's V9 command asserts no extension at
all, so this is an improvement the report must not describe as enforcing the pair.
**Correction.** Require the suffix set to be exactly `{aff, dic}`.

### 7 — no staleness defence (minor)

`E-RUN` (`:175`) checks only that the folder's basename equals the record's `runId`, and
`collect` (`:142-156`) writes over any existing run folder without refusal. Measured (`ce.mjs`
CE8, exit 0): re-collecting into the **same** `runId` overwrote it silently and the pair still
validated. D-02 is closed only against a caller passing the *wrong* session string (N6), not
against a stale file, so report §3's "run- and session-scoped" describes the paths the
collector picks, not a gate. **Correction.** Mint `runId` per attempt, refuse an existing run
folder (`E-EXISTS`), record the attempt in the manifest.

### 8 — nit

`:267` hardcodes the `2.0.0` pin, so a licence election that moves it fails the proof on an
unrelated change. Deriving it instead would lose the pin check — keep it, but say in the
report that the pin is asserted, not derived.

## Limitations

- My counterexamples drive a **transcription** of the proof's validator, not the proof file
  itself (importing it would run its suite and delete its scratch on exit); the transcription
  is line-for-line for every branch I attack.
- All records are synthetic: nothing here is evidence about real Vite hashes, real browser
  behaviour or the shipped `dictionary-es-mx`; no browser, build or dictionary install ran.
- Findings 1–4 are properties of the *gate logic*: a real collector might supply honest fields
  and every gate here would still accept a swapped, re-sealed or mislabelled record.
- For section A I confirmed the transcription matches the proposal and that A1–A4 assert what
  the report says, without re-deriving every figure.
