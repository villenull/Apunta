No row is decorative. Each has a named regression.

  It does not detect the defect this card exists for; that is by design.

## S3.3 ↔ S3.3a mismatches

Checked row by row. **What S3.3a specifies does satisfy S3.3's V1–V8 as
written** — `--locale` consumed before `only` (V3's conjunct 1), `--only` taking
the following value (S3.3 V8 → S3.3a V6(a)), `--expect-scenarios` counting what
**ran** (S3.3 V2/V8 → S3.3a FD5), `--print-rules` exiting `0` before any HTTP
call (S3.3 V3 and V6's last command → S3.3a FD3 step 3, which sits **above** the
step-5 tree resolution, so `--print-rules --locale es-MX` is `0` on a tree that
does not exist and on one that does), the `source`/`flags` split making S3.3's
`git show {{BASE}}:…` byte-presence proof possible at all, and the whole parse
sitting above `check-refine.mjs:48` — which is what makes S3.3's V3 and V7
hermetic **and** what stops S3.3's V6 from dialling the live port on its first
two commands (unset `APUNTA_CHECK_URL` → `BASE` → `7717`, which is loopback and
would pass the guard). That ordering is correct and load-bearing. The four
mismatches below are textual, not structural.

1. **Unknown `--only` id.** S3.3 FD2: "An unknown id, or `--only` with no value,
   exits 2" — unconditional. S3.3a FD2: "Refusing an unknown `--only` id is
   therefore a property of `--locale <tag> --only <id>` together, and never of
   `--only` alone." No S3.3 row depends on the unconditional form (V8 passes
   both), so both can hold at once — but the two texts cannot both be the
   specification. **One card is wrong and the coordinator must rule.**
2. **The flag set is stated for both scripts in S3.3, and for one script in
   S3.3a.** S3.3 FD2 says `process.argv` is parsed "into exactly this flag set,
   and nothing else", listing `--only` and `--expect-scenarios`, in a decision
   written about "both scripts". S3.3a's V2 asserts `check-note-format
   --expect-scenarios 2` and `check-note-format --only tone-request` both exit
   **2** — because, on that script, `--expect-scenarios` and `--only` are
   *unknown flags*. **No fixed decision establishes that asymmetry**; it is
   asserted by a row alone, and S3.3 FD2 argues for the opposite. If an
   implementer gives `check-note-format` the symmetric flag set, V2 goes red
   while S3.3's text says it should not.
3. **Codes 5 and 6 do not exist in S3.3.** S3.3 Stop 4: "A `2` where a `0` was
   expected, or a `0` where a `3` or `4` was expected." After S3.3a, S3.3's V7
   returning `5` because the es-MX controls were forgotten is outside that stop
   entirely — the exact vacuous green the owner split the card to prevent, with
   no stop condition watching it in the downstream card.
4. **Code `2` is overloaded and S3.3's V6 cannot discriminate.** S3.3a inherits
   `2` for *usage* refusals (unknown flag, unknown locale) and for *environment*
   refusals (fake AI, no server, no format, no patient). V1 and V2 discriminate by
   message; **S3.3's V6 does not** — it asserts `rc = 2` with no message check,
   so an Apunta left in fake-AI mode makes S3.3's V6 green for the wrong reason.

## Defects — settleable now (card text only)

**D-1 — V5 demands a test that cannot exist under V5's own hermeticity claim.**
*Where:* V5's required-name list (`:322`) vs Preconditions `:72-74` and the
Verification preamble `:307-308` ("no server, no port, no model, no database, no
build").
*Conflicting text:* FD5 puts the count comparison "after the run and after the
summary is printed", so code `3` is reachable only once a measurement run has
**completed** — which needs a server. Yet V5 requires a test named
`exits-3-on-a-count-mismatch`, and `exits-0-on-a-complete-run`, on a row declared
to need no server. There is no injection seam: both scripts call `fetch(BASE +
path)` directly.
*Failure scenario:* the implementer cannot write the required test. Either V5 is
red for a reason the card does not own, or they bind a loopback listener — which
Stop condition 1 ("no port other than the one this card is dispatched") tells
them is a stop — and the packet stalls on its own hermeticity claim.
*Correction:* say in Preconditions that V5's suites stand up an in-process
`node:http` stub on an **ephemeral** loopback port (`listen(0)`, no fixed port —
the `scripts/v2/sandbox.test.mjs` precedent already does this on 7880-7889) and
carve that single exception out of "no port" in one sentence; or grant the two
scripts an injectable fetch and keep V5 genuinely portless.

**D-2 — V1 is not hermetic on a clean checkout, and the card says it is.**
*Where:* Preconditions `:72-74` ("V1 … need none of that … and (by Fixed
decision 3) no `server/dist` either") vs V1 conjuncts three and four.
*Conflicting text:* `check-refine.mjs:48-51` imports `server/dist/ai/fact-guard.js`

places.
*Failure scenario:* a clean checkout without `npm run build` runs V1 and two of

reviewer reads it as the parse having moved.
*Correction:* the Expected cell is right and the Preconditions sentence is wrong.
Move `npm run build` into Preconditions as an explicit requirement for V1's
`check-refine` conjuncts (or split those two conjuncts into a row that is not
declared hermetic), so one of the two sentences is deleted rather than leaving
both.

**D-3 — Stop condition 1 forbids what V2, V3 and V4 do on purpose.**
*Where:* Stop 1 `:329-334`.
*Conflicting text:* "no port other than the one this card is dispatched, no
live data folder … The `http://10.0.0.1:7800` and `http://127.0.0.1:1` literals

*Correction:* split the sentence. Keep "refused as a string" for the RFC 1918
literal only, and state that `http://127.0.0.1:1` **is expected to be dialled**
