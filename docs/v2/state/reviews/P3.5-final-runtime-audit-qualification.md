## Correction 1 — source-outputs column 4 is the driver, not a sink name

The audit at line 42 labels the fourth column (`%s` at `0xc8(%r12)`) a **sink
name**. It is the **driver**. A source output has no sink column in this format.

Corrected zero-based mapping for `pactl list short source-outputs`:

| col | field | expression |
| --- | --- | --- |
| 0 | stream index | `*(u32*)(info+0x00)` |
| 1 | source index | `*(u32*)(info+0x18)` |
| 2 | client index, or `-` | `*(u32*)(info+0x14) == UINT32_MAX` (no client) |
| 3 | **driver** | `*(char**)(info+0xc8)` |
| 4 | sample spec | `pa_sample_spec_snprint(...)` |

Two code paths in the one binary agree: the JSON branch names `0x00` `index`,
`0x18` `source`, `0x14` `client` (skipped when `-1`) and `0xc8` `driver`
(`objdump` `0xbd22-0xbd9f`; member strings `index@0x11bdc`, `source@0x11af1`,
`client@0x1105d`, `driver@0x1157b`). The frozen row
`8043\t8035\t-\tPipeWire\tfloat32le 2ch 48000Hz` has five fields, and its
column 3 is `PipeWire` — a driver, not a sink.

The defect the audit identifies is unchanged: `classifySourceOutputs`
(`scripts/v2/tauri-audio.test.mjs:300-312`) reads `columns[2]` as `clientId`
and requires `Number.isInteger`, but `pactl` prints `-` there for a clientless
stream, so the first legitimate row ends the row. Only the prose label is
corrected.

## Correction 2 — the virtual-default guard does not prove device attachment

The audit at line 50 calls it "Proven by the preflight guard" that "the
physical microphone was never the capture device". The guard proves something
narrower: that `pactl get-default-source` read back `apunta_p35_mic` before the
launch (`05-V3.txt:39-40`, `06-V4.txt:37-38`). A default is what a
default-following client would choose; it is not an observation of which node
the app's stream attached to. Nothing in the repository observes the attached
node.

Likewise, the app reaching `recording` (`05-V3.txt:60`) and the permission
signal prove that the app entered the recording phase, not which device it
opened. So:

- the physical microphone being non-default does **not** prove it was not
  captured from;
- actual device attachment is **unproven**, exactly as the audit's own line 53
  already states — line 50 overstates it;
- it is **not** claimed that the physical microphone *was* used either; the
  attached node is **unknown**.

The one live table read (`05-V3.txt:63-65`, `06-V4.txt:61-63`) shows no
source-output naming the physical-mic index, but the harness had already
stopped and the audit already labels that observation eye-read, not asserted.
It narrows the window without closing it.
