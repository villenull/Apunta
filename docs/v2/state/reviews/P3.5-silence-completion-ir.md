## 3. Findings — the proposal's technical content is sound

1. **Command extraction is exact.** My own `parseCells` + `&&`-split of the
   card's V4 row gives 9 segments; the silence arm is segments 6, 7, 8
   verbatim (`… env --port 7839 > /tmp/apunta-v2-p3.5-v4-silence.env`,
   `. /tmp/apunta-v2-p3.5-v4-silence.env`,
   `node scripts/v2/tauri-audio.test.mjs silence`). The proposal's §4
   completion command is byte-equal to my independent reconstruction and to
   the author's `completion-command.sh`.
2. **The seven unsets are exactly `printEnv`'s seven names**, derived from
   `scripts/v2/sandbox.mjs` source (`APUNTA_DATA_DIR, APUNTA_PORT,
   APUNTA_NO_OPEN, APUNTA_TEST_RUN_ID, APUNTA_V2, APUNTA_CHECK_URL,
   APUNTA_E2E_PORT`), in order. No other name is unset: `HOME`, `XDG_*`,
   `DISPLAY`, `DBUS_SESSION_BUS_ADDRESS`, `WAYLAND_DISPLAY`, `PULSE_SERVER`,
   `PATH` all pass through (checked against all ten).
3. **The root cause is correctly diagnosed and reproduced through the real
   exported guard.** `resolveSandboxDataDir(env, runDataDir)` takes the
   proposed dir from its `env` argument but computes the platform default
   from `process.env` (`platformDataDir(process.platform, process.env,
   homedir())`), and `platformDataDir` returns `APUNTA_DATA_DIR` first. With
   `APUNTA_DATA_DIR` leaked into `process.env` (the 22:40:18 shape) the
   guard refuses the synthetic run folder with the recorded message; with the
   seven names absent it accepts; the **real default folder is still refused**
   (isolation did not slack the guard); and the `env` argument — not
   `process.env` — supplies the proposed dir. No folder was created by any
   guard call.
4. **Host audio/display/XDG routing is preserved by construction.** The
   `env -u` list touches only the seven `APUNTA_*` names, and the harness's
   own `launchApp` (`tauri-audio.test.mjs:663-690`) spreads `process.env`
   and then overrides only `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`,
   `XDG_CACHE_HOME`, `WAYLAND_DISPLAY`, `GDK_SCALE`, `GDK_DPI_SCALE`,
   `XDG_BACKEND`, `GDK_BACKEND` for the AppImage child. `PULSE_SERVER` is
   untouched. The harness still refuses without the three sandbox keys and
   without `APUNTA_ALLOW_AUDIO_TEST=1` (both exit 2).
5. **The silence arm truly never started.** `/tmp/apunta-v2-p3.5-v4-silence.env`

   runs; no run folder exists newer than the V4-tone run; no capture record

   fired before `ensureRunDir`, so no sink/module/port was ever created

## 4. Doc defect — Option 2 (must be remedied before the owner is asked)

Option 2 (proposal §7) reads:

> `V4 BLOCKED` and `V5 FAIL` stand, P3.5 closes on V3 plus V4-tone, and the
> silence mode — both its `levelPeak` claim and its `transcription_empty`
> and UI-string clauses, already deferred to **S4a.2** by the card — is
> proven there instead, where a real model exists and the deferred assertions
> actually live.

Two defects:

1. **"P3.5 closes on V3 plus V4-tone" is ambiguous and dangerous.** With
   `V4 BLOCKED` and `V5 FAIL`, COORDINATOR §4 (attempt budget exhausted),
   §6 (no approval over a `FAIL`/`BLOCKED` row) and AM-194 (no fifth
   attempt) mean the card **parks BLOCKED**: no approval, and no dependency
   release — `build-dispatch.mjs` refuses anything but `APPROVED`, and
   P3.6 and P3.R depend on P3.5. "Closes" can be misread as the card being
   closed out, which would silently release P3.6/P3.R.
2. **The deferral scope is misstated.** The card defers **only** the
   `transcription_empty` clause and the `ai.transcription_empty` UI string
   to S4a.2 ("The `transcription_empty` clause is deferred to S4a.2 … S4a.2
   inherits both arms and asserts the error code and the string itself").
   The silence arm's `levelPeak`-stayed-0, phase-`recording` and
   timer-advancing assertions are **this card's own load-bearing criteria**,
   deferred nowhere; S4a.2 (the Spanish benchmark card) contains no P3.5
   silence-arm assertions. As written, Option 2 tells the owner the whole
   silence mode "is proven there instead" — under Option 2 the `levelPeak`
   half would ship unproven **and orphaned**, with no card owning it. The
   proposal's final clause ("this card's non-speech half ships unproven")
   acknowledges the cost but contradicts the middle clause for `levelPeak`.

**Exact minimal remedy** (two wording changes in Option 2, no other edit):

- Replace "P3.5 closes on V3 plus V4-tone" with: "P3.5 **parks BLOCKED** on
  V3 plus V4-tone — no approval, no dependency release".
- Replace "the silence mode — both its `levelPeak` claim and its
  `transcription_empty` and UI-string clauses, already deferred to
  **S4a.2** by the card — is proven there instead, where a real model exists
  and the deferred assertions actually live" with: "the silence mode's
  `transcription_empty` and UI-string clauses — the only clauses the card
  defers, to **S4a.2**, which asserts the error code and the string itself —
  are proven there instead, where a real model exists; the silence arm's
  `levelPeak`, phase and timer assertions are this card's own criteria,
  deferred nowhere, and would ship unproven with no other card owning
  them".

Option 1 (the recommended choice) contains neither defect and needs no
change. The remedy is wording-only; it does not alter the technical content
verified in §3, so no re-review of the mechanism is needed once applied.
