**On "no whitespace stripping that would accept malformed multiline":** exactly
one trailing newline is consumed, because that is a line terminator, not padding;
nothing else is normalised. `trim()` appears only as a **rejection test**
(`value !== value.trim()` fails), never as a normalisation. A value with an
interior newline (`B5`) or a trailing blank line (`B6`) is a `FAIL`, and the
recorded `prevDefault` is held to the same rule (`A5` multiline, `A7` padded) so
a baseline recorded with a stray newline cannot quietly agree with a live value.

**Tie to V3/V4 provenance and to the last teardown.** `runId` is the run's own
`APUNTA_TEST_RUN_ID`, which each capture row's `sandbox.mjs env` already provides
(`tauri-lifecycle.test.mjs:69-84`), so the record identifies *which run's*
pre-state it is. Three distinct `runId`s, one per capture run, are required;
records that disagree on the value are rejected; and because the last of them is
V4-silence's — the last teardown before V5 runs — the value V5 compares against
is the one the final teardown was required to re-apply.

**Two things this cannot decide, stated rather than hidden.** (a) A wholly stale
record set — one written by an earlier attempt and never superseded — is
indistinguishable from a current one if the host's default source has not changed
in between, because the card's existing contract records no attempt or run anchor
that V5 could compare against. §6 branch **A15** shows the failure direction when
it *is* distinguishable: a stale value that no longer matches the live default is
a `FAIL`, never a pass. A false pass additionally needs the host default to have
changed **and** a teardown to have failed. Closing this completely needs an
attempt anchor in the checkpoint schema, which is the coordinator's file and
outside this attempt's write scope. (b) The three-record count makes a re-run of
one capture run fail closed by design; the card now says the re-running session
removes the abandoned record first.
