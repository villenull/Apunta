## One accepted deviation, verified rather than taken on trust

Deviation 2 in the return — the unit test matches the mark's viewBox **value** by
hand (`HomeLauncher.test.tsx:37-39`) instead of with
`svg[viewBox="0 0 562 754"]` — is justified, and I checked the mechanism
myself rather than accepting the claim:

```
$ node -e "…new JSDOM('<div id=r><svg viewBox=\"0 0 562 754\"></svg>…')…"
querySelector svg[viewBox=...] -> null
querySelector svg[viewbox=...] -> null
getAttribute                   -> 0 0 562 754
outerHTML                      -> <svg viewBox="0 0 562 754"></svg>
```

The attribute is present and readable; jsdom's selector engine never matches it.
So the pin holds — the same value `BrandMark.test.tsx:58` pins is asserted, the
mark is the `.home-inner` first child, and the e2e spec uses the selector
verbatim because a real browser resolves it (V1 counted exactly one match) — and
the two files still cannot drift apart. The same mechanism confirms the
implementer's report that `TopBar.test.tsx:102` is the one vacuous line in the
tree's tests: that `querySelector` is `null` whether or not a wordmark is
present, and the `querySelectorAll('svg')` assertion two lines below (`:103`)
still has teeth, so nothing is unpinned. Correctly reported, correctly not
edited (`TopBar.test.tsx` is in Must-not-edit).
