## Root cause: the proposal is a runtime state machine written as prose, so every repair mints a new unsatisfiable rule

The loop is not a review-quality problem; it is a **specification-form** problem. Four independent reviews of the same 1,455-line document have produced, in order: 21 findings (ir1) → 3 blockers (ir2) → 3 blockers + 6 (ir3) → 3 blockers + 6 (ir4). The count is not falling, and every blocker in ir3/ir4 is the **same family AM-183 records**: *a rule whose own text cannot be satisfied by the code or fixtures the same document specifies*. N1 (step 9 manufactures the duplicate step 10 forbids), N2 (the snippet computes the opposite of its own prose), N3 (the fixture cannot exist) are all instances. Adding prose repairs adds surface; the next review finds the next contradiction. The document is effectively specifying a calibration/completeness/containment state machine that has never run, line by line, and each line is a new place to be inconsistent.

## Minimum internal contract (the small coherent core)

**Facts** (all inside the one gate/one poll/one marker path; P3.5's seam untouched):
`tauri`, `ipc`, `ipcInvoke`, `ipcProbe`∈{pending,rejected,resolved}, `ipcProbeMsg`; pointer observation (`ptrN`, clientX/Y, screenX/Y); click observation (`clickN`, clientX/Y, `clickEl` tag/testid/trimmed-text); rectangle batch (`i{n}_x/y/w/h/l/t/d`, `total`, `frame`).

**One state machine, two windows — no per-move budget:**
1. Gate: wait ≤ existing 45 s for a fact line with `href` **and** `ipcProbe !== pending`.
2. (a): `tauri=undefined ∧ ipc=object ∧ ipcInvoke=function ∧ ipcProbe=rejected ∧ ipcProbeMsg=ACL`. `pending`/`resolved`/other rejection = FAIL. Unreadable hook = the existing 5-row NOT RUN cascade with the two-arm cause.
3. (d), inside the **existing 30 s click window**:
   - Select a complete frame: every batch `0..ceil(total/40)-1` present, all with the same `total` **and** `frame`, refreshed on every sighting. Incomplete at window end = FAIL with "n of m batches".
   - **Calibration = one probe move**, not a two-point solve. Ask a screen point known to be inside the window rect (`windowX+W/2, windowY+H/2`); require the page's own `screenX/Y` to equal the asked point within 1 px (its own native witness). Then `offset = asked − client`. If the witness disagrees, or no `pointermove` arrives, **NOT RUN, no click** (this is the fail-closed form of U-1).
   - Convert target `T` to screen `T + offset`, check it is inside the window rect before warping, warp once, read back `getmouselocation` ≤1 px, click once.
   - Require `clickN+1`, `|clickCX−T.x|≤2`, and `clickEl` == selected rectangle's (tag,testid,label). Landing proved by a fact line **after** `clickN` with `href` changed (patient) or `scriptText` true (final). `rectSignature` is never a pass condition. **One click per target, no retry, no widening.**
4. No guessed titlebar, no `outer−inner` attribution, no `src-tauri/**`, no second hook/gate/poll/marker path, no new capability check.

This removes S1 (bootstrap/solve/containment), S2 (separate caps), and the N1/N2/M2/M3 contradictions by construction.
