### Source classification defect — corrected claim

The evidence states: "column 3 is the sink index, and `pactl` prints `-` when a stream has no sink."

**This is incorrect.** Disassembly of `/usr/bin/pactl` (v17.0) shows:

- Format string at offset `0x11763`: `%u\t%u\t%s\t%s\t%s`
- Column 1 (`%u`): stream index
- Column 2 (`%u`): source index
- Column 3 (`%s`): **client index** — compared with `-1` at `0x14(%r12)`; prints `-` when client index is -1 (no client)
- Column 4 (`%s`): **sink name** — pointer at `0xc8(%r12)`; prints `(null)` when NULL (no sink)
- Column 5 (`%s`): sample spec

The code `classifySourceOutputs` (`scripts/v2/tauri-audio.test.mjs:300-312`) reads `columns[2]` as `clientId` — the variable name is correct. The defect is real: the code requires `Number.isInteger(clientId)` but `pactl` prints `-` for a clientless stream. The evidence's **description** of which column is wrong, but the **defect itself is confirmed**: a legitimate row with `-` in the client column ends the row.
