1. **Code-point walk instead of a character class** (`escapeMarkdownInline`).
   The implementer's V2 failed on `no-control-regex` when the escape set was
   written as the character class `` [\u0000-\u001f\u007f`\\|] ``; `eslint.config.js` is not in May edit
   and AM-070 forbids an exemption, so the set is walked as
   `code < 0x20 || code === 0x7f || MARKDOWN_ESCAPED_CODE_POINTS.has(code)`. I
   verified equivalence myself rather than taking the word: importing the real
   `escapeMarkdownInline` and comparing it against the regex form over sixteen
   samples (NUL, TAB, U+001F, DEL, backtick, backslash, pipe, accented text,
   emoji, astral characters, CR/LF, the A07 names) and exhaustively over all
   65,536 BMP code points — **zero differences**, astral characters passing
   through untouched in both. The escaped set is identical to Fixed decision 5's
   (U+0000–U+001F, U+007F, U+0060, U+005C, U+007C, lowercase hex). The deviation
   is implementation form, not behaviour; no guard, threshold or verdict moved.
   **Accepted.**
2. **Reworded doc comment.** The probe's `redactUserInfo` comment spelled an
   example authority as `https://user:pass@host/p`; it now reads
   `user:pass@host`, so the file holds no `https://` text at all. This keeps
   the file's own header claim ("It holds no URL literal") true against the
   outbound-URL rule, is comment-only, and changes no behaviour. **Accepted.**
3. **V3 output summarised.** The evidence quotes case names, counts, assertion
