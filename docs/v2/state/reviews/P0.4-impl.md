## Method (stated because it differs from the dispatch's step 3)

The dispatch says to re-run every verification row. On the coordinator's instruction for
this session I did **not** re-run all eight invocations; I substituted independent
re-derivation plus one live re-run, and say exactly what each row rests on:

1. **Every rate re-derived from the eight reports by script**, not read across. Each printed
   rate was turned back into its numerator by finding every integer `i` in `0..n` whose
   `((i/n)*100).toFixed(1)` reproduces the printed string, using the report's own `percent()`
   (`server/src/eval/report.ts:441-444`). Each printed rate had exactly one such integer, and
   that integer is the numerator `BASELINE.md` records. Min/max, §3.3/§4.3 per-case tables and
   the §5 range table were checked against the four per-corpus reports.
2. **Identity recomputed**: model digest, GGUF metadata, the four source-file hashes, both
   corpora, CPU/RAM/GPU, kernel.
3. **One live re-run of the V2 shape** (the fast one) to confirm the CLI's exit behaviour and
   that the committed reports are what the command prints.
4. **The exit convention read in code** rather than inferred, so the V1 exit-1 can be
   *derived* from the committed report instead of re-produced.
