## Numbered defects — settleable now

**D-1 — V1 and V2 assert an exit code the two scripts cannot produce on a
finding, so neither row can detect any Spanish regression.**
*Where:* `docs/v2/cards/S3.3.md:39-40` ("exit 0 (script runs; results recorded,
not judged)" / "exit 0 (runs; results recorded)").
*Conflicting text:* both scripts' every `process.exit` is a pre-flight refusal
with code 2 — `check-note-format.mjs:46,52,157,164,172` and
`check-refine.mjs:38,50,66,210`. Flags and problems are counted
(`check-note-format.mjs:200,212`; `check-refine.mjs:214,423,433`) and printed, and
then the process falls off the end with status 0.
*One concrete failure scenario:* the implementer ships a Spanish
`flagsFor` whose section constants stay English, so every Spanish note comes back
with zero recognised sections and every fixture is flagged "Discussion empty
though the source has material" — or, the other way, the borrowed-wording rule
never matches because its regex is ASCII-only. Both scripts print the flags and
exit 0; V1 and V2 are green; the defect is in the tree for S5 to inherit.
*One specific correction:* make each row assert a pinned count that a broken
Spanish path cannot produce, e.g. require the script to exit non-zero when any
flag fires (`process.exitCode = 1` after the summary, with the printed output
unchanged), and pin the fixture set each locale runs — "exit 0 **and** the
summary line reads `0 flag(s) across N fixtures` where `N` equals the file count
of `e2e/fixtures/her-format-es/`, with the run wrapped by
`node scripts/v2/sandbox.mjs run`". If the owner does not want these manual
harnesses to gate, the honest alternative is a **negative row**: a copy of the
Spanish fixture set with one deliberately mis-routed note must produce a named
flag.

**D-2 — `--locale es-MX` is inert today in both scripts, and in

*Where:* `docs/v2/cards/S3.3.md:39-40` pass `-- --locale es-MX`; neither script

*One concrete failure scenario:* V2 passes today, unchanged, on a checkout where
the Spanish refine path does not exist — and it would go on passing after the
implementer added the flag, unless the implementer also happens to exclude the

*One specific correction:* state in Fixed decisions that `--locale` must be

## Verdict

**DEFECT — 7 of 10 checks fail.** S3.3 is not ready to dispatch as written. The
defects are concentrated and cheap to fix, and none of them is a wrong
objective: Spanish support for the two check scripts plus a recorded "before" is
the right work. What is wrong is that **all four verification rows are currently
incapable of failing on a Spanish regression** (D-1, D-2, D-3, D-4) and that one
row is red for a reason that has nothing to do with the card (D-5). Fix D-1
through D-7 in the card text, re-check D-8 when S3.2's repair lands, and this
becomes a dispatchable self-check card. I would not manufacture a verdict
lighter than this: a self-check card whose rows cannot fail is the exact failure
class this project keeps paying for, and here it is present three times over.
