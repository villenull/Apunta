## Defects

### D1 — IR-01: write scope is wider than the objective and omits where the card must write

- **Location:** `docs/v2/cards/P3.5.md:22-29` ("May edit"), dispatched at
  `docs/v2/state/dispatch/P3.5-ir.md:74-81`.
- **Text that conflicts / missing:** "May edit" grants the whole shell —
  `src-tauri/**` — for what the Fixed decision describes as a single media
  permission handler, and it grants nothing for the two places the plan
  obliges this card to write: `docs/v2/evidence/<card-id>/` (Run configuration
  §4) and the checkpoint `docs/v2/state/cards/P3.5.json` (dispatch line 8).
  HS-9 then forbids every write outside that list, so a compliant implementer
  that records evidence as instructed is in breach of HS-9.
- **Failure scenario:** The implementer writes V1's SHA-256 to
  `docs/v2/evidence/P3.5/v1.md` because §4 of the run configuration demands it,
  and reports the commit blocked by HS-9 — or commits it and violates the card.
- **Correction:** add `docs/v2/evidence/P3.5/**` and
  `docs/v2/state/cards/P3.5.json` to "May edit", and narrow `src-tauri/**` to the
  permission-handler module (and its test) once the implementer names it.

### D2 — IR-02: two named prerequisites are absent today and the third is contradictory at the reviewed commit

- **Location:** `cards/P3.5.md:9` ("Depends: P3.3, S1.R"); `dispatch/P3.5-ir.md:99`
  (V2 "real whisper"); `cards/P3.5.md:84-87` (Fixed decision, A09/A10).
- **Missing:** (a) The en_US voice (A10) has never been acquired — only
  `es_MX-ald-medium` is on disk, and the card's Fixed decision requires `en_US`
  with no acquisition step, no row, and no stop response if it is absent.
  (b) V2 requires **real whisper**, but no GGUF model exists on the host and A07's
  "selected one only" model belongs to S4a.2, which is `NOT STARTED`; the default
  resolves to `<sandbox data dir>/models/<filename>`
  (`server/src/ai/stt-settings.ts:52-57`), which is empty in every fresh run

  is `APPROVED` in `PROGRESS.json` but `SUBMITTED` in `cards/P3.3.json`; only the

  The P3.3 `SUBMITTED`/`APPROVED` split is the coordinator's to reconcile in a

### D3 — IR-03: the card never says how the audio is captured *by the app*, and never pins the input device

- **Location:** `cards/P3.5.md:31-41` (Fixed decisions), `:47-49` (V2–V4).
- **Missing:** (a) **No automation path.** V2 must "dictate inside the Linux app
  window", i.e. press record in a real WebKitGTK window and capture what
  `web/src/lib/recorder.ts` sees. The repo has no driver for that window: Playwright
  drives Chromium only (`e2e/fixtures/audio/README.md:5-7` fake-capture flag), and
  P3.3's harness explicitly runs "no stub, no fake bridge line and **no test
  hook**" (`scripts/v2/tauri-lifecycle.test.mjs:12-14`). "May edit" excludes
  `web/`, so no trigger can be added either.
  (b) **Input device unpinned.** The Fixed decision says "feed audio through a
  virtual source", but nothing requires the app/portal to be pointed at it; the
  host's default source is a real USB microphone
  (`alsa_input.usb-UGREEN_Camera_2K_…`, `pactl list short sources`). (c) The
  mechanism is left as "PulseAudio **or** PipeWire"; this host has PipeWire only
  (no `pulseaudio`, no `pacmd`), so the implementer must choose a
  `pactl load-module` / `pw-cat` route unaided.
- **Failure scenario:** The test leaves the default source alone; the app captures
  10 s of the room, including whatever the owner said near the machine, writes it
  through the transcribe path, and the row "passes" on unrelated speech — a live
  privacy incident (HS-1/HS-8) that no row can detect.
- **Correction:** name the trigger (an owner-performed press with a recorded
  `NOT RUN`-style manual step, or a narrow amendment permitting a test-only hook
  in `web/`), require the virtual source to be made the default before capture and
  the previous default restored afterwards, and pin the mechanism for this host
  (PipeWire) with the exact create/remove commands. These are owner/coordinator
  decisions, not implementer choices.

### D5 — IR-05: V1–V4 are not runnable as written

- **Location:** `cards/P3.5.md:44-49`, dispatched verbatim at `dispatch/P3.5-ir.md:96-101`.
- **Text that conflicts / missing:** (a) V2/V3 write
  `scripts/v2/tauri-audio.test.mjs` with no interpreter and no invocation mode; the
  sibling harness requires `APUNTA_PORT`, `APUNTA_DATA_DIR` and
  `APUNTA_TEST_RUN_ID` or it exits before doing anything
  (`tauri-lifecycle.test.mjs:69-80`), i.e. `sandbox.mjs env` sourcing plus the
  AppImage path from `src-tauri/target/release/bundle/appimage/` — none of it in
  the row. (b) V1 `bash scripts/v2/make-en-audio.sh` names no inputs: `piper` is
  not on PATH, so `PIPER_BIN`/`PIPER_MODEL` must be supplied, and Piper's 22,050 Hz
  output must be resampled to 16 kHz with `ffmpeg` — the existing Spanish
  generator does exactly that and says so
  (`scripts/v2/generate-es-audio.mjs` header). (c) V1's "SHA-256 recorded" names no
  destination (see D1/D10). (d) The table header does supply cwd (repo root).
- **Failure scenario:** `scripts/v2/tauri-audio.test.mjs` is executed as a command,
  fails with "permission denied"/"not found", or runs and exits 2 on the missing
  sandbox variables; V1 fails at `piper: command not found` — two rows of four
  fail on the harness, not on the behaviour.
- **Correction:** write each row as the literal two-step used elsewhere
  (`node scripts/v2/sandbox.mjs env --port 78xx > …env && . …env` then
  `node scripts/v2/tauri-audio.test.mjs <mode>`, AppImage path named), give V1 its
  env inputs and the resample step, and name the evidence path for the SHA-256.

- **Location:** `cards/P3.5.md:47-49` vs `dispatch/P3.5-ir.md:21-24` (HS-2) and
  the L3 row of the run configuration ("the card's listed commands, **all through

  `APPROVED`, and C-ISO@1 rule 1 confines every path to `/tmp/apunta-v2/<runId>/`.
