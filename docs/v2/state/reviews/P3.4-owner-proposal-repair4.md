## The six defects

**D1 — frame identity, and a claim no stronger than the enforcement.** Every
batch of one `sendRects` call now carries one `frame` value drawn from a single
counter in the hook, the harness
collects `frame` per batch beside `batch` and `total`, and completeness requires
every batch index `0 .. ceil(total/40) − 1` present **declaring the same `frame`
and the same `total`**. The sentence "**stale or mixed frames are never
selectable**" is deleted. In its place the proposal claims exactly one thing — a
frame is complete when every batch of one publication is present and agrees on
`frame` and `total`; a mixture of two publications is not a frame and the read
restarts — and then says plainly **what is not claimed**: the hook publishes on
change and never retracts, so a "current" frame is not a decidable property of
the live buffer, and closing that would need a retraction protocol, which is a new
mechanism and is not sought here.

The invariants survive untouched and the proposal says so where they are checked:
one gate (`main.tsx:186-188`), one 250 ms change-only poll (`:171-183`), one marker
path (`:40`), one hook, `sendRects` still called from exactly one place
(`poll()` at `:177`), the batch size, the 200 cap, the text-leaf rule and
P3.5's seam all unchanged — AM-138 honoured, and §G's first row now names the one
new counter and the one new query parameter so a later reader cannot mistake them
for a second poll.

**D2 — one classification, and no warp ever sent outside the window.** The defect
was real and the two readings genuinely conflicted: containment "from the second
move onward" made the *second bootstrap move* a `FAIL`, while step 4 classified
bootstrap failures as `NOT RUN`. Now: the containment `FAIL` rule begins at **the
first point computed through the solved transform** (the step-9 click point) and
covers step 9's one re-warp and every step-5 repeat; the two step-4 bootstrap
points are its **only** exemption, bounded by its cause. Move 1 is the naive 1:1
guess, cannot be checked before it is issued, presses nothing, and yields the
named `NOT RUN` if nothing comes back. **Move 2 is checked before it is warped** —
if the displacement would leave the window rectangle, the calibration is `NOT
RUN` with the cause "the second bootstrap displacement left the window rectangle"
and **the move is not issued at all**. So no point outside the window rectangle
can ever be warped or clicked, which is what the safety requirement actually asks
for; the earlier draft of my repair would have let move 2 be issued and then
reported, and I changed it for that reason.

**D3 — the fixture shape is now the real one.** §T.2's comment reads
`JSON.stringify({ cards: { [id]: 'APPROVED' } })`, with the two source lines
(`:62`, `:63`) cited, because `build-dispatch.mjs:174-177` reads

**D4 — the snippet is the inner loop, and the return value is named.** §E now
