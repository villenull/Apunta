## Verdict

**DEFECT (bounded).** The config patch itself is correct and validates, and the
A10, attempt-accounting and privacy handling are sound. But the package is not
approval-ready: its **first** step would fail on this host because `patchelf` is
absent and `linuxdeploy` does not put its bundled copy on the plugin's `PATH`;
its dry-inspection step cannot check the four elements as written; and three of
its owner-decision items (A03, R-a, R-b) change more than the literal text they
claim to repair. Findings IR-01..IR-09 below, each with an exact before/after.
IR-10 is a note, not a blocker.

## Findings

### IR-01 (blocking) — the grant would fail at the first build: `patchelf` is absent and `linuxdeploy` does not supply it to the plugin

**Before** (`P3.5-ENVIRONMENT-PROPOSAL.md:240-243`, U-1): "Whether
`linuxdeploy` supplies its own on the plugin's `PATH` was not established …
If it does not, step 1 fails loudly and the answer is a separate, minimal owner
decision." §3 treats this as benign and the package as ready for the owner.

**Why that is wrong.** It *does not*, and the failure is immediate, not a
finding the trial build can work around:

- the Tauri CLI's embedded `linuxdeploy-plugin-gstreamer.sh` is byte-identical
  to `~/.cache/tauri/linuxdeploy-plugin-gstreamer.sh` (122/122 lines of ≥4
  chars; evidence `environment-proposal-ir/patchelf-resolution.md` §1) and both
  `exit 2` unless `which patchelf`/`type patchelf` succeeds;
- `linuxdeploy` bundles `usr/bin/patchelf` but resolves it itself via
  `$PATCHELF` or `<dir of /proc/self/exe>/patchelf`, never by adding it to a
  child's `PATH` (§2);
- every `PATH` reference in the `linuxdeploy` binary is a `getenv`, with no
  `setenv`/`putenv` and no `PATH` immediate (§3); the AppImage runtime sets only
  `HOME`/`XDG_CONFIG_HOME`/`FUSERMOUNT_PROG`/`APPIMAGE`/`ARGV0`/`APPDIR`/`OWD`,
  not `PATH` (§4);
- this host has no `patchelf` (`which` exit 1, `pacman -Q` exit 1); it is in
  Arch `extra` as `0.19.1-1` (`pacman -Si`, exit 0).

So step 1 fails before any plugin is copied, and the "separate minimal owner
decision" is needed **now**, not after a failed grant.

**After (recommended).** Make the prerequisite explicit in the same package:
add `patchelf` to the owner-run install, e.g.
`pkexec pacman -S --needed gst-plugins-base gst-plugins-good patchelf`
(owner authorises; the coordinator runs `pkexec`; the graphical prompt
authenticates — see IR-09), and add to step 0 the assertion
`command -v patchelf` (exit 0). Note that `patchelf` is a Tauri Linux
prerequisite, not a GStreamer plugin, so A03's "GStreamer plugins only if
P3.5's failing test proves them needed" clause does not by itself admit it —
the package must say which row/addition covers it. Do not present U-1 as
something the trial build will merely reveal.

### IR-02 (blocking) — step 2's dry `gst-inspect` cannot verify the four elements

**Before** (`:227`): a single invocation
`gst-inspect-1.0 appsink autoaudiosrc alsasrc` with "Expected: each names an
element, exit 0".

**Why that is wrong.** `gst-inspect-1.0` takes one element/plugin name; with
several it inspects only the last and ignores the rest. Measured here
(`environment-proposal-ir/ir-checks.mjs`, exit 0):

```
single appsink: exit=0
single autoaudiosrc: exit=255
single alsasrc: exit=255
single pulsesrc: exit=255
multi appsink autoaudiosrc alsasrc: exit=255 firstLine="No such element or plugin 'alsasrc'"
```

`appsink` and `autoaudiosrc` are never inspected, and `pulsesrc` is missing
from the command entirely.

**After.** Four separate invocations, one per element, each asserted on its own
exit code, and `pulsesrc` added:

```sh
for e in appsink autoaudiosrc alsasrc pulsesrc; do
  GST_REGISTRY=... LD_LIBRARY_PATH="$A/usr/lib" \
  GST_PLUGIN_SYSTEM_PATH_1_0="$A/usr/lib/gstreamer-1.0" \
  GST_REGISTRY_REUSE_PLUGIN_SCANNER=no \
  gst-inspect-1.0 "$e" || exit 1
done
```

### IR-03 (blocking) — step 2 uses a scanner path that U-2 says may not exist, with no existence assertion

**Before** (`:227`): `GST_PLUGIN_SCANNER_1_0="$A/usr/lib/gstreamer1.0/gstreamer-1.0/gst-plugin-scanner"`,
expecting success; U-2 (`:244-249`) concedes the script's guessed helpers
directory does not exist on Arch, so the scanner may not be bundled.

**After.** Assert the path before use and never let a missing scanner read as a
pass:

```sh
test -f "$A/usr/lib/gstreamer1.0/gstreamer-1.0/gst-plugin-scanner" \
  || { echo "scanner not bundled (U-2)"; }
```

and then run the element checks **with and without** `GST_PLUGIN_SCANNER_1_0`,
recording which produced the result. If GStreamer falls back to in-process
scanning, that is the recorded outcome, not a silent success; the registry file
must be fresh (`GST_REGISTRY` in scratch) so no stale success is reused.

### IR-04 (internal contradiction) — §1 claims the flag copies "the scanner"; U-2 says it cannot on Arch

**Before** (`:33-36`): "it makes the bundler copy the host's plugins **and** the
scanner into the AppDir"; §8 U-2 says `gst-plugin-scanner` may not be bundled.

**After.** Qualify §1 to match the evidence file and U-2, e.g.: "copies the
host's plugins, and the scanner only where the script's guessed helpers
directory exists — which it does not on Arch (U-2)".

### IR-05 (authority / manifest) — the proposed A03 replacement removes the Ubuntu host and widens the row

**Before** (`:130-136`, proposed *Source* cell): "Official Arch Linux
repositories (`pacman`, per `INSTALL.md` / `archlinux.org` package pages) for
the Tauri Linux prerequisites and, only where a failing P3.5 test proves them
needed, the named GStreamer plugin packages `gst-plugins-base` and
`gst-plugins-good`."

Three problems:

1. It **replaces** `Ubuntu archive via apt` rather than adding an Arch case.
   The manifest is OS-portable and A03 names Ubuntu; §4's claim "This adds a
   host" is false.
2. It **widens** to "the Tauri Linux prerequisites" generally, beyond the two
   packages the failing test proved needed.
3. It cites `INSTALL.md` and `archlinux.org` pages. `docs/INSTALL.md` is the
   Mac-facing, "no commands" guide and contains no `pacman`/`Ubuntu`/`Arch
   Linux` (checked, `ir-checks.mjs`); the manifest's *Source* cell is a host
   list, not a documentation pointer.

**After.** Keep Ubuntu and add the narrow Arch case, e.g.:

> Ubuntu archive via `apt`; on this Arch host only, the official Arch
> repositories via `pacman`, for the two GStreamer plugin packages a failing
> P3.5 test proves needed and for `patchelf` (IR-01).

No `INSTALL.md`/`archlinux.org` citation; *Allowed query keys* stays `none`;
*Shipped?* stays `no (system)`.

**One consistency point on *Shipped?*.** With Option A the shipping AppImage
copies host GStreamer **system libraries** into the bundle — the exact L-POLICY
row "System libraries bundled into an AppImage … public distribution requires
owner review". A03's *Shipped?* = `no (system)` is defensible only if it means
"not acquired/downloaded as a shipped item"; the shipping-bundle review trigger
is still real. The proposal calls it "a review item, not a blocker"; the owner
decision should state the trigger explicitly rather than leave it as an aside,
since Option A is the recommended choice.

### IR-06 (owner-decision content) — R-a weakens the default-source condition and cites a command V0 does not run

**Before** (`:187-190`, proposed): "the default source line is `*` **or**
`pactl get-default-source` prints a source that is not `apunta_p35_mic`".

Two problems:

1. V0's literal command (`cards/P3.5.md:692`) runs `pactl list short sources`
   and `pactl list short sinks`, **not** `pactl get-default-source`; the second
   arm of the `or` is not executed by V0, so the replacement describes a check
   the row does not make.
2. The `or` is unsound: a `*` on the virtual `apunta_p35_mic` line passes the
   first arm even though the default **is** this run's virtual source — the
   opposite of the card's substantive condition ("the default source line is
   `*` and is **not** `apunta_p35_mic`").

**After.** Keep the substantive condition in both arms and make the row run the
command it relies on: add `pactl get-default-source` to V0's command (assert it
is not `apunta_p35_mic`), and word the Expected cell as "the default source is
not `apunta_p35_mic`; on pactl 17.0 this is read with `pactl
get-default-source`, because `pactl list short sources` carries no `*` marker".
Do not add an `or` that can pass on the virtual source.

### IR-07 (authority) — R-b changes a requested outcome, not a literal

**Before** (`:192-199`): replaces the card's "a fabricated 30-second progress
dictation" with "15.78 s …" and "one 30-second clip" with "one spoken clip of
at least 15 s".

The card's Fixed decisions and V1 request a 30-second clip; the only
load-bearing assertion is `>10 s` (`cards/P3.5.md:199-210,693`). The filename
`dictation-30s.wav` is a name, not a duration requirement, and V1's command has
no duration control, so Piper's rate produced 15.78 s. Lowering "30 s" to
"at least 15 s" is an acceptance/outcome change and therefore the owner's, not
a mechanical literal fix.

**After (recommended trade, no source change authorised here).** Keep the
"30-second" wording and make the fixture reach it — loop the generated clip in
V1 (e.g. `ffmpeg -stream_loop … -t 30`), preserving the requested outcome. If
the owner instead prefers the "≥15 s" wording, record it explicitly as an
acceptance change; do not fold it into a "literal" repair.

### IR-09 (framing) — "agents cannot install" is wrong after the owner's `pkexec` grant

authorises; coordinator runs `pkexec`; the graphical polkit prompt
authenticates. Agents still never type a password." This is the mechanism
