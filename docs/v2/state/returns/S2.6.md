## Findings

1. **`e2e/support/no-english.ts:187-196` — the arrival wait has a floor AM-073
   does not cover, and it is a latent version of the same defect. MINOR,
   reported not fixed.** `arrivedStrings` stops as soon as it has read *any*
   string, which is exactly right for the wrapper — the whole subtree is at
   `opacity: 0` until the transition ends, so the first non-zero read is the
   first moment the screen is legible. It is not sufficient for a *staggered*
   entrance: `.note-editor-col` and the list rows use `rise-in` with delays up to
   144ms and `backwards` fill, so they finish ~144ms after the wrapper does, and
   a text node still at `opacity: 0` under one of them is dropped while the rest
   of the screen is read. No screen in this run reads 0 because of it and I
   measured no partial read I can attribute to it, but it is the same failure
   mode at a smaller scale, and a future screen whose visible text lives
   entirely inside a staggered subtree would read 0 again. I did not fix it: the
   obvious fix is to require a *stable* count across two reads, which changes
   the guard's behaviour on legitimately dynamic screens (a streaming draft,
   typing dots) and is a decision about what the check should assert, not one
   this card's amendment decides. The new non-zero assertion means such a screen
   would now **fail loudly** rather than pass quietly, which is the improvement
   that matters here.
2. **`e2e/tests/language-control.spec.ts:441` and `:444` (line numbers after
   this attempt) — the review's finding 3 also applied to the second

   reported.** The review named the exposure at both of these lines; at attempt 2

   produced a green V1 with these two calls still able to report a clean screen
