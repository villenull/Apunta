`NN-` prefix is the sorted position, so the split is derivable from the filename; the checker re-derives it and

## Deviations

Four, none of which changes behaviour.

1. **Section names are Spanish, which is an interpretation.** The card fixes the `_schema` *keys* and says nothing
   about the `sections` *values*. I used the Spanish sets from
   `docs/research/es-mx-clinical-documentation.md` §5 — `["Subjetivo","Objetivo","Análisis","Plan"]`,
   `["Motivo de consulta","Antecedentes","Formulación","Plan terapéutico"]`, and her seven. Reasoning: the notes
   are Spanish, and a Spanish note with English headers is its own kind of fabrication; and §5 is the card's own
   Read material. Consequence, stated plainly: `defaultInstructionsFor` matches none of them, so these fixtures
   route to the generic fallback until S3.2 settles locale-aware instruction selection. **S3.2 should confirm or
   overrule this before running the corpus.** The alternative — English headers — would route today and would be
   wrong.

2. **The owner corpus never declares `Revisión de riesgo` or `Tareas entre sesiones` blank.**
   `docs/note-instructions/owner-progress-instructions.md` ("Empty sections") says those two read `"None."` by
   her standing convention and every other section reads `""`. A `blank` claim on either would be false gold, so
   the `section-never-covered/` fixtures in her format blank the other five sections, one each. This is the
   instruction file speaking, not a judgement call, but it is not in the card and a reviewer should know.

3. **`requiresMarker` is a shape, not a string.** The English harness's marker is the literal
   `[unclear in dictation]`; the Spanish one is S3.2's to settle, and the card gives S3.2 the scorer. Ten fixtures
   depend on the answer, so I wrote a permissive alternation covering the plausible Spanish renderings rather
   than inventing a production string. **S3.2 should tighten these ten to whatever it settles on.** Same for the
   seven `markerFreeSource: true` claims.

4. **Extra assertions in the checker beyond the card's six.** The split rule, the `_schema` parity with the
   English sidecars, `words` recount, `blank`/`statedAbsence` disjointness, the no-banned-pattern-matches-its-own-
   headers rule, and the reverse name direction. Each is marked `extra:` in the source with its reason. They are
   additions, not substitutions: all six the card names are present and pass.

Two things I got wrong and fixed, both worth the reviewer's attention because the first would have shipped a false
pass:

- **V3a initially exited 0.** The name check compared individual capitalised words, and sentence- and line-initial
  words were skipped — which is where the patient's name is, on the first line. Deleting a `NAMES.md` row tripped
  nothing. Word-level checking can never be sufficient here: surnames recur, so `Ruiz` stays authorised by six
  other rows. Fixed with a full-name check in both directions plus a capitalised-run scan. This is the layer that
  makes the corpus's privacy boundary real rather than aspirational.
- **I inverted the split.** My first cast held out the 1st and 3rd sorted names; the card's `i % 5 ∈ {1, 3}` is
  0-based, so it is the 2nd and 4th. The checker caught it on 55 files at once and I moved them. Held-out share
  was 40% either way, which is exactly why the share alone is not a sufficient check.
