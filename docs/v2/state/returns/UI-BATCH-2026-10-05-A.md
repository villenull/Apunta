## What was built

**One mounted workspace across the whole route family (task 1).**

- `AppRoutes` keys the transition wrapper on the **effective** location
  (`routeFamilyKey((background ?? location).pathname)`), and `/` and `/patients`
  share one `workspace` key. Opening or closing the capture window never re-keys
  anything, so the DOM node, the open editor, the sidebar and the fetched lists
  all survive; the three obsolete `key={location.pathname}` remounts are gone.
- Background/overlay routing, as siblings under the same `<Suspense>` so the
  tree reconciles instead of remounting:
  `<div class="route-background" inert-while-open><Routes location={background ?? location}>` renders
  every route except capture; `<Routes location={location}>` renders
  `/capture/:patientId`. A2 holds: the overlay is a **sibling** of the node that
  is made `inert`, so neither the capture panel nor the leave-confirmation
  inside it is ever inerted, while the practice behind it leaves the tab order.
  `#apunta-content`'s existing `inert` for a blocked (secondary/unsupported)
  window still covers everything, overlay included.
- A6: the capture id comes from `matchPath('/capture/:patientId', …)` —
  `AppRoutes` sits at `path="*"`, so `useParams` cannot supply it — and a
  deep link gets a memoized synthetic background (`/` + `?patient=<id>`, built
  once per id so the `LocationContext` value keeps its identity). A carried
  `state.backgroundLocation` is honoured only when it is Location-shaped
  (string `pathname` starting `/`) and is not itself a capture path, so B's
  synthetic home background works and a double-overlay cannot happen.
- A3: the return from capture refetches **notes only**, once per unknown id.
  `Workspace` records the array each `listNotes` request answered with
  (`notesAnswerRef`, emptied as the request starts) so the check can only fire on
  the newest answer, and a per-patient ref keeps a deleted id costing one
  request instead of one per render. No patients re-read, no remount, `refresh`
  rather than `reload` so the column and any open editor stay on screen.
- Back/Forward and direct links are untouched: every exit is an ordinary
  navigation, and the capture entry is only popped by B's validated
  `navigate(-1)`.
- The IR's keyboard note: `#apunta-content` now carries
  `data-capture-overlay="true"` while the window is up, and `Workspace`'s
  Ctrl+B listener reads it, so the chord no longer collapses a sidebar hidden
  behind a modal. (The cosmetic `becomePrimary` focus no-op was left alone.)

**The notes column (task 2).**

- No patient heading; `New note` in the top band beside the narrow-window way
  back to Patients (still `.narrow-back`, still inside a `.col-header-title`);
  the notes alone in the band that scrolls (`flex: 1 1 auto; min-height: 0`);
  the three tools in a footer that never scrolls away.
- A5: the narrow-pane focus target moved off the deleted heading to
  `[data-testid='notes-new-note']`, so the keyboard still lands somewhere
  useful in the notes pane.
- B1/B2: the click surface is the scroll band itself, and it bails on any
  interactive descendant (`button, a, input, textarea, select, [role=button],
  [role=link], [contenteditable=true]`), so New note, the three tools, note rows
  and their inner wrappers never clear. A plain label (the "Notes" heading) does
  behave like the blank space around it, per the disposition.
- A4: blank space calls `onDeselect`, and `Workspace.handleDeselect` awaits the
  existing `window.__apuntaFlushBeforeRelease` **before** clearing, keeping the
  patient. A rejected flush (failed save, unresolved conflict) clears nothing,
  keeps the editor mounted and surfaces the reason through the existing
  `actionError`/`Toast`. After the await the current patient/note/view is
  re-read from a ref and only cleared if it still matches what the request
  started from, so a late resolution cannot clobber newer navigation.
- `NoteView` and the flush hook itself are untouched.
- CSS lives only in the new private `styles/notes-column.css`, imported by
  `NotesColumn`.
