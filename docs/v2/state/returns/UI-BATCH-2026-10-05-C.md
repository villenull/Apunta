## Findings addressed

**F1 (HIGH) — a draft was not selected after the open note had been saved.**
The refetch of a `?note=` id the workspace had not seen was gated on
`notes.state.data === notesAnswerRef.current` — the identity of the array the
newest request answered with. `notes.update` (a save, a refine-chat rewrite, a
delete) replaces that array, so from the first local edit the guard never
passed again for the rest of that patient's visit: no `refresh()`, the new id
absent from `visibleNotes`, `note === null`, and the main pane on
`PatientWelcome`.

**F2 (LOW) — the two new component stylesheets lose to `app.css` on import
order.** `main.tsx` imports `./App.js` before `./styles/app.css`, so
`capture-modal.css` and `notes-column.css` are emitted *before* `app.css` and
equal-specificity `app.css` rules win. Root's probe confirmed the built window at
460px, not the declared 560px; the same cause dropped `.notes-col-new`'s
`margin: 0` and `.notes-col-body`'s `flex: 1 1 auto`.

**Focus restoration (reviewer's residual, now confirmed by root's probe).**
Root's `focus-probe.mjs` on a clean New note → Escape returned
`{focus: {tag: "BODY", testId: null, inert: false}}`. Root's reading: the
background was **not** inert at observation time, so the reviewer's
`inert`-still-true theory did not hold as stated — but the mechanism is the
ordering one, and the fix is the same. `Dialog` restores focus from its `open`
effect **cleanup**; React runs all passive cleanups for a commit before any
passive setup, so `App`'s passive effect that clears `inert` ran *after* the
`focus()` call. The focus landed, found nothing wrong with it at that instant,
and was then discarded — with `inert` cleared afterwards and focus on `<body>`.
Root's `inert: false` reading is consistent with exactly that: the flag is false
by the time the probe looked, which is *after* the failed restore.

## What changed

### F1 — the guard now asks which request the list came from

`Workspace.tsx` tracks a **request identity** instead of an array identity:

- `notesRequestRef` counts `listNotes` requests; each one takes a number and
  empties `notesAnswerRef` as it starts (as before).
- An answer records `{ request, patient }` — **not** the array — and only if the
  request was neither aborted nor overtaken by a newer one. A late answer for the
  patient she just left therefore records nothing.
- The effect's guard is: status ready, an answer exists, and
  `answer.patient === patientId`. A request number is untouched by `update`, so
  the local edit that used to poison the guard is now irrelevant, while a stale
  cross-patient answer still cannot pass.

Once-per-unknown-id (`refetchedNoteRef`, reset per patient) and
notes-only-refresh are unchanged: no patients re-read, no remount, still
`refresh` so the column and any open editor stay on screen. `patientId` joined
the effect's dependencies so a switch re-evaluates against the new patient.

### F2 — stronger selectors, no import-order dependence

Each rule that overrides an `app.css` rule is now compounded with the class
`app.css` puts on the same element, which raises specificity above `app.css`'s
regardless of which file is emitted first:

- `capture-modal.css`: `.capture-modal` → `.modal.capture-modal` (the 560px
  `max-width`, plus its own `max-height`/`overflow-y`/`overscroll-behavior`).
- `notes-column.css`: `.col-header-title.notes-col-head-row`,
  `.new-note-btn.notes-col-new`, `.col-body.notes-col-body`.

The shared scrim is **not** restated: `capture-modal.css` still writes no
`backdrop-filter` and no background, and `.capture-modal` remains named in the
one rule in `app.css`. `app.css` itself is untouched.

### Focus restoration — the inert change moves to the layout phase

`App.tsx`'s overlay-inert effect is now `useLayoutEffect`. Layout effects for a
commit run before passive cleanups, so the practice behind the window is out of
`inert` *before* `Dialog`'s cleanup returns the keyboard to the opener.

Verified rather than assumed: `Dialog.tsx` restores from a `useEffect` cleanup
(`Dialog.tsx:77-79`), and the new test asserts the ordering at the moment the
opener receives focus (see below).

Nothing about the restriction is weakened. `inert` is still applied to
`.route-background` for exactly as long as the overlay is open; it is applied in
an earlier phase of the same commit, not less often. The overlay is still a
**sibling** of that node, so neither the capture panel nor the leave-confirmation
inside it is ever inerted, and `Dialog`'s own key handling and Tab trap are
untouched. The primary-window `inert` on `#apunta-content` (`blocked`) is a
separate effect and is unchanged; that restriction and `PrimaryBlocker`'s trap
are as they were.

## Tests

**1. F1, end to end — "selects a draft made after the open note was saved,
rather than leaving the welcome".** Opens John's draft, edits it and waits for
the debounced save to reach the server (the local `update`), then New note →
summary → Create draft. Asserts the window closes on
`?patient=…&note=<new id>`, the new draft is the note on screen with the real
streamed body, `GET /api/patients/<id>/notes` is **2** (the refetch) and
`GET /api/patients` is still **1** (no sidebar reload). It waits for the window to
close before asserting the body, because the editor of the note she had open is
mounted behind the window the whole time and would otherwise satisfy a naive
assertion.

**2. F1, patient-switch staleness — "does not take a late answer for the previous
patient as this one".** Holds John's first read open, switches to Maria asking
for an id that is not hers, then releases John's answer while Maria's own read is
still in flight. Asserts Maria's list is read once at that point (his late
answer triggered nothing), then exactly twice once hers answers, and quiet after.
The two reads are gated through a `fetch` stub; no extra patient is invented.

**3. Focus ordering — "takes the practice out of the tab order before the
keyboard goes back to the opener".** Focuses the New note button (a real click
focuses it in a browser; jsdom does not, and `Dialog` captures
`document.activeElement`), opens the window, records the background's `inert` in
a `focus` listener on the opener, presses Escape, and asserts **every** recorded
value is `false` and that `document.activeElement` is the opener. jsdom does not
model `inert`, so this asserts the invariant the browser result depends on —
the ordering — rather than the browser's own refusal to focus.

**4 + 5. F2 — "compounds every new-note rule that overrides the shared `.modal`"
and "compounds every notes-column rule that overrides a `.col` rule".** Read the
three stylesheets as source (the same technique the existing shared-scrim test
uses, because jsdom has no cascade): each overriding rule is asserted present
under its compounded selector, the `app.css` rule it beats is asserted present,
and `capture-modal.css` is asserted to contain no `backdrop-filter`, so the
shared scrim stays the only copy.
