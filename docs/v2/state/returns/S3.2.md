4. **`{{lexicon}}`'s negative-control claim about `stem`.** FD2c motivates
   unstemmed negation matching with two statements that do not survive
   measurement, so the tests assert what is true instead:
   - `stem('jamás') === 'jamá'` — true, and it is the whole reason the entry is
     carried as written. But `\bjamá\b` still *matches* `jamás`, because `á` is a
     non-word character in JavaScript and `\b` therefore sits between `á` and `s`.
   - `stem` does turn `nos` into `no`, but `\bno\b` does **not** match
     `stem("nosotros")` (`nosotro`), so the false positive does not arise.
   The implemented behaviour is exactly what FD2c's normative rule states —
   negation entries built from the unstemmed term under the Latin boundary,
   number/unit/medication stemmed on both sides — and the two boundary
   consequences FD2c *does* measure (`dejó` 10 where `\b` gives 0, and `nosotros`
   not matching `no`) are asserted.
