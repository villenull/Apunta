## What this attempt did

One correction, in the two places the attempt-3 review named, plus the
assertion the review said was missing.

`server/src/ai/refine-request.ts`'s `changeSentence` builds the first paragraph
of every successful refine reply. Attempt 3 routed its parts through
`chat.list.last`, whose English is `{first} and {last}` with `first`
pre-joined by `", "`. That is byte-identical for one part and for two, and
wrong from three on: `a, b and c` where the wire has always carried
`a and b and c`. Fixed decision 6 is explicit that a tidier English is a stop,
not a copy improvement, and that S2.7 and S2.8 own the copy — so the default
locale's bytes do not move.

**The code.** One branch in `changeSentence`:

```ts
  const changes =
    locale === DEFAULT_LOCALE
      ? parts.join(' and ')          // the wire's own expression, restored
      : parts.length === 1
        ? (parts[0] as string)
        : msg(locale, 'chat.list.last', { first: …, last: … });
```

The default locale joins with `' and '` and nothing else, at every part count.
Every **non-default** locale keeps the catalogue list, which is what makes
`a, b y c` read as Spanish and is the whole reason `chat.list.last` exists.
No key was added, removed or reworded; `chat.list.last` keeps its two callers
(`listSections`, and `changeSentence` outside the default locale).

**The assertion.** Nothing anywhere pinned the three-part form, which is why
four green rows missed it. Five new cases in
`server/src/ai/refine-request.test.ts`, each asserted **twice** — once built by
`wire(parts) = \`I ${parts.join(' and ')}.\`` from the parts spelled out beside
it, which is the pre-card expression verbatim, and once as a fully written
string literal so the bytes are visible in the file. The three- and four-part
cases also assert `not.toContain(',')`, and a fifth case pins the Spanish at all
four counts so the fix cannot be "make English right by making every language
the same".

**The documentation that asserted the opposite.** Three comments claimed more
than the tests proved, and all three now say what is actually guaranteed:

- `changeSentence`'s docstring said *"The English is unchanged, character for
  character: this is the sentence the wire has always carried"* — false in the
  branch it covered. It now says the default locale's separator is the wire's
  and is deliberately not a key; that `a and b and c` is what already-stored
  replies are stored with, because FD5 renders at write time and a stored row
  is displayed as stored; that the awkwardness is the guarantee and not an
  oversight; that better English is S2.7's and S2.8's to write; and that the
  four counts are pinned in `refine-request.test.ts`.
- `listSections`' docstring said the list key is "shared with the diff

- `shared/src/i18n/en.ts`'s comment on `chat.list.last` said the pre-separator
  is a comma with no exception. It now records the exception and points at
