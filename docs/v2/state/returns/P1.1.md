## Behaviour notes, for the reviewer

1. **The Drafting model group now shows her stored choice first.** It read
   `llm_effective_profile` before; it reads `llm_profile` when that is one of
   the offered profiles, and `llm_effective_profile` otherwise. This is forced
   by the contract: with the control's own `selected` state gone, an optimistic
   `update({ llm_profile })` has to be visible at once, and
   `llm_effective_profile` is computed by the server on `GET` and would not move
   until a reload — which is the disagreement this card exists to remove. It is
   only observable while the server offers both profiles; today
   `server/src/ai/profiles.ts` promotes `quick` alone, so the card renders
   `null` in production either way. Recorded because it is a change in what the
   control displays, not only in how.
2. **Nothing repaints twice.** Each control still calls its own `apply*` for the
   instant preview, and `App.tsx`'s existing effect repaints from the provider
   once the patch lands; both read the same value, so the page settles where it
   started. On a rollback the effect is what repaints, which is why
   `Settings.test.tsx` renders the real `App` rather than the route alone.
