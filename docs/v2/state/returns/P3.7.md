## The check, and why it is shaped this way

The three existing SPA assertions inspect `GET /` only, and `index.html`
survives `rm -rf web/dist/assets` intact, so a bundle with no JavaScript in it
passed all of them. The new check fetches the one hashed script the **served**
shell names and requires three things of it: 200, a content type containing
`javascript`, and a byte length equal to what the bundle's own manifest records
for that path.

`server/src/app.ts` was **not** changed, and did not need to be. The SPA fallback
answers a missing asset `200 text/html` and a real one
`200 application/javascript`, so the content type alone discriminates — the
control returned 1265 bytes of HTML where a real asset returns 169523 bytes of
JavaScript. Changing the fallback to `404` for unmatched asset paths would alter
what a reload of a client-side route does (it is why `/patients` resolves on a
fresh load) and would buy this row nothing it can measure. Stop condition 4 was
not reached.

The length is the bundle's own record, not a floor. A hard-coded floor would be
a new threshold, which HS-7 forbids inventing inside a card, and a floor under
the review's 169523 would pass a half-copied bundle.

The path is read from the served response, so a bundle whose `index.html` and
`assets/` disagree cannot pass. A count other than one `src="` is a `FAIL` with
the count in the detail — never a skip, never a pass — and there is no
`modulepreload` fallback, no glob over `web/dist`, no hard-coded asset name and
no file read from disk (Stop condition 2 was not reached). One judgement call is
recorded in `docs/v2/evidence/P3.7/change.md`: a reference that is not
site-absolute is refused with the path named rather than resolved against `/`,
because resolving it would be a guess.

Nothing about the launch changed: the same `sandbox.mjs env` run under the
bundled Node, the same whole-folder relocation, `cd /`, `env -i` with
`PATH=/usr/bin:/bin`, the four `APUNTA_*` overrides, the ownership poll before
the first assertion and both ownership halves, `whisper-cli --help`, the
missing-SQLite negative case asserted rather than tolerated, rule-7 shutdown and
exit-1-on-first-failure. The script's own default port `7834` was read, not
