## What changed

### Findings closed

**D1 + D2 — one quit, three doors (`src-tauri/src/quit.rs`, new).** The review's
two blocking defects were one missing abstraction: three independent quit paths.
`QuitGate` is a `compare_exchange` one-shot — the first caller to claim it runs
the ladder exactly once, every later caller through any door does nothing. The
main window's `CloseRequested` is now a real door (it prevents the close so the
window outlives cleanup), the `ExitRequested` arm only defers the exit while the
ladder is live, and the signal watchdog hands over to the same function. The
process-group id is taken with a single `swap(0)` and never written back, so a
reaped group can never be signalled again and a recycled pid can never be
reached through it. 5 gate tests including an **8-thread race** asserting exactly
one winner, plus two tests that run the **real ladder against real processes** and
assert real exit statuses (one where the child honours `shutdown` and exits 0
inside the grace period; one where it ignores `shutdown` and is stopped by
`SIGTERM`).

**The forced-destroy case the review asked to be reproduced.** `xdotool windowclose`
is `XDestroyWindow` — a destroy, not a close — and `xdotool windowquit` sends
`_NET_CLOSE_WINDOW`, a **window-manager** message that nothing routes under
`xvfb-run` (both established from this host's own `man xdotool` and
`strings libxdo`, and measured twice: window up, process alive, `/api/health`
200). So `CloseRequested` cannot be reached headlessly here, and this attempt
does not pretend otherwise. Instead the shell's death is handled where it can
actually be handled: the shell holds the write end of the child's stdin, so when
GDK's error handler aborts it (`Gdk-WARNING … BadDrawable`, reproduced verbatim)
the child sees **end-of-file** and closes itself (`onParentGone` in
`server/src/shell-bridge.ts`, wired in `server/src/index.ts`). Measured on the
built AppImage: port released, **no server process survives**, data lock
released, dummy and Ollama untouched — 12/12, with no signal sent by anyone,
because there is no shell left to send one.

**D3 — CI could not pass.** The `rust` job now installs `libwebkit2gtk-4.1-dev`,
`libgtk-3-dev`, `libayatana-appindicator3-dev` before the three checks (compiling
needs them, not just bundling: `webkit2gtk-sys`'s build script exits non-zero
otherwise), the misleading comment is replaced with the real reason, and D12 is
folded in — both unpinned third-party actions removed in favour of
`rustup component add rustfmt clippy` on the toolchain the image already ships.
**Hosted CI was not run and no CI pass is claimed.**

**D4 — the CLI is declared.** `package.json` now carries
`"@tauri-apps/cli": "^2.12.1"`, the range the lockfile's root entry had already
resolved, so `package.json` was reconciled **to** the lock (`package-lock.json`'s
diff is unchanged at +234/−1; no re-resolution, nothing downloaded). Proven the

`npm ci --dry-run --offline` → `add @tauri-apps/cli 2.12.1` +
`add @tauri-apps/cli-linux-x64-gnu 2.12.1`, exit 0, from cache.

**D5 — V6 is five recorded commands, not one chain.** Each step executed and
recorded separately with its own exit code, so no result depends on a chain
reaching it. `npm run lint` is **0**.

**D6 — the home-screen assertion is real.** Exact string `Apunta` (the hidden
lowercase 20×20 GTK helper cannot match), `WINDOW_PID` equal to this run's shell,
≥ 400×300, and the rectangle inside `xdotool getdisplaygeometry`. Asserting the
geometry **exposed a genuine defect**: the app's window was off-screen (2560×1720
at `-960,-620` on a 1400×1000 display) because a fixed size plus `center()`
overflows small displays, and because the 880×600 *logical* minimum is 1760×1200
*physical* on a scaled display, clamping the window back up to its own minimum.
The app now fits both the requested size and the minimum to the monitor, in
physical pixels, divided by the scale factor. Render evidence is three pieces
rather than one, because a non-uniform screenshot alone could be a splash or an
error page: a **polled** capture (≥ 8 distinct colours — 179/271/290 measured; the
same unpainted window measures 2), and the document the server actually served at
that origin (200, `text/html`, 1265 bytes, `id="root"`).

**D7 — three quit directions, each asserted on its own terms.** `stopPid` now
returns whether it escalated, and each case requires the shell to be gone

server is gone), and the data lock released or naming a dead pid, plus the
containment that makes this a containment row: the unrelated dummy alive and

**D8 — the origin check is an origin check.** `is_allowed_origin` parses and

port **suffix** (`…:78310` refused), **userinfo** (`…:7831@evil.example`, which

hosts, scheme, `file:` and a missing port.

## Deviations

1. **V3 is now three modes, not one.** The card names one command
   (`… launch`). `launch` still exists and is the signal case; `window-close`
   and `forced-close` are two more modes of the same harness, because the review
   required the two directions to be asserted separately and required the forced
   destruction not to be passed off as a native close. The card's command and its
   exit code are unchanged.
2. **The window is now fitted to the monitor** (`main_window_geometry`). A
   behaviour change inside `src-tauri/**`: the app no longer opens a fixed
   1280×860 window centred on the screen, but one sized and positioned to fit
   whatever monitor it opens on. It was made because V3's geometry assertion
   proved the fixed behaviour put the window off-screen — the app was unusable on
   a 1400×1000 display and on any small laptop. A window large enough for the
   work and no larger than the screen is the intent, not a new feature.
3. **The child now shuts down on stdin end-of-file** (`onParentGone`), inside the
   card's May-edit files and needing no new crate or API. It is what contains a
   forced window destruction, where the shell is gone before it can do anything.
   Gated on `APUNTA_SHELL=1`, so browser mode reads no stdin at all and is
   unchanged.
4. **The harness names its own Xvfb screen** (`-screen 0 1400x1000x24`) instead
   of inheriting `xvfb-run`'s 640×480 default, which is smaller than the app's
   minimum window. A harness-side choice, recorded in every row's evidence.
5. **CI's `rust` job changed shape** (packages installed, third-party actions
   removed) to make clippy and test able to compile at all. CI-only; no host
   package was touched.
