## Deviations

1. **`Spelling.error` is optional on the type, always present on the value.**
   D4.1 writes `readonly error: MessageKey | null;`. Two hand-built `Spelling`
   doubles outside May edit (`web/src/components/NoteBody.test.tsx:38`,
   `web/src/components/RefineColumn.test.tsx:213`) would have to change, and
   `exactOptionalPropertyTypes` makes a required new field a `typecheck` error
   in them. The field is therefore `readonly error?: MessageKey | null`, with
   `INERT` and every published value carrying it explicitly. The part D4.1 cares
   about is unchanged: the type is still the `MessageKey` union, so a typo in the
   key is a `npm run typecheck` failure, not a runtime one. No behaviour changes.
2. **A language change re-asks for the dictionary if a surface had already asked.**
   Not in D4.3, and needed: the guard increments the request id on a language
   change, which discards the load in flight, and `useSpelling` asks once, when
   it mounts. Without the re-ask, a session whose settings arrive after the first
   surface mounts ends the tab with **no** dictionary and no error — observed, and
   it is why the es-MX pages initially showed no marks at all. The added line is
   in `SpellingProvider.tsx`, a May-edit path, and both (f) cases cover it.
3. **`spelling-assets.spec.ts` waits for `html lang` before it opens the note.**
   Every page mounts a spell surface before its settings land, so without the wait
   the first mount loads the pair for the language guessed at that moment and the
   row measures that transient instead of what D3 rule 1 selects. Recorded in
   `V3-assets.md`.
4. **The owner-facing size figure is in this summary and in
   `docs/v2/evidence/S6.1/acquisition.md`, not in `docs/decisions.md`'s size
   row.** *Evidence* asks for both, but *May edit* allows **one** appended row in
   `docs/decisions.md` and that row already exists (AM-203, the election).
   Appending a second row for the size figure would exceed the approved limit, so
   the figure is reported here as the Evidence section's fallback asks.
5. **V5 and V7 are `FAIL`, not `PASS` and not `BLOCKED`.** Neither failure is a
   safety instrument or a threshold: one is an out-of-scope test query that a
   fixed decision made ambiguous, and the other is four committed screenshots a
   requested global gate rewrites. Both are described above with the one-line
   fix each needs, and neither was worked around.
6. **In the browser rows the menu is opened with a real click rather than a
   dispatched `MouseEvent`.** D6 condition 2 names the case (the caret inside the
   marked word, then a click that reaches the editor, and the menu must open); the
   dispatched form does not reach the handler on a single-line input at all, so
   the real click is what makes the named case executable on all five surfaces.
   The menu's `aria-label`, which names the word it is about, is asserted too, so
   a menu left over from an earlier value cannot pass for this one.
