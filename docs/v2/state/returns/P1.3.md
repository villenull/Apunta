## What the guard does

`server/src/http/request-guard.ts`, applied as `onRequest` in `buildApp` and in
`buildBootErrorApp`, in that order: `host`, `sec_fetch_site`, `options_origin`
(OPTIONS only), `origin`. The first rule that fails is the one logged, with the
method and the URL and never the body, and the answer is always the hand-built
`403 {"error":{"code":"forbidden_request"}}` — never a throw, because the boot
server registers no error handler. `<port>` is `app.server.address()`'s port
while listening and the configured port otherwise, so an injected request is
checked against `config.port` and a real socket against the port actually bound.

Both Vite allowances (`127.0.0.1:5173` as a `Host`, `http://127.0.0.1:5173` as
an `Origin`) are unconditional, with no flag, exactly as the card's Fixed
decisions state. Nothing is exempted by path, method or environment.

Checked, not run: `e2e/playwright.config.ts` builds its `baseURL` as
`http://127.0.0.1:<port>`, so a browser session presents a conforming `Host`,
`Origin` and `Sec-Fetch-Site` — P3.4's e2e run should not meet this guard. The
e2e suite was not run here: HS-2 allows it only through `scripts/v2/sandbox.mjs`,
and P0.3 is not approved.

   the pass-through half that gave it away. I overwrote that run's log with the
