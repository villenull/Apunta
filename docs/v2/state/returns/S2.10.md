## Finding 2, reproduced and fixed

**Reproduced first, targeted, on the unmodified tree.** The three whole-suite
base runs at `cbe52d5` were all green (0, 0, 0; 108 passed / 6 skipped each),
which is a deviation from the card's Step 1 expectation and explicitly **not**
treated as a licence to do nothing — the premise was reproduced by amplifying
the one spec the finding names:

```
( cd e2e && PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npx playwright test \
    --project=chromium --repeat-each=4 halaxy-import.spec.ts )
```

**2 of 3 runs red**, at `e2e/tests/halaxy-import.spec.ts:98`, with the
reviewer's exact message and numbers — `Expected: 1`, `Received: 2`, *"one undo
button per row the API returned"* — and the same log showing the sibling
`POST /api/import/batches/<id>/undo` landing between the page's read and the
spec's.

**The fix, and why that shape.** The rows on screen come from the GET the route
fires when it mounts and are only reloaded after an undo
(`web/src/hooks/useImportBatch.ts:20-28`), so the spec now arms
`page.waitForResponse` **before** `page.goto('/import/halaxy')` and reads
`batches` out of *that* response. The separately timed `request.get` is gone.
Both identity assertions are unchanged and still fire:

- `batches[ownRow]?.id` must be the `batch_id` this run's `POST
  /api/import/halaxy` answer carried;
- the undo-button count must equal `batches.length`, so a DOM index and a
  `batches` index mean the same row or the test fails;
- the undone-line assertion at the end is untouched.

So the assertion still proves the button clicked is this test's own batch — and
it now proves the question the click actually depends on, which the old shape
could not: *is row n of the DOM row n of the list these rows were rendered
from*. Nothing is retried, skipped, timed out, deleted or weakened, and no
production file moved. After the fix the same amplified probe is **4 runs, 16
of 16 copies green, all 16 undos 200**.

**A control, because "still proves identity" is a claim worth testing.** With the
click index mirrored (`.nth(ownRow)` → `.nth(batches.length - 1 - ownRow)`, a
different row whenever the list holds more than one), 13 control runs produced
**one red**: `Expected substring: "Undone: 2 notes and 1 patient removed."`,
`element(s) not found` — clicking the wrong row fails loudly. Both
perturbations were restored from the sandbox `tmp/` copy and verified with
`sha256sum -c`.

## AM-099 — the CI shape of the appearance lock

CI runs `npm run e2e` without `scripts/v2/sandbox.mjs`, so `APUNTA_DATA_DIR` is
unset and `appearanceLockPath()` threw before any lock-taking test could run.
The fix keeps the `APUNTA_DATA_DIR` path when the wrapper provided one and
otherwise uses `join(os.tmpdir(), 'apunta-e2e-appearance-' + e2ePort + '.lock')`,
where `e2ePort` is this file's existing `APUNTA_E2E_PORT ?? 7788` — the same
value `e2e/playwright.config.ts:16` computes. One path per run, shared by every
worker process of that run, and shared with no other run. `openSync(path,
'wx')`, the 20 s deadline, the 50 ms poll, the non-nesting guard, the pid in the
file and the `finally` release are all unchanged.
