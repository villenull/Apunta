1. **The pass on the base commit is the deliverable, not a missing failure.**
   The card says this twice, and it is worth saying plainly to whoever reads the
   diff: nothing in `Settings.tsx` changed, the three pre-existing cases still
   pass, and the four new ones passed the first time they ran. A green run here
   is what "the behaviour is shipped; the tests are the deliverable" looks like.
2. **The new assertions were checked for sensitivity, not just for green.** Four
   of the non-obvious ones were deliberately given the wrong expected value in
   the test's own expectation and each failed with the real observed value —
   the wrap (`[ { theme: 'system' } ]`, not `light`), focus moving to
   `theme-light`, the page painted `light` and never `system`, and `tabindex`
   moving to `0`. Reverted, then re-run: 7 passed. Table in
   `docs/v2/evidence/P1.2/v1-unit.md` §4. This is what a coverage-only card owes
   a reviewer; a test nobody has seen fail is not yet evidence.
3. **`data-theme` is asserted as the resolved theme in both environments, and the
   literal is asserted absent.** jsdom does not ask for dark, so System paints
   `light`; Playwright emulates a light OS, so it paints `light` there too. The
   unit cases say so in a comment where a future editor could otherwise "fix" an
   apparently wrong expectation, and the e2e additionally asserts
   `not.toHaveAttribute('data-theme', 'system')`.
4. **The wrap is the assertion most worth keeping.** `THEMES` is
   `system, light, dark`, so `ArrowRight` from Dark is System, and an
   implementation that clamped, reversed or appended would go to Light instead.
   The case comment says that, and the sensitivity run shows it is reachable.
