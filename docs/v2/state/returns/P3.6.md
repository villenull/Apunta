## Deviations

None that widen scope. Two things are worth stating plainly rather than as
tidiness:

- **Flow actions and their proof changed shape, not strength.** Six flows used to
  assert API facts that were already true before the action (`patients.length`,
  `plan !== null` on a `{ plan: null }` envelope, an always-200 `GET`, and a
  colour count for the Copied control). They now drive a real UI action and
  assert a **pane-only label** read offline by OCR plus the fact the action
  produced. A control whose label is not unique on screen is **not clicked**:
  the flow records `NOT RUN` with the count it saw. That makes some flows more
  likely to record `NOT RUN` than the previous version's always-true passes —
  which is the correct direction, and it is the reason no row is claimed here.
- **The rail's mission control is icon-only**, so the settings flow opens it with
  the app's own keyboard and then *verifies* the menu by its label before
  clicking. After six attempts with no label the flow is `NOT RUN`. This is a
  real limit of a screenshot-grounded harness with no observation hook.
