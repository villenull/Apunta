## What was built

**Capture renders a `Dialog` and nothing else.** No `Workspace`, no `Screen`, no
Back link. The panel is `modal card capture-modal`, so the shared scrim rule in
`app.css` dims and blurs the practice behind it — the blur is not restated in
`capture-modal.css`, which is the B4 invariant.

- **Header.** Heading text is the existing catalogue copy (`capture.newNoteFor`
  when the patient has loaded, `capture.newNote` otherwise) and the close
  control is the reserved `capture.closeLabel` ("Close new note"), styled like
  the add-patient and language × (bare glyph, no box). `showTitle={false}`, so
  the dialog is named by `aria-label` = the heading and the heading is rendered
  as the panel's own row.
- **C1 / disposition.** The outer `Dialog` is `open={blocker.state !== 'blocked'}`,
  so while the leave confirmation is up the capture panel ignores keys and is
  `aria-hidden`, and `ConfirmDialog` is a **sibling** of the panel — never inside
  the hidden ancestor. One Escape, one live modal.
- **C2.** `initialFocusRef` points at the `SpellLayer` textarea, so the caret
  lands in the summary rather than on the × that precedes it. `autoFocus` is gone
  (it would fight the `Dialog`'s own focus); the behaviour it provided is the
  same one, now by the mechanism `AddPatient` uses.
- **C3.** The missing-patient state is rendered inside the same `Dialog` (the
  error, `capture.missingPatient` and the `capture.backToPatients` link), so a
  patient who has gone away cannot put a second full page over the practice.
  Still no microphone.
- **C4 / disposition.** `close()` — the ×, `Dialog`'s Escape, and the missing
  patient link's route — pops with `navigate(-1)` only when **both** halves hold:
  a validated `backgroundLocation` (a `Location`-shaped object with a non-empty
  `pathname` that is not itself `/capture/…`) and in-app history
  (`window.history.state.idx > 0`, read as `AddPatient` reads it). Otherwise it
  leaves for `/?patient=<id>` with `replace: true`, so a URL typed into the
  address bar never walks out of the app even when the browser's own back stack
  is full. No path hides state to dodge the blocker: every exit is an ordinary
  navigation, so unfinished work still raises the confirmation, and browser
  Back/Forward go through the same `useBlocker`.
- **C5.** Both `PatientWelcome` links and `HomeLauncher`'s "Write a note"
  navigate with `state: { backgroundLocation }`. `PatientWelcome` passes its own
  `useLocation()` (the workspace's background location). `HomeLauncher` is the
  one entry point that is not already showing the chosen patient, so its
  background is that location with `search` set to `?patient=<id>` — the home
  pathname with the patient selected — and its own `hash`.
- **C6.** On unmount the capture retracts **only what it published**:
  `publishedRef` records whether this window set the recording and
  editor-unpersisted flags, and the cleanup clears each of those (beside the
  existing abort). A modal closing over a workspace that is merely sitting there
  therefore does not retract a recording or unsaved-text claim the note editor
  behind it owns. Residual, recorded rather than hidden: the reporter has one
  flag per fact, so if the workspace's editor is unpersisted *at the same
  moment* this window is discarded and leaves, the shared editor flag clears
  with it. No controller edit, no P5.3 repair, nothing else in
  `lib/maintenance.ts` touched.
- **Unchanged, deliberately.** Field/record/type/draft/retry/progress markup and
  test ids, the `beforeunload` guard, the recording guards, the in-flight abort,
  the transcription and refine behaviour, the `/?patient=id&note=<newid>` success
  `replace`, and the primary-window restrictions (all of which live in `App`).
- **CSS.** `capture-modal.css`: 560px panel, `max-height: calc(100vh - 2 *
  var(--space-24))` with `overflow-y: auto` and `overscroll-behavior: contain`,
  so the content scrolls at a short viewport and Create draft and the × stay
  reachable; the head row and its borderless ×. Imported by `Capture.tsx` alone.

`Capture.test.tsx` renders the route on its own — the three providers `App` puts
above the router, plus `/`, `/onboarding/format` and `/capture/:patientId`
routes and a stub for the workspace `AppRoutes` keeps mounted behind. Nothing
here expects a background; what is mounted behind the window is `App.test.tsx`'s
to assert. New/changed:

- the window is a `role="dialog"` named for the patient's note, the × is
  "Close new note", there is no `.back`, and the caret is in the summary;
- every field and option is still there (format chooser, Record audio, Type
  notes, Session summary) and Create draft keeps its disabled-until-there-is-
  something rule;
- × and Escape both close a clean window, landing on `/?patient=<id>`;
- **new**: with a validated background and in-app history, × pops to the entry
  the window was opened from (`search === ''`, where the fallback would have
  replaced with `?patient=…`), which is what keeps Back from reopening it;
- the leave confirmation is the only live modal — two `role="dialog"` elements,
  the capture panel `aria-hidden="true"`, the confirm not inside it, and one
  Escape on the confirm returns to the work with the text intact;
- browser Back is guarded exactly like the × (confirm, text intact, Discard →
  `/`), and Forward reopens an empty window;
- the rewritten dirty-navigation test uses the × (the Back link is gone) and
  asserts nothing was uploaded before the discard;
- recording, the 60-minute cap, the 30-minute warning, lost device, refused
  microphone, retry-after-transcription-failure, discard, the `Mac` timer
  sentence, the live dot/words/growth tests and the unload guard are unchanged
  and green. The record-to-note test now asserts the landing route carries
  `note=<the new id>` (the workspace is not in this harness).

Two test-mechanics notes, both deliberate: a blocked `router.navigate(-1)` stays
pending until she answers, so it is fired in a synchronous `act` and the
assertion waits (awaiting it inside `act` deadlocks the scope); and the in-app
history test stubs `window.history.state.idx`, because a memory router keeps
that counter in its own history rather than the browser's — the stub is restored
in a `finally`.
