## Deviations

Five, all disclosed in place, none of which changes an assertion, a threshold or
a result. **None of them is a behaviour change in the app.**

1. **`GDK_SCALE=1` for the AppImage child.** The desktop session this card runs
   in exports `GDK_SCALE=2`, and it reached the app through the environment. That
   made the shell read scale 2 off a plain 1400x1000 Xvfb screen, halve its
   window in CSS pixels (1330x950 physical = 665x475 logical) and push the very
   controls this card must click below the fold. The harness now launches the
   child with `GDK_SCALE=1` **and asserts the scale from the app's own stderr
   line** (`… at scale 1`), stopping if it is anything else. This is the test
   environment being stated, not the app being configured: nothing in `web/`,
   `server/` or `src-tauri/` changed, and no titlebar height is guessed anywhere —
   every rectangle is checked to lie inside the window before it is clicked, and a
   rectangle that does not is a stop with both numbers printed.
2. **The app's own first-run path is driven, not skipped.** A fresh run folder has
   no note format, and `Workspace.tsx:527-529` redirects to onboarding until one
   exists, so `reachHome` clicks the app's own **Continue** (which is what creates
   its standard format) and dismisses the add-patient dialog with a real Escape
   key press. The harness creates only the patient, through the API, as the card
   says. Without this the row would have asserted against an app state it skipped
   past.
3. **`console.info` was dropped from the hook.** The card lists it as a
   convenience channel, but `web/`'s own lint forbids every `console` method
   except `warn` and `error`, and I did not want to weaken a repo-wide rule for a
   convenience. The channel the harness *requires* — the same-origin `fetch`
   whose URL Fastify logs to the bundled server's stdout, which the shell
   re-emits to **stderr** — is unaffected and is the one every assertion reads.
   `document.title` was likewise not written to, because P3.4's harness asserts
   the exact window name `Apunta` and I may not edit P3.4's harness; writing the
   marker into the title would break it. So only one of the card's three delivery
   channels is in use, and the evidence says which.
4. **V2's literal command needed cargo on `PATH`** (above). One environment
   variable, the same pinned-`PATH` discipline V0 already uses.
5. **`docs/v2/state/OWNER-ACTIONS.md` was written**, beyond the four granted
   feature files, because the card's A03 stop condition names that file as the
   place the install command goes.
