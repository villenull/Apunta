## How an off-list query key is refused before contact, and an on-list one admitted

Both directions are asserted by counting the requests an injected `fetch`
received, because a refusal that happened *after* asking would look identical
from the error alone.

**Off-list, before contact.** `before a single request is made > refuses a query
carrying one name outside the list, naming it and not its value` requests
`https://huggingface.co/x/y.bin?Expires=1&extra=never-shown` with the speech
entry's ten names. The downloader throws `RequestRefusedError` with
`refusal: 'query_key_not_allowed'`, the recorded call list is `[]` — **zero
requests** — the message contains `extra` and does **not** contain
`never-shown`. The guard runs in `downloadWithResume` before the first
`fetchImpl` call (`download.ts:88`), and again on every `Location` before that hop
is requested (`download.ts:143`). The redirect shape is covered too: an off-list
name on a `Location` yields exactly one call, the initial one, with the
offending address in none of them.

**On-list, admitted and downloaded.** `downloading one speech file > admits the
enumerated query on a redirect, and completes the download` serves the real
pinned URL, answers `302` to the admitted CDN host carrying all ten enumerated
names, then the bytes. Two calls are recorded, the second is the signed address
byte for byte (`calls[1].url === signed`, and its query string is unchanged), the
body matches the entry's pinned `sha256`, the file is committed under the entry's
own name, and a receipt is written.

**The check is a name set, not a prefix.** `queryParameterNames` splits the raw
query on `&` and cuts each pair at its first `=`, so the text after that position
is never read, decoded or stored — a value cannot leak through it because it is
never materialised. Membership is exact and case-sensitive:
`refuses a name that differs only in case` fails `Sign`, `Signature2`, `Policy-`,
`expires`, `EXPIRES`, `X-Xet`; `admits every name the manifest enumerates` passes
all ten together. Any refusal message renders its URL through `safeUrl`, which
keeps scheme, host, port and path and replaces the query with `?<redacted>` —
asserted directly, including that a user-info password and a fragment value do
not survive. **No value is read, logged, recorded or compared anywhere**, and the
only place a `Location` is written out is the probe, which writes `<redacted>`
plus the names.

## Deviations

1. **`allowedQueryKeys` is on the two speech entries, not "empty for every entry
   but the six C-STT ones" — the literal reading is unimplementable, and it would
   have broken the product's only working download.** The card's Fixed decision 2
   says the field is "empty for every entry but the six C-STT ones", but the six
   C-STT candidates **are not catalogue entries** — `S4a.2` chooses one of them
   later — so there is no entry to hang a permission on. Meanwhile the two entries
   that *do* exist are the ones the probe proves present a signed query on all
   seven responses, and `ACQUISITION.md`'s own justification for the ten names
   says they were "observed across all six C-STT artifacts **and the one speech
   artifact**". Setting the speech entries' list empty would make
   `downloadWithResume` refuse the first hop of every real speech-model download —
   the exact outcome attempt 1's return named as unacceptable. So:
   `A07_ALLOWED_QUERY_KEYS` is a named constant holding the ten names verbatim,
   attached to `SPEECH_MODEL` and `PREVIEW_SPEECH_MODEL`, and
   `C_STT_CANDIDATE_ALLOWANCE` is named and admitted so that the candidate
   `S4a.2` picks is fetched under the guard that already exists. The
   catalogue test asserts the two speech entries carry the whole set and the
   union. **This is a reading, not a decision — flagging it for the reviewer
   because if the coordinator meant something else by that sentence, the fix is
   one line.**

2. **The request guard moved out of `catalog.ts`.** `assertAllowedHost` and
   `DisallowedHostError` are gone, and `assertRequestAllowed` in `readiness.ts`
   replaces them. Fixed decision 2 puts the refusal vocabulary in `readiness.ts`
   and step 4's order is "the union and the guard", so a guard in the catalogue
   could not speak those words. `ALLOWED_DOWNLOAD_HOSTS` stays exported in
   `catalog.ts`, now *derived* as the union so an admission cannot skip it, and it
   is a record rather than the guard's list — which is why a licence page on
   `ollama.com` is now in the union but not requestable, which is correct: Apunta
   shows that link and never opens it. The `AllowedDownloadHost` literal-union
   type is gone with it; nothing referenced it.

3. **Readiness never writes, so a restored file with no receipt is re-hashed on
   every probe.** Fixed decision 10 ("a run that only probes … writes nothing on
   disk") and C-ACQ@1 rule 5 ("or a fresh hash matches (then a receipt is
   written)") pull in opposite directions here. I took the card's explicit
   instruction: `assessModel` is read-only, and the receipt is written only by the
   step a Start press began. The cost is bounded and real — a file restored from a
   backup, correct size and correct digest but with no receipt is hashed on each
   launch instead of once, roughly a third of a second for 75 MiB — and it is
   asserted as intended in `assessing a model writes nothing`. If the reviewer
   prefers rule 5's letter, the change is to let `probeState` write the receipt it
   just earned, and one test changes with it.

4. **`sizeBytes: 77_704_715` is a transcription, not a measurement.** It comes
   from upstream's own `models/README.md` figure, quoted in the base's
   `approxBytes` comment. No machine in this project has measured the file, and
   this card is authorised to download nothing, so the pin is as good as the
   comment it replaces — and now load-bearing. A verified download whose size is
   not this number is refused with `size_mismatch` and no receipt is written,
   which is the signal that the **pin** is wrong. That is the shape of stop
   condition 5, and it is implemented; what is *not* implemented is detecting a
   **second** one: nothing in May edit can persist a failure count, and a run that
   counts would be a run that writes on a probe. Stop condition 5 therefore stays
