## What the change does, and what it deliberately does not

`queryKeyNames` decoded every parameter name with a bare `decodeURIComponent`.
A `Location` that parses as a URL but whose query name carries a malformed
percent escape therefore threw a `URIError` out of `describeLocation`, out of
`main()`'s bare loop, and out of the process — **before** the evidence file was
written, leaving the previous run's `redirects.md` on disk where it reads as
this run's record. A malformed name is now left exactly as it arrived, which
fails closed downstream (an unreadable name cannot be on an allow-list) and is
the pattern `queryParameterNames` in `installer/src/readiness.ts:116-134`
already ships and tests.

Not changed, and verified as unchanged: no contract, threshold, size guard,
checksum guard, host rule, query allowance or `ALLOWED` entry; no
`eslint.config.js` edit; no URL literal in `probe-redirects.mjs`; no new
dependency; no change at all in `installer/`, whose guard already fails closed
on this input. The evidence file format, the renderer, the entry-point guard and
the write order are all untouched.

regression detected only after the evidence file has been overwritten. I did not
