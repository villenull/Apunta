## Unresolved items

1. **The card's "one resolver" has two entry points in the server, one of them
   without a product caller.** `configuredModel(db)` is now a one-line call into
   `effectiveModel` and is what the generation path uses
   (`ai/index.ts` → `resolveModel` → `resolveLlmProfile` → `configuredModel`);
   `resolveEffectiveModel(db, options)` is the same resolver with the runtime
   asked as well, so it can return `present`, and it has **no production caller**
   — only its test. Wiring it into the generation path would mean a second
   `/api/tags` read per resolution (the 2 s cache would answer the second from
   the first, but the failure path would retry) for a `present` the generation
   path has no use for: `requireUsableModel` already produces the existing
   `model_missing` error. The health route cannot use it either, because it has
   to feed the resolver an injected list. So the honest statement is the one in
   the code comment: the tag is resolved once, by the resolver, and `installed:
   null` is the honest input for a caller that does not need the third field.
   P4.3 and Q1.1 are the named consumers of the full answer and should call it.

2. **The residual the card's rule cannot close**, stated in full because it is
