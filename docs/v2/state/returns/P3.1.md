## Deviations

**One, and it is an addition rather than a substitution.** The card fixes the
esbuild invocation as `--bundle --platform=node --format=esm --target=node24
--external:better-sqlite3 --outfile=…`. I pass **every one of those flags
exactly as fixed** and added `--banner:js=…`. Without it the bundle is broken:
an ESM bundle has no `require`, so esbuild's shim throws `Dynamic require of
"node:stream" is not supported` and the server dies at load time. The banner
only gives that shim a `require` to call, and adds no dependency and no network
access. **Without it the card's objective — a folder that runs the server — is
not met**, so this is reported rather than hidden. The diagnostic caught it;
see `diagnostic.md` §7.

Two smaller judgement calls, both disclosed:

- **The broken-copy launch uses the same `APUNTA_DATA_DIR` as the healthy one.**
  The card does not name a data folder for it. I chose the same one because
  that is what "start the bundled server again" says, and the healthy process
  is stopped (releasing its lock) and the port proven free before the second
  launch. A separate folder would have been marginally less coupled but would
  have stopped testing the lock-release path the first stop already exercises.
- **`whisper-cli`'s shared libraries go beside the binary** in `bin/`, not in a
  separate `lib/`. `CMAKE_BUILD_RPATH_USE_ORGN=ON` makes the binary look for
  them via `$ORIGIN`, which is its own folder. Unverifiable until a real binary
  exists; the script fails loudly if `--help` does not exit 0.
