## The two Windows behaviour changes, stated

Both are the table winning over two copies that had drifted. This card performs
**no migration** and touches no data folder (HS-1).

1. **The installer on Windows.** At the base commit
   `installer/src/cli.ts:35-41` had **no `win32` branch** — R13's exact wording
   — so a Windows install fell through to `XDG_DATA_HOME` or
   `<home>/.local/share/apunta`, the Linux-style path. After this card it gets
   the table's two rows: `<APPDATA>/Apunta` when `APPDATA` is set, and
   `<home>/AppData/Roaming/Apunta` when it is not. This is the defect, fixed.
2. **The server on Windows without `APPDATA`.** `config.ts:144` returned
   `<home>/Apunta`; it now returns `<home>/AppData/Roaming/Apunta`, the table's
   fourth row. The consequence is deliberate and **not silent**: an existing
   Windows install keeps its data in `<home>/Apunta` while the server looks in
   the new location. This card does not read, list, copy, rename or delete the
   old folder, and nothing in May edit could carry an honest migration.
   Carrying it over needs a separate card with its own owner action; this card
   neither creates that action nor decides it. C-PATH@1's Compatibility clause
   was not edited (HS-7).

The server's Linux and macOS results are unchanged, as the contract requires,
and its result on **this** host is byte-identical before and after
(`~/.local/share/apunta`), which is one of the three attribution proofs in
`v3.md`.

## The relative-override divergence, recorded

The function is pure and takes no working directory, so a **relative**
`APUNTA_DATA_DIR` is joined onto `home` rather than onto `process.cwd()`. The
contract's override row says `resolve(env.APUNTA_DATA_DIR)`; Fixed decisions
read that as "absolute, normalised, `/`-separated", which an already-normal
absolute value satisfies byte-identically — and every producer in this
repository, the sandbox, the e2e harness and the installer writes an absolute
path.

**No caller or test depends on cwd-relative resolution, so the card's stop
condition did not fire.** The two producers of an `APUNTA_DATA_DIR` override
that were checked: `installer/src/cli.ts:60`'s `--data-dir` flag keeps its own
`resolve(value)`, which resolves against the cwd exactly as before and is
**not** the platform default; and `server/src/test/harness.ts:44` uses
`mkdtempSync(join(tmpdir(), …))`, an absolute path. `server/src/config.ts`'s
`loadConfig` likewise keeps its own `resolve` at `:157-158`, so the override row
never runs on the server path at all.

Also recorded, from Fixed decisions, as decisions rather than accidents: a
literal `\` inside a POSIX filename is read as a separator (no producer in this
repository creates one), and an input consisting only of separators normalises
to an empty prefix — the one input class where "a non-empty input never
normalises to empty" does not hold (`home: '/'`). The ten rows pin every
observable result, and no producer writes either.
