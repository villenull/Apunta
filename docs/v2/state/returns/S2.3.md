## Deviations

1. **The home launcher's "New" row lost its `<strong>`.** It was
   `New: <strong>{query.trim()}</strong>`; it is now
   `t('home.newWith', { name: query.trim() })`, one string. Fixed decision 5
   requires the rendered line to be "the catalogue's English with the typed name
   in it", which is one key and one rendering — and inline emphasis is the one
   thing a single string cannot carry. The **text** is unchanged
   (`New: Jo` either way); only the bold on the typed name is gone, and no test
   or e2e asserted it. Recorded in the component's own doc comment. If the
   coordinator would rather keep the bold, the only clean way back is a
   stylesheet rule on the row, not a second key.
2. **`note.editedMeta` and `note.editedMetaToday` carry a leading ` · ` inside
   the catalogue value.** The two halves of the header line are two keys, and
   the separator is what joins them; putting it in the value is what makes
   `John Smith · created Aug 8, 2026 · edited Aug 8, 2026` come out byte for
   byte as `NoteView.tsx:624-631` did. The card's "Each sentence becomes one
   key" is read as each *half*, since the English is two template renderings.
   The card's own wording ("the two header sentences") is ambiguous here; this
   is the reading that keeps English unchanged, which is the rule the card
   leans on hardest.
3. **`ConfirmDialog`'s `cancelLabel` default became `t('common.cancel')`**
   instead of the literal `'Cancel'`. It was a user-visible literal in an owned
   file, so the objective takes it. The prop type is unchanged
   (`cancelLabel?: string`) and it is now read as `cancelLabel ?? t(...)` — a
   default parameter cannot call a hook, since defaults are evaluated before the
   body. No caller is affected: `BrainstormView`, `Capture` and `Workspace` pass
   `confirmLabel` and get the same English `Cancel` they always had.
4. **`note.unsavedConflict` and `note.unsavedError` were keyed.** The two
   `throw new Error(...)` in `NoteView`'s `flush` are not internal-only: the
   `flush()` promise rejects, `handlePublishToggle` catches it and calls
   `setError(errorMessage(thrown))` (`api/client.ts:120-124` returns
   `error.message` for a plain `Error`), and the editor paints it in its
   `note-error` line. Both sentences are in the S1.4 glossary
   (`conflict`, `saving / saved`). Untested for that path before; untouched now.
5. **`NoteView.tsx` gained a local `sameDay`.** Fixed decision 4 asks for the
   same-day test to be a local-date comparison over the ISO values the component
   already holds, "so no helper is added and no line of `format.ts` or
   `plural.ts` changes" — the helper is in the screen, not in the oracle, and
   both oracle files are byte-identical to the base commit. A value that is not
   a date falls to the `date`-kinded key, which renders it as it stands, exactly
   as `formatNoteDate` did.
6. **The catalogue comments' `file:line` citations were re-derived.** A
   `prettier --write` on `NoteView.tsx` (a nested ternary) moved every line in
   that file by two after the comments were written. All 57 keys' citations
   were then re-derived and checked by script against the real `t()` call site;
   every one resolves.
7. **`prettier --write` was run once**, on `web/src/components/NoteView.tsx`
   only, because `npm run lint`'s `prettier --check` failed on it. That is the
   lint's own remedy, not a change to any guard (HS-7).
8. **V1's count is 374, not the row's quoted 370.** The card names 370 as the
