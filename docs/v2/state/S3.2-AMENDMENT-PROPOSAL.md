## C5. Fixed decisions — replaces the whole section (closes IR-02, IR-03.1, IR-03.2, IR-06)

```markdown
## Fixed decisions

**FD1 — New flags, and what "unchanged" means.**
`--locale en|es-MX` (default `en`), `--mode provider|pipeline` (default
`provider`), `--blind-lexicon <negation|number|unit|medication|all>` (default:
none). `--blind-lexicon` is a **test-only negative control**: it empties that
lexicon for the run and changes nothing else. It is not a scoring option, not a
threshold, and not something any acceptance run passes.
Provider mode with no new flag behaves exactly as it does at the base commit:
same prompts, same corpus handling, same report. A test asserts that
`runEval({models, runs, fake}, no locale)` and the same call with
`locale: 'en'` produce identical reports.

**FD2 — Where the Spanish lexicons come from.**
Number words, units and medications: `docs/research/es-mx-clinical-glossary.json`,
filtered to `category ∈ {number, unit, medication}` — 51 + 8 + 93 = 152 entries,
verified present — using each entry's `es_mx` as the term. Nothing is read from
production guard code, and no new entry is added to that file.
Negation: the rule in §B-negation below. It is the one lexicon with no entry in
the glossary, and inventing one is a stop, not a decision (see Stop conditions).

**FD3 — `loadCorpus` must read a nested Spanish split root.**
`corpus.ts:77-79` reads `<dir>/expectations.json` and globs
`/^\d{2}-.*\.txt$/` **non-recursively**. The Spanish corpora S3.1 shipped are one
level deeper: `e2e/fixtures/eval-es/tuning/expectations.json` is keyed
`lost-negation/01-sin-dormir.txt`, with the transcripts in per-trap-type
directories. `loadCorpus` must therefore read the split root's
`expectations.json` and recurse **exactly one level** into the trap-type
directories, using the sidecar's keys as the relative paths. English flat
corpora keep working unchanged, and the existing `CorpusError` for a transcript
without an expectation is kept. This is a prerequisite recorded on S3.1; S3.2
owns the change because `server/src/eval/**` is its May edit.

**FD4 — Pipeline mode: the exact call sequence.**
Pipeline mode drives the HTTP surface; it does not call a provider. Per
invocation, once:

0. Refuse and exit 2 unless `APUNTA_CHECK_URL` is set, matches
   `^http://(127\.0\.0\.1|localhost)(:\d+)?$`, and its port is 7800–7889 and

   `fakeAi: false`, and a `testRunId` equal to `APUNTA_TEST_RUN_ID`

   failing is exit 2 before a single fixture is touched: a pipeline run against
   a fake or foreign server measures nothing and says so.
1. `POST /api/patients` **once per invocation**, `{"name": …}` — `John Smith`

   `e2e/fixtures/eval-es/NAMES.md` when `--locale es-MX`. One patient for the

   corpus, `{"name": …, "sections": [...], "locale": <run locale>}`, with

   (`server/src/ai/default-instructions.ts:659-666`), which is the same
   selection the provider path makes through `run.ts:78-84` — so both modes
   measure the same prompt. The runner asserts the created format's `sections`

3. Per fixture, per run: `POST /api/generate`
   `{"patient_id", "format_id", "title", "typed_notes" | "transcript"}`, with

   The note stays `draft`; the runner never calls

**FD5 — The error rule. One rule, no judgement.**
Any of the following is recorded through the existing
`failedNote(fixture, model, run, message)` (`score.ts:127-158`) with

`GET /api/notes/:id`; a `note.content` that is empty or whitespace; a
`textToSections` result whose every section body is empty; a `note.locale` that
does not equal the run's `--locale`. A failed run **counts**: one run in that
fixture's denominator, `safetyPassed: false`, printed per fixture with its
message verbatim. It is never retried inside the invocation, never dropped from
the min or the max, and never replaced by a re-run — a re-run is the next
invocation, in a fresh run folder, and its result stands on its own. Bounded:
four invocations per corpus, nothing repeats.
```

```
Controls are loaded **beside** the corpus, never inside it, and the rule is
stated so no implementer has to infer it:

- Controls are **scored outside the corpus denominators.** The report's existing
  "Corpus denominators per run" line counts corpus fixtures only; a control
  never appears in it, and a corpus run's percentages are unchanged by the
  presence or absence of controls.
- Controls get **their own table** in the report — `positive: n flagged of n`,
  `clean: n passed of n`, `degenerate: n failed of n` — each with its own
  denominator printed beside it.

  **never** in fabrication, safety, restraint or any aggregate, and never in
  `BASELINE.md`.
- **A missed control makes the run inadmissible**: exit non-zero, naming the
  control, in fake mode as well as real. C-EVAL@1 §3: "An instrument that
  misses a control is broken; nothing it scores counts."

  that class's real detection — the negation lexicon for negation, the
  sidecar-shaped gold for the rest — so blinding the lexicon (V3) blinds the
  control too. A control built from a different source than the thing it
  controls proves nothing.
```
