## 2. The cause, in the source, at line level

`resolveSandboxDataDir(env, runDataDir)` (`scripts/v2/sandbox.mjs:177-201`)
compares the proposed folder against
`platformDataDir(process.platform, process.env, homedir())` — computed from
`process.env`, not from its `env` argument — and refuses when they are equal or
nested. `platformDataDir` (`shared/src/platform-paths.ts:30-31`) returns
`APUNTA_DATA_DIR` **first**, before any platform branch.

The cell sources the tone env file earlier in the same `&&` chain, and that file
holds exactly seven exports (`printEnv`, `sandbox.mjs:299-310`; the bytes are on
disk at `/tmp/apunta-v2-p3.5-v4-tone.env` and quoted in evidence `01`). So the
second guard call inherited `APUNTA_DATA_DIR`, computed it as its own platform
default, and refused. The failure is in the **card's cell**, not in the source
under review. No source repair is proposed or needed.

and approving a row that is `BLOCKED` or `FAIL`, and §4 caps attempts; AM-194
fixed "no fifth attempt, counter reset, **row retry**, schema/threshold/Expected

- **`V4` itself already ran once** (exit 2, at 22:40:18). Executing its command

  provenance is a second execution of that row.

The distinction the owner is asked to rule on is narrow and stated so it can be

of that case, not a second of anything, and it changes no threshold, no
Expected cell, no contract and no source. `NOT RUN` for a case that never began
is not a PASS and is not converted into one here. The owner exception, if
granted, would read in the form of AM-192's: bounded to this one command and
this one re-evaluation inside attempt 4, overriding the row-retry clause for
these two cases only.
