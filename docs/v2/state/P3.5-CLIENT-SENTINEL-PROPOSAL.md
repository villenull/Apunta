## 1. The defect, verified against primary evidence

Attempt 3 stopped V3 and V4-tone at the same assertion, on the literal row both
read (`05-V3.txt:64`, `06-V4.txt:62`):

```
8043	8035	-	PipeWire	float32le 2ch 48000Hz
```

`classifySourceOutputs` (`scripts/v2/tauri-audio.test.mjs:300-312`) requires
columns 1–3 to be integers, so the third column's `-` ends the row. **What that
`-` is**, from the host's own `/usr/bin/pactl` (`libpulse 17.0+r98+gb096704c0-1`),
read three independent ways in `format-primary-evidence.md`:

| col | value | evidence |
| --- | --- | --- |
| `[0]` | source-output index | `*(u32*)(info+0x00)` |
| `[1]` | **source index** | `*(u32*)(info+0x18)`; pactl's own JSON member at `0x18` is `source` |
| `[2]` | **client index, or the literal `-` when the stream has no client** | `*(u32*)(info+0x14) == 0xffffffff ? "-" : decimal`, and pactl's JSON member at `0x14` is `client` |
| `[3]` | driver name (`PipeWire`) | `info+0xc8` = JSON member `driver` |
| `[4]` | sample specification | `pa_sample_spec_snprint` |

So the harness's column mapping is **correct**, and the `-` is pactl's own
sentinel for "this stream has no PulseAudio client" — the normal shape for the
playback stream this card's containment creates with `paplay --device=apunta_p35`.

**One correction to the attempt-3 record**: `05-V3.txt:23` says "column 3 is the
sink index, and `pactl` prints `-` when a stream has no sink". That label is
wrong — it is the client column, and there is no sink column in this format. The
stop cause and the fail-closed direction are unaffected; the stale label is left
in place, this card is not mine to edit.

## 2. The prepared patch (one function, one file)

Full text: `evidence/P3.5/client-sentinel-proposal/candidate.patch` (18 lines, one
hunk, headers `a/`/`b/scripts/v2/tauri-audio.test.mjs`). It applies to the
shipping file itself with `patch -p1`; the replayed result hashes `85fbb13d…`.
The added/removed text is:

```js
-    const clientId = Number(columns[2]);
-    if (![streamId, sourceId, clientId].every((value) => Number.isInteger(value))) {
+    // Only the literal `-` means "no client"; any other client-column value
+    // must still be a plain integer, exactly as before.
+    const clientId = columns[2] === '-' ? null : Number(columns[2]);
+    if (
+      ![streamId, sourceId].every((value) => Number.isInteger(value)) ||
+      (clientId !== null && !Number.isInteger(clientId))
+    ) {
       throw new Error(`non-numeric source-outputs column: ${JSON.stringify(raw)}`);
     }
```

Properties, each checked rather than asserted:

- **Only the literal `-` is accepted.** `-`, `--`, `-1`, `n/a`, `x`, `PipeWire`
  are all still refused; the tests cover each.
- **Numeric client behaviour is retained unchanged**, including `0`, `-1` and a
  float-shaped `167.0`, because `Number.isInteger` still gates it.
- **Stream and source columns stay strict integers**, and every source index must
  still resolve in `parseSourceTable`'s table or the row throws the existing
  unknown-source error. No row skipped, no table ignored, no catch added.
- **`clientId` is not a safety input.** It is written at `:309`, checked at
  `:310` and carried at `:319`; nothing else in the file reads it, and the
  containment assertions at `:1441-1466` use only `virtual`, `realMic`,
  `unrelated` and `raw`, so accepting `-` cannot loosen a safety decision.
- **Scope.** Everything before the edit and everything from the unknown-source
  guard onwards is byte-identical, so `parseSourceTable`, the guard and the
  grouping are untouched and no top-level function is added.
