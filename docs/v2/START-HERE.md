# Apunta v2: start here

This folder is the complete plan for Apunta v2: bug fixes, a Linux desktop
app (Tauri) with in-app updates, Mac and Windows configuration, and a
Mexican Spanish mode that stays hidden until every Spanish check, including
the owner's clinical review, has passed.

It is written for **Muse Code on the Linux PC**, which coordinates,
implements and reviews (decision D14). The plan is version 2; it replaces
the earlier `apunta-v2-orchestration` package entirely.

## 1. Put the plan in the repository

On the Linux PC, in the Apunta checkout, with a clean working tree on
`main`:

```sh
unzip ~/Downloads/apunta-v2-orchestration-v2.zip -d docs/
node docs/v2/tools/check-plan.mjs
```

The second command must print `Plan consistent: ...`. Card C0.1 commits
the folder on the new `feature/v2` branch.

## 2. Start the coordinator

Open Muse Code in the repository folder and give it this prompt:

> You are the coordinator for Apunta v2. Read `docs/v2/START-HERE.md`, then
> `docs/v2/COORDINATOR.md`, and follow `COORDINATOR.md` exactly, starting
> with card C0.1. Never cross `docs/v2/HARD-STOPS.md`. Never merge into
> `main`.

If Muse Code cannot start sub-sessions, the coordinator stops at each step
that needs one and writes `docs/v2/state/NEXT-SESSION.md` with the exact
prompt to paste into a fresh Muse Code session. Open a new session, paste
that prompt, and when it finishes, return to the coordinator session and
say "continue".

## 3. What the owner will be asked to do

The coordinator lists these in `docs/v2/state/OWNER-ACTIONS.md` when they
come up, and carries on with other work meanwhile:

- run one `sudo apt install ...` command for the Tauri build prerequisites
  (agents never type passwords);
- review Spanish notes for clinical meaning, using the pack in
  `docs/v2/owner/`, and write the verdict (only the owner may);
- at the end: review and merge `feature/v2`, back up the production update
  key, create the two GitHub secrets, decide on history cleanup and repository
  visibility, stop the v1 service before the first production launch of v2,
  and decide whether to release Spanish.

The live Apunta instance keeps running throughout. No agent may touch its
data or port 7717.

## 4. Contents

| File | Purpose |
| --- | --- |
| `COORDINATOR.md` | The coordinator's loop, authority, budgets, checkpoints |
| `HARD-STOPS.md` | Rules no session may cross; copied into every dispatch |
| `DECISIONS.md` | Owner and engineering decisions, owner-only actions |
| `CONTRACTS.md` | Versioned contracts every card relies on |
| `ACQUISITION.md` | Everything that may be downloaded; the licence policy |
| `RUN-CONFIG.md` | Ports, gate levels, the full test suite, evidence rules |
| `MILESTONES.md` | Parent milestones and their review cards |
| `DEPENDENCIES.md` | Dispatch order (generated by `tools/check-plan.mjs`) |
| `TRACEABILITY.md` | How each external review finding is handled |
| `cards/` | 63 small work cards |
| `templates/` | Instruction review, return, implementation review, checkpoint, final report |
| `tools/` | `check-plan.mjs` (consistency), `build-dispatch.mjs` (dispatch files) |
| `assets/` | Brand files for P2 and the Tauri icon set |
| `patches/` | The timezone test fix for P0.2 |
| `state/`, `evidence/`, `owner/` | Filled in as the work runs |
