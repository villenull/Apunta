## Interruption and recovery

The destructive span was wrapped in `restore()` under `trap restore EXIT INT
TERM`, and the aside path was printed **before** the `mv`:

```
aside=/tmp/opencode/p3.7-control/assets-aside before-files=19
```

So an interrupted run leaves the only copy at
`/tmp/opencode/p3.7-control/assets-aside`, and the recovery is the one line the
row prints on its own guard:

```sh
rm -rf build/linux-resources/web/dist/assets; mv /tmp/opencode/p3.7-control/assets-aside build/linux-resources/web/dist/assets
```

A resumed run refuses first if a prior aside exists or if the folder is missing.
It never `rm -rf`s a live aside and never rebuilds — the recovery is an `mv`
back, not a re-run of `scripts/v2/package-linux-resources.sh`, which is L3 work
and re-fetches A06 (Stop condition 3).
