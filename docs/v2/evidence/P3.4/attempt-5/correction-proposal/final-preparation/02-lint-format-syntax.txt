## 4. prettier — three modes, because two of them are vacuous

`.prettierignore` lists `docs/v2/evidence/` (line 11), so `npm run lint`'s
`prettier --check .` **skips this file by design**; its exit says nothing either way.

```
$ npx prettier --check docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs
Checking formatting...
All matched files use Prettier code style!
exit: 0   <- skipped by .prettierignore; VACUOUS
```

```
$ npx prettier --check --stdin-filepath docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs < docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs
exit: 0   <- still skipped (stdin-filepath inherits the ignore)
```

The only mode that actually applies the repo config to this file is a
**non-ignored** `--stdin-filepath`, because printWidth is 110:

```
$ npx prettier --check --stdin-filepath scripts/v2/tauri-security.test.mjs < docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs
exit: 1
```

```
$ npx prettier --ignore-path /dev/null --check docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs
[warn] docs/v2/evidence/P3.4/attempt-5/correction-proposal/review/probe.mjs
[warn] Code style issues found in the above file. Run Prettier with --write to fix.
exit: 1   <- ALSO VACUOUS, the other way: it silently drops .prettierrc.json
```

Note that the first mode reports clean and the third reports a violation, for the
same file — that disagreement is the tell that one of them is not looking at
anything. Modes 3 and 4 were also run on the BEFORE snapshot and return exactly
the same results, so the format delta is **pre-existing and untouched by this
pass**:

```
mode 4 on BEFORE snapshot: exit 1
mode 4 rewrite, diff lines BEFORE: 160   AFTER: 160   (unchanged by this pass)
```

**Decision, stated:** this pass does **not** reflow those lines. `docs/v2/evidence/`
is outside prettier's remit for this repo, the 26 lines over `printWidth: 110` are
pre-existing, and rewriting 160 lines of a file a reviewer must diff for semantic
fidelity is not a mechanical cleanup. eslint — which the repo *does* enforce on
docs/ — went 1 -> 0, and that is the only lint state this pass changed.
