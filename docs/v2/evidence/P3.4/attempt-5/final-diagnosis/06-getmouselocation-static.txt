3. libxdo.so.4 xdo_get_mouse_location2 (0x6930) static control flow:
   - loops screens; XQueryPointer(xdpy, root, &root_ret, &child, ...).
   - if child == 0 -> substitutes root_ret.
   - if child != 0 and child != root -> xdo_find_window_client(xdo, child,
     &client, 0), then possibly direction 1; may set child = 0 when the client
     resolution yields 0.
   - *window_ret = child.
   xdo_find_window_client (0x6740) walks the tree via XQueryTree looking for the
   WM_CLASS class hint (XInternAtom at .rodata b3d3; the adjacent rodata reads
   "XGetClassHint[WM_CLASS]").

   => WINDOW=0 can occur when the WM_CLASS client resolution fails. On a bare
   Xvfb with no window manager, over a non-client subwindow, this is a plausible
   false negative. The exact trigger in this run is NOT proven from the frozen
   evidence and is not claimed.
