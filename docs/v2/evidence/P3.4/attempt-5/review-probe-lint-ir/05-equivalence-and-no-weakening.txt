05 — output-transformation equivalence, and the no-weakening audit
==================================================================

The whole behavioral risk of this pass reduces to one substitution, applied
twice:

  console.log(EXPR)      ->   process.stdout.write(format('%s', EXPR) + '\n')

Node's own definitions, from the builtin source and semantics:

  console.log(x) with a single string argument x writes exactly
  formatWithOptions(inspectOptions, x) + '\n', and util.format's single-
  string short-circuit returns that argument verbatim. So
  console.log(x) === x + '\n' for any string x.
  format('%s', x) substitutes x into the specifier and returns String(x);
  x is the SUBSTITUTION ARGUMENT, not the format string, so any '%' sequence
  inside x is emitted literally and is never re-interpreted.

Equivalence tested empirically on pinned Node v24.19.0 over adversarial
strings, including the format-string hazards, the empty string, an embedded
newline, a leading newline (the summary line's case), non-ASCII, and a
300-char string:

  "", "plain", "a %s b", "%d%%", "100%", "ends with %", "multi\nline",
  "\nALL PASS", "éü", "x"*300 + "%j"

  single-string equivalence mismatches: 0 of 10

As a bonus, the real probe output contains no '%' character at all
(`grep -c '%'` on the capture -> 0), so no live path even reaches the
hazard. The two call sites were both string template literals, so both took
the single-string path in both versions.

Conclusion: the substitution is byte-total for the values this probe can
produce. Combined with 04 (stdout sha256 identical across four runs), the
pass's central claim — statuses and outputs byte-exact, verdict and status
unchanged — is established, not merely asserted.
