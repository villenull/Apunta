### `formatInstantAsDate` needed the module reloaded, not just the variable

The first attempt at that describe pinned `TZ` and still failed under Sydney:

```
FAIL  |web| src/lib/format.test.ts > formatInstantAsDate > reads an instant as the local day it fell on, with no "Today"
AssertionError: expected 'Aug 13, 2026' to be 'Aug 12, 2026' // Object.is equality
```

`web/src/lib/format.ts:20` builds `DATE_FORMAT` at module load, and an
`Intl.DateTimeFormat` keeps the zone it was *constructed* in — so a `TZ` set
in `beforeEach` arrives too late to affect a formatter built at import time.
Measured on this Node (24.19.0), under `TZ=Australia/Sydney`:

```
before Australia/Sydney Australia/Sydney Aug 13, 2026
after  America/Denver  America/Denver  Aug 12, 2026
old formatter still Aug 13, 2026
```

So the describe sets `TZ`, calls `vi.resetModules()` and re-imports
`./format.js` **under the pinned zone**. The assertion stays the literal
`'Aug 12, 2026'`. No production code changed, and this is not a test-only
trick: a formatter constructed in the user's zone formats in the user's zone,
which is the contract the production doc at `format.ts:97-100` states.

### The pins are load-bearing (mutation check)

Flipping all four pins from `America/Denver` to `Australia/Sydney` and
running the four files **under UTC** (`2026-09-26T08:09:0xZ`) reproduced the
original six failures exactly — 4 files failed, 6 failed | 44 passed (50).
So every pinned assertion still genuinely tests the local-day contract; none
of them passes by accident of the ambient zone. The pins were then restored
and the files verified byte-identical to the intended version.
