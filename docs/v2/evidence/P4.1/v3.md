## Two consequences of the May-edit boundary worth naming

1. **`checksum.ts` is not this card's to edit.** `verifyFile` checks a file's
   digests and does not return them, so `run.ts` cannot get the value its
   receipt needs from the call it already made. The cost is one extra
   `hashFile` of the committed file after a successful download — about a third
   of a second for 75 MiB, once, at the end of a download that just moved 75
   MiB. Weakening the two-digest check to avoid it would have been the wrong
   trade, and a note in the code says so.
2. **`plan.ts` imports the catalogue directly**, so a catalogue seam (letting
   tests supply a synthetic entry all the way to `buildPlan`) was not available.
   The synthetic-entry cases therefore drive `downloadSpeechFile` directly, which
   is exported for exactly that reason and is the same function the plan's
   `speech_model` step calls.
