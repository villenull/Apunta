## What this row is the only witness of

**The type-level catalogue parity.** `es-MX.ts`'s
`satisfies Record<MessageKey, Message>` against `MessageKey = keyof typeof en`
is a `tsc` error for a key added to `en` and forgotten in `es-MX`, and vitest
strips types so no test can see it. This card added **501** keys to `en`; a
forgotten one would be a non-zero exit here and nowhere else. The
`// @ts-expect-error` pair in `shared/src/i18n/t.test.ts:389` and `:403` — which
this card may not touch — proves the same rule from the other side, and an unused
`@ts-expect-error` is itself an error, so neither case can go vacuous.

**The two `kind` maps this card leaned on.** `tsc` also checks that every
`t()` call passes the parameters its entry names, in the shape
`MessageParams` allows. The 501 new entries between them declare `dateOnly`,
`date` and `number` parameters, and the screen code that fills them is all in
`web/src`. A `{day}` declared `dateOnly` and handed an ISO timestamp would
compile here and print the wrong thing in a browser.
