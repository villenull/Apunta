## What the two invariants this row exists for did

`shared/src/i18n` is in the filter because `t.test.ts` is the only runtime
witness of two things V4 cannot see. Both read the catalogues rather than a
written-out list, so the 501 keys this card added are covered the day they were
added:

- **`names the same placeholders in both, for every key either holds`** — for all
  573 keys, the `{name}` set of the `en` and `es-MX` entries is equal. A
  `settings.saved: 'Guardado como {name}'` against `'Saved as {title}'` fails
  here, four cards before S2.8's copy pass would have seen it.
- **`gives every counted key the plural floor its locale can select`** — every
  key with a `plural` map declares a `number` parameter to select on, and carries
  `one` and `other` in `en` and `one`, `many` and `other` in `es-MX`
  (`Intl.PluralRules('es-MX').resolvedOptions().pluralCategories` is exactly
  `many`, `one`, `other` on this box, ICU 78.3). It caught one real defect
  during the work: five `format.report*` keys were generated with
  `kind: { count: 'text' }`, which is a plural map with nothing to select on, and
  the case named the key.

`t.test.ts` also re-asserts S2.2's and S2.3's twenty-seven cases unchanged, and
the nine seed keys are still all there.
