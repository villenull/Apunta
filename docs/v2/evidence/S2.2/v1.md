## What attempt 2 changed, and what this row now proves about it

Attempt 1 was reviewed **FAIL** on one point, reproduced by the reviewer against
the built package with `VITEST` unset (the browser case): `t()` threw, in every
build, for a counted parameter that was a `string` (`{ count: '3' }` — which
Fixed decision 2's own `MessageParams` admits, which `tsc --strict` accepts, and
which both oracles Fixed decision 6 pins `notes.count` to produce, since
`noteCountLabel` (`format.ts:60`) and `plural` (`plural.ts:3`) both stringify the
count) and for a count `params` did not carry at all, where Fixed decision 7
requires the **English** string. `shared/src/i18n/t.ts` now:

- coerces the counted parameter with `Number(value)`, the same coercion
  `format()` already applied, and selects the plural category from the coerced
  number, so a string count is grouped and pluralised like any other;
- treats a value that will not coerce as the missing-value case rather than as a
  category, so it takes Fixed decision 7's third path: the same throw in a test
  build, and the **English** `other` form with the hole left empty everywhere
  else;
- documents all three of Fixed decision 7's paths in one place on `t()`, saying
  for each whether the test build throws.

Two cases were added to `t.test.ts` for it — `coerces a count that arrived as a
string, in a test build too` and `answers a missing count with the English
\`other\` form outside a test build` — which is why the count below is 29 and not
27. Neither weakens a case: the pre-existing test-build throw for
`t('notes.count', {}, 'en')` is untouched and still asserted.

The reviewer's own two reproductions, re-run against `shared/dist` with `VITEST`
unset after this repair (the browser build, where the old code crashed):

```
t('notes.count', { count: '3' }, 'en')      "3 notes"
t('notes.count', { count: '3' }, 'es-MX')   "3 notas"
t('notes.count', { count: '1000000' }, 'es-MX')  "1,000,000 notas"
t('notes.count', {}, 'en')                  " notes"
t('notes.count', {}, 'es-MX')               " notes"
t('notes.count', { count: 'three' }, 'en')  " notes"
t('backup.stale', { days: '7' }, 'en')      "No backup for over 7 days."
t('backup.stale', {}, 'es-MX')              "No backup for over  days."
t('brainstorm.empty', {}, 'en')             "Think out loud about  — this conversation is never written into their notes."
t('notes.count', { count: 3 }, 'en')        "3 notes"
```

A hole left empty is Fixed decision 7's own answer for a value a message names
and `params` does not carry — the same answer `t('brainstorm.empty', {}, 'en')`
has always given, and pinned since attempt 1 — and the alternative the old code
produced, a `NaN` in the middle of a sentence, is exactly what the decision
forbids. Nothing a screen shows is affected: the provider is still unmounted
(Fixed decision 10) and no existing component or string was edited.

## Note on the oracles

`web/src/lib/format.ts` and `web/src/lib/plural.ts` are the oracle for
"English output stays exactly as today" and are read-only for this card — no
line of either changed. `shared` may not import across packages
(`shared/tsconfig.typecheck.json` sets a `rootDir` that would refuse a file
outside it), so the four oracle expressions the tests need are transcribed into
`t.test.ts`, each with the file and line it was read at in a comment. The
card's seed table is the reviewer's check on those transcriptions.
