## Why this row had to run after the commit

The row's last step is `git diff --quiet -- shared/src/i18n/es-MX.ts`, which
compares the working tree against **HEAD**. Run against a dirty tree it fails for
the wrong reason: this card's own (correct) addition of 118 keys to that file is
itself a non-empty diff, so `git diff --quiet` would return 1 whatever the
perturbation did. The first attempt of this row, run before the card was
committed, returned **1** with the perturbed run correctly red — the
`git diff --quiet` step, not the perturbation. The row was then re-run against
the committed tree (`f33776c`), where it returns **0**, and that is the run
recorded here. The first attempt is described rather than discarded, because a
`1` from this row is a real signal and a reader should know which one it was.
