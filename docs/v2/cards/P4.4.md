## Objective
First launch shows setup inside the Tauri window, driven by the **existing**
installer protocol, then opens the app.

## Read
`installer/src/cli.ts` (lines 1-40); `installer/src/main.ts`;
`installer/src/protocol.ts`; `installer/src/resume.ts`; `shared/src/i18n/*`.

## May edit
`src-tauri/**` (setup page and relay); `src-tauri/setup-ui/**` (new, static
page); `installer/src/protocol.ts` (optional fields only) and tests;
`installer/src/run.ts` (error codes only); `scripts/v2/tauri-setup.test.mjs` (new).

## Must not edit
`server/`, `web/` (nothing there imports the installer; the existing test for
that must still pass).

## Fixed decisions
- Screens: Welcome (wordmark) → Language (English, and Español only when the
  test build has `APUNTA_DEV_SPANISH=1`) → What will be downloaded (files,
  publisher, licence, size, free space; effective model per C-MODEL) →
  Download (per-file and overall progress, verification state, Cancel) →
  Done. Nothing is downloaded before **Start** on the Download screen.
- The language choice is written to `<dataDir>/first-run.json`
  (`{ "language": "..." }`); the server applies it to settings on its first
  start and deletes the file.
- Error screens distinguish `runtime_missing` (Ollama not reachable: plain
  instructions, "Check again"), `model_unavailable`, `model_invalid`,
  `network_temporary`, `no_space`, `cancelled`. Mac-specific wording in
  installer errors becomes codes plus catalogue text.
- Cancel ends only the installer child's process group; exactly one terminal
  event is shown; relaunch resumes `.part` files deterministically.
- A fake installer mode (no network) drives the e2e.
