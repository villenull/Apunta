## Objective
The shell runs C-UPD@1's state machine; the web app shows the notice through
the server; release builds can contact only the production endpoint. **The native
window close request runs the same check as the browser close, enforced through
the server rather than re-derived natively: close is deferred while a save is in
flight, an active recording asks for confirmation, and unsaved text is never
discarded silently.**

## Fixed decisions
- Endpoint `https://github.com/villenull/Apunta/releases/latest/download/latest.json`,
  production public key only in the release config. Test endpoint and test
  key only under Cargo feature `test-updater`.
- Linux target: AppImage (E4); manifest key per the updater's
  `{os}-{arch}-{installer}` form (updater ≥ 2.10).
- Launch check after 30 s if the toggle is on; offline or failure is silent.
- The previous AppImage is kept beside the new one as `Apunta.previous.AppImage`
  for recovery mode.
- `check-release-config.mjs` fails if a release build's config or binary
  strings contain `127.0.0.1:78`, `127.0.0.1:789`, the test public key, or
  `dangerousInsecureTransportProtocol`.
- **The native close handler asks the server, it does not re-implement the rules.**
  On the shell's close request it sends the C-BRIDGE@1 rule-2 stdin
  `quiesce{}` — the same message and the same server entry point as
  `POST /api/app/quiesce` — and reads the `quiesce_result{ok, blockers[]}` line
  back, which is the only channel that carries the client `recording`,
  `conflict` and `save_error` blockers. On `ok:false` it asks first and reports
  what to finish; on `ok:true` it closes. It keeps **no** copy of the vocabulary,
  no local re-implementation of "what counts as a save in flight", and no
  second source of truth. `GET /api/app/quiesce/status` (P5.3's route) is
  available for observation and is the same in both modes; the route's shape is
  unchanged. Per the C-BRIDGE@1 rule-3 clause recorded in AM-202,
  `/api/app/quiesce*` is a **server-mode** route, not an updater endpoint, so it
  is available in browser mode too — the shell-only 404 still applies to the
  updater endpoints and is untouched.
