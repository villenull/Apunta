## Objective
The Language / Idioma row works under the dev switch, is disabled during
active work, and the core flows pass in both languages.

## Read
`web/src/routes/Settings.tsx`; `web/src/lib/i18n.tsx`;
`server/src/jobs/registry.ts`; `e2e/playwright.config.ts`.

## May edit
`web/src/routes/Settings.tsx` and test; `web/src/lib/i18n.tsx`; web
components that start jobs (to report active work to the control);
`server/src/routes/settings.ts` (409 rule); `e2e/playwright.config.ts` (a
second project `es-MX` that starts the server with `APUNTA_DEV_SPANISH=1`);
`e2e/tests/*.spec.ts` (language-aware assertions); `e2e/support/*` (a helper
`expectNoEnglishUi(page)`).

## Must not edit
Prompts; guards.

## Fixed decisions
- Row at the top of Settings, label "Language / Idioma", visible only when
  `spanishAvailable`. Applies without reload; updates `<html lang>`.
- Disabled while any job or save is active, with the reason text; server 409
  `language_change_blocked` as defence in depth.
- `expectNoEnglishUi`: collects visible text from elements whose text comes
  from catalogue keys (mark them with `data-i18n` in dev and test builds) and
  fails if any shows an English catalogue value that differs from the
  Spanish one. Patient content, model names, filenames and brand names are
  excluded by construction.
- Core flows in both projects: onboarding, capture, draft review, refine
  chat, publish and copy, patient list, treatment plan, briefing,
  brainstorm, settings, backup, imports (fake AI mode).
