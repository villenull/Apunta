## Fixed decisions
- C-REQ@1 in full, including the Sec-Fetch-Site and OPTIONS rules, the error
  code `forbidden_request`, the 403 body, and the log line (method, path and
  which rule failed, never the body). Nothing below relaxes any of it.
- **What `<port>` is.** The port the app is serving on: the bound port from
  `app.server.address()` while it is listening, otherwise the port it is
  configured with — `config.port` in the main app, and the value
  `serveBootError` passes on to `buildBootErrorApp`, which now takes it as a
  required argument. An injected request is not listening, so it is checked
  against the configured port; a request on a real socket is checked against
  the port actually bound, which is why the six existing route suites that
  already `listen({ port: 0 })` (`chat`, `generate`, `plans`, `prep`,
  `transcribe`, `brainstorm`) need no change. The whole of the harness change
  is that `APUNTA_PORT` becomes the port its injected requests present —
  light-my-request's default `Host: localhost:80` for a path-only URL — instead
  of `'0'`; `server/src/boot-error.test.ts` passes the same value to
  `buildBootErrorApp`; and the two route tests that build their own app
  (`server/src/routes/health.test.ts`, `server/src/routes/licenses.test.ts`,
  both `loadConfig({ APUNTA_PORT: '0' })` today) set `APUNTA_PORT` to their
  injected port the same way, so their path-only `inject` calls do not 403.
- **The dev allowances carry no flag.** `AppConfig` has no dev flag and
  `npm run dev` sets none, so the two "in dev" clauses are implemented as: the
  Vite host `127.0.0.1:5173` and the Vite origin `http://127.0.0.1:5173` are
  always allowed, and nothing else is. They are needed because the Vite proxy
  runs `changeOrigin: false`, so in `npm run dev` the browser's `Host` and
  `Origin` arrive as `:5173`. This does not open the guard to a web page: a
  page on any other origin still arrives as `Sec-Fetch-Site: cross-site` and is
  rejected.
- **The 403 is hand-built, never thrown.** The guard answers
  `reply.code(403).send(...)`. `buildBootErrorApp` registers no error handler,
  so a throw there would answer Fastify's default 500 envelope and break
  C-REQ@1's "403 on both servers". The body is exactly C-REQ@1's
  `{ "error": { "code": "forbidden_request" } }`, built the same way in both
  servers.
- **The body is the contract's, not `ApiErrorSchema`'s.**
  `forbidden_request` joins `ApiErrorCodeSchema` so the code lives in the one
  registry instead of being a bare literal, but the nested body is C-REQ@1's as
  written and does not validate as an `ApiErrorSchema`. Consequence, named here
  so it is not rediscovered: `web/src/api/client.ts` reports this one code as
  `internal_error`. Amending the contract is the owner's call under HS-7; this
  card does not touch `docs/v2/CONTRACTS.md`, and the mismatch is reported in
  the return file's "Unresolved items" for P3.4.
- **OPTIONS: the guard decides the reject side only.** A foreign origin is
  403. With an allowed origin, or with no `Origin` at all, the guard passes the
  request through — not 403 — and no response from either server carries an
  `access-control-allow-*` header (neither app registers a CORS plugin). Each
  server keeps its own answer for that request, main app 404 JSON and boot
  server 503 `storage_error`; unifying them is not this card's work.
- **Test isolation (HS-2):** V1/V2/V3 run bare, as in run configuration §3
  (which runs `npm test` bare). No Apunta server is launched, no platform data
  folder is opened and port 7717 is never contacted. The one listener this card
  adds is inside `server/src/test/real-socket-guard.test.ts`: it binds this
  card's sandbox port **7812** (C-ISO@1 rule 2's 7800-7889, assigned to P1.3),
  overridable through `APUNTA_PORT`, opens only a `mkdtemp` data dir of its own
  and closes its listener in `afterAll`. That row is **not** wrapped in
  `sandbox.mjs run`, whose ownership check (C-ISO@1 rule 5) assumes the wrapper
  started the server; record `none` in the return file's "Sandbox run IDs used".
  `npm test` also runs the six existing suites named above, which already bind
  an ephemeral port in their own tests; that is unchanged by this card.

## Steps
1. Tests first, naming the client per case, because no single client can
   express them all:
   - `app.inject`, with an explicit `host` header: `Origin: null`, malformed
     `Origin`, wrong port, a foreign `Origin` on a multipart route and on a
     JSON route, `Sec-Fetch-Site: cross-site`, OPTIONS from a foreign origin,
     and OPTIONS from an allowed origin and with no `Origin` (assert: not 403).
     Every response is checked for the 403 body and the code, and for the
     absence of any `access-control-allow-*` header.
   - `node:http.request` over a real listener for the foreign `Host` case.
     undici's `fetch` replaces a caller-supplied `Host` with the connection
     authority, so a `fetch` test of it would pass and prove nothing.
   - a raw `node:net` HTTP/1.0 request line for the missing `Host` case, which
     neither `fetch` (always sends one) nor `app.inject` (always defaults one)
     can produce.
   Drive the injected half through `buildApp` and `buildBootErrorApp`, and the
   real-socket half through `serveBootError` — it is the function that listens;
   `buildBootErrorApp` is the injected one. Give the real-socket file a
   `testTimeout`: `server/vitest.config.ts` sets none and vitest's default is
   five seconds. Record failures.
2. Implement; apply as `onRequest` in both servers.

## Stop conditions
The guard is not weakened to make a test pass — not by accepting a non-loopback
`Host`, not by skipping the `Sec-Fetch-Site` or OPTIONS rules, not by exempting
a path, a method or a test-environment flag from the check. A **test helper**
that must change so its requests present a conforming `Host` (or `Origin`) is
expected, is in scope as the Fixed decisions state, and is **not** a stop. Stop
and report only if a conforming change would require the guard to accept
something C-REQ@1 rejects, or if a rejection would have to be downgraded from
403 to keep an existing assertion true.
