## Objective
Measure on the tuning set, allow a bounded number of improvement cycles,
then run the held-out acceptance exactly as C-EVAL@1 specifies.

## Read
C-EVAL@1; `docs/v2/BASELINE.md`; `docs/eval-reports/*-es-mx-baseline.md`.

## May edit
`docs/eval-reports/<date>-es-mx-drafting.md` (new); `docs/v2/evidence/S5.6/**`.

## Must not edit
Any code. A tuning cycle's change is a separate small implementation card
(`S5.6.c1` to `S5.6.c3`) that the coordinator instantiates from the template
`S5.6-cycle` below and reviews like any other card.

## Fixed decisions
- **Tuning cycles: at most 3.** Each cycle changes one thing (one prompt
  section, one lexicon entry group, or one guard rule), is implemented as
  card `S5.6.cN` (May edit: the single file changed; Verification: the
  tuning run below plus L1), and is measured on `tuning/` only, 4
  invocations, pipeline mode. Record before and after.
- **Held-out acceptance: once**, after the cycles (a second run is allowed
  only after a further approved cycle, and never more than two held-out runs
  in total). Pipeline mode, `qwen3.5:4b-q4_K_M`, 4 invocations.
- Gemma 4 information run on `tuning/` only (A08; pull only if absent), not
  used for any decision (A2).
- English non-regression: pipeline runs on both English corpora, compared
  with BASELINE.md's min–max.
