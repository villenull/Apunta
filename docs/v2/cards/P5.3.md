## Objective
Unchanged. The server can enter maintenance mode safely: every long-running
writer is registered, new work is refused, active work drains, the editor
flushes, and conflicts refuse the transition. Window close uses the same rules —
the rules and the browser half are this card's; the native close request is
**P5.4's**, enforced by the amendment in P5.4's Verification row V6.

## Fixed decisions
1. **The flush channel is HTTP, with four named routes.** Named exactly, with
   method, path and body:
    - `GET /api/app/quiesce/wait` — held open by **every** window, from mount, with
      the query string `?tab=<tabId>`, where `tabId` is the per-tab identity the
      reporter generates once and keeps in `sessionStorage` (FD13's re-register
      key), absent on the very first request only if `sessionStorage` is
      unavailable, in which case the window registers under a fresh
      per-connection id and therefore never supersedes a retained record. On
      quiesce entry it answers `200 {"request":"flush","quiesceId":"<uuidv7>"}`;
      otherwise it stays open until the server resolves it. **The query string is
      the only thing that carries the tab identity, and it is the one
      non-`{quiesceId}` value the channel sends**; the report body stays exactly
      as FD8 has it, because `tabId` rides the registration that the report is
      matched against.
   - `POST /api/app/quiesce/report` — body
     `{"quiesceId":"<id>","ok":boolean,"blockers":["conflict"|"save_error"|"recording"]}`.
   - `POST /api/app/quiesce` — body `{}`; starts a quiesce, returns
     `200 {"quiesceId":"<id>","ok":boolean,"blockers":[…]}` when it settles. It is
     the **same exported entry point** the shell's `quiesce{}` case calls: one
     function, two callers, not a test-only switch and not a fault-injection
     flag.
   - `GET /api/app/quiesce/status` — a **read-only sibling**, →
     `{"quiescing":boolean,"activeJobs":[{"kind"}],"windows":number,"maintenance":boolean}`.
     `windows` counts **live registered windows** (windows with a wait bound in
     the current quiesce); a retained-but-disconnected record of FD13 is not one,
     because it holds no wait. It exists because FD6 hands it to P5.4 and the
     browser rows need to wait for a precondition instead of assuming a timing.
   **Authorization (AM-202, Choice 1 A2(iii)):** `POST /api/app/quiesce` is
   **ungated in browser mode** — it is a server-mode route, not an updater
   endpoint, and C-BRIDGE@1 rule 3 carries the clause saying so. In browser mode
   a successful quiesce holds maintenance while **at least one window is
   registered**, and the last unregistration (socket close, page unload, hook
   teardown) releases it. In shell mode maintenance stays on through the
   snapshot and is released by the shell's next transition. C-REQ@1's guard is
   unchanged and still runs first on every one of these routes.
   There is **no** SSE event for this, **no** `BroadcastChannel` message
   (C-BRIDGE@1 rule 3: the page talks only to the server over HTTP) and **no**
   new browser API. A `quiesceId` is minted at quiesce entry (UUIDv7, the
   repository convention) and is the **only** thing that ties a report to a
   quiesce.
2. **Registration, reporting, and the client transport's whole lifecycle.**
   - **(a) Registration is the held-open `GET /api/app/quiesce/wait`.** Every
     window that mounts the reporter registers, *including* a window with no
     editor; such a window answers `ok` immediately once asked, **holding the
     request open until it is asked** — a window that does not hold a request
     open is invisible to the server, and "no editor" would become "no window".
   - **(b) Every window with an editor registers and reports**, primary or not.
     "The primary window is the only reporter" is **deleted**: the reporter is
     mounted once per window by a plain module call in `main.tsx`, outside
     `App.tsx`'s primary logic, and it cannot read `usePrimaryWindow`'s phase
     without editing `App.tsx`, which is in Must-not-edit. The stronger rule loses
     nothing — a covered secondary window is `inert` (`App.tsx:67-91`) and can hold
     neither unsaved text nor a microphone — and it is strictly safer.
   - **(c) A report is applied only when its `quiesceId` equals the in-flight
     quiesce's id *and* that window has a registered wait in the current
     quiesce.** Anything else — a stale id, a spoofed id, a report from a window
     that is not registered, a report for a quiesce that already settled — is
     **refused with 409, counted, and never applied**. Without this, the ignored
     report from a timed-out quiesce satisfies the next one and the text it was
     protecting is lost with both rows green.
   - **(d) A closed socket removes that window's wait** and starts the retained
     record FD13 describes; it does **not** discharge what the window held. If
     the registered set is empty at the deadline **and** no retained record
     carries an unpersisted obligation, the quiesce returns `ok:false` with
     blocker `no_response`: **a disconnect is never read as `ok`**.
   - **(e) "No browser attached at all" is a named state, distinct from a
     disconnect**: the set has been empty since entry (shell up, window not yet
     loaded). It also returns `ok:false` with `no_response`. Both cases get a V1
     case.
   - **(f) Transport lifecycle.** The reporter holds **exactly one** long-poll,
     armed with an `AbortController`, aborted on `pagehide`, after a report is
     sent, and when the server resolves it at the deadline; it re-arms immediately
     after each of those. It **never** reuses, wraps or aborts the SSE reader in
     `web/src/api/sse.ts`. It calls `window.__apuntaFlushBeforeRelease` **if it is
     a function** and reports `ok` when it is not (that hook is deleted by its own
     owner cleanup, `NoteView.tsx:356`), so the reporter cannot throw on a
     torn-down editor. Nothing else kills it for it: `web/src/api/client.ts:45-58`
     applies no global timeout.
   - **A window that has not answered when the budget ends is a blocker named
     `no_response` and is never read as `ok`; a window that answers after the
     deadline is refused under (c).**
3. **One deadline, two concurrent phases.** The deadline is measured from the
   instant the quiesce begins — `deadline = now() + DRAIN_MS` — and the two
   phases run **concurrently**: the flush request is answered to every registered
   window **at entry**, not after the drain, and the drain runs alongside it. Each
   phase gets `deadline − elapsed`; the two phases never extend the budget between
   them. Sequencing the report phase *after* the drain would let a drain that
   consumed the whole 30 s end the quiesce before any window was ever asked to
   flush — the editor's unsaved text unrequested, no conflict ever detected, and
   `no_response` unable to fire because nobody had been asked. The drain's own
   exit is FD4's rule; the deadline resolves **every** outstanding wait at its
   end, so no request is left hanging past the budget.
4. **The drain's entry rule and its bound.** `DRAIN_MS = 30_000`, module-internal,
   **not exported**, not read from `process.env`, not in any request body, not
   settable by a caller or a route. The quiesce snapshots `active()` at entry; a
   non-empty snapshot returns `ok:false` at once with the still-active kinds as
   blockers and never enters the drain; an empty snapshot runs the drain — so a
   job already past the refusal hook still gets to finish — under the same bound,
   returning success when the registry empties and failure with the still-active
   kinds as blockers when the bound is reached. It never returns `ok:true` on a
   timeout and never waits past the bound. The clock seam is an options object on
   `buildApp` in the house style of `CreateBackupOptions.now`
   (`server/src/backup/archive.ts:73,82`) — `{ now?: () => number; sleep?: (ms)
   => Promise<void> }` — with production passing **nothing**, so a unit test drives
   the boundary in milliseconds and no 30-second test exists. The contract
   sentence "waits up to 30 s" (`CONTRACTS.md:386`) is an **upper bound**, and
   this entry rule is the approved reading of it.
5. **Maintenance mode is left on every failure path, and re-entry is
   idempotent.** A quiesce that fails — an active job, a client `conflict`, a
   `save_error`, a `no_response`, a retained unpersisted obligation — returns
   `ok:false` **and puts the server back into normal service in a `finally`**, so
   the next request is not a 503 until restart. A second `quiesce` while one is in
   flight **joins** the first and returns its result; it does not nest, and no
   state is left set. A quiesce that succeeds leaves maintenance **on** in shell
   mode, because the next contract step (the snapshot) must not be able to write
   either; in browser mode it is held while at least one window is registered and
   released when the last one unregisters, per FD1.
6. **The close policy: the rules, the browser half here, the native owner named.**
   The three rules are normative and are not reworded (`CONTRACTS.md:390-392`):
   close is deferred while a save is in flight; an active recording asks for
   confirmation; unsaved text is never discarded silently. The browser half is
   **built here**, in two places:
   - `web/src/routes/Capture.tsx:157-167` already refuses an unload while
     `unfinished` is true (`text || recording !== 'idle' || wav || busy`,
     `:150`) — verified, not built;
   - `web/src/components/NoteView.tsx` gains the matching `beforeunload` guard on
     the screen where the note text actually lives, because **nothing there
     guards it today**: `NoteView.tsx:339-361` is a best-effort flush on
     `pagehide`/`visibilitychange`, and no draft of the note text is stored
     anywhere in `web/src`. The condition is "the editor holds text the server has
     not acknowledged" — `latestTextRef.current !== persistedContentRef.current ||
     saveStateRef.current === 'saving' || saveStateRef.current === 'error'`. The
     existing `__apuntaFlushBeforeRelease` hook stays the flush interface and is
     not edited.

   The **native** close request is a Tauri window event, so it belongs to
   **P5.4**, which already holds `src-tauri/**` and already depends on this card.
   P5.4's fixed decision runs the bridge `quiesce{}` and reads
   `quiesce_result{ok, blockers[]}` — which is the only channel that carries the
   client `recording` / `conflict` / `save_error` blockers — and is verified by
   P5.4's V6. This card creates no `src-tauri/**` and adds no rule of its own.

8. **The client report has a status and a blocker list.** The body is
   `{"quiesceId":…,"ok":boolean,"blockers":[…]}` with `blockers ⊆ {conflict,
   save_error, recording}` and `ok:true` requiring an empty list. The three map
   exactly onto the three outcomes `NoteView.flush()` already has (`:321-326`):

13. **A disconnected window's record is retained, and its unpersisted obligation
    keeps counting.** This is the production data-loss gap the protocol proof named
    and did not close (`state/reviews/P5.3-protocol-proof-v3.md` §2 (1), §5 (9),
    §7's last-but-one row): deleting the record on a socket close deletes every
    obligation on it, so a **dirty disconnect before a quiesce** could settle
    `ok:true` over typed content that was never persisted, and a reconnect — which
    arrives under a new instance identity — recovers nothing. The rules:
    - **(a) A closed socket marks the record, it does not delete it.** The window's
      entry stays, with a `disconnectedAt` stamp and everything it held. Only the
      live wait is removed, which is what FD2(d) already does.
    - **(b) "Unpersisted" ranges over disconnected-but-present records.** A
      window's obligation is **unresolved until it has reported `ok` for a
      quiesce that flushed cleanly** — the reporter's own signal, never a
      server-side guess: the registry carries `{kind, id}` with no window↔note
      association, and outside a quiesce the client tells the server nothing. So a
      socket close marks the record **unresolved** (FD13(a)), a quiesce report of
      `ok` with an empty blocker list resolves it (FD2(c)/(d), FD8), and **an
      unresolved obligation is a blocker on every later quiesce**. This is the
      fail-closed reading: a window that disconnects for any reason, dirty or
      not, keeps the obligation until that same tab registers again and answers,
      and nothing is asserted about content the server never held. **A quiesce
      can never settle `ok:true` while any retained record carries one** — including
      the case that motivates this row: a dirty primary window disconnects while
      an inert secondary stays registered and answers `ok`, so the quiesce is
      refused rather than settled over the primary's lost text.
    - **(c) A re-register supersedes it.** When a window registers again, the
      retained record is superseded by the new registration and stops counting;
      the store is **not** back-filled and the lost content is **not** claimed to
      be recovered — recovery is out of scope and nothing here asserts it.
    - **(c2) A report of `ok` resolves it.** A retained record's obligation is
      cleared by a clean report from the same tab identity, which is the
      ordinary case: a tab whose poll dropped re-registers and reports its real
      state, so nothing is settled over it and nothing is refused over text that
      is already on disk.
    - **(d) A retained record is invisible to the registered set.** It holds no
      wait, so it is never asked, never reported for, and never counted in the
      status route's `windows` (FD1); it can only ever contribute a blocker.
    - **(e) Nothing here is a threshold.** No TTL, cap or age evicts a retained
      record, because no repository fact supplies one and inventing one would be
      inventing a bound (HS-7). Records are in-process only and do not survive a
      restart, exactly like the registry itself (`registry.ts:9-13`).

    **Coordinator decisions on FD13, 2026-10-04 (AM-205 follow-through; recorded
    in `state/P5.3-APPLIED-CHANGELOG.md`).**
    - **Eviction:** none. FD13(e) stands: no TTL, cap or age; a retained record
      blocks `ok:true` until a re-register supersedes it or the process restarts.
      This is the fail-closed direction AM-205 asked for, and no number is invented.
    - **Blocker name:** reuse `no_response` — the existing server-side word, no
      contract change and no vocabulary widening. V1 and V9 assert it by name.
    - **Re-register key:** a per-tab identity the reporter keeps in
      `sessionStorage` (generated once per tab, so it survives a same-tab reload
      and is distinct across tabs and windows). A registration carrying the same
      tab identity supersedes the retained record. Why: the case worth protecting
      is a tab still alive whose long-poll dropped — it re-registers from the same
      tab with its text still in memory and then reports its real state (dirty →
      `conflict`/`save_error` or a flush), so nothing is settled over it. A
      reloaded tab has already lost its unsaved text, so continuing to refuse
      protects nothing recoverable. A different tab never supersedes another
      tab's record. V9 asserts both: a different tab's registration does **not**
      supersede, the same tab identity does.
