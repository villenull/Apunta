## Fixed decisions

**1 — Exit codes report harness integrity, never a flag count.**
The two scripts' only non-zero exits today are pre-flight refusals
(`check-note-format.mjs:46,52,157,164,172`; `check-refine.mjs:38,50,66,210`),
and flags are counted and printed (`:200,212`; `:214,423,433`) while the
process falls off the end with status 0. So a row asserting "exit 0" asserts
something the tool cannot report otherwise. This card keeps that meaning and
adds the codes that make it falsifiable, with **three distinct codes**:

- `0` — the run exercised what it claimed and printed its measurement. **A
  non-zero flag count is still exit 0**: a flag is a prompt to read the note,
  not a verdict, and the scripts say so in their own words. Gating on flags
  would make this card's own baseline unrecordable.
- `2` — pre-flight refusal, unchanged: unknown flag, unknown locale, no server,
  a non-loopback `APUNTA_CHECK_URL`, fake AI, missing format or patient.
- `3` — **an assertion about the run was not met**: `--expect-fixtures N` /
  `--expect-scenarios N` where the number of fixtures actually read or
  scenarios actually run is not `N`.
- `4` — **a control did not fire**: `--self-test` fed a pinned Spanish or
  English control through the rule functions and the expected named flag did
  not appear.

`3` and `4` are what make "ran zero scenarios" distinguishable from "ran them
all and passed", and both are reachable by a broken Spanish path. They are
**not relaxed to make a row green** (HS-7): a row that wants them gone is a
report, not a fix.

**2 — `--locale` is parsed, consumed, and falsifiable.**
Today `--locale` is inert in both scripts, and in `check-refine.mjs` it is
worse: `check-refine.mjs:62` is
`new Set(process.argv.slice(2).filter((arg) => arg !== '--only'))`, so **every**
argument except the literal `--only` enters `only`, and `:239`'s
`if (only.size > 0 && !only.has(scenario.id)) continue;` then skips every
scenario — `-- --locale es-MX` runs **zero** scenarios and exits 0. That is a
vacuous green and it is the reason V2 as previously written could not fail.

So `process.argv` is parsed into exactly this flag set, and nothing else:

- `--locale <tag>` — `en` or `es-MX` only. **Consumed**: it is removed from
  the positional set and never reaches `only`. It selects the fixture tree
  (`e2e/fixtures/her-format-es/`, `e2e/fixtures/refine-es/`) and that locale's
  section names. Any other tag exits 2.
- `--only <id>` — the value that **follows** `--only` is the scenario filter,
  and `--only` itself contributes nothing to the set. An unknown id, or
  `--only` with no value, exits 2.
- `--expect-fixtures N`, `--expect-scenarios N` — exit 3 on a mismatch.
- `--print-rules` — print the rules JSON and exit 0 **before any HTTP call**.
- `--self-test` — run the pinned controls and exit 4 on a control that does not
  fire.

Any other token — including a bare positional argument — exits 2, **before any
HTTP call**, so with no server up the refusal is exit 2 and never a fetch
failure. Each of the three properties is separately checkable and each has its
own row: consumption (V2, V8), tree selection (V1, V2, V7), refusal (V6).

**3 — "Unicode-aware" names all four sites, by line, at `92f0d7e`.**
The previous decision covered one line and left three neighbours ASCII, which is
a claim that reads as coverage and is not:

- `wordCount` — `check-refine.mjs:119-124`, the split `/[^a-z0-9]+/` at `:122`,
  which fragments every accented Spanish word. `shortens` (`:383`),
  `changed`/`unchanged` (`:387`,`:390`) and `claimProblems`' "did anything
  grow" (`:146-150`) all read that count.
- `exampleSentences` — `check-note-format.mjs:104`, the ASCII regex
  `/"[A-Z][A-Za-z ]+":\s*"([^"]{25,})"/g`. Spanish headings make the
  borrowed-sentence list **empty**, so the "wording copied from the worked
  example" flag can never fire in Spanish.
- The English section constants and the flag rules —
  `check-note-format.mjs:122-126` (`at('Client presentation')`,
  `at('Discussion')`, `at('Note for next session')`, `at('Risk review')`) with
  `risk === 'None.'` at `:138`, and the rule regexes at `:129`, `:135`,
  `:138`. With an empty `found` every `at()` is `''` and both the "Discussion
  empty" and the "risk flattened" rules fire on every fixture. The rules become
  **table-driven over the locale's section names**: `at()` takes a name per
  locale and the empty-risk sentinel has a per-locale value.
- The hard-coded fixture list — `check-refine.mjs:223`'s
  `['scenarios.json', 'owner-progress.json']` and the directory at `:224`, which
  makes `refine-es/` unreachable without an edit the old card did not name.
- (Same regex, named for completeness: `sectionsOf`'s heading match at
  `check-refine.mjs:107` and `splitSections`' at
  `check-note-format.mjs:81` — one heading pattern in two scripts.)

**4 — No production fact logic in `check-refine.mjs`, and `keeps` is judged by a
named lexicon.** There are **two** production imports, not one, and the old
decision named only the first: `factTokens` from `server/dist/ai/fact-guard.js`
at `check-refine.mjs:48`, and `lostWords` from `server/dist/ai/refine-request.js`
at `:193`. **Both are removed**, and after this card the script imports nothing
from `server/dist/ai/` (its fallback is silent: `lostWords === null` prints one
line and skips the check, so a missing build reads as a pass). The replacement
is the scorer's locale lexicon, imported as
`loadLocaleLexicon('es-MX')` from `server/src/eval/lexicon.ts` reached through
`server/dist/eval/lexicon.js`, with `availableLexicons('es-MX')` naming what
exists; `namedLexiconTerms(locale, name)` is used where one category is needed.
`stillHas` (`:54-60`) and `losses` (`:198-201`) are reimplemented in the check
script over that term list, in both cases, for each locale.

`keeps` is judged against **all five named lexicons for the locale**
(`clinical`, `negation`, `number`, `unit`, `medication` — the union of
`availableLexicons(locale)`), not one of them, so a `keeps` phrase of numbers,
negations, units, medications and clinical terms is judged whole.

**The empty-vocabulary case is a reported outcome, not a loss.** Today
`stillHas` returns `false` when a phrase yields no fact tokens (`:57`), so "no
tokens" silently means "the fact was lost". After this card a phrase with no
lexicon term is printed as a named line —
`· no <locale> lexicon term in "<phrase>" — not judged` — and is **excluded from
the loss count and from the problem count**, and the summary prints
`K phrase(s) with no lexicon term (unjudged)`. Same for `losses`: a section
with no lexicon term reports nothing and contributes no problem. A wrong
vocabulary therefore shows up as a **reported** row of unjudged phrases, which
is visible, instead of a fabricated defect rate the baseline would freeze.

**5 — The baseline report has a fixed, checkable shape.** V5 asserts it
mechanically rather than trusting a sentence. `docs/eval-reports/<date>-es-mx-baseline.md`
carries, in this order: the **identity block** required by C-EVAL@1 rule 7 —
the literal lines `GET /api/health → ollama.tag` and `GET /api/health →
ollama.model` with their values, the git commit, and `GET /api/settings →
language: en` and the format's `sections` and `locale: es-MX`; the phrase
`4 invocations`; and, for every case, a `min` and a `max` across those 4
(C-EVAL@1 rule 6). The statement
`English-prompted pipeline, Spanish tuning fixtures` appears verbatim, with the
sentence that this is the "before" and not a Spanish measurement. Model tag
`qwen3.5:4b-q4_K_M`. Tuning splits only; held-out is not run (C-EVAL@1 rule 2).

The **Rates** section is the **last** thing in the file, its heading is the
literal line `## Rates`, and **every non-blank line after that heading begins
`<n>/<d> `** — no prose, no sub-headings, no table. **No percentage may appear
anywhere in the file except on one of those lines.** This is the shape that
makes "with numerators and denominators" an assertion rather than a hope: it is
checked *per rate* by counting, so a report that gives two rates and then drops
one denominator is red, which a `grep` for the word "rate" would not catch.

**6 — English is pinned by constants; model output is not compared.**
V3 diffs a deterministic `--print-rules` JSON, anchored on `{{BASE}}`, and
states plainly what it does not do: **no English model output is compared, here
or anywhere in this card**, because both scripts drive a live LLM
(`check-note-format.mjs:188`, `check-refine.mjs:283`) and its output is not
reproducible. A row that compared it would go red for temperature. What is
compared is the English *rule surface* — the section-name list, the flag-rule
sources, `CLAIM_VERBS`, `SERVER_OPENINGS`, the borrowed-sentence extractor, the
fixture filter, the heading pattern and the word-count split — against the
literal values recorded in `docs/v2/evidence/S3.3/english-rules.json`, **and**
every literal in that file is proved byte-present in the base-commit sources by
`git show {{BASE}}:`. A pin that does not match the base is a stop, never a
rewritten pin.
