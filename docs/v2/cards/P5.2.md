## Objective
Implement the migration section of C-UPD@1: inspect without migrating,
snapshot, migrate all-or-nothing, refuse newer schemas.

## Read
`server/src/index.ts` (lines 18-40); `server/src/db/index.ts` (lines 47-58);
`server/src/db/migrate.ts` (lines 70-100); `server/src/backup/restore.ts`.

## May edit
`server/src/db/index.ts`, `migrate.ts` and tests; `server/src/index.ts`
(ordering); `server/src/db/safety.ts` (new) and test.

## Must not edit
Existing migration SQL files.

## Fixed decisions
C-UPD@1 migration steps 1 to 5 and decision E8. Error codes
`newer_schema`, `snapshot_failed`, `migration_failed` map to the boot-error
page (bilingual, S2.5).

## Steps
Tests first with synthetic v5, v6 and v7 databases (WAL, representative
formats, settings, notes): pending restore then snapshot then migrate;
snapshot failure (read-only safety folder) leaves schema unchanged; a
deliberately failing second migration rolls back the first; a database with
a schema version above the code's → `newer_schema`, untouched; the safety
snapshot restores to a working database; retention keeps 3.

## Stop conditions
A migration file cannot run inside an outer transaction (for example it
uses `VACUUM` or toggles `journal_mode`): report the file; do not edit it.
