  literal in one file, not a widening of the rule that governs the tree. **And
  no URL may be assembled from parts to get past a rule.** Writing the hostname
  as a concatenation, a template element, an array `join` or any other
  decomposition in order to satisfy `no-restricted-syntax` while producing the
  same non-loopback URL is routing around a guard, is forbidden here, and is an
  `HS-7` finding for a reviewer — **it is not a lint pass, because lint stays
  green on it**, which is exactly why it is a rule here and not a check. A
  session that finds the decomposed form in `web/src/main.tsx` **replaces it**

  suppression does not make V4 green, that is a stop and a report — never a
  licence to decompose the URL again and never a licence to edit
  `eslint.config.js`. **Why the origin has to be non-loopback, and why a
  loopback substitute proves less:** (b) asserts that navigation *away* from the
  app is refused, and a loopback origin is something this app is **supposed to
  allow** — it is the app's own origin, it is the URL the window loads, and the

  to permit, so a row that passed on it would prove nothing about the refusal
  and V2(b) would go green on a window that went somewhere allowed. Only a host
  the app is meant to refuse makes (b) and (c) decidable, and `.invalid` is
  reserved and cannot resolve (HS-6), so no request is ever made and the only
  outcome the harness can observe is a refusal.
- **The CSP is registered as an `onSend` hook**, beside the existing `onRequest`
  guard, in **both** servers — `buildApp` in `server/src/app.ts` and
  `buildBootErrorApp` in `server/src/boot-error.ts` — by one exported function
  from `server/src/http/csp.ts`. An `onSend` hook sees the finished payload and
  the reply's status, which is what "every HTML response" needs: it cannot tell a
  static file from the SPA fallback or the boot page by route table, but it can
  tell a `text/html` response from JSON. `onRequest` would be wrong (the reply
  does not exist yet); a per-route `reply.header` would put the header inside
  route bodies, which Must not edit forbids.
- **The minimum set is rule 6's six directives, exactly** — `default-src
  'self'`, `script-src 'self'`, `connect-src 'self'`, `object-src 'none'`,
  `base-uri 'none'`, `frame-ancestors 'none'` — and nothing weaker. Rule 6 says
  "with **at least**" these six, so two further directives on every HTML
  response (below) satisfy the contract rather than relax it: nothing is dropped,
  replaced or weakened, and no source is added to any of the six.
- **`style-src` is not in rule 6**, so with no `style-src` a `style` attribute
  falls back to `default-src 'self'` and is blocked. The header therefore also
  carries `style-src 'self' 'nonce-<n>'` and **`style-src-attr 'unsafe-inline'`**
  on every HTML response — see the nonce bullet for why both.
- **The boot-error page's inline `<style>` is authorised by a per-response
  nonce, not by `'unsafe-inline'`, and the `onSend` hook is the only place that
  nonce exists.** `server/src/boot-error.ts:46` carries `<style>body{…}</style>`
  inside the document, and rule 7's bilingual error screen is worthless
  unstyled. So `csp.ts` generates a fresh nonce **inside the hook**, per
  response, and in that one hook call it (1) emits `style-src 'self'
  'nonce-<that nonce>'` on the reply and (2) puts the same nonce on the
  `<style>` element of the payload it is decorating, by replacing that
  element's opening tag `<style>` with `<style nonce="<that nonce>">` in the
  payload string. **Only `server/src/http/csp.ts` changes for this.**
  `bootErrorHtml` is not given a nonce parameter, is not re-rendered per
  request, and its call site at `boot-error.ts:65` — which computes the HTML
  once at construction and sends that one frozen string from `:67` and `:71` —
  is untouched, as Must not edit says. The hook only rewrites a payload that is
  a **string** and contains a `<style` tag; the app's `index.html` is sent by
  `@fastify/static`/`reply.sendFile` and has no `<style>` element at all
  (`web/index.html` carries none), so nothing is rewritten there and nothing
  needs to be. If the payload of an HTML response is ever **not** a string, the
  hook does not attempt to rewrite it — it emits the header and nothing else,
  which is why V1(ii) is scoped to the boot page's two consecutive responses.
  **V1 asserts the nonce form and asserts that `'unsafe-inline'` appears in
  `style-src-attr` and nowhere else** — in no other directive of any header, in
  `csp.ts`, or in the test (V1(iii) below). The
  `style-src 'unsafe-inline'` form rule 6 and the stop condition allow —
  justified by a failing test submitted **first** — is **not** the decision
  this card makes; if the nonce form turns out not to work on this stack, that
  is a stop condition, not a licence to switch (see Stop
  conditions). No `script-src` relaxation is contemplated: the boot page has no
  inline `<script>`.
- **Why `style-src-attr 'unsafe-inline'` rides along with the nonce (owner's
  change, AM-114).** A nonce or a hash authorises `<style>` **elements** only.
  CSP3's `style-src-attr` **falls back to `style-src`** when `style-src-attr` is
  absent, and a nonce does not apply to a `style=""` attribute at all, so
  `style-src 'self' 'nonce-<n>'` alone would block every inline style attribute
  in the app. It would do so silently: V1 and V2(d) assert header presence, not
  rendering, so the app would lose every absolutely-positioned overlay — the
  spelling and patient menus, the patient-row drag ghost, the sidebar resizer
  and view-menu positions, the recording level meter — with nothing in this
  card failing. `web/src` sets `style={{…}}` in **8 files and 11 places**:
  `components/BrandMark.tsx`, `components/BrandWordmark.tsx`,
  `components/LiveRecording.tsx` (the level meter's own component),
  `components/PatientMenu.tsx`, `components/PatientsColumn.tsx`,
  `components/SidebarResizer.tsx`, `components/SidebarViewMenu.tsx`,
  `components/SpellingMenu.tsx`. `style-src-attr 'unsafe-inline'` permits style
  **attributes only**: it grants no script, no `eval`, no remote source and no
  network origin, it does not affect `<style>` elements (which still need the
  nonce), and it leaves all six of rule 6's directives exactly as written. So
  the relaxation is deliberate, bounded and proved deliberate: **V1(vi)** asserts
  it and **V2(e)** asserts that a style attribute on app HTML actually applies
  in the shipped binary.
- **`src-tauri/ui/error.html` is out of rule 6's reach and out of scope.**
  `tauri.conf.json:13` sets `"csp": null`, so Tauri injects no CSP into that
  asset window, and C-BRIDGE@1 rule 6 is a rule about what **the server** sends.
  Its inline `<style>` and `<script>` (`src-tauri/ui/error.html:20,93`) therefore
  need nothing here. Do not add a CSP, do not move the file, do not widen this
  card into `src-tauri/ui/` — the `**` in May edit is written as `src-tauri/**`
  **except** `src-tauri/ui/` for that reason.
- **Which responses carry the header** (N2): every `text/html` response, and only
  those — the static `index.html` served by `@fastify/static`, the SPA fallback
  `sendFile('index.html')` at `app.ts:163` (so `GET /patients`, the note view's
  URL, carries it), any stray `.html` asset, and the boot page's `/` at
  `boot-error.ts:67` and its non-`/api` not-found HTML at `:71`. **JSON, SSE and
  the `/api` 404 JSON carry no header** (`app.ts:157-161`; the boot server's
  `/api/health` JSON at `boot-error.ts:68` and its not-found JSON at `:72`):
  they are not HTML, adding one would be scope, and V1(iv) asserts their absence so
  "the header is on HTML" is a property and not "the header is on everything".
- **The new work is the server CSP, the harness and the one observation hook.**
  At `07dce9c` the shell side already satisfies rule 4 and rule 5:
  `withGlobalTauri: false`, `"csp": null`, `"capabilities": []`, no
