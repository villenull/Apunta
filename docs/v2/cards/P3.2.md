## Objective
Only one process can own a data folder, from before restore and migration to
shutdown.

## Read
`server/src/index.ts` (lines 18-40, start-up order); `server/src/db/index.ts`
(lines 47-58); `server/src/backup/restore.ts` (`applyPendingRestore`).

## May edit
`server/src/platform/data-lock.ts` (new) and test; `server/src/index.ts`
(ordering only); `server/src/db/index.ts` (`locking_mode=EXCLUSIVE` after
migration).

## Must not edit
Migration logic (P5.2).

## Fixed decisions
C-OWN@1 in full; exit code 75; message code `data_folder_in_use`.

## Steps
1. Tests first, with synthetic temp folders: two in-process acquisitions
   (second refused); stale lock from a dead PID taken over; stale lock whose
   PID is alive but start time differs taken over; race of two concurrent
   acquirers leaves exactly one owner; a second child process (spawned by the
   test) that opens the database without the lock after migration gets
   `SQLITE_BUSY` on write. 2. Implement.

## Stop conditions
`locking_mode=EXCLUSIVE` breaks an existing feature that opens a second
connection (for example backup): report which, do not remove the backstop.
