## Objective

shutdown.

## Fixed decisions
C-OWN@1 in full; exit code 75; message code `data_folder_in_use`.

- **`processStart` is a raw kernel number, not a timestamp.** Linux: field 22
  of `/proc/<pid>/stat` (start time in clock ticks since boot), read as a
  decimal string. macOS: the value `ps -o lstart= -p <pid>` prints. It is
  written into the lock file exactly as read and compared as a string. Liveness
  is `process.kill(pid, 0)`: `ESRCH` is dead (take the lock), `EPERM` is a live
  process owned by another user (**refuse**), no error means alive. A start
  time that cannot be read — unreadable `/proc`, a failed or unparsable `ps`,
  a missing field — is treated as **alive**, so the takeover branch is not
  taken. Writing an ISO-8601 timestamp here is the mistake this bullet exists
  to prevent: rule 3's equality can then never hold, so a **live** owner's lock
  is declared stale, overwritten, and two processes run on one folder — the
  exact outcome C-OWN@1 exists to prevent.
- **The module's exported surface, fixed.** `acquireDataFolderLock(dataDir)`
  returns `{ nonce, release(): void }` on success and **throws**
  `DataFolderInUseError` (exported from the same module) carrying
  `code === 'data_folder_in_use'` and the live owner's `pid` on refusal.
  `DATA_FOLDER_IN_USE = 'data_folder_in_use'` is exported for the shell and for
  P3.3. The nonce is generated inside `acquireDataFolderLock` and returned on
  the handle, so rule 3's re-read check compares the file on disk against the
  caller's own nonce. No other module state: `release()` is idempotent and a
  test releases between cases instead of resetting a singleton.
- **The refusal exits 75 and binds nothing.** On refusal the process logs
  `data_folder_in_use` and calls `process.exit(75)` immediately — from inside
  the start-up `try`, before `serveBootError`, `buildApp`, `app.listen`,
  `applyPendingRestore` and `openDatabase`. It must not take today's path
  (`index.ts:27-44`): that `catch` serves a boot-error page, keeps the port
  bound and `return`s, so the process would answer forever and leave with 0,
  never 75. A genuine storage failure still gets the boot-error page; the lock
  refusal is the one error that does not.
- **Release happens in the existing `onClose` hook.** The handle's `release()`
  is called from the `onClose` hook at `index.ts:48-50` beside `db.close()`, so
  it runs on the `SIGINT`/`SIGTERM` path (`app.close()` then
  `process.exit(0)`, `index.ts:83-87`) and on any other clean close. It is
  idempotent, a no-op when nothing was acquired, and it unlinks
  `<dataDir>/apunta.lock` only when the file on disk still carries this
  process's `nonce` — a lock already taken over by someone else is never
  removed. A crash leaves the file behind and rule 3 takes it over.
- **`data_folder_in_use` is defined and exported here; carrying it is P3.3's.**
  C-BRIDGE@1 rule 2's `fatal{code}` stdout line is built by **P3.3**:
  `src-tauri/` does not exist at this base and no file in May edit is a shell
  file. This card prints no such line, writes no file to carry the code, and
  touches no i18n string — `shared/src/i18n/en.ts` has no "Apunta is already
  open" string and this card adds none. The refusal is observable here as exit
  75 plus the logged code, and that is all P3.2 promises.
- **Rule 1's pre-migration snapshot step is P5.1's, not this card's.** P3.2
  guarantees exactly one ordering fact: the lock is acquired **before**
  `applyPendingRestore`, and therefore before anything in C-UPD@1's chain.
  C-SNAP@1's pre-migrate snapshot belongs to P5.1, whose
  `server/src/db/snapshot.ts` is a (new) file in that card's May edit; P5.1
  inserts its snapshot after the restore and before `migrate`. This card calls
  no snapshot and does not block on one.
- **V1's databases and its child process live in the sandbox run folder.** V1
  runs under `node scripts/v2/sandbox.mjs env --port 7829`, so the test's
  parent folder is `$APUNTA_DATA_DIR` = `/tmp/apunta-v2/<runId>/data/`, mode
  700 (C-ISO@1 rule 1). Each case makes its own `mkdtemp` subfolder **there**;
  `os.tmpdir()` is not used, because `/tmp/apunta-lock-…` sits outside the
  C-ISO root with no run id and no cleanup guarantee, and a case whose child is
  SIGKILLed by a test timeout would leave a database and a lock there that
  nothing ties to a run. Case 5's spawned child inherits that same folder, so
  no database, `-wal`, `-shm` or `apunta.lock` is ever created outside
  `/tmp/apunta-v2/<runId>/`, and evidence quotes those paths as `<sandbox>`.
  When `APUNTA_DATA_DIR` is unset — V3's bare `npm test` drives the same file
  through the repo's own vitest project, with no sandbox around it — the parent
  folder is `os.tmpdir()`; a test that refused to run without the wrapper
  could not be run by `npm test` at all.

## Steps
1. Tests first, in `server/src/platform/data-lock.test.ts`, one folder per case
   under the run folder Fixed decisions names. The five cases and what each
   asserts:
   - **two in-process acquisitions** — the second throws
     `DataFolderInUseError` with `code === 'data_folder_in_use'`, and
     `<dataDir>/apunta.lock` still carries the **first** acquirer's `pid` and
     `nonce`: nothing was rewritten.
   - **stale lock from a dead PID, taken over** — the fixture's PID is one the
     test has just probed free (`process.kill(pid, 0)` throws `ESRCH`, e.g. a
     child it spawned and reaped), never a hard-coded number, which on a busy
     container can be live. Acquisition then succeeds and the rewritten file's
     `nonce` equals the **new** owner's, not the fixture's.
   - **stale lock whose PID is alive but start time differs, taken over** — the
     lock carries this process's real `pid` with a `processStart` that is not
     this process's; the takeover branch is taken and the same nonce assertion
     holds. This is the case that catches a wrong `processStart` unit, where
     the two takeover branches silently collapse into one.
   - **race of two concurrent acquirers** — two acquirers on one folder leave
     exactly one owner: one resolves with a handle, one throws
     `DataFolderInUseError`, and the file's `nonce` is the winner's.
   - **SQLite backstop** — a second **child process** the test spawns (its own
     `process.execPath`, on that same folder, no lock) opens the database after
     migration and gets `SQLITE_BUSY` on write.
2. Implement `server/src/platform/data-lock.ts` and the two call sites until
   all five pass.
3. Write `scripts/v2/second-start.mjs` (new, this card — the V2 helper): it
   spawns the **built** `server/dist/index.js` (never
   `tsx server/src/index.ts`, which would not be the artefact the wrapper
   runs), with the wrapper's own sandbox environment except that `APUNTA_PORT`
   is overridden to **7830**; it refuses to run unless that port is an integer
   in 7800-7889, and never inherits 7829. It stops only the process it started
   (C-ISO@1 rule 7) and exits non-zero on any failed assertion.
