## Fixed decisions
C-ACQ@1 rules 1 to 7, in full, and these say how each one is reached.

1. **Where the approved redirect hosts come from, and in what order.** A07's
   redirect cell was a placeholder before AM-042. Attempt 2 already introduced
   the two per-artifact allowances and their derived global union; request checks
   now use `assertRequestAllowed` in `readiness.ts`. Preserve that implementation.
   The original acquisition sequence below is historical for steps already
   recorded in the checkpoint. The probe was **step 1**: `node scripts/v2/probe-redirects.mjs` runs before any test needs
   an approved redirect host, writes
   `docs/v2/evidence/P4.1/redirects.md`, and the hosts it recorded are the only
   candidates. Step 2 admits them under this rule and no other: a host goes into
   an allowance's `allowedRedirectHosts` **iff** (a) the probe recorded it as a
   `Location` host for that artifact, and (b) it ends in `huggingface.co` or
   `hf.co` on a dot boundary, case-insensitively — the mechanical form of A07's
   "only Hugging Face CDN hosts". A host failing (b), or one the probe saw but
   cannot attribute to a single artifact, is stop condition 1, never an
   admission. A probe that records no `Location` at all leaves the list empty,
   and an empty list is the correct answer, not a gap. The two allowances are
   named in `catalog.ts` — `SPEECH_DOWNLOAD_ALLOWANCE` for the two speech
   entries, `C_STT_CANDIDATE_ALLOWANCE` for the six C-STT candidates — each
   `{ allowedHosts: readonly string[]; allowedRedirectHosts: readonly string[] }`,
   and `downloadWithResume` takes the one matching the artifact it is fetching,
   so rule 2 is per artifact and not a second global list. `catalog.ts` stays the
   only file in the package naming a host (`catalog.test.ts:77-92` keeps
   asserting that), and `ALLOWED_DOWNLOAD_HOSTS` is the union of every allowance's
   `allowedHosts` **and** `allowedRedirectHosts`, plus the hosts the licence
   pages already name (`registry.ollama.ai`); a test asserts that union. The
   admitted redirect hosts enter through the allowances' `allowedRedirectHosts`,
   so they are included by construction — there is no second, separate list.
2. **The code vocabulary, and where it lives.** One closed union declared in the
   new `installer/src/readiness.ts` and exported from there, so the request
   guard and the readiness verdict speak the same words. Readiness is
   `state: 'missing' | 'ready' | 'invalid'`, and `invalid` carries exactly one
   code: `size_mismatch` (the size is not the pinned `sizeBytes` — what the
   11-byte and zero-byte cases assert), `hash_mismatch` (a fresh hash did not
   match the pinned digest), `not_a_regular_file` (a directory, or a symlink
   resolving to one — `lstatSync`, not `statSync`), `stale_pin` (the `.part`
   sidecar's `url` or `checksum` is not the pin the catalogue holds now,
   `resume.ts:58-63`), `dangling_part` (a `.part` with no sidecar, or with one
   that does not describe it), `no_pinned_hash` (the entry pins neither `sha256`
   nor `sha1`; the existing refusal at `run.ts:256-262`, kept). Request
   refusals, same file: `scheme_not_https`, `port_not_allowed`,
   `user_info_present`, `fragment_present`, `query_not_allowed`,
   `query_key_not_allowed`, `host_not_allowed`, `too_many_hops`,
   `redirect_loop`. `query_not_allowed` is a row that admits no query at all;
   `query_key_not_allowed` is a query carrying a parameter name outside the
   row's *Allowed query keys* cell. `ACQUISITION.md` §1 now carries that cell
   and its rule (AM-042, owner-approved): A07 enumerates the ten names its
   artifacts actually present, and every other row is `none`, which is the
   pre-existing behaviour. The catalogue gains a per-entry
   `allowedQueryKeys`, taken from the ACQUISITION manifest row covering the
   artifact: A07's enumerated names apply to its two existing speech entries
   and subsequent candidate entries covered by that row; all other rows retain
   their own explicit allowances. The check
   is membership of the **name** set, never a prefix, wildcard or blanket
   permission, and it runs before the URL is requested. No value is ever read,
   logged, recorded or compared. No code enters
   `SETUP_ERROR_CODES` and none reaches the JSONL in this card: a refusal thrown
   by the downloader surfaces through today's `describeFailure` as `unexpected`
   carrying the refusal sentence as its `override` (`errors.ts:118-124`), and
   P4.4 is what puts a code on the wire. When P4.4 does give one a sentence, the
   banned-words regex at `errors.test.ts:20-27` still forbids "checksum",
   `SHA-?n` and `HTTP n` in the prose, so `hash_mismatch` and `size_mismatch`
   are identifiers only.
3. **The verdict reaches `ProbedState` as a boolean, not as a widened field.**
   `readiness.ts` returns the verdict and its code; `probeState` derives the
   three booleans from `state === 'ready'` and from nothing else.
   `ProbedState` keeps three `boolean`s and gains no member, so `plan.ts` and
   `protocol.ts` stay out of scope and `buildPlan` keeps receiving booleans at
   `run.ts:132-139`. Putting the code on the wire is P4.4's, and only P4.4's.
4. **The receipt, pinned verbatim.** `<modelsDir>/<file>.receipt.json`, mode
   `0o600`, one JSON object, no other keys and no trailing fields:

   ```json
   {
     "version": 1,
     "filename": "ggml-tiny.en.bin",
     "algorithm": "sha256",
     "digest": "921e4cf8686fdd993dcd081a5da5b6c365bfde1162e72b08d75ac75289920b1f",
     "sizeBytes": 77704715,
     "mtimeMs": 1758230400000,
     "dev": 66310,
     "ino": 4242
   }
   ```

   - `version` is `1`; any other value, or a file that will not parse, counts as
     no receipt.
   - `algorithm` is `"sha256"` when the entry pins one and `"sha1"` when it does
     not. That is the `sha256: null` case: the receipt records the SHA-1 the
     catalogue does pin (`run.ts:212`) and the download path is unchanged. Both
     null is `no_pinned_hash` — refused, never downloaded.
   - `mtimeMs` is `Math.floor(stat.mtimeMs)`: integer milliseconds, because
     `fs.Stats` reports ms everywhere and an `mtimeNs` field would need a
     `bigint` stat and a second comparison rule. A file whose mtime moved at all
     — a restore, a copy that did not preserve it — fails the match and is
     hashed once more. Correctness is worth one hash of 75 MiB.
   - `dev` and `ino` are the inode identity `statSync` reports, as two JSON
     numbers; both are safe integers on Linux and macOS for a file this size.
     Together they are "inode" for rule 5, and a file copied onto another volume
     fails them even with the same size, mtime and digest.
   - **Written only** by explicit acquisition or repair after verification,
     never while a `.part` exists and never before verification. Readiness
     probes never write receipts, including after a fresh matching hash.
   - **Rewritten in full** after any repair, and the old receipt goes with the
     file it described. A receipt whose `filename`, `algorithm`, `digest` or
     `sizeBytes` disagrees with the catalogue is treated as no receipt: hash
     again; a readiness probe does not rewrite it.
   - A missing receipt is not a failure, readiness uses a fresh hash without writing
     a receipt. Subsequent receiptless probes re-hash.
   - P4.3, P4.4 and S4b.1 read this shape. Nothing else may.
5. **The pinned size is a pin.** `SpeechModelEntry` gains
   `readonly sizeBytes: number` beside `approxBytes`, and `SPEECH_MODEL` and
   `PREVIEW_SPEECH_MODEL` pin `77_704_715` — the measured count that survives
   today only in the `approxBytes` comment (`catalog.ts:93-99`). `approxBytes`
   stays and keeps its one job, refusing a download on a full disk before it
   starts; `sizeBytes` is what rule 5's "size equals the pinned size" means, and
   it is what the 11-byte, zero-byte and wrong-build cases are asserted against.
   A verified file whose size is not `sizeBytes` is `size_mismatch`; a **second**
   mismatch on the same artifact after a repair is stop condition 5, because
   re-downloading cannot fix a wrong pin.
6. **The test transport is an injected `fetch`, and nothing else.** There is no
   HTTPS test server in this card. `DownloadOptions.fetchImpl` and
   `SetupEnvironment.fetchImpl` are both `typeof fetch` (`download.ts:42`,
   `run.ts:38`), so there is nowhere to pass a dispatcher that would trust a
   self-signed certificate, and the only host a loopback server can offer is one
   `assertRequestAllowed` must refuse — the hole `download.test.ts:12-19` declines
   to open on purpose. Tests inject a `fetch` that answers from memory, keep the
   **real pinned URL** so rule 1 runs for real, and open no socket. No test
   binds a port, no test certificate exists, `127.0.0.1` never enters any
   allow-list, and the "exemption cannot spread" scan at `catalog.test.ts:77-92`
   keeps passing.
7. **A hop is one redirect followed.** The initial request is hop 0 and is not
   counted. Each `Location` is resolved against the current URL, validated under
   rule 1, checked against that artifact's `allowedRedirectHosts`, and only then
   requested — that request is hop 1, and at most 5 hops may be followed. A 6th
   `Location` fails with `too_many_hops` before it is requested. A `Location`
   that resolves to a URL already requested for this download (the initial URL
   or any earlier hop, compared as the absolute string
   `new URL(location, current).href` produces) fails with `redirect_loop` before
   it is requested. And the only header the downloader ever sends is `Range`, on
   the initial request alone: a redirect hop carries no header at all, so a
   resumed download that meets a redirect restarts from byte 0 at the new host
   rather than asking it for a range it was never offered the whole of. No
   custom header exists anywhere in `download.ts` and none is added.
8. **The probe's URLs come from the built catalogue, and it holds no host
   literal.** `scripts/v2/probe-redirects.mjs` imports `SPEECH_MODEL` and
   `PREVIEW_SPEECH_MODEL` from `installer/dist/catalog.js` (built by
   `npm run build --workspace @apunta/installer`; `dist/` is gitignored and
   rebuilt per row). `eslint.config.js` exempts exactly one file,
   `installer/src/catalog.ts` (`:144`), the probe is not that file, and a literal
   in it fails V3 — so the script names no host. It requests
   `SPEECH_MODEL.url` and `PREVIEW_SPEECH_MODEL.url` (the same file;
   `catalog.test.ts:111-120` pins the two entries equal, so this is one request
   recorded under both entry names) and the six C-STT candidates — `ggml-base.bin`,
   `ggml-base-q5_1.bin`, `ggml-small.bin`, `ggml-small-q5_1.bin`,
   `ggml-large-v3-turbo-q5_0.bin`, `ggml-large-v3-turbo-q8_0.bin`
   (`CONTRACTS.md:450-452`) — by substituting each filename into
   `SPEECH_MODEL.url`'s path. Seven requests, six distinct artifacts. Building a
   URL from fragments so the lint selector misses is forbidden: that is
   loosening a guard (HS-7). If the built catalogue cannot be imported, V2 is
   `BLOCKED`; it is never a reason to add an exemption.
9. **Rule 7 lives in the installer's own Ollama client.** `installer/src/ollama.ts`
   gains a digest read: after a successful `pullModel`, one `POST /api/show` for
   that tag over the same loopback `fetchImpl`, and the tag with its digest is
   reported in the existing `message` event's text — no wire change, because
   `message` already carries free text. The daemon's own network behaviour stays
   outside these checks and the message says so in as many words, because that
   is what rule 7's last clause requires; the same statement goes in
   `WritingModelEntry`'s doc comment in `catalog.ts`, which is why no doc outside
   May edit is needed for it. No pull is started for a tag `hasModel` already
   reports (`ollama.ts:76-94`; A08 and HS-3), and no tag is ever removed or
   replaced: the client has no such call and this card adds none. HS-3's Ollama
   clauses are therefore met by construction, not by a stop condition.
10. **Repair happens only after the user presses Start.** Readiness is computed
    on every run and repairs nothing. The repair — `discardDownload`, then
    `downloadWithResume` — happens only inside the step the user's Start press
    began (`run.ts:175-193`). A run that only probes, such as the one behind the
    plan, writes nothing on disk.

## Egress (this card only)
HS-3 permits only what `docs/v2/ACQUISITION.md` lists, and it lists no row for
probing a download host, so this card states its own grant and its own limits,
in P1.5's shape (`docs/v2/cards/P1.5.md:108-118`).

- **The exact URL set:** the seven in Fixed decision 8 — the two speech entries'
  one URL, and the six C-STT candidate paths — and nothing else. No other host,
  no other path, no sub-resource, no retry against a different host, no
  `Range`.
- **Method:** `HEAD` only, with `redirect: 'manual'`. The `Location` is read
  from the response and never followed. A `GET` is not authorised by this card
  and no response body is ever read.
- **No credentials**, no query of its own, no fragment, no cookie jar, no custom
  header. Whatever `User-Agent` Node sends is left alone.
- **No bytes are acquired.** Nothing is downloaded or installed, no model is
  pulled, and no Ollama daemon is contacted by the probe at all. Rule 7's
  `/api/show` in Fixed decision 9 is a loopback call the installer's own runtime
  client makes, reached only through `SetupEnvironment.ollamaBaseUrl`, and is
  exercised only by a test with an injected `fetch`.
- **Logged:** the method, the request URL, the response status, each `Location`
  host in hop order with its scheme, port and query-presence verdict, the hop
  count and the date, into `docs/v2/evidence/P4.1/redirects.md`, which the script
  writes itself. Per artifact, `ACQUISITION.md` §1's item fields are recorded as
  "not acquired — HEAD only, no bytes": there is no size and no SHA-256 in that
  file because none was computed, and a reviewer is not left hunting for one.
- **Sanitisation by construction:** the script writes no machine, user or
  container identifier — no `os.hostname()`, no login name, no home or sandbox
  path — so RUN-CONFIG §4's bar is met without redacting the one thing the file
  exists to record. The only paths it writes are the repository-relative
  evidence path and the catalogue's own public URLs. An observed query string is
  written `<redacted>`, never pasted; an observed host is the artefact's content
  and is written as observed, the way `docs/v2/evidence/P1.5/licence-evidence.md`
  records a public vendor URL. Stop condition 4 covers the case where the
  coordinator reads §4 more widely than this.
- `CLAUDE.md` hard rule 1's model-acquisition carve-out covers the installer
  process, not an agent's ad-hoc fetch, and is **not** relied on here: this
  grant is the card's own, it covers the step 1 probe and the V2 re-run and
  nothing else, and it is spent when V2 completes.

## Attempt 4 fail-closed query-name decode (AM-064, owner-approved 2026-09-28)

**Attempt 4 of 4. There is no fifth attempt.** If P4.1 is still short after this
one it is approved or blocked on its own merits and returns to the owner, not to
another implementer. This section is the whole of the attempt's scope; nothing
outside it is authorised.

**The defect.** `queryKeyNames` (`scripts/v2/probe-redirects.mjs:188-199`) calls
`decodeURIComponent` on every query parameter **name** with no `try`/`catch`. A
`Location` that parses as a URL but whose query name carries a malformed percent
escape takes the unguarded path and throws a `URIError` out of `main()`, which
calls `describeLocation` in a bare loop and writes the evidence file afterwards.
The process therefore dies **before** writing, leaving the previous run's
`docs/v2/evidence/P4.1/redirects.md` on disk where it reads as this run's record.

**What is *not* wrong, verified independently, so the scope stays narrow.** The
shipped downloader guard already fails closed on this input and is tested: the
only gate is `assertRequestAllowed`, called before the only model fetch, and it
reads names through `queryParameterNames` (`installer/src/readiness.ts`), which
wraps the same decode in `try`/`catch` and leaves an unreadable name undecoded so
the allow-list can refuse it. `'%zz'` is not an allowed key. Nothing unsafe ships
and nothing is red in the product. The defect is confined to a **diagnostic
script and the evidence record it writes.**

**The fix, and nothing else.** Wrap that one decode so a malformed escape is left
as it arrived, exactly as `queryParameterNames` already does — an unreadable
name is not a name that can be on an allow-list, so it fails closed downstream.
No other behaviour of `queryKeyNames` changes: the same names, the same
de-duplication, the same sort order, the same return type.

**The V4 case, and how it must be built — this is the part that is easy to get
wrong.** A case written with this file's own `withQuery` helper, or with
`URLSearchParams`, **cannot fail**, and a green test that cannot fail is worse
than no test. `URLSearchParams.set` percent-encodes the `%` of a literal `%zz`
into `%25zz`, which decodes cleanly and never reaches the malformed branch — so
every assertion below would pass against the *unfixed* code. Equally, copying the
adjacent control at `probe-redirects.test.mjs:113-115` is the mirror-image
mistake: that control asserts the **unparseable** branch (`new URL` throws), not
the parseable-with-malformed-name branch this defect lives in.

**The literal must be loopback, and that is not a detail — it is the only
construction that is both faithful to the defect and legal in this file.** The
outbound-URL rule bans any string literal matching an `http(s)://` URL whose host
is not `127.0.0.1`, `localhost` or `[::1]`, and it applies to
`**/*.{ts,tsx,js,mjs}`. The exemption that lets tests name real vendor URLs
covers `**/*.test.{ts,tsx}` and `e2e/**/*.ts` — **not** a `.test.mjs` file. So a
literal `https://vendor.example/?%zz=1` is faithful to the defect and fails V3,
while every other repair available (deriving from the catalogue, editing
`eslint.config.js`, weakening the assertion) is a prohibition breach. Use a
loopback literal on a non-`https` scheme, e.g. `http://127.0.0.1/<path>?%zz=1`.

That choice has a **recorded, expected consequence**, stated precisely so no one
writes an assertion against the wrong shape. The host is not judged by a refusal
string: it is the separate `domainRule` boolean (`probe-redirects.mjs`, rendered

verdict anywhere in this card. So the `refusals` array for this fixture holds
**exactly two** entries — the scheme verdict, because the literal is not `https`,
and the query-key verdict, because the malformed name is not on the artifact's
allowance — plus `domainRule: false` alongside them. Assert that shape. An array
of three means the implementer has added a verdict the code does not produce, and
the correct response is to fix the assertion, not the probe. The row is about the
malformed query name, and the query verdict is what it asserts.
