## Objective
The installer catalogue states the licence evidence actually checked, the
licences record says the same thing about the same read, and two docs are
corrected.

## Read
`installer/src/catalog.ts` (`LicenceReference` lines 64-76; the three tiers
lines 175-199, especially 180, 186 and the `qwen3.5:4b-q4_K_M` comment at
195-197); `installer/src/catalog.test.ts` (the "the writing models" block);
`THIRD-PARTY-LICENSES.md` ("Open points" item 2, the writing models' terms);
`README.md` (the milestone count, line 191); `docs/HANDOFF.md` (the bold line
at 466, "Explicitly removed from the active backlog"); `docs/decisions.md`
(the 2026-09-22 rows only); `docs/v2/DECISIONS.md` (E9, line 47);
`docs/v2/ACQUISITION.md` (§1 A08, §2).

## May edit
`installer/src/catalog.ts`; `installer/src/catalog.test.ts`; `README.md`;
`docs/HANDOFF.md`; `THIRD-PARTY-LICENSES.md` — and there only its "Open
points" item 2 (the writing models' terms), and only when this card actually
sets a writing model's `verified` to `true`. On the `verified: false` path
that file is not touched, because nothing in it changes.

## Must not edit
Anything else. In particular: `installer/src/protocol.test.ts` (its licence
literal is a self-contained fixture and V1 stays green without it);
`installer/src/protocol.ts` and the `LicenceReference` interface — no new
field, so the `SetupEvent` wire shape is unchanged; the
`<!-- npm-dependencies:start -->` to `<!-- npm-dependencies:end -->` block
in `THIRD-PARTY-LICENSES.md`, which `npm run licenses` regenerates and
`npm run lint` fails on when stale; `docs/v2/ACQUISITION.md`;
`docs/decisions.md`.

## Fixed decisions
- **Evidence mechanism, named, per tag.** Either GET its Ollama library page —
  `https://ollama.com/library/gemma4` for `gemma4:12b-it-qat`,
  `https://ollama.com/library/qwen3.6` for `qwen3.6:35b-a3b` — as the Egress
  section below permits, or, if and only if `ollama list` already shows that
  tag on this machine, `ollama show <tag> --license` (local, and
  `docs/v2/ACQUISITION.md` §2 allows a tool already installed, used as found).
  This card never pulls, removes or replaces a tag: A08 assigns the
  `gemma4:12b-it-qat` pull to S5.6, and HS-3 forbids pulling a tag that is
  already here. A read means reading the licence text itself — the blob
  shipped with the tag, or the licence text on the page. A licence named from
  memory, from the registry listing, or from another tag's evidence is not a
  read and leaves `verified: false` alone.
- **Where the evidence is recorded.** The entry's existing `licence.url`
  field keeps naming the library page — that is what the field is for
  ("where the user can read it", never a download) — and the date of the read
  goes in the entry's existing code comment (the `qwen3.5:4b-q4_K_M` comment
  at `catalog.ts:195-197` is the precedent) and in
  `docs/v2/evidence/P1.5/licence-evidence.md`, which carries the tag, the page
  URL, the date, and the licence text as read. If the read was the local blob,
  its identifier goes in the evidence file, never in `url`. Do not add a field
  to `LicenceReference` or to `SetupEvent`: a date has no home in a
  three-field shape, and adding one would change the wire shape
  `installer/src/protocol.ts` encodes.
- **What supports the licence value.** `verified: true` is admissible only
  together with a read, and with that read's URL and date recorded. Until
  then, keep the publisher-neutral name the entry already has:
  `gemma4:12b-it-qat` stays `name: 'Gemma Terms of Use', verified: false`
  (`catalog.ts:186`), which is what `LicenceReference.verified` documents —
  before the page is read the window "names the publisher and links the page
  rather than asserting a licence identifier". Do not write `Apache-2.0` for
  it: "(plan reference E9)" is the licence *policy* row at
  `docs/v2/DECISIONS.md:47` and says nothing about gemma4, so the identifier
  stands only if the read says it. If the read returns the Apache License 2.0
  text, the name becomes `Apache-2.0` and `verified` becomes `true` in the
  same edit, with the licences record moved by the next bullet. If the read
  says something else, the stop condition governs and neither value changes.
  `qwen3.6:35b-a3b` follows the same rule: it already reads
  `name: 'Apache-2.0', verified: false` (`catalog.ts:180`), and that stays
  `false` unless its own licence text is read.
- **The licences record moves with the read.** Whenever this card sets
  `verified: true` for either tag, it edits `THIRD-PARTY-LICENSES.md` "Open
  points" item 2 in the same card: the writing models' terms are no longer
  wholly unread, so say which terms were read, on what date, from which URL,
  and which tags remain unread. Otherwise `THIRD-PARTY-LICENSES.md:4000-4005`
  and the catalogue assert two different things about the same read — the
  drift R17 exists to remove. A read this card did not make is not this card's
  to report, and a `verified: false` outcome leaves that file untouched.
- **README.** The count only: `M0–M12` becomes `M0–M13`, keeping the
  existing en dash and the rest of the sentence (`README.md:191`).
- **HANDOFF.** Fill the bold line **"Explicitly removed from the active
  backlog (owner decision 2026-09-22):"** (`docs/HANDOFF.md:466`) with a bullet
  list directly under it, one bullet per removed item. Do not convert it to a
  `###` heading and do not delete it. Selection filter: only the 2026-09-22
  `docs/decisions.md` entries that remove or decline work — the owner scope
  cleanup (`:225`: vocabulary acquisition, A/B experiments, the Tailscale
  invite), the model-switch declinations (`:231`–`:234`: no Thorough default,
  the four authorised arms) and the Mac pause (`:227`) — and not the same
  day's entries that add work (Halaxy as M13, Inter bundled, Keep mine / Take
  theirs, and the rest). If that filter yields no item, delete the line and
  say so in the evidence file; that branch is decided by the filter, not a
  second guess.

## Egress (this card only)
HS-3 permits only what `docs/v2/ACQUISITION.md` lists, and it lists no row for
reading a web page, so this card states its own grant and its own limits: GET
`https://ollama.com/library/gemma4` and
`https://ollama.com/library/qwen3.6`, and nothing else — no credentials, no
query string, no download, no model pull. Log the URL, the HTTP result and the
date in `docs/v2/evidence/P1.5/licence-evidence.md`. Write nothing outside this
card's "May edit" list and `docs/v2/evidence/P1.5/` (the dispatch-required
evidence directory, AM-017). `CLAUDE.md` hard rule 1's model-acquisition
carve-out covers the installer process, not an agent's ad-hoc fetch, and is
not relied on here.

## Stop conditions
- Either licence page or blob — `gemma4:12b-it-qat` or `qwen3.6:35b-a3b` —
  states something other than Apache-2.0: record the licence text found, the
  URL and the date in `docs/v2/evidence/P1.5/`, leave both `licence.name`
  values unchanged, set the card status `BLOCKED` (RUN-CONFIG §4) and say so in
  the return file.
- The read cannot be made — not permitted, page unreachable, or the tag is
  absent locally and this card may not pull it: do not substitute a remembered
  licence. Leave `verified: false` and the existing `licence.name` in place,
  record the attempt, the reason and the date in the evidence file, and report
  `BLOCKED`.
