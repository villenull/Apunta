## Objective
`t(key, params)` exists with English and es-MX catalogues in `shared/`,
plus the checks that keep them complete.

## Read
`shared/src/i18n/locales.ts` (S2.1); `docs/research/es-mx-ui-conventions.md`.

## May edit
`shared/src/i18n/en.ts`, `shared/src/i18n/es-MX.ts`, `shared/src/i18n/t.ts`
(new) and tests; `web/src/lib/i18n.tsx` (new: provider and hook reading the
language setting through C-SETTINGS); `scripts/check-ui-strings.mjs` (new);
`package.json` (add it to `lint`); `eslint.config.*` only if the check is an
ESLint rule instead.

## Must not edit
Existing UI strings (extraction is S2.3 to S2.5).

## Fixed decisions
- In-house `t()` using `Intl.PluralRules`, `Intl.DateTimeFormat`,
  `Intl.NumberFormat`; no new dependency.
- The es-MX catalogue's type is derived from the English one (a missing key
  is a type error). Placeholder names must match (test).
- Server-facing messages use stable codes plus parameters; catalogues map
  codes to text. Logs stay English and content-free.
- Date-only values are formatted without timezone conversion; timestamps use
  the local zone. English output stays exactly as today (test with fixed
  inputs).
- `check-ui-strings.mjs` fails on JSX text or string attributes
  (`aria-label`, `title`, `placeholder`, `alt`) that are literal user-visible
  words in `web/src`, with an allowlist file for the brand name and
  technical tokens. It starts in **report-only** mode listing current
  literals; S2.4 switches it to failing.
