## Fixed decisions
- C-MODEL@1 in full. `modelForMemory` is renamed `recommendedModelForMemory`
  and no longer selects anything: it is the informational "this machine could
  also run X" recommendation, and `LARGE_TIER_GIB`/`DEFAULT_TIER_GIB` keep
  meaning what they mean.
- **Resolver shape.** `shared/src/effective-model.ts` exports
  `effectiveModel(input: { override?: string | null; installed: readonly string[] | null }): { tag: string; source: 'override' | 'promoted'; present: boolean | null }`.
  `override` is the `llm_model` setting (or the installer's `--model`), trimmed;
  blank or absent means no override. `installed` is the runtime's installed-tag
  list, or `null` when the runtime could not be asked — `null` and `[]` are
  different facts and must never be conflated. `present` is `true` when
  `installed` contains `tag`, `false` when `installed` is a list that does not,
  and `null` when `installed` is `null`: an unreachable runtime is **unknown**,
  never "not present", so a machine that did not answer is not reported as
  missing a model it has. `source` is `'override'` or `'promoted'` and nothing
  else, in the reachable and unreachable cases alike — `tag` and `source` come
  from the setting and a constant, not from the runtime, and the unreachable
  case is carried by `present: null` alone. The resolver is pure and never
  fetches: `server/src/ai/profiles.ts` exports the installed list
  (`readonly string[] | null`, built on today's 2s `/api/tags` cache, whose
  empty-set-on-error is what becomes `null`), and the server resolution and the
  health route both feed the resolver from it. The profile-availability list
  keeps today's behaviour for an unreadable runtime.
- **The health change is additive.** `HealthResponseSchema.ollama` gains
  `tag: string`, `source: 'override' | 'promoted'` and `present: boolean | null`
  **alongside** `reachable`, `model: string | null` and `modelPresent: boolean`.
  Nothing is renamed or removed, so `web/src/lib/setup.ts:81,129` and
  `web/src/components/AiBanner.tsx` keep compiling and behaving exactly as they
  do today. The three new fields are the resolver's answer; `model` and
  `modelPresent` keep their current `describe()`-derived values. Whenever
  `reachable` is true the two must agree — `model === tag` and
  `modelPresent === (present === true)` — and
  `server/src/routes/health.test.ts` asserts it; a disagreement is a bug in this
  card, not a tolerated difference. `present` is `null` exactly when
  `reachable` is false.
- **The promoted default is a new constant.** `shared/src/models.ts` adds
  `PROMOTED_DEFAULT_MODEL = 'qwen3.5:4b-q4_K_M'`, and the resolver returns it
  whenever there is no override. `LARGE_MODEL`, `DEFAULT_MODEL` and `SMALL_MODEL`
  keep their current values and their current recommendation meanings, so
  `DEFAULT_MODEL` is still the *middle* tier and is **not** redefined to the
  promoted tag. The promoted tag's value is the current `SMALL_MODEL` value, so
  `installer/src/catalog.ts`'s `WRITING_MODELS` (keyed by tag string) already
  resolves it and needs no edit, and the tag literals in `scripts/setup-macos.sh`
  and `scripts/preflight-macos.sh` do not change.
- **`llm_profile` is not a second override path, and the "cloud" filter stays a
  guard.** `effectiveModel` reads `llm_model` only. `LLM_PROFILES.quick.model`
  stays as that profile's tag for `llm_available_profiles` and must equal the
  promoted default, asserted in `server/src/ai/profiles.test.ts`; the profile
  label the settings screen shows is unchanged, so no stored `llm_profile` value
  changes meaning. The resolver does not judge locality or weight format: a
  non-empty stored override is resolved as `source: 'override'`, and
  `isLocalModelTag` and `assertSupportedModelName` remain the guards at the use
  site, unchanged. An override a guard rejects is reported `present: false`,
  because a cloud name is never in the local installed list — health says "your
  setting is in effect and that model is not here", which is the truth, rather
  than silently resolving and showing a different tag.
- **Machine reading survives only for the recommendation.**
  `defaultModelForMachine()` stops selecting: `server/src/ai/ollama.ts:231` falls
  back to the promoted default and `server/src/eval/cli.ts` defaults to the
  promoted default. The name stays exported from
  `server/src/ai/model-picker.ts`, returning the promoted default, because
  `scripts/smoke-live.mjs:39,217` imports it dynamically and that script is
  outside this card's scope; it is a historical name, not a second policy.
  `machineMemoryGib()` survives only as the input to
  `recommendedModelForMemory()`. `installer/src/cli.ts` and
  `installer/src/machine.ts` need no change — `PlanInput.memoryGib` and
  `PlanEvent.memoryGib` stay and are informational.
- **Exports.** `shared/src/index.ts` exports `effectiveModel` and its input and
  result types, and `recommendedModelForMemory`, in the block that re-exports
  `./models.js` today (which loses the `modelForMemory` line), so
  `@apunta/shared`'s single `exports` entry carries the new module deliberately
  rather than by accident. `shared/package.json` is not touched.
- **The setup UI does not move in this card.** `web/**` keeps reading
  `ollama.model` and `ollama.modelPresent`; that is exactly why the health
  change is additive. Collapsing the two pairs into one is deferred, and the
  follow-up is recorded in the return file rather than done here.
- **The installer's `reason`.** `ChosenModel.reason` may no longer cite the
  machine's memory as the reason. For a promoted tag it says Apunta uses the
  same writing model on every machine and that this one was not chosen from
  this Mac's memory; for an override it keeps naming the tag and says it was
  chosen for the machine rather than by Apunta. `PlanEvent.memoryGib` is still
  reported. The recommendation is not added to a new surface in this card;
  `scripts/preflight-macos.sh` may print it as one informational line.
- **The eval digest is not this card's.** C-MODEL@1's "every measurement records
  tag and digest" is S3.2's obligation (`docs/v2/cards/S3.2.md`, Fixed
  decisions: the report records the model tag and digest), and nothing in
  `server/src/eval/` records a digest at the base commit. P1.4 proves the eval
  *default tag* and nothing about digests; adding `ollama show` here would be a
  new measurement path, not a resolver change.
- **Test isolation (HS-2):** V1/V2 run the repository's own vitest suite, which
  opens only temporary databases created by `server/src/test/harness.ts` and by
  `mkdtempSync` under the OS temp dir
  (`server/src/routes/health.test.ts:31-33`), never the platform data folder and
  never the live instance. No test in these rows calls `listen` —
  `health.test.ts` drives `buildApp` and `server.inject` (`:50,61,72`) — and no
  sandbox port is bound, so as in RUN-CONFIG §3 these rows run bare and port
  7717 is never contacted. If any row is later found to bind a fixed port, that
  row alone must move to `scripts/v2/sandbox.mjs`.

## Stop conditions
A **stored** `llm_model` or `llm_profile` value would change meaning under the
new policy — report the value and the case, and do not migrate settings or
touch the owner's database in this card. The by-design change of the effective
tag on installs with no `llm_model` (the promoted default replacing the RAM
tier, e.g. the owner's 16 GiB Linux box moving from `gemma4:12b-it-qat` to
`qwen3.5:4b-q4_K_M`) is C-MODEL@1's intent and is **not** a stop: record that
case in the return file as evidence.
