## Fixed decisions
1. **What becomes a key.** Visible text, aria labels, titles, placeholders,
   empty states, toasts and errors are all catalogue keys, and "Apunta" is
   never translated. This holds for a string **wherever** it is written: a JSX
   text node, one of the four visible attributes, a module-level const, or the
   argument of a thrown `Error`. Such a string is a **UI** key, not
   `errors.<code>`: S2.2's Fixed decision 9 reserves that namespace for the
   server's codes and S2.5 owns the list. This card owns far more of the hard
   class than S2.3 did, so the rule is restated rather than inherited: a
   module const that reaches the screen is a key, exactly as S2.3 made
   `RefineColumn.tsx:15` one.
2. **Keep-as-is tokens, and the only legitimate way to add one.** A keep-as-is
   token that is a **whole literal** (`BrandMark`'s and `BrandWordmark`'s
   `aria-label="Apunta"`, and nothing else in the owned set today) stays in
   `scripts/check-ui-strings.allow.json`, matched whole — a token may be added
   **only** when the whole literal it matches is a product name, an identifier
   or a file name, which is the shape of the ten seeded tokens
   (`check-ui-strings.mjs:44-47`). Adding one to make a row green is HS-7, and
   the response is a `BLOCKED` return naming the `file:line`. A keep-as-is
   token **inside** a translatable sentence is the opposite case: it is
   preserved verbatim in **both** catalogue values, never allowlisted, never
   dropped, never translated, and never split off into a key of its own —
   because the allowlist matches whole strings only (`:248`). The known case is
   `Capture.tsx:389`, `{formatTimer(seconds)} recorded. Nothing has left this
   Mac.`: one key for the whole sentence, with `Mac` verbatim in both values,
   even though `Mac` is already in the allowlist as a whole-literal token.
   That pairing is the trap — a file this card may edit, and a matching entry
   already in the list. `PlanGoalCard.tsx:43`'s `const BLANK = '—'` is the
   other known shape: a separator, which renders as it is in any language and
   is not a key at all.
3. **A date reaches a catalogue as a parameter, never as English text.**
   `PrepView.tsx:174` composes `Review due {formatPlanDate(…)}.`, and
   `formatPlanDate` returns English (`format.ts:90-95`, the hardcoded `en-US`
   `Intl.DateTimeFormat` of `:20-24`); `BackupCard.tsx:393` does the same with
   `instantToLocalDay`. Each becomes one key whose date parameter is declared
   `date` (an ISO value, formatted in the local zone through S2.2's option
   set), so `Aug 8, 2026` is produced by `t()` and never handed to it.
   **Passing the pre-formatted English as a parameter is the failure this
   decision forbids**: V1 goes green, English is unchanged, and the briefing
   keeps saying `Aug 8, 2026` in Spanish until S2.7's copy review finds it. No
   line of `format.ts` or `plural.ts` changes — they stay the oracle.
4. **Stored values are parameters, never keys.** `PlanView.tsx:192` and `:289`
   render `Version {current.version} · {current.status}`: `version` and
   `status` are stored values and go into the catalogue as parameters of one
   key, verbatim, in both languages. C-LANG@1 rule 5 is the reason — guards use
   section roles, not strings, and stored strings are not rewritten. A status
   that needs a display name is a key with the stored value as its parameter,
   not a translation of the stored value.
5. **The checker is necessary, not sufficient, and the two blind spots are
   pinned by tests.** A literal is "JSX text nodes plus the `placeholder`,
   `aria-label`, `title` and `alt` string attributes" (`:29-36`), and the
   pieces JSX leaves when it splits a sentence around an interpolation are
   deliberately unreported. So V1 at `TOTAL 0` is compatible with in-scope
   strings still hardcoded, and this card has more of them than S2.3 did:
   `BackupCard.tsx:180,315-318,393`, `PrepView.tsx:174`,
   `NotesColumn.tsx:132`, `PlanView.tsx:304`, `InstructionsPanel.tsx:124`. Each
   is one key with the interpolated value as a parameter — never two keys
   either side of the interpolation. Each is pinned where a row can see it: the
   owned test files gain cases asserting the rendered text is the catalogue's
   English, in `BackupCard.test.tsx` and `PrepView.test.tsx` for the two date
   sentences and `BrainstormView.test.tsx` for its empty state. Both files
   exist and V2 collects them.
6. **The catalogue grows; the guard does not.** New keys go into both
   `en.ts` and `es-MX.ts` and nowhere else, and the type-level parity rule
   (S2.2's Fixed decision 2) is what stops a key `es-MX` lacks — V4 is its
   only witness, since vitest strips types. A key this card cannot fill with a
   real es-MX string is **reported, not filled with the English**: this is the
   card that adds the large majority of the keys, and an English string in
   `es-MX.ts` passes every row here and is first caught by S2.7's copy review,
   three steps downstream.
7. **English is unchanged.** Every English value this card writes is the
   English the app produces today, character for character (S2.2's Fixed
   decision 6, C-LANG@1 rules 3 and 5). A key whose English is not what the
   screen shows today is a stop, not a copy improvement — S2.7 and S2.8 own the
   copy.
8. **The switch is one line, and only one.** `REPORT_ONLY` at `:62` goes from
   `true` to `false`, and nothing else in `scripts/check-ui-strings.mjs` moves.
   Stated because V1's criterion (`TOTAL 0`) is reachable three ways — by
   extracting the strings, by emptying `DEFAULT_ROOTS` (`:68`) or
   `SCANNED_EXTENSIONS` (`:71`), or by inverting the `allowlist.has` filter
   (`:248`) — and the second set makes every row green with the guard scanning
   nothing. The second set is out of May edit above, and V5 is the row that
   witnesses the difference.
