## Objective
The suite passes in any zone, and each nominal zone run really runs in that
zone.

## Read
`docs/v2/patches/fix-activeSince-timezone.patch`;
`server/src/import/claude.test.ts`; `server/src/import/claude.ts`
(`activeSince`, `planImport`); every `vitest.config.ts`.

## May edit
`server/src/import/claude.test.ts`; `server/src/test/zone.test.ts` (new);
`server/vitest.config.ts` only if a setup file is needed.

## Must not edit
`server/src/import/claude.ts` unless a test proves a real day-boundary bug
(then stop and report instead: that is a different card).

## Fixed decisions
- Apply the patch as is.
- **Do not pin `TZ` globally.** Tests that depend on a zone set and restore
  it themselves (in `beforeEach`/`afterEach`).
- New test `zone.test.ts` prints and asserts
  `Intl.DateTimeFormat().resolvedOptions().timeZone === (process.env.TZ ?? <that value>)`
  so each run's evidence shows its effective zone.

## Known facts
Unpatched, `activeSince` fails under UTC; two `planImport` tests fail under
`Australia/Sydney` (observed on the plan editor's snapshot).

## Steps
1. Run V2 before any change and record the failures. 2. Apply the patch.
3. Make the two `planImport` tests set their own zone. 4. Add `zone.test.ts`.
